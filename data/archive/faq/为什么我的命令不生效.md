# 为什么我的命令不生效？

## Q: 我的数据包加载了但什么都不发生

A: 按优先级排查：
1. **检查加载状态**：`/datapack list` 查看是否启用
2. **检查错误**：`/reload` 后看控制台是否有红色错误
3. **#minecraft:load 会执行但无玩家在线**：`tellraw` 会静默失败。在 load 函数开头加 `say loaded`
4. **语法错误**：`/data get entity @s Inventory` 注意拼写。用 Tab 补全。
5. **文件位置**：函数必须在 `data/<namespace>/function/` 下

## Q: 热重载后还是不生效

- **函数/配方/战利品表/谓词/标签**可以热重载（`/reload`）
- **附魔/世界生成/维度/进度**不可热重载，需**重启服务器**或**重进世界**
- **数据包增加新文件**后必须 `/reload` 才能生效
- **数据包结构变化**：新增目录可能需要重启

## Q: `@e[tag=hello]` 找不到实体

- 标签区分大小写：`Tags:["hello"]` ≠ `Tags:["Hello"]`
- 标签是逗号分隔列表：`Tags:["hello","world"]`
- 用 `data get entity @s Tags` 确认标签存在

## Q: `Inventory[-106b]` 报错

- **1.20.5 ~ 26.0**：副手物品路径为 `Inventory[{Slot:-106b}]`（带 `Slot:`）
- **26.1+**：副手物品路径为 `equipment.offhand`
- 记住：`Inventory` 是列表，后面必须跟索引方式 `[N]` 或 `[{key:value}]`
- 错误的：`Inventory[-106b]` → 正确的：`Inventory[{Slot:-106b}]`

## Q: 文本组件显示为 `[object Object]` 或无法解析

- **1.21.5+** 的 **NBT 存储**（如物品组件、看板）中，文本组件是原生 NBT 复合标签，不再是转义后的 JSON 字符串
- 例子：在命令中依然使用 JSON 格式 `{"text":"Hello"}`，但在 data modify 或物品组件内部，应使用 `{text:"Hello"}`（去掉外层引号和转义）
- 在数据包 JSON 文件中，文本组件字段直接使用 NBT 格式

## Q: `execute storage` 或 `@s[...]` 报错

- **`execute store ...`** 不是 `execute storage` — 没有 `execute storage` 这个命令
- 选择器和参数之间**不能有空格**：`@s[distance=..8]` 正确，`@s [distance=..8]` 错误

## Q: `if items` 检测不对劲

- 物品组件匹配：
  - `*`：任意物品（只检查槽位是否存在物品）
  - `~`：子集匹配（只检查指定组件是否匹配）
  - `=`：精确匹配（物品和所有组件必须完全一致）
- 例子：
  - `if items entity @s weapon.mainhand *[custom_data~{key:true}]`：检查自定义数据
  - `if items entity @s weapon.mainhand minecraft:stone`：精确匹配石头

## Q: 计分板值没有更新

- 检查计分板目标是否存在：`/scoreboard objectives list`
- 检查目标类型是否正确（`dummy` 只能手工改，`kill` 只对杀怪计数）
- 用 `scoreboard players set @s test 5` 手工测试
- 虚拟玩家用 `#` 前缀比用名字更安全

## Q: `/schedule` 函数永远不触发

- `schedule` 的路径必须**带 namespace**：`schedule function mypack:delayed 5s`（不是 `function mypack:delayed 5s`）
- 检查函数路径是否正确
- 重进世界后 `schedule` 会丢失

## Q: 无限递归导致服务器崩溃

- 函数递归深度有限制。MC 会检测到并在崩溃前停止
- 用 `execute if score ... matches 1..` 控制递归条件
- 确保每次递归有终止条件（递减计数器或边界检查）

## Q: 数据包在低版本加载不了

- `pack_format` 必须匹配目标版本
- 使用 `pack.mcmeta` 的 `overlays` 支持多版本（详见[版本兼容策略](../1_最佳实践与设计决策/07_可维护性版本兼容策略.md)）
