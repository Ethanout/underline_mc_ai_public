# 如何做二段跳

## 核心挑战

二段跳（Double Jump）在 Minecraft 原版数据包中的核心挑战是：**原版没有“玩家是否在空中”的直接触发器**。玩家跳跃（Jump）是一个瞬时动作，而“在空中”是一个持续状态。我们需要通过间接手段检测玩家离开地面后再次按下跳跃键，并给予第二次跳跃能力。

## 方案一：基于落地检测 + 跳跃次数计数（推荐，1.13+）

### 原理

1. 使用 `minecraft:location` 进度触发器检测玩家是否在空中（`location` 谓词中的 `dimension` 和 `position` 条件无法直接检测“在空中”，但我们可以检测玩家脚下的方块是否为空气）
2. 使用 `minecraft:tick` 函数每 tick 检测玩家是否在地面上（`on_ground` 选择器参数）
3. 当玩家在地面上时，重置跳跃次数为 0
4. 当玩家在空中且按下跳跃键时（通过 `minecraft:jump` 进度触发器），减少跳跃次数并执行二段跳

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancement/
      jump_detect.json
      reset_jumps.json
    function/
      load.mcfunction
      tick.mcfunction
      double_jump.mcfunction
      reset_jumps.mcfunction
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 初始化所有玩家的跳跃次数
scoreboard objectives add <namespace>.jumps dummy
scoreboard objectives add <namespace>.jump_trigger minecraft:jump
scoreboard players set @a <namespace>.jumps 0

# 给予玩家跳跃检测进度
advancement grant @a only <namespace>:jump_detect
advancement grant @a only <namespace>:reset_jumps
```

#### 2. 跳跃检测进度 (advancement/jump_detect.json)
```json
{
  "criteria": {
    "jump": {
      "trigger": "minecraft:jump"
    }
  },
  "rewards": {
    "function": "<namespace>:double_jump"
  }
}
```

#### 3. 重置跳跃次数进度 (advancement/reset_jumps.json)
```json
{
  "criteria": {
    "on_ground": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": {
          "flags": {
            "is_on_ground": true
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:reset_jumps"
  }
}
```

#### 4. 二段跳执行函数 (function/double_jump.mcfunction)
```mcfunction
# 检查玩家是否在空中（不在空中则不执行）
execute unless entity @s[nbt={OnGround:1b}] run function <namespace>:double_jump/check
# 移除进度，防止重复触发
advancement revoke @s only <namespace>:jump_detect
advancement grant @s only <namespace>:jump_detect
```

#### 5. 二段跳检查子函数 (function/double_jump/check.mcfunction)
```mcfunction
# 检查跳跃次数是否大于0
scoreboard players remove @s <namespace>.jumps 1
execute if score @s <namespace>.jumps matches 0.. run function <namespace>:double_jump/execute
```

#### 6. 执行二段跳 (function/double_jump/execute.mcfunction)
```mcfunction
# 给予玩家向上的速度（二段跳）
effect give @s minecraft:levitation 1 1 true
# 或者使用 motion 直接设置速度（1.13+）
# data modify entity @s Motion set value [0.0,0.42,0.0]
```

#### 7. 重置跳跃次数 (function/reset_jumps.mcfunction)
```mcfunction
# 玩家落地时重置跳跃次数
scoreboard players set @s <namespace>.jumps 2
advancement revoke @s only <namespace>:reset_jumps
advancement grant @s only <namespace>:reset_jumps
```

### 陷阱与注意事项

1. **跳跃检测延迟**：`minecraft:jump` 进度触发器在玩家按下跳跃键的瞬间触发，但此时玩家可能还在地面上（跳跃动作尚未完成）。因此需要在 `double_jump.mcfunction` 中检查 `OnGround` 状态。
2. **多次触发**：玩家在空中连续按下跳跃键会多次触发进度，需要确保每次触发后立即 revoke 并重新 grant 进度。
3. **落地检测精度**：`is_on_ground` 条件在玩家接触地面时立即触发，但有时玩家在跳跃过程中会短暂接触地面（如从台阶上跳下），导致跳跃次数被错误重置。建议使用 `nbt={OnGround:1b}` 配合延迟检测。
4. **性能开销**：每个玩家每次跳跃都会触发函数调用，开销较低。但如果有大量玩家同时跳跃，需要考虑函数调用频率。

## 方案二：基于运动状态检测（1.20.5+，更精确）

### 原理

1. 使用 `minecraft:player_movement` 进度触发器（1.20.5+）检测玩家的运动状态变化
2. 通过 `minecraft:location` 进度检测玩家是否在空中
3. 使用 `minecraft:jump` 进度检测跳跃动作
4. 结合 `scoreboard` 记录跳跃次数

### 陷阱与注意事项

1. **版本要求**：`minecraft:player_movement` 进度触发器在 1.20.5 引入，但本方案未使用该触发器，而是使用 `minecraft:location` 和 `minecraft:jump`，因此兼容 1.13+。
2. **空中检测延迟**：`is_on_ground: false` 条件在玩家离开地面后立即触发，但有时玩家在跳跃过程中会短暂接触地面（如从台阶上跳下），导致跳跃次数被错误重置。
3. **性能开销**：每个玩家每次位置变化都会触发函数调用，开销中等。建议在 tick 函数中统一处理，而不是使用进度触发器。

## 方案三：基于 tick 函数 + 运动检测（1.13+，最稳定）

### 原理

1. 在 tick 函数中每 tick 检测所有玩家的 `OnGround` 状态
2. 使用 `scoreboard` 记录玩家上一 tick 的 `OnGround` 状态
3. 当玩家从 `OnGround: true` 变为 `OnGround: false` 时，记录跳跃次数
4. 当玩家按下跳跃键时（通过 `minecraft:jump` 进度），检查跳跃次数并执行二段跳

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancement/
      jump_detect.json
    function/
      load.mcfunction
      tick.mcfunction
      double_jump.mcfunction
      check_ground.mcfunction
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
scoreboard objectives add <namespace>.jumps dummy
scoreboard objectives add <namespace>.jump_trigger minecraft:jump
scoreboard objectives add <namespace>.on_ground dummy
scoreboard players set @a <namespace>.jumps 2
scoreboard players set @a <namespace>.on_ground 1

advancement grant @a only <namespace>:jump_detect
```

#### 2. 跳跃检测进度 (advancement/jump_detect.json)
```json
{
  "criteria": {
    "jump": {
      "trigger": "minecraft:jump"
    }
  },
  "rewards": {
    "function": "<namespace>:double_jump"
  }
}
```

#### 3. 二段跳执行函数 (function/double_jump.mcfunction)
```mcfunction
# 检查玩家是否在空中
execute unless entity @s[nbt={OnGround:1b}] run function <namespace>:double_jump/check
advancement revoke @s only <namespace>:jump_detect
advancement grant @s only <namespace>:jump_detect
```

#### 4. 二段跳检查子函数 (function/double_jump/check.mcfunction)
```mcfunction
scoreboard players remove @s <namespace>.jumps 1
execute if score @s <namespace>.jumps matches 0.. run function <namespace>:double_jump/execute
```

#### 5. 执行二段跳 (function/double_jump/execute.mcfunction)
```mcfunction
data modify entity @s Motion set value [0.0,0.42,0.0]
```

#### 6. 地面检测函数 (function/check_ground.mcfunction)
```mcfunction
# 检测玩家是否落地
execute as @a at @s run function <namespace>:check_ground/player
```

#### 7. 玩家地面检测子函数 (function/check_ground/player.mcfunction)
```mcfunction
# 获取当前 OnGround 状态
execute store result score @s <namespace>.on_ground if entity @s[nbt={OnGround:1b}]

# 如果上一 tick 在地面，当前也在空中，则减少跳跃次数
execute if score @s <namespace>.on_ground matches 0 if entity @s[nbt={OnGround:0b}] run scoreboard players remove @s <namespace>.jumps 1

# 如果当前在地面，重置跳跃次数
execute if score @s <namespace>.on_ground matches 1 run scoreboard players set @s <namespace>.jumps 2
```

#### 8. tick 函数 (function/tick.mcfunction)
```mcfunction
function <namespace>:check_ground
```

### 陷阱与注意事项

1. **性能开销**：每 tick 对所有玩家执行 `nbt={OnGround:1b}` 检测，开销中等。对于大量玩家（>50），建议使用 `@e[type=player]` 选择器配合 `limit` 参数。
2. **跳跃次数重置时机**：玩家落地时立即重置跳跃次数，但玩家在跳跃过程中可能会短暂接触地面（如从台阶上跳下），导致跳跃次数被错误重置。建议在落地后延迟 1-2 tick 再重置。
3. **跳跃检测精度**：`minecraft:jump` 进度触发器在玩家按下跳跃键的瞬间触发，但此时玩家可能还在地面上。需要在 `double_jump.mcfunction` 中检查 `OnGround` 状态。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 精度 | 适用场景 |
|------|---------|---------|------|---------|
| 方案一：落地检测 + 跳跃计数 | 1.13+ | 低 | 中等 | 简单二段跳，不需要精确控制 |
| 方案二：运动状态检测 | 1.13+ | 中 | 高 | 需要精确检测空中状态的场景 |
| 方案三：tick 函数 + 运动检测 | 1.13+ | 中 | 最高 | 需要稳定、精确的二段跳系统 |

## 总结

- **推荐方案一**：实现简单，性能开销低，适合大多数场景
- **推荐方案三**：精度最高，适合需要精确控制的场景（如平台跳跃游戏）
- **方案二**：介于两者之间，但实现复杂度较高，不推荐

所有方案都需要注意：
1. 玩家在空中时不能无限二段跳，需要限制跳跃次数
2. 玩家落地后需要重置跳跃次数
3. 跳跃检测和落地检测之间可能存在延迟，需要适当处理
