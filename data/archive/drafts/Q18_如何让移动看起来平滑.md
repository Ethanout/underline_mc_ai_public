# 如何让移动看起来平滑

## 问题核心

在 Minecraft 数据包开发中，"平滑移动"通常指让实体（如展示实体、盔甲架、玩家）的位移不是瞬移跳跃，而是像动画一样连续过渡。原版 Minecraft 没有内置的补间动画系统，因此需要利用游戏刻循环、插值机制或实体属性来实现平滑效果。

## 方案一：利用展示实体 (Display Entity) 的插值属性（推荐）

### 原理

Minecraft 1.19.4 引入了展示实体（`minecraft:item_display`、`block_display`、`text_display`），它们原生支持位置和旋转的插值。通过设置 `interpolation_duration`（插值持续的游戏刻数）和 `start_interpolation`（触发插值的 tick 数），可以让展示实体在移动时自动产生平滑过渡动画。

核心机制：
- `interpolation_duration`：指定插值持续多少游戏刻（1 tick = 50ms）
- `start_interpolation`：设置为当前游戏刻数（`game_time`）时触发插值
- 每次修改实体的位置/旋转后，更新 `start_interpolation` 即可触发新的插值

### 完整代码

#### 1. 创建展示实体（初始化）

`data/<namespace>/function/smooth_movement/spawn_display.mcfunction`
```mcfunction
# 生成一个 item_display 实体
summon minecraft:item_display ~ ~ ~ {Tags:["smooth_moving"],interpolation_duration:5,start_interpolation:0,transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[1f,1f,1f]}}

# 设置显示物品（可选）
item replace entity @e[tag=smooth_moving,limit=1] weapon.mainhand with minecraft:diamond
```

#### 2. 移动展示实体并触发插值

`data/<namespace>/function/smooth_movement/move.mcfunction`
```mcfunction
# 假设目标位置存储在 scoreboard 中
# 使用 data modify 修改位置
execute as @e[tag=smooth_moving,limit=1] run data modify entity @s Pos set value [10.0d, 64.0d, 10.0d]

# 触发插值：将 start_interpolation 设置为当前游戏刻
execute store result entity @e[tag=smooth_moving,limit=1] start_interpolation int 1 run time query gametime
```

#### 3. 持续移动（每 tick 更新目标位置）

`data/<namespace>/function/smooth_movement/tick.mcfunction`
```mcfunction
# 每 tick 更新目标位置（例如跟随玩家）
execute as @e[tag=smooth_moving] at @s run function <namespace>:smooth_movement/follow_player
```

`data/<namespace>/function/smooth_movement/follow_player.mcfunction`
```mcfunction
# 获取玩家位置
execute store result score #target_x <namespace> run data get entity @p Pos[0]
execute store result score #target_y <namespace> run data get entity @p Pos[1]
execute store result score #target_z <namespace> run data get entity @p Pos[2]

# 将位置写入展示实体（这里简化，实际需要精确的坐标转换）
data modify entity @s Pos set value [<x>, <y>, <z>]

# 触发插值
execute store result entity @s start_interpolation int 1 run time query gametime
```

### 陷阱与注意事项

1. **插值持续时间**：`interpolation_duration` 设置过小（如 1）会导致动画生硬，过大（如 20）会导致响应延迟。建议 3-5 tick 作为平衡。
2. **位置更新频率**：每 tick 更新位置并触发插值，展示实体会自动处理中间帧。但如果目标位置变化过快，插值可能跟不上，导致"拖尾"效果。
3. **性能开销**：展示实体本身开销较低，但每 tick 修改 NBT 会有一定开销。建议控制展示实体数量在 50 个以内。
4. **版本要求**：需要 Minecraft 1.19.4+。

## 方案二：利用盔甲架 + 计分板插值（通用方案）

### 原理

对于 1.19.4 之前的版本，或需要更精细控制的场景，可以使用盔甲架配合计分板实现线性插值。核心思路：
1. 记录起始位置和结束位置
2. 每 tick 计算当前位置 = 起始位置 + (结束位置 - 起始位置) * (当前进度 / 总进度)
3. 使用 `tp` 命令移动盔甲架

### 完整代码

#### 1. 初始化

`data/<namespace>/function/smooth_movement/init_armor_stand.mcfunction`
```mcfunction
# 生成盔甲架
summon minecraft:armor_stand ~ ~ ~ {Tags:["smooth_as"],Invisible:1b,NoGravity:1b,Marker:1b}

# 初始化计分板
scoreboard objectives add <namespace>.move_progress dummy
scoreboard objectives add <namespace>.move_total dummy
scoreboard objectives add <namespace>.start_x dummy
scoreboard objectives add <namespace>.start_y dummy
scoreboard objectives add <namespace>.start_z dummy
scoreboard objectives add <namespace>.end_x dummy
scoreboard objectives add <namespace>.end_y dummy
scoreboard objectives add <namespace>.end_z dummy
```

#### 2. 设置移动目标

`data/<namespace>/function/smooth_movement/set_target.mcfunction`
```mcfunction
# 假设目标位置在计分板 #target_x/y/z 中
# 记录起始位置
execute as @e[tag=smooth_as,limit=1] store result score @s <namespace>.start_x run data get entity @s Pos[0] 1000
execute as @e[tag=smooth_as,limit=1] store result score @s <namespace>.start_y run data get entity @s Pos[1] 1000
execute as @e[tag=smooth_as,limit=1] store result score @s <namespace>.start_z run data get entity @s Pos[2] 1000

# 设置结束位置
scoreboard players operation @e[tag=smooth_as,limit=1] <namespace>.end_x = #target_x <namespace>
scoreboard players operation @e[tag=smooth_as,limit=1] <namespace>.end_y = #target_y <namespace>
scoreboard players operation @e[tag=smooth_as,limit=1] <namespace>.end_z = #target_z <namespace>

# 设置总进度（例如 20 tick = 1 秒）
scoreboard players set @e[tag=smooth_as,limit=1] <namespace>.move_total 20
scoreboard players set @e[tag=smooth_as,limit=1] <namespace>.move_progress 0
```

#### 3. 每 tick 更新位置

`data/<namespace>/function/smooth_movement/tick_armor_stand.mcfunction`
```mcfunction
# 对每个正在移动的盔甲架执行
execute as @e[tag=smooth_as] if score @s <namespace>.move_progress < @s <namespace>.move_total run function <namespace>:smooth_movement/update_position
```

`data/<namespace>/function/smooth_movement/update_position.mcfunction`
```mcfunction
# 计算当前进度比例（简化：使用整数运算，精度有限）
# 实际位置 = start + (end - start) * progress / total

# 计算差值
scoreboard players operation #dx <namespace> = @s <namespace>.end_x
scoreboard players operation #dx <namespace> -= @s <namespace>.start_x
scoreboard players operation #dy <namespace> = @s <namespace>.end_y
scoreboard players operation #dy <namespace> -= @s <namespace>.start_y
scoreboard players operation #dz <namespace> = @s <namespace>.end_z
scoreboard players operation #dz <namespace> -= @s <namespace>.start_z

# 乘以当前进度
scoreboard players operation #dx <namespace> *= @s <namespace>.move_progress
scoreboard players operation #dy <namespace> *= @s <namespace>.move_progress
scoreboard players operation #dz <namespace> *= @s <namespace>.move_progress

# 除以总进度
scoreboard players operation #dx <namespace> /= @s <namespace>.move_total
scoreboard players operation #dy <namespace> /= @s <namespace>.move_total
scoreboard players operation #dz <namespace> /= @s <namespace>.move_total

# 加上起始位置
scoreboard players operation #dx <namespace> += @s <namespace>.start_x
scoreboard players operation #dy <namespace> += @s <namespace>.start_y
scoreboard players operation #dz <namespace> += @s <namespace>.start_z

# 转换为浮点数并 tp（⚠️ 需验证：scoreboard 到 double 的转换）
execute as @s run tp @s ~ ~ ~
# 实际需要将计分板值转换为坐标，这里简化处理

# 增加进度
scoreboard players add @s <namespace>.move_progress 1
```

### 陷阱与注意事项

1. **精度问题**：计分板是整数运算，位置精度有限。可以通过乘以 1000 再运算来提升精度。
2. **性能开销**：每 tick 进行大量计分板运算，10 个盔甲架以上可能产生明显延迟。
3. **坐标转换**：从计分板到 `tp` 命令的坐标转换需要额外处理，不能直接使用计分板值。
4. **版本兼容**：适用于所有版本，但 1.20.5+ 有更好的方案（展示实体）。

## 方案三：利用玩家移动插值（客户端预测）

### 原理

对于玩家实体，Minecraft 客户端本身有移动插值机制。当服务器更新玩家位置时，客户端会在两帧之间进行插值。通过控制玩家位置更新的频率和幅度，可以让玩家移动看起来更平滑。

核心思路：
1. 使用 `tp` 命令移动玩家，但每次移动距离较小
2. 利用客户端的自动插值产生平滑效果
3. 配合 `attribute` 修改移动速度

### 完整代码

#### 1. 修改玩家移动速度

`data/<namespace>/function/smooth_movement/set_player_speed.mcfunction`
```mcfunction
# 设置玩家移动速度属性（1.20.5+）
attribute @p minecraft:movement_speed base set 0.2

# 1.20.5 之前使用 effect
effect give @p minecraft:speed 999999 0 true
```

#### 2. 平滑传送玩家

`data/<namespace>/function/smooth_movement/smooth_tp.mcfunction`
```mcfunction
# 每 tick 移动一小段距离
# 假设目标位置在 #target_x/y/z 中
# 当前位置在 #current_x/y/z 中

# 计算方向向量
scoreboard players operation #dx <namespace> = #target_x <namespace>
scoreboard players operation #dx <namespace> -= #current_x <namespace>
scoreboard players operation #dy <namespace> = #target_y <namespace>
scoreboard players operation #dy <namespace> -= #current_y <namespace>
scoreboard players operation #dz <namespace> = #target_z <namespace>
scoreboard players operation #dz <namespace> -= #current_z <namespace>

# 归一化并乘以速度（简化：直接除以固定值）
scoreboard players operation #dx <namespace> /= #speed_divisor <namespace>
scoreboard players operation #dy <namespace> /= #speed_divisor <namespace>
scoreboard players operation #dz <namespace> /= #speed_divisor <namespace>

# 执行 tp
tp @p ~ ~ ~
```

### 陷阱与注意事项

1. **客户端预测冲突**：如果服务器频繁更新玩家位置，客户端预测可能被覆盖，导致卡顿。
2. **网络延迟**：玩家移动插值依赖网络延迟，高延迟下效果不佳。
3. **版本差异**：1.20.5+ 的 `attribute` 命令更稳定，旧版本使用 `effect` 可能被其他效果覆盖。
4. **适用场景**：仅适用于玩家实体，不适用于其他实体。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 平滑度 | 适用场景 |
|------|---------|---------|--------|---------|
| 展示实体插值 | 1.19.4+ | 低 | 高（原生插值） | 展示物品、文字、方块 |
| 盔甲架计分板插值 | 所有版本 | 中高 | 中（整数精度限制） | 旧版本兼容、需要自定义缓动函数 |
| 玩家移动插值 | 所有版本 | 低 | 中（依赖客户端） | 玩家传送动画 |

## 总结

- **推荐方案**：展示实体插值（1.19.4+），性能好、平滑度高、实现简单。
- **兼容方案**：盔甲架计分板插值，适用于旧版本或需要自定义缓动函数的场景。
- **玩家专用**：玩家移动插值，适用于玩家传送动画。
