# 如何处理多目标命中

## 问题背景

在 Minecraft 数据包开发中，"多目标命中"指的是一个攻击（如范围爆炸、穿透箭矢、横扫之刃、范围伤害效果）同时命中多个实体时，如何分别检测每个被命中的实体，并对每个实体执行独立的逻辑（如扣血、施加效果、触发事件等）。

核心挑战在于：原版的 `player_hurt_entity` 和 `entity_hurt_player` 进度触发器**每次只记录一个实体**，无法直接获取"本次攻击命中的所有实体"列表。我们需要通过不同的机制来绕过这个限制。

---

## 方案一：基于 `damage` 进度的逐个检测（推荐，1.20.5+）

### 原理

1.20.5 引入了 `minecraft:damage` 进度触发器，它会在**每个实体受到伤害时**触发，并提供了伤害来源的详细信息（包括攻击者、伤害类型、伤害量等）。通过为每个可能的被攻击者添加进度，可以实现"每次命中都触发一个函数"的效果。

核心思路：
- 为所有可能被攻击的实体（如 `@e` 中的生物）添加一个 `damage` 进度
- 进度条件设置为 `source_entity` 为攻击者
- 每次实体被攻击者命中时，进度触发，执行对应的函数

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/damage_detect.json`
```json
{
  "criteria": {
    "damaged": {
      "trigger": "minecraft:damage",
      "conditions": {
        "source_entity": {
          "type": "minecraft:player",
          "distance": {
            "absolute": {
              "max": 64
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_hit"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_hit.mcfunction`
```mcfunction
# 此时 @s 是被命中的实体
# 可以通过 advancement 的 player 参数获取攻击者
# 但注意：damage 进度的 player 是被攻击者，不是攻击者

# 获取攻击者（通过伤害来源）
execute store result score @s hit_count <namespace>.temp run data get entity @s HurtTime

# 实际逻辑：对每个被命中的实体执行操作
# 例如：给被命中的实体施加发光效果
effect give @s minecraft:glowing 3 0 true

# 通知攻击者（如果有）
# 需要先获取攻击者的 UUID，然后通过 @e 选择
execute if data entity @s LastDamageSource.entity run function <namespace>:notify_attacker

# 撤销进度，以便下次再次触发
advancement revoke @s only <namespace>:damage_detect
```

#### 3. 通知攻击者函数

`data/<namespace>/function/notify_attacker.mcfunction`
```mcfunction
# 获取攻击者 UUID
execute store result score $attacker_id <namespace>.temp run data get entity @s LastDamageSource.entity.UUID.Most
execute store result score $attacker_id_low <namespace>.temp run data get entity @s LastDamageSource.entity.UUID.Least

# 通过 UUID 选择攻击者
execute as @e[type=!player] if score $attacker_id = @s UUID.Most if score $attacker_id_low = @s UUID.Least run ...
execute as @a if score $attacker_id = @s UUID.Most if score $attacker_id_low = @s UUID.Least run ...
```

### 陷阱与注意事项

1. **进度触发时机**：`damage` 进度在伤害**应用之后**触发，因此被攻击者的生命值已经减少。如果需要修改伤害量，需要使用 `hurt` 谓词或 `attribute` 修改器。

2. **性能开销**：每个实体每次受伤都会触发进度，如果场景中有大量实体（如 100+），性能开销较高。建议只在需要检测的实体上添加进度，而不是所有实体。

3. **进度撤销**：必须及时撤销进度，否则同一个实体受伤多次时，进度只会触发一次（进度是"一次性"的）。撤销后下次受伤会重新触发。

4. **攻击者获取**：`damage` 进度的 `player` 是被攻击者，不是攻击者。攻击者信息需要通过 `LastDamageSource` NBT 获取，但该 NBT 在实体死亡后会消失。

5. **版本要求**：需要 Minecraft 1.20.5+，因为 `damage` 触发器是在此版本引入的。

## 方案二：基于 `player_hurt_entity` 进度的逐个检测（1.16+）

### 原理

`minecraft:player_hurt_entity` 进度触发器在**玩家**伤害实体时触发，进度条件可以指定被伤害实体的类型、伤害量等。这个方案适用于**只有玩家**作为攻击者的场景。

核心思路：
- 为玩家添加 `player_hurt_entity` 进度
- 每次玩家命中实体时，进度触发，执行函数
- 在函数中通过 `@s` 获取被命中的实体（注意：这里的 `@s` 是玩家，不是被攻击者）

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/player_hurt_detect.json`
```json
{
  "criteria": {
    "hurt_entity": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {
        "entity": {
          "type": "#minecraft:enemy"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_player_hurt"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_player_hurt.mcfunction`
```mcfunction
# @s 是玩家（攻击者）
# 被攻击的实体需要通过 advancement 的 context 获取
# 但 mcfunction 无法直接访问 advancement 的 context

# 方案：使用 storage 存储最近被攻击的实体
# 在 tick 函数中持续更新
execute store result score $last_hurt_id <namespace>.temp run data get entity @s LastHurtEntity

# 通过 LastHurtEntity 选择被攻击的实体
execute as @e[type=!player] if score $last_hurt_id = @s UUID.Most if score $last_hurt_id_low = @s UUID.Least run function <namespace>:process_hit

# 撤销进度
advancement revoke @s only <namespace>:player_hurt_detect
```

#### 3. 处理命中函数

`data/<namespace>/function/process_hit.mcfunction`
```mcfunction
# @s 是被命中的实体
# 执行具体逻辑
effect give @s minecraft:slowness 5 1 true
particle minecraft:crit ~ ~1 ~ 0.5 0.5 0.5 0.1 10

# 通知攻击者（玩家）
execute as @p run tellraw @s [{"text":"命中！","color":"green"}]
```

### 陷阱与注意事项

1. **`@s` 是攻击者**：在 `player_hurt_entity` 进度的奖励函数中，`@s` 是玩家（攻击者），不是被攻击的实体。被攻击的实体需要通过 `LastHurtEntity` NBT 获取。

2. **`LastHurtEntity` 的时效性**：`LastHurtEntity` 在玩家攻击后立即更新，但如果玩家在短时间内攻击多个实体，只有最后一个会被记录。对于范围攻击（如爆炸），这个方案无法检测所有被命中的实体。

3. **非玩家攻击者**：如果攻击者是生物（如骷髅射箭、苦力怕爆炸），这个方案无效。需要回退到方案一。

4. **版本要求**：需要 Minecraft 1.16+，`player_hurt_entity` 触发器在此版本引入。

## 方案三：基于 `entity_hurt_player` 进度的反向检测（1.16+）

### 原理

`minecraft:entity_hurt_player` 进度触发器在**实体伤害玩家**时触发。这个方案适用于检测玩家被多个实体同时攻击的场景（如被多只僵尸围攻）。

核心思路：
- 为玩家添加 `entity_hurt_player` 进度
- 每次玩家被实体伤害时，进度触发
- 通过 `LastAttackedEntity` 获取攻击者

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/entity_hurt_player_detect.json`
```json
{
  "criteria": {
    "hurt_by_entity": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "entity": {
          "type": "#minecraft:enemy"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_player_hurt_by_entity"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_player_hurt_by_entity.mcfunction`
```mcfunction
# @s 是玩家（被攻击者）
# 攻击者通过 LastAttackedEntity 获取
execute store result score $last_attacker_id <namespace>.temp run data get entity @s LastAttackedEntity

# 通过 LastAttackedEntity 选择攻击者
execute as @e[type=!player] if score $last_attacker_id = @s UUID.Most if score $last_attacker_id_low = @s UUID.Least run function <namespace>:process_attacker

# 撤销进度
advancement revoke @s only <namespace>:entity_hurt_player_detect
```

### 陷阱与注意事项

1. **反向逻辑**：这个方案检测的是"玩家被攻击"，而不是"玩家攻击"。适用于防御性逻辑（如反击、护盾）。

2. **`LastAttackedEntity` 的时效性**：与 `LastHurtEntity` 类似，只记录最后一个攻击者。对于同时被多个实体攻击（如范围伤害），无法检测所有攻击者。

3. **版本要求**：需要 Minecraft 1.16+。

## 方案四：基于 `tick` 轮询的批量检测（通用方案，1.13+）

### 原理

不使用进度触发器，而是在每个 tick 中主动检测所有实体的受伤状态。通过检查实体的 `HurtTime` NBT（受伤后的计时器），判断实体是否刚刚受伤。

核心思路：
- 在每个 tick 中遍历所有实体
- 检查 `HurtTime` 是否等于某个特定值（如 9，表示刚刚受伤）
- 如果符合条件，执行命中逻辑

### 完整实现

#### 1. Tick 函数

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 遍历所有实体，检测是否刚刚受伤
execute as @e[type=!player] if data entity @s HurtTime run function <namespace>:check_hurt
execute as @a if data entity @s HurtTime run function <namespace>:check_hurt_player
```

#### 2. 检测函数

`data/<namespace>/function/check_hurt.mcfunction`
```mcfunction
# @s 是实体
# HurtTime 的值：0=未受伤，1-9=受伤后计时，9=刚刚受伤
execute if score @s hurt_time = $target_time run function <namespace>:process_hurt_entity
```

#### 3. 初始化计时器

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 设置目标 HurtTime 值
scoreboard objectives add <namespace>.temp dummy
scoreboard players set $target_time <namespace>.temp 9
```

### 陷阱与注意事项

1. **性能开销高**：每个 tick 遍历所有实体，如果实体数量多（如 200+），性能开销很大。建议只在需要检测的场景中使用，并配合 `type=` 选择器缩小范围。

2. **`HurtTime` 的精度**：`HurtTime` 的值从 9 递减到 0，9 表示刚刚受伤。但不同伤害类型可能导致不同的初始值（如火焰伤害可能不同）。⚠️ 需验证：火焰伤害的 `HurtTime` 初始值是否也是 9。

3. **无法区分攻击者**：这个方案只能检测"实体受伤了"，无法直接获取攻击者信息。如果需要攻击者信息，需要额外存储 `LastDamageSource`。

4. **版本要求**：需要 Minecraft 1.13+（NBT 路径支持）。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|---------|------|------|
| 方案一：`damage` 进度 | 1.20.5+ | 中（每个受伤实体触发一次） | 任何攻击者，任何被攻击者 | 通用性强，能获取攻击者信息 | 需要进度撤销，版本要求高 |
| 方案二：`player_hurt_entity` 进度 | 1.16+ | 低（仅玩家攻击时触发） | 玩家作为攻击者 | 性能好，版本要求低 | 只能检测玩家攻击，无法处理范围攻击 |
| 方案三：`entity_hurt_player` 进度 | 1.16+ | 低（仅玩家被攻击时触发） | 玩家作为被攻击者 | 性能好，版本要求低 | 只能检测玩家被攻击 |
| 方案四：tick 轮询 | 1.13+ | 高（每个 tick 遍历所有实体） | 需要实时监控所有实体受伤 | 通用性最强，版本要求最低 | 性能开销大，无法获取攻击者 |

## 推荐方案

### 场景一：通用多目标命中检测（推荐使用方案一）

如果项目目标版本是 1.20.5+，强烈推荐使用方案一（`damage` 进度）。它是最通用、最可靠的方案，能处理任何攻击者（玩家、生物、环境）和任何被攻击者，并且能获取完整的伤害来源信息。

### 场景二：仅玩家攻击检测（1.16-1.20.4 兼容）

如果项目需要兼容 1.16-1.20.4，使用方案二（`player_hurt_entity` 进度）。注意它只能检测玩家作为攻击者的场景。

### 场景三：低版本通用方案（1.13-1.15）

如果项目需要兼容 1.13-1.15，只能使用方案四（tick 轮询）。注意性能开销，建议配合 `type=` 选择器缩小检测范围。
