# 如何制作机关

## 一、核心挑战与设计思路

在 Minecraft 原版数据包中制作机关，核心挑战在于**如何将玩家的行为（踩压、点击、投掷等）转化为可被数据包持续检测的信号**。原版没有直接的"机关触发"事件，所有检测都需要通过进度（advancement）、谓词（predicate）和命令链的组合来实现。

机关设计通常遵循以下模式：
1. **触发层**：玩家行为 → 进度触发 / 方块状态变化
2. **信号层**：进度奖励函数 / 方块更新 → 执行检测逻辑
3. **响应层**：检测结果 → 执行机关效果（开门、发射、传送等）

## 二、方案一：基于压力板/按钮的简单机关（最基础）

### 原理

利用原版红石元件（压力板、按钮、拉杆）改变方块状态，通过 `execute if block` 或 `execute if blocks` 检测方块状态变化，从而触发机关。

### 适用版本
1.13+（所有版本通用）

### 完整实现

#### 1. 检测压力板被踩下

```mcfunction
# tick.mcfunction - 每 tick 检测
# 检测坐标 (x, y, z) 处的石质压力板是否被激活
execute if block 100 64 200 minecraft:stone_pressure_plate[powered=true] run function namespace:mechanism/triggered
```

#### 2. 检测按钮被按下（需要状态保持）

```mcfunction
# 使用 scoreboard 记录按钮状态
# 初始化（load 中执行）
scoreboard objectives add button_state dummy

# tick.mcfunction
execute store result score #button_pressed namespace if block 100 64 200 minecraft:stone_button[face=wall,facing=north,powered=true]
execute store result score #button_prev namespace run scoreboard players get #button_state namespace

# 检测上升沿（从 0 变 1）
execute if score #button_pressed namespace > #button_prev namespace run function namespace:mechanism/button_press

# 更新状态
scoreboard players operation #button_state namespace = #button_pressed namespace
```

#### 3. 响应函数示例

```mcfunction
# namespace:mechanism/triggered.mcfunction
# 示例：打开铁门
setblock 101 64 200 minecraft:iron_door[facing=north,half=lower,open=true]
# 播放音效
playsound minecraft:block.iron_door.open block @a 101 64 200 1.0 1.0
```

### 陷阱与注意事项

1. **压力板检测延迟**：`execute if block` 每 tick 执行一次，但玩家踩压力板到方块状态更新有 1 tick 延迟（红石 tick），实际检测到的时间可能比预期晚 1-2 tick。
2. **按钮的上升沿检测**：按钮按下后 `powered=true` 持续 1.5 秒（30 tick），如果不做上升沿检测，每 tick 都会触发机关。
3. **多玩家同时触发**：如果多个玩家同时踩同一压力板，`execute if block` 只会检测到一次状态变化，无法区分触发者。

## 三、方案二：基于进度（Advancement）的玩家行为检测

### 原理

利用原版进度系统监听特定玩家行为（如进入特定位置、使用物品、击杀实体等），通过进度奖励函数执行机关逻辑。这是数据包制作机关最灵活的方式。

### 适用版本
1.13+（部分 trigger 需要特定版本）

### 方案 2a：基于位置进入检测（进入区域触发）

#### 原理

使用 `minecraft:location` trigger 检测玩家进入特定位置范围。

#### 完整实现

```json
// data/namespace/advancement/enter_room.json
{
  "criteria": {
    "enter_area": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "location": {
                "position": {
                  "x": {
                    "min": 100,
                    "max": 110
                  },
                  "y": {
                    "min": 63,
                    "max": 68
                  },
                  "z": {
                    "min": 200,
                    "max": 210
                  }
                },
                "dimension": "minecraft:overworld"
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "namespace:mechanism/enter_room"
  }
}
```

```mcfunction
# namespace:mechanism/enter_room.mcfunction
# 触发机关
setblock 105 64 205 minecraft:redstone_block
# 给玩家标记，防止重复触发
advancement revoke @s only namespace:enter_room
# 播放音效
playsound minecraft:block.note_block.bell block @a 105 64 205 1.0 1.0
```

### 方案 2b：基于物品使用检测（投掷物品触发）

#### 原理

使用 `minecraft:item_used_on_block` trigger 检测玩家在特定方块上使用物品。

#### 完整实现

```json
// data/namespace/advancement/use_item_on_block.json
{
  "criteria": {
    "use_item": {
      "trigger": "minecraft:item_used_on_block",
      "conditions": {
        "location": [
          {
            "condition": "minecraft:location_check",
            "predicate": {
              "block": {
                "blocks": ["minecraft:stone_button"],
                "state": {
                  "powered": "false"
                }
              },
              "position": {
                "x": 100,
                "y": 64,
                "z": 200
              }
            }
          }
        ],
        "item": {
          "items": ["minecraft:stick"]
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:mechanism/use_item"
  }
}
```

```mcfunction
# namespace:mechanism/use_item.mcfunction
# 触发机关
setblock 100 64 205 minecraft:redstone_lamp[lit=true]
# 移除进度，允许再次触发
advancement revoke @s only namespace:use_item_on_block
```

### 方案 2c：基于击杀实体检测（击杀触发）

#### 原理

使用 `minecraft:player_killed_entity` trigger 检测玩家击杀特定实体。

#### 完整实现

```json
// data/namespace/advancement/kill_entity.json
{
  "criteria": {
    "kill": {
      "trigger": "minecraft:player_killed_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "minecraft:zombie",
              "nbt": "{Tags:[\"mechanism_target\"]}"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "namespace:mechanism/kill_trigger"
  }
}
```

```mcfunction
# namespace:mechanism/kill_trigger.mcfunction
# 触发机关
execute at @s run summon minecraft:tnt ~ ~ ~ {Fuse:80}
# 移除进度
advancement revoke @s only namespace:kill_entity
```

### 陷阱与注意事项

1. **进度触发频率**：进度触发后不会自动重置，必须在奖励函数中 `advancement revoke` 才能再次触发。如果忘记 revoke，机关只会触发一次。
2. **多玩家并发**：进度是每个玩家独立的，多个玩家可以同时触发同一个进度，奖励函数会为每个触发者执行一次。如果机关需要全局唯一触发（如只开一次门），需要在函数中添加全局状态检测。
3. **`location` trigger 的精度**：`location` trigger 每 tick 检测一次玩家位置，但检测范围是轴对齐的立方体。如果玩家快速移动（如疾跑），可能跳过检测区域。
4. **`item_used_on_block` 的版本要求**：此 trigger 在 1.16+ 引入。1.15 及以下版本需要使用 `minecraft:item_used_on_entity` 或 `minecraft:player_interacted_with_entity` 替代。

## 四、方案三：基于实体交互的机关（右键点击实体触发）

### 原理

利用 `minecraft:player_interacted_with_entity` trigger 检测玩家右键点击特定实体（如盔甲架、村民），从而触发机关。

### 适用版本
1.13+（trigger 在 1.13 引入）

### 完整实现

#### 1. 放置交互实体

```mcfunction
# setup.mcfunction - 在机关位置放置盔甲架
summon minecraft:armor_stand 100 64 200 {Tags:["mechanism_interact"],Invisible:1b,NoGravity:1b,Invulnerable:1b,Marker:1b}
```

#### 2. 创建进度

```json
// data/namespace/advancement/interact_entity.json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "minecraft:armor_stand",
              "nbt": "{Tags:[\"mechanism_interact\"]}"
            }
          }
        ],
        "item": {
          "items": ["minecraft:air"]
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:mechanism/interact_trigger"
  }
}
```

#### 3. 触发函数

```mcfunction
# namespace:mechanism/interact_trigger.mcfunction
# 触发机关
execute at @e[tag=mechanism_interact,limit=1] run setblock ~ ~1 ~ minecraft:redstone_block
# 给玩家反馈
tellraw @s [{"text":"机关已触发！","color":"green"}]
# 移除进度
advancement revoke @s only namespace:interact_entity
```

### 陷阱与注意事项

1. **空手交互检测**：`item` 条件设置为 `minecraft:air` 可以检测空手右键。但注意，如果玩家手持物品右键，即使物品无法与盔甲架交互，也会触发进度。要严格限制空手，需要额外检测。
2. **Marker 盔甲架的交互范围**：Marker 盔甲架（`Marker:1b`）的交互范围是 0，玩家无法右键点击。如果需要交互，必须使用非 Marker 的盔甲架（但会显示碰撞箱）。⚠️ 需验证：1.20.5 之后 Marker 盔甲架的交互行为是否有变化。
3. **多实体冲突**：如果多个交互实体距离很近，玩家右键可能触发错误的实体。建议每个机关使用唯一的 tag。

## 五、方案四：基于记分板（Scoreboard）的定时机关

### 原理

利用 `scoreboard` 的计时功能，实现延迟触发、周期性触发等复杂机关逻辑。

### 适用版本
1.13+（所有版本通用）

### 完整实现

#### 1. 初始化记分板

```mcfunction
# load.mcfunction
scoreboard objectives add mechanism_timer dummy
scoreboard objectives add mechanism_state dummy
```

#### 2. 设置定时器

```mcfunction
# tick.mcfunction - 每 tick 更新定时器
# 增加所有激活的定时器
execute as @e[tag=mechanism_active] run scoreboard players add @s mechanism_timer 1

# 检测定时器到达阈值
execute as @e[tag=mechanism_active] if score @s mechanism_timer >= 20 run function namespace:mechanism/timer_trigger
```

#### 3. 触发定时器

```mcfunction
# namespace:mechanism/start_timer.mcfunction
# 在玩家踩压力板时调用
# 给盔甲架添加 tag 并重置计时
tag @e[type=minecraft:armor_stand,tag=mechanism_timer,limit=1] add mechanism_active
scoreboard players set @e[type=minecraft:armor_stand,tag=mechanism_timer,limit=1] mechanism_timer 0
```

#### 4. 定时触发函数

```mcfunction
# namespace:mechanism/timer_trigger.mcfunction
# 定时器到达 20 tick（1秒）
# 执行机关效果
execute at @s run setblock ~ ~1 ~ minecraft:redstone_block
# 重置定时器
scoreboard players set @s mechanism_timer 0
tag @s remove mechanism_active
```

### 陷阱与注意事项

1. **实体数量限制**：每个定时器需要一个实体（如盔甲架）来存储记分板值。大量定时器会消耗实体数量上限（`max_entities`）。
2. **记分板溢出**：`scoreboard players add` 不会自动溢出，如果定时器值超过 2^31-1（约 21 亿），会回绕到负数。对于机关定时器，通常不会达到这个值。
3. **多实例冲突**：如果多个定时器使用同一个实体，需要确保 tag 和记分板值的管理正确，避免互相干扰。

## 六、方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|---------|------|------|
| 压力板/按钮检测 | 1.13+ | 低 | 简单触发、红石联动 | 实现简单，无需进度系统 | 无法区分触发者，延迟 1-2 tick |
| 位置进入检测 | 1.13+ | 低 | 区域进入、房间检测 | 精确检测玩家位置，可区分触发者 | 需要进度 revoke，快速移动可能跳过 |
| 物品使用检测 | 1.16+ | 低 | 解谜、投掷触发 | 可检测特定物品，交互自然 | 版本要求较高 |
| 击杀实体检测 | 1.13+ | 低 | 战斗机关、Boss 战 | 与战斗系统结合紧密 | 需要实体存在 |
| 实体交互检测 | 1.13+ | 低 | 按钮替代、NPC 交互 | 可自定义交互位置 | Marker 盔甲架交互范围问题 |
| 记分板定时器 | 1.13+ | 中 | 延迟触发、周期性机关 | 灵活控制时间 | 需要实体存储状态 |

## 七、综合建议

1. **简单机关**（如开门、亮灯）：优先使用压力板/按钮检测，配合红石即可，无需数据包。
2. **需要区分玩家的机关**（如单人解谜）：使用进度系统，特别是 `location` 或 `item_used_on_block` trigger。
3. **需要延迟或周期的机关**（如陷阱、传送带）：使用记分板定时器方案。
4. **需要交互反馈的机关**（如点击按钮）：使用实体交互方案，配合 `tellraw` 给玩家反馈。
