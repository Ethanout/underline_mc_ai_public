# 如何创建世界实体

## 一、什么是世界实体

在 Minecraft 数据包开发中，"世界实体"（World Entity）指的是**不绑定到任何玩家、区块加载或特定维度的持久化实体**。常见用途包括：
- 全局计时器/调度器
- 跨维度数据存储
- 全局状态标记（如是否下雨、是否白天）
- 数据包内部的事件总线

核心挑战：原版 Minecraft 没有原生的"全局实体"概念。所有实体都存在于特定维度、特定位置，且受区块加载影响。我们需要用各种技巧模拟出"全局存在"的效果。

## 二、方案一：虚空中的标记实体（最常用）

### 原理

在世界的虚空（y=-64 以下）生成一个标记实体（Marker），并确保它始终处于加载状态。通过 `@e[type=minecraft:marker,limit=1,sort=nearest]` 或自定义标签来引用它。

### 版本要求

- 1.17+（Marker 实体引入）
- 1.20.5+（推荐，Marker 实体行为更稳定）

### 完整实现

#### 1. 生成世界实体（load 函数）

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 检查是否已存在世界实体
execute unless entity @e[type=minecraft:marker,tag=<namespace>.world_entity] run function <namespace>:world_entity/spawn
```

`data/<namespace>/function/world_entity/spawn.mcfunction`
```mcfunction
# 在虚空生成标记实体
summon minecraft:marker ~ ~-100 ~ {Tags:["<namespace>.world_entity"]}

# 可选：设置初始数据
data modify entity @e[type=minecraft:marker,tag=<namespace>.world_entity,limit=1] data.<namespace>.tick_count set value 0
```

#### 2. 使用世界实体（tick 函数）

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 确保世界实体存在（防止被意外清除）
execute unless entity @e[type=minecraft:marker,tag=<namespace>.world_entity,limit=1] run function <namespace>:world_entity/spawn

# 执行全局逻辑
execute as @e[type=minecraft:marker,tag=<namespace>.world_entity,limit=1] run function <namespace>:world_entity/tick
```

`data/<namespace>/function/world_entity/tick.mcfunction`
```mcfunction
# 示例：全局计时器
data modify entity @s data.<namespace>.tick_count set value 0
scoreboard players add @s <namespace>.global_timer 1

# 每 100 tick 执行一次事件
execute if score @s <namespace>.global_timer matches 100 run function <namespace>:events/every_100_ticks
```

#### 3. 数据存储（使用 Storage）

`data/<namespace>/function/world_entity/save_data.mcfunction`
```mcfunction
# 将世界实体的数据复制到 Storage 以便跨维度访问
data modify storage <namespace>:global data set from entity @e[type=minecraft:marker,tag=<namespace>.world_entity,limit=1] data
```

### 陷阱与注意事项

1. **区块加载问题**：标记实体必须位于常加载区块中。推荐在出生点区块（spawn chunk）生成，或使用 `/forceload` 强制加载。
   ```mcfunction
   # 在 spawn 函数中
   execute positioned 0 -60 0 run forceload add ~ ~
   ```

2. **实体被意外清除**：`/kill @e[type=minecraft:marker]` 或某些模组可能清除标记实体。需要在 tick 中定期检查并重生。

3. **多维度问题**：标记实体只能存在于一个维度。如果需要在多个维度访问，建议使用 Storage 作为中间层（见方案二）。

4. **性能开销**：较低。Marker 实体本身不进行 AI 计算，仅占用实体列表中的一个槽位。

## 三、方案二：Storage 全局存储（纯数据方案）

### 原理

利用 Minecraft 的 `storage` 数据存储机制。Storage 是全局的、跨维度的、不依赖于任何实体的数据容器。通过 `data modify storage <namespace>:global` 读写数据。

### 版本要求

- 1.15+（Storage 引入）

### 完整实现

#### 1. 初始化 Storage

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 初始化全局数据
data modify storage <namespace>:global data set value {tick_count: 0, flags: {}}
```

#### 2. 使用 Storage

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 更新全局计时器
data modify storage <namespace>:global data.tick_count set value 0
scoreboard players add $global <namespace>.timer 1

# 每 100 tick 执行事件
execute if score $global <namespace>.timer matches 100 run function <namespace>:events/every_100_ticks
```

#### 3. 跨函数访问

`data/<namespace>/function/check_global_state.mcfunction`
```mcfunction
# 检查全局状态
execute if data storage <namespace>:global {data: {flags: {event_triggered: true}}} run say 事件已触发！
```

### 陷阱与注意事项

1. **无法直接执行实体相关命令**：Storage 不是实体，不能使用 `execute as`、`execute at` 等。如果需要实体上下文，必须结合方案一。

2. **数据持久化**：Storage 数据在服务器重启后**不会自动保存**。需要在 `minecraft:save` 事件中手动保存到实体或文件。
   ```mcfunction
   # 在 save 事件中
   data modify entity @e[type=minecraft:marker,tag=<namespace>.world_entity,limit=1] data set from storage <namespace>:global data
   ```

3. **性能开销**：极低。Storage 操作是纯内存操作，没有实体开销。

## 四、方案三：常加载区块中的盔甲架（兼容旧版本）

### 原理

在 1.17 之前，没有 Marker 实体。使用盔甲架（Armor Stand）作为替代，放置在常加载区块中，并设置 `Marker:1b` 和 `Invisible:1b` 使其不可见。

### 版本要求

- 1.13+（数据包功能引入）
- 1.17 之前（Marker 实体未引入时）

### 完整实现

#### 1. 生成盔甲架

`data/<namespace>/function/world_entity/spawn.mcfunction`
```mcfunction
# 生成不可见标记盔甲架
summon minecraft:armor_stand ~ ~-100 ~ {Marker:1b,Invisible:1b,NoGravity:1b,Tags:["<namespace>.world_entity"],Small:1b}
```

#### 2. 使用盔甲架

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 确保存在
execute unless entity @e[type=minecraft:armor_stand,tag=<namespace>.world_entity,limit=1] run function <namespace>:world_entity/spawn

# 执行逻辑
execute as @e[type=minecraft:armor_stand,tag=<namespace>.world_entity,limit=1] run function <namespace>:world_entity/tick
```

### 陷阱与注意事项

1. **盔甲架有碰撞箱**：即使设置了 `Marker:1b`，在某些版本中仍可能被活塞推动或受到伤害。建议同时设置 `Invulnerable:1b`。

2. **性能开销**：中等。盔甲架比 Marker 实体有更多的属性（如装备、姿势等），占用更多资源。

3. **版本兼容性**：在 1.17+ 中，Marker 实体是更好的选择。盔甲架方案仅用于兼容旧版本。

## 五、方案对比

| 方案 | 版本要求 | 性能开销 | 跨维度访问 | 数据持久化 | 适用场景 |
|------|---------|---------|-----------|-----------|---------|
| 虚空标记实体 | 1.17+ | 低 | 需通过 Storage 中转 | 自动（实体保存） | 需要实体上下文的全局逻辑 |
| Storage 全局存储 | 1.15+ | 极低 | 直接访问 | 需手动保存 | 纯数据存储、跨维度通信 |
| 常加载盔甲架 | 1.13+ | 中 | 需通过 Storage 中转 | 自动（实体保存） | 兼容旧版本（1.17 之前） |

## 六、最佳实践建议

1. **现代版本（1.20.5+）**：使用"虚空标记实体 + Storage"组合。标记实体负责实体上下文（如执行命令），Storage 负责数据存储。

2. **旧版本（1.13-1.16）**：使用"常加载盔甲架 + Storage"组合。

3. **纯数据包（无实体需求）**：仅使用 Storage 即可。

4. **数据持久化**：始终在 `minecraft:save` 事件中将 Storage 数据同步到实体。

## 八、陷阱总结

1. **区块加载**：标记实体必须位于常加载区块中，否则会随区块卸载而消失。
2. **实体清除**：`/kill @e` 或某些命令会清除所有实体，包括标记实体。务必在 tick 中检查并重生。
3. **多维度问题**：标记实体只能存在于一个维度。跨维度访问必须通过 Storage。
4. **数据持久化**：Storage 数据不会自动保存，必须在 `minecraft:save` 事件中手动同步。
5. **版本兼容性**：Marker 实体在 1.17 引入，旧版本需使用盔甲架。
6. **性能考虑**：虽然单个标记实体开销很低，但大量使用（如每个玩家一个）仍可能影响性能。
