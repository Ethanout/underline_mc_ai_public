# 如何制作过场镜头

## 一、核心挑战

Minecraft 原版没有内置的“过场动画”系统。制作过场镜头的核心挑战在于：
1. **视角控制**：原版无法直接锁定/强制玩家视角（Spectator 模式除外）
2. **平滑移动**：需要实现位置/旋转的插值过渡
3. **玩家输入屏蔽**：防止玩家在过场期间移动或操作
4. **多玩家兼容**：多人模式下需要为每个玩家独立控制

## 二、方案一：Spectator 模式 + 实体视角绑定（推荐，1.13+）

### 原理

利用 Spectator 模式（`gamemode spectator`）的特性：
- 玩家可以穿透方块
- 玩家无法与方块/实体交互
- 玩家可以绑定到任意实体上，跟随其视角

通过创建一个标记实体（Marker），控制其位置和旋转，让玩家绑定到该实体上，即可实现过场镜头。

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      cutscene/
        start.mcfunction
        tick.mcfunction
        stop.mcfunction
        move.mcfunction
        rotate.mcfunction
      _init.mcfunction
    advancements/
      cutscene_tick.json
```

#### 1. 初始化（创建标记实体）

`data/<namespace>/functions/_init.mcfunction`
```mcfunction
# 创建过场镜头标记实体（仅执行一次）
summon marker ~ ~ ~ {Tags:["cutscene_camera"],CustomName:'"Cutscene Camera"',CustomNameVisible:0b}
```

#### 2. 开始过场

`data/<namespace>/functions/cutscene/start.mcfunction`
```mcfunction
# 用法：execute as <player> run function <namespace>:cutscene/start
# 将玩家设为旁观模式并绑定到镜头实体
gamemode spectator @s
spectate @e[tag=cutscene_camera,limit=1] @s

# 存储玩家信息以便恢复
scoreboard players set @s cutscene_active 1
```

#### 3. 每 tick 控制镜头

`data/<namespace>/functions/cutscene/tick.mcfunction`
```mcfunction
# 每 tick 执行一次，控制镜头移动
# 示例：沿 X 轴移动并旋转
execute as @e[tag=cutscene_camera] at @s run tp @s ~0.1 ~ ~ ~0.5 ~
```

#### 4. 停止过场

`data/<namespace>/functions/cutscene/stop.mcfunction`
```mcfunction
# 恢复玩家为生存模式
gamemode survival @s
spectate @s

# 清除标记
scoreboard players set @s cutscene_active 0
```

#### 5. 自动 tick 系统（使用进度）

`data/<namespace>/advancements/cutscene_tick.json`
```json
{
  "criteria": {
    "tick": {
      "trigger": "minecraft:tick"
    }
  },
  "rewards": {
    "function": "<namespace>:cutscene/tick"
  }
}
```

### 陷阱与注意事项

1. **玩家无法交互**：Spectator 模式下玩家无法打开容器、攻击、放置方块。过场结束后必须恢复模式。
2. **多人兼容**：每个玩家需要独立的镜头实体，否则所有玩家会看到同一个视角。
3. **实体加载**：标记实体必须在玩家所在区块加载范围内，否则 spectate 会失效。
4. **版本要求**：`spectate` 命令在 1.15+ 可用，1.13-1.14 需使用 `/execute as @e[tag=cutscene_camera] at @s run tp @s ~ ~ ~` 间接控制。
5. **平滑移动**：上述示例是线性移动，如需缓动效果，需使用 scoreboard 计算插值。

## 三、方案二：TP 命令 + 玩家位置覆盖（1.13+，无需 Spectator）

### 原理

不改变玩家游戏模式，通过每 tick 强制 TP 玩家到指定位置和旋转角度，同时使用 `input` 谓词检测玩家输入并屏蔽。

### 完整实现

#### 1. 开始过场

`data/<namespace>/functions/cutscene/start.mcfunction`
```mcfunction
# 存储玩家原始位置
data modify storage <namespace>:cutscene player_pos set from entity @s Pos
data modify storage <namespace>:cutscene player_rot set from entity @s Rotation

# 标记过场状态
scoreboard players set @s cutscene_active 1

# 设置初始镜头位置
tp @s <x> <y> <z> <yaw> <pitch>
```

#### 2. 每 tick 强制位置

`data/<namespace>/functions/cutscene/tick.mcfunction`
```mcfunction
# 对每个活跃玩家强制 TP
execute as @a[scores={cutscene_active=1}] at @s run function <namespace>:cutscene/force_tp
```

`data/<namespace>/functions/cutscene/force_tp.mcfunction`
```mcfunction
# 示例：沿路径移动
# 使用 scoreboard 计算当前帧位置
scoreboard players add @s cutscene_frame 1

# 根据帧数计算位置（简化示例，实际需用更复杂的插值）
execute if score @s cutscene_frame matches 0..100 run tp @s ~0.1 ~ ~ ~0.5 ~
execute if score @s cutscene_frame matches 101..200 run tp @s ~ ~0.05 ~ ~0.3 ~
execute if score @s cutscene_frame matches 201.. run function <namespace>:cutscene/stop
```

#### 3. 停止过场

`data/<namespace>/functions/cutscene/stop.mcfunction`
```mcfunction
# 恢复玩家到原始位置
execute as @s at @s run tp @s <x> <y> <z> <yaw> <pitch>

# 清除状态
scoreboard players set @s cutscene_active 0
scoreboard players set @s cutscene_frame 0
```

### 陷阱与注意事项

1. **玩家输入问题**：玩家仍然可以移动、跳跃、攻击。需要额外屏蔽输入：
   - 使用 `effect give @s minecraft:slowness 1 255 true` 限制移动
   - 使用 `effect give @s minecraft:mining_fatigue 1 255 true` 限制挖掘
   - 使用 `effect give @s minecraft:weakness 1 255 true` 限制攻击
   - 使用 `effect give @s minecraft:jump_boost 128 0 true` 限制跳跃（负效果）
2. **网络延迟**：强制 TP 会有轻微延迟，玩家可能看到短暂闪烁。
3. **多人兼容**：每个玩家独立控制，但需要确保所有玩家都在同一位置序列中。
4. **版本要求**：1.13+ 可用，1.12 及以下需使用 `/tp @p <x> <y> <z>` 语法。

## 四、方案三：Camera 命令（1.21.2+，最推荐）

### 原理

Minecraft 1.21.2 引入了 `/camera` 命令，可以原生控制玩家视角，支持平滑过渡、淡入淡出、视角锁定等功能。这是目前最优雅的过场镜头方案。

### 完整实现

#### 1. 基本过场

`data/<namespace>/functions/cutscene/start.mcfunction`
```mcfunction
# 设置过场镜头
camera @s set minecraft:fixed 0.5 0.5 0.5
# 参数：fadeInDuration, stayDuration, fadeOutDuration（单位：tick）
# 这里设置 20 tick 淡入，100 tick 停留，20 tick 淡出

# 设置镜头位置
camera @s set minecraft:fixed 0.5 0.5 0.5 pos ~10 ~5 ~10 rotation 45 30
```

#### 2. 平滑过渡

`data/<namespace>/functions/cutscene/move.mcfunction`
```mcfunction
# 平滑移动到新位置
camera @s set minecraft:fixed 0.5 0.5 0.5 pos ~20 ~10 ~20 rotation 90 45
# 使用默认的 0.5 秒过渡
```

#### 3. 淡入淡出效果

`data/<namespace>/functions/cutscene/fade.mcfunction`
```mcfunction
# 淡出
camera @s fade color 0 0 0 fade 0 20 0
# 等待 20 tick 后执行下一个镜头

# 淡入
camera @s fade color 0 0 0 fade 20 0 0
```

#### 4. 停止过场

`data/<namespace>/functions/cutscene/stop.mcfunction`
```mcfunction
# 恢复玩家视角
camera @s clear
```

### 陷阱与注意事项

1. **版本要求**：仅 1.21.2+ 可用，早期版本无法使用。
2. **玩家交互**：`fixed` 模式下玩家无法移动视角，但可以移动和交互。如需完全锁定，需配合其他机制。
3. **多人兼容**：每个玩家独立控制，命令支持 `@s` 选择器。
4. **过渡时间**：`fade` 参数的单位是 tick，注意换算。
5. **坐标系统**：`pos` 参数使用绝对坐标，`rotation` 使用 yaw/pitch。

## 五、方案对比

| 特性 | Spectator 绑定 | TP 强制 | Camera 命令 |
|------|---------------|---------|-------------|
| 最低版本 | 1.13 (spectate 1.15+) | 1.13 | 1.21.2 |
| 玩家交互屏蔽 | 完全屏蔽 | 需额外效果 | 部分屏蔽 |
| 平滑过渡 | 需手动实现 | 需手动实现 | 内置支持 |
| 淡入淡出 | 需手动实现 | 需手动实现 | 内置支持 |
| 性能开销 | 低 | 中（每 tick TP） | 低 |
| 实现复杂度 | 中 | 高 | 低 |
| 推荐场景 | 1.15-1.21.1 | 1.13-1.14 | 1.21.2+ |

## 六、最佳实践建议

1. **1.21.2+ 首选 Camera 命令**：最简洁、功能最完整。
2. **1.15-1.21.1 使用 Spectator 绑定**：性能好，但需注意版本差异。
3. **1.13-1.14 使用 TP 强制**：兼容性最好，但实现最复杂。
4. **所有方案都需要考虑**：
   - 过场结束后恢复玩家状态（模式、位置、效果）
   - 多人模式下为每个玩家独立控制
   - 防止玩家在过场期间断开连接导致状态残留
