# 如何制作残影

## 一、什么是残影

残影（Afterimage / Ghost Trail）是指玩家移动时，在身后留下一系列逐渐消失的玩家模型副本，常见于动作游戏或跑酷地图中。在 Minecraft 原版数据包中实现残影的核心挑战是：**如何高效地复制玩家外观并使其随时间淡出**。

## 二、方案一：ArmorStand + 玩家 NBT 复制法（推荐）

### 原理

利用 `summon` 命令生成 ArmorStand，通过 `data modify` 将玩家的外观数据（皮肤、装备、主副手物品等）复制到 ArmorStand 上，使其看起来像玩家。然后通过计分板或 `age` 标签控制其消失。

### 版本要求

- 1.13+（`data modify` 命令引入）
- 1.20.5+（`item` 组件系统变化，但本方案使用 NBT 路径，兼容性较好）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      load.mcfunction
      tick.mcfunction
      afterimage/
        spawn.mcfunction
        tick.mcfunction
        remove.mcfunction
    advancements/
      afterimage_trigger.json
```

#### 1. 加载函数
`data/<namespace>/functions/load.mcfunction`
```mcfunction
# 初始化计分板
scoreboard objectives add afterimage_timer dummy
scoreboard objectives add afterimage_id dummy

# 设置全局参数（可选）
scoreboard players set #max_distance afterimage_timer 3
scoreboard players set #spawn_interval afterimage_timer 2
```

#### 2. 主循环
`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 执行残影逻辑
execute as @a at @s run function <namespace>:afterimage/spawn
execute as @e[type=minecraft:armor_stand,tag=afterimage] at @s run function <namespace>:afterimage/tick
```

#### 3. 生成残影
`data/<namespace>/functions/afterimage/spawn.mcfunction`
```mcfunction
# 检查是否达到生成间隔（每 2 tick 生成一次）
scoreboard players add @s afterimage_timer 1
execute if score @s afterimage_timer >= #spawn_interval afterimage_timer run function <namespace>:afterimage/spawn_actual
```

`data/<namespace>/functions/afterimage/spawn_actual.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s afterimage_timer 0

# 生成 ArmorStand
summon minecraft:armor_stan ~ ~ ~ {Invisible:1b,NoGravity:1b,Marker:1b,Tags:["afterimage"],ArmorItems:[{},{},{},{}],HandItems:[{},{}]}

# 复制玩家外观到 ArmorStand
execute as @e[type=minecraft:armor_stand,tag=afterimage,sort=nearest,limit=1] run data modify entity @s ArmorItems set from entity @p ArmorItems
execute as @e[type=minecraft:armor_stand,tag=afterimage,sort=nearest,limit=1] run data modify entity @s HandItems set from entity @p HandItems
execute as @e[type=minecraft:armor_stand,tag=afterimage,sort=nearest,limit=1] run data modify entity @s Rotation set from entity @p Rotation

# 设置残影存活时间（20 tick = 1 秒）
execute as @e[type=minecraft:armor_stand,tag=afterimage,sort=nearest,limit=1] run data merge entity @s {Tags:["afterimage","alive"],Age:-20}
```

#### 4. 残影更新
`data/<namespace>/functions/afterimage/tick.mcfunction`
```mcfunction
# 增加年龄（Age 会自动增加，但我们可以用计分板控制）
scoreboard players add @s afterimage_id 1

# 当年龄达到阈值时移除
execute if score @s afterimage_id matches 20.. run function <namespace>:afterimage/remove
```

#### 5. 移除残影
`data/<namespace>/functions/afterimage/remove.mcfunction`
```mcfunction
# 播放粒子效果（可选）
particle minecraft:cloud ~ ~1 ~ 0.5 0.5 0.5 0 5

# 移除 ArmorStand
kill @s
```

### 陷阱与注意事项

1. **ArmorStand 的 `Marker` 标签**：设置为 `1b` 后，ArmorStand 的碰撞箱消失，但外观仍然可见。如果不设置，残影会阻挡玩家移动。
2. **`Invisible` 与 `Marker` 的关系**：`Invisible:1b` 会使 ArmorStand 本体不可见，但装备物品仍然显示。这是残影显示的关键。
3. **性能问题**：每个残影都是一个实体，大量残影（>50）会导致性能下降。建议限制最大残影数量。
4. **玩家外观复制不完整**：`ArmorItems` 和 `HandItems` 只能复制装备和手持物品，无法复制玩家的皮肤纹理。ArmorStand 会使用默认的史蒂夫皮肤。
5. **`Age` 标签的自动增长**：ArmorStand 的 `Age` 标签每 tick 自动增加 1，但初始值可以设置负数来延迟消失。注意：`Age` 达到 0 时实体不会被自动清除，需要手动检测。

## 三、方案二：玩家实体克隆法（更逼真但更复杂）

### 原理

利用 `clone` 或 `summon` 生成一个完整的玩家实体（通过 `data modify` 复制玩家 NBT），然后通过 `team` 和 `effect` 控制其行为。这种方法可以复制玩家的皮肤和完整外观。

### 版本要求

- 1.13+（`data modify` 命令）
- ⚠️ 需验证：`summon` 玩家实体在 1.20.5+ 是否仍然有效

### 完整实现

#### 1. 生成克隆玩家
`data/<namespace>/functions/afterimage/spawn_clone.mcfunction`
```mcfunction
# 生成一个标记实体作为占位
summon minecraft:marker ~ ~ ~ {Tags:["afterimage_clone","temp"]}

# 复制玩家 NBT 到标记实体
execute as @e[type=minecraft:marker,tag=temp,sort=nearest,limit=1] run data modify entity @s data set from entity @p

# 将标记实体转换为玩家（⚠️ 需验证：此方法在 1.20.5+ 是否可行）
execute as @e[type=minecraft:marker,tag=temp,sort=nearest,limit=1] run summon minecraft:player ~ ~ ~ {Tags:["afterimage_clone"]}
execute as @e[type=minecraft:player,tag=afterimage_clone,sort=nearest,limit=1] run data modify entity @s set from entity @e[type=minecraft:marker,tag=temp,sort=nearest,limit=1] data

# 移除标记实体
kill @e[type=minecraft:marker,tag=temp]
```

#### 2. 控制克隆玩家
`data/<namespace>/functions/afterimage/tick_clone.mcfunction`
```mcfunction
# 设置克隆玩家为旁观模式（不可交互）
effect give @s minecraft:invisibility 1 0 true

# 设置队伍（避免攻击）
team join afterimage @s

# 逐渐透明（通过计分板控制）
scoreboard players add @s afterimage_alpha 1
execute if score @s afterimage_alpha matches 10.. run kill @s
```

### 陷阱与注意事项

1. **玩家实体生成限制**：Minecraft 不允许通过命令直接 `summon` 玩家实体（`minecraft:player` 不是有效的实体类型）。此方案理论上不可行，仅作为思路参考。
2. **替代方案**：可以使用 `minecraft:interaction` 或 `minecraft:marker` 作为占位，但无法复制玩家皮肤。
3. **安全性问题**：克隆玩家实体可能被服务器视为作弊行为，在多人服务器上可能触发反作弊系统。

## 四、方案三：粒子系统模拟法（轻量级）

### 原理

利用粒子效果模拟残影。在玩家经过的位置生成大量粒子，通过粒子的颜色、大小和持续时间来模拟残影效果。

### 版本要求

- 1.13+（粒子命令支持自定义数据）
- 1.20.5+（粒子系统优化）

### 完整实现

#### 1. 生成粒子残影
`data/<namespace>/functions/afterimage/particle_spawn.mcfunction`
```mcfunction
# 在玩家位置生成粒子
particle minecraft:dust 0.5 0.5 0.5 1 ~ ~1 ~ 0.5 0.5 0.5 0 10

# 使用实体效果粒子（更逼真）
particle minecraft:entity_effect ~ ~1 ~ 0.5 0.5 0.5 0.5 5
```

#### 2. 连续生成（在 tick 中调用）
`data/<namespace>/functions/afterimage/particle_tick.mcfunction`
```mcfunction
# 每 tick 生成粒子，形成拖尾效果
execute at @s run particle minecraft:dust 0.3 0.3 0.3 0.5 ~ ~1 ~ 0.2 0.2 0.2 0 3
execute at @s run particle minecraft:entity_effect ~ ~1 ~ 0.3 0.3 0.3 0.3 2
```

### 陷阱与注意事项

1. **粒子可见性**：粒子效果受 `particle` 设置影响，玩家可能需要在视频设置中开启粒子效果。
2. **性能影响**：大量粒子（>100/tick）会导致性能下降，建议控制粒子数量。
3. **视觉效果有限**：粒子无法完全模拟玩家外观，只能提供模糊的残影效果。

## 五、方案对比

|------|---------|---------|---------|---------|

## 六、最佳实践建议

1. **对于大多数场景**：使用 ArmorStand 复制法，配合 `Marker` 和 `Invisible` 标签，可以获得较好的视觉效果和性能平衡。
2. **限制残影数量**：使用计分板跟踪残影数量，超过阈值时移除最早的残影。
3. **优化生成间隔**：每 2-3 tick 生成一个残影，避免每 tick 生成导致性能问题。
4. **使用 `return` 优化**：在 1.20.5+ 中，可以使用 `return run` 来优化函数调用链。

## 八、常见问题

### Q: 残影会阻挡玩家移动吗？
A: 使用 `Marker:1b` 标签后，ArmorStand 没有碰撞箱，不会阻挡移动。

### Q: 残影会显示玩家的皮肤吗？
A: 不会。ArmorStand 只能显示装备物品，无法复制玩家的皮肤纹理。如果需要皮肤效果，可以考虑使用资源包配合。

### Q: 如何让残影逐渐消失？
A: 可以通过逐渐减少 ArmorStand 的 `ArmorItems` 中的物品数量，或者使用粒子效果配合。但原版 ArmorStand 不支持透明度渐变。

### Q: 多人服务器上性能如何？
A: 每个玩家生成 10-20 个残影，30 个玩家同时在线时，实体数量可能达到 600+，会对服务器造成较大压力。建议限制残影数量并优化生成间隔。
