# 如何同步动画和实际判定

## 问题背景

在 Minecraft 数据包开发中，"动画"（如玩家挥臂、物品使用动画、实体姿态变化）和"实际判定"（如伤害计算、效果应用、状态变更）之间存在天然的时序差异。动画是客户端渲染的视觉表现，而判定是服务端逻辑。两者不同步会导致：
- 玩家看到自己挥剑但伤害已经打出（视觉滞后）
- 玩家看到怪物抬手但实际伤害已经计算（判定超前）
- 使用物品时动画播放完毕但效果未触发（判定滞后）

核心挑战：**服务端无法直接控制客户端动画的播放时机，只能通过触发机制间接同步。**

---

## 方案一：使用 `used_item` 进度 + 物品使用时长控制

**适用版本**：1.20.5+（`used_item` trigger 在 1.20.5 引入）
**推荐程度**：⭐⭐⭐⭐⭐（最推荐，原生支持）

### 原理

Minecraft 1.20.5 引入了 `minecraft:used_item` 进度触发器，它在玩家**完成**物品使用（即物品使用动画播放完毕）时触发。通过配合物品的 `use_duration` 组件，可以精确控制动画时长与判定时机同步。

### 完整实现

#### 1. 定义自定义物品（使用数据包物品）

`<namespace>/item/ritual_sword.json`
```json
{
  "model": {
    "type": "minecraft:model",
    "model": "<namespace>:item/ritual_sword"
  },
  "components": {
    "minecraft:use_duration": 20,
    "minecraft:use_animation": "bow",
    "minecraft:max_stack_size": 1,
    "minecraft:rarity": "epic"
  }
}
```

#### 2. 创建进度监听

`<namespace>/advancement/use_ritual_sword.json`
```json
{
  "criteria": {
    "used_sword": {
      "trigger": "minecraft:used_item",
      "conditions": {
        "item": {
          "items": "<namespace>:ritual_sword"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:ritual/on_use_complete"
  }
}
```

#### 3. 判定函数

`<namespace>/function/ritual/on_use_complete.mcfunction`
```mcfunction
# 此时动画已播放完毕，执行实际判定
effect give @s minecraft:strength 10 1 true
particle minecraft:witch ~ ~1 ~ 0.5 0.5 0.5 0.1 50

# 移除进度，允许下次触发
advancement revoke @s only <namespace>:use_ritual_sword
```

### 陷阱与注意事项

1. **`use_duration` 的单位是游戏刻**：20 游戏刻 = 1 秒。注意 `use_duration` 是物品使用所需的总时长，不是动画时长。动画时长由 `use_animation` 决定，但 `use_duration` 必须 >= 动画时长才能保证动画完整播放。
2. **`used_item` 只在物品使用完成时触发**：如果玩家中途松开右键（取消使用），不会触发。这符合"动画完成才判定"的需求。
3. **物品必须可食用或可使用**：只有设置了 `use_duration` 和 `use_animation` 的物品才能被"使用"。普通物品（如剑）默认没有使用动画，需要手动添加组件。
4. **版本要求**：`used_item` trigger 是 1.20.5 新增，旧版本无法使用此方案。

## 方案二：使用 `player_interacted_with_entity` + 延迟函数

**适用版本**：1.16+
**推荐程度**：⭐⭐⭐⭐（兼容性好，但需要手动控制延迟）

### 原理

当玩家与实体交互（右键点击）时，客户端立即播放交互动画（如挥臂），而服务端同时触发 `player_interacted_with_entity` 进度。通过在触发后延迟执行判定函数，可以模拟"等待动画播放完毕"的效果。

### 完整实现

#### 1. 创建进度

`<namespace>/advancement/interact_with_entity.json`
```json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "minecraft:villager"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:interact/delayed_judge"
  }
}
```

#### 2. 延迟判定函数

`<namespace>/function/interact/delayed_judge.mcfunction`
```mcfunction
# 方案A：使用 schedule 延迟（推荐）
schedule function <namespace>:interact/judge 10t replace

# 方案B：使用计分板倒计时（更精确但更复杂）
# scoreboard players add @s <namespace>.interact_delay 1
# execute if score @s <namespace>.interact_delay matches 10 run function <namespace>:interact/judge

advancement revoke @s only <namespace>:interact_with_entity
```

`<namespace>/function/interact/judge.mcfunction`
```mcfunction
# 10 游戏刻后执行实际判定
say 交互动画已播放完毕，执行判定！
# 实际判定逻辑...
```

### 陷阱与注意事项

1. **延迟时长需要手动调整**：不同交互动画的时长不同（如挥臂约 5-6 刻，使用物品约 20 刻）。需要根据实际动画测试确定最佳延迟值。
2. **`schedule` 的精度问题**：`schedule` 函数在指定延迟后执行，但如果服务器负载高，可能会有 1-2 刻的偏差。对于要求精确同步的场景（如连击判定），建议使用计分板倒计时。
3. **玩家可能移动或死亡**：在延迟期间，玩家可能移动位置或死亡。判定函数中需要重新获取玩家位置，并检查玩家是否存活。
4. **`player_interacted_with_entity` 触发条件**：只有玩家右键点击实体时触发，左键攻击不会触发。如果需要检测攻击动画，请使用方案三。

## 方案三：使用 `player_hurt_entity` + 攻击冷却同步

**适用版本**：1.16+
**推荐程度**：⭐⭐⭐（仅适用于攻击场景，需要处理冷却）

### 原理

Minecraft 的攻击动画（挥臂）与攻击冷却（`attackStrength`）绑定。当玩家攻击实体时，服务端触发 `player_hurt_entity` 进度，同时客户端播放挥臂动画。通过检测攻击冷却状态，可以判断动画是否播放完毕。

### 完整实现

#### 1. 创建进度

`<namespace>/advancement/attack_entity.json`
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "#minecraft:enemy"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:attack/on_hit"
  }
}
```

#### 2. 攻击判定函数

`<namespace>/function/attack/on_hit.mcfunction`
```mcfunction
# 获取攻击冷却进度（0.0 ~ 1.0）
execute store result score @s <namespace>.attack_cooldown run data get entity @s Attributes[0].Base 100

# 如果冷却进度 >= 0.8（动画接近完成），执行判定
execute if score @s <namespace>.attack_cooldown matches 80.. run function <namespace>:attack/judge

# 否则延迟执行
execute if score @s <namespace>.attack_cooldown matches ..79 run schedule function <namespace>:attack/delayed_judge 5t replace

advancement revoke @s only <namespace>:attack_entity
```

`<namespace>/function/attack/delayed_judge.mcfunction`
```mcfunction
# 重新检查冷却状态
execute store result score @s <namespace>.attack_cooldown run data get entity @s Attributes[0].Base 100
execute if score @s <namespace>.attack_cooldown matches 80.. run function <namespace>:attack/judge
```

### 陷阱与注意事项

1. **攻击冷却数据获取方式**：⚠️ 需验证。`Attributes[0].Base` 可能不是攻击速度的正确路径。实际应使用 `data get entity @s Attributes[0].Base` 获取基础攻击速度，然后通过 `attackStrength` 属性计算冷却进度。更可靠的方式是使用 `scoreboard players get @s minecraft:attack_strength`（如果已启用）。
2. **攻击动画时长不固定**：挥臂动画时长取决于攻击速度（`attackSpeed` 属性）。默认攻击速度为 4.0（即 5 刻冷却），但可以通过属性修改。需要动态计算延迟。
3. **`player_hurt_entity` 在伤害应用后触发**：这意味着实际伤害已经计算完毕，动画同步主要用于视觉反馈，而非控制伤害时机。
4. **多目标攻击问题**：如果玩家使用横扫攻击（Sweeping Edge），一次攻击可能触发多次 `player_hurt_entity`。需要在判定函数中处理重复触发。

## 方案四：使用 `item_used_on_block` + 方块放置动画同步

**适用版本**：1.20.5+
**推荐程度**：⭐⭐⭐（特定场景，如自定义方块交互）

### 原理

当玩家在方块上使用物品时，客户端播放使用动画（如放置方块、交互等）。`item_used_on_block` 进度在物品使用完成时触发，与 `used_item` 类似，但额外提供了方块位置信息。

### 完整实现

#### 1. 创建进度

`<namespace>/advancement/use_on_block.json`
```json
{
  "criteria": {
    "use_block": {
      "trigger": "minecraft:item_used_on_block",
      "conditions": {
        "item": {
          "items": "<namespace>:magic_wand"
        },
        "location": [
          {
            "condition": "minecraft:location_check",
            "predicate": {
              "block": {
                "blocks": ["minecraft:enchanting_table"]
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:magic/on_use_complete"
  }
}
```

#### 2. 判定函数

`<namespace>/function/magic/on_use_complete.mcfunction`
```mcfunction
# 获取方块位置（通过 advancement 的 location 条件已确保）
# 执行魔法效果
setblock ~ ~1 ~ minecraft:redstone_block
particle minecraft:end_rod ~ ~1 ~ 0.5 0.5 0.5 0.1 20

advancement revoke @s only <namespace>:use_on_block
```

### 陷阱与注意事项

1. **`item_used_on_block` 与 `used_item` 的区别**：`item_used_on_block` 专门用于"在方块上使用物品"的场景，而 `used_item` 是通用的物品使用完成触发。如果物品使用不涉及方块（如喝药水），应使用 `used_item`。
2. **方块位置获取**：进度条件中的 `location` 只能用于过滤，无法直接传递方块坐标给函数。如果需要方块位置，需要在函数中通过 `execute positioned` 或 `data get` 获取玩家视线目标方块。
3. **物品使用取消**：如果玩家在使用过程中移动或受到攻击，物品使用可能被取消，此时不会触发进度。

## 方案对比

| 方案 | 版本要求 | 同步精度 | 性能开销 | 适用场景 |
|------|---------|---------|---------|---------|
| 方案一：`used_item` | 1.20.5+ | 高（原生同步） | 低 | 自定义物品使用、魔法施法、物品交互 |
| 方案二：延迟函数 | 1.16+ | 中（手动调参） | 中 | 实体交互、NPC对话、旧版本兼容 |
| 方案三：攻击冷却 | 1.16+ | 中（依赖冷却计算） | 中 | 攻击动画同步、连击系统 |
| 方案四：`item_used_on_block` | 1.20.5+ | 高（原生同步） | 低 | 方块交互、自定义工作台 |

**推荐选择**：
- 如果目标版本 ≥ 1.20.5，优先使用方案一或方案四
- 如果需要兼容旧版本（1.16-1.20.4），使用方案二
- 如果专门处理攻击动画，方案三可作为补充

## 通用陷阱与最佳实践

1. **避免在 tick 函数中频繁检测动画状态**：动画是客户端概念，服务端无法直接读取。不要尝试通过 `data get entity` 获取动画状态，这会导致性能问题且不可靠。
2. **使用 `advancement revoke` 防止重复触发**：所有进度方案都需要在判定函数中撤销进度，否则玩家每次触发都会执行判定函数。
3. **考虑多人游戏延迟**：在多人游戏中，客户端和服务端之间存在网络延迟。即使动画同步完美，玩家感知到的"同步"也可能有偏差。对于竞技性场景，建议以服务端判定为准。
4. **测试不同物品的动画时长**：不同 `use_animation` 的动画时长不同（如 `bow` 约 20 刻，`crossbow` 约 25 刻，`eat` 约 32 刻）。使用方案二时，需要针对每种物品单独测试并调整延迟。
