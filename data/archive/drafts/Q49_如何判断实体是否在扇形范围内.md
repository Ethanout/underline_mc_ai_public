# 如何判断实体是否在扇形范围内

## 问题核心

在 Minecraft 数据包中判断实体是否在扇形范围内，核心挑战在于：
1. 原版没有直接的“扇形检测”谓词或命令
2. 需要结合**距离检测**和**角度检测**两个维度
3. 角度计算需要借助数学运算，而原版命令的数学能力有限

## 方案一：基于 `execute` 条件子命令 + 记分板数学运算（推荐）

### 原理

利用 `execute if entity` 的距离筛选先缩小范围，再通过记分板计算目标实体相对于检测者的水平角度，与检测者的朝向角度进行比较，判断是否在扇形内。

扇形参数：
- 圆心：检测者位置
- 半径：最大检测距离
- 方向：检测者的水平朝向（yaw）
- 角度：扇形张角（如 90° 表示左右各 45°）

### 完整实现

#### 1. 初始化记分板（load 函数）

```mcfunction
# load.mcfunction
scoreboard objectives add angle dummy
scoreboard objectives add yaw_diff dummy
scoreboard objectives add distance dummy
```

#### 2. 主检测函数（每 tick 执行）

```mcfunction
# tick.mcfunction
execute as @a at @s run function namespace:scan/check
```

```mcfunction
# namespace:function/scan/check.mcfunction
# 参数设置（可根据需要调整）
# 扇形半径：10 格
# 扇形张角：90°（左右各 45°）

# 第一步：筛选距离 ≤ 10 的实体
execute as @e[type=!minecraft:player, distance=..10] at @s run function namespace:scan/calc_angle
```

```mcfunction
# namespace:function/scan/calc_angle.mcfunction
# 计算目标相对于检测者的水平角度
# 使用 atan2 近似：通过记分板计算

# 存储检测者的位置
scoreboard players operation @s angle = @s angle

# 计算相对坐标
execute store result score @s angle run data get entity @s Pos[0] 1000
scoreboard players operation @s angle -= @p angle
# 此时 @s angle 存储的是 (target_x - player_x) * 1000

# 计算相对 Z
execute store result score @s yaw_diff run data get entity @s Pos[2] 1000
scoreboard players operation @s yaw_diff -= @p yaw_diff
# 此时 @s yaw_diff 存储的是 (target_z - player_z) * 1000

# 计算水平角度（近似 atan2）
# 使用预计算的角度查找表或近似公式
# 这里使用简单的象限判断 + 比例近似
execute if score @s angle > 0 if score @s yaw_diff > 0 run scoreboard players operation @s angle = @s angle
# ...（实际需要更复杂的角度计算，此处简化）

# 获取检测者的 yaw
execute store result score @p yaw_diff run data get entity @p Rotation[0] 100

# 计算角度差
scoreboard players operation @s angle -= @p yaw_diff
# 取绝对值
execute if score @s angle < 0 run scoreboard players operation @s angle *= -1

# 判断是否在扇形内（角度差 ≤ 45°）
execute if score @s angle matches ..4500 run function namespace:scan/in_cone
```

```mcfunction
# namespace:function/scan/in_cone.mcfunction
# 目标在扇形内，执行后续逻辑
say 发现目标！
# 可以在这里执行攻击、标记等操作
```

### 陷阱与注意事项

1. **角度计算精度**：原版记分板只能存储整数，角度需要乘以 100 或 1000 来保留精度。但 atan2 的精确计算在原版中非常困难，通常需要预计算查找表或使用近似公式。
2. **Yaw 范围**：Minecraft 的 yaw 范围是 -180 到 180，计算角度差时需要处理跨边界情况（如 -179° 和 179° 实际只差 2°）。
3. **性能开销**：每 tick 对每个潜在目标执行数学运算，如果目标数量较多（>50），性能开销会显著增加。
4. **版本要求**：1.13+（`execute store` 和 `data get` 命令）

## 方案二：基于 `predicate` + `execute if predicate`（1.19+）

### 原理

利用 1.19 引入的 `player` 谓词中的 `looking_at` 条件，结合距离检测，实现扇形检测的近似效果。

**注意**：此方案只能检测玩家是否**看向**某个实体，不能检测任意实体之间的扇形关系。

### 完整实现

#### 1. 创建谓词

```json
// namespace:predicate/looking_at_target.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "player": {
      "looking_at": {
        "distance": {
          "absolute": {
            "max": 10.0
          }
        }
      }
    }
  }
}
```

#### 2. 检测函数

```mcfunction
# namespace:function/check_looking.mcfunction
# 检测玩家是否看向某个实体
execute as @e[type=!minecraft:player, distance=..10] at @s run function namespace:check_target
```

```mcfunction
# namespace:function/check_target.mcfunction
# 对每个潜在目标，检测玩家是否看向它
execute if predicate namespace:looking_at_target run say 玩家正在看向我！
```

### 陷阱与注意事项

1. **局限性**：`looking_at` 只能检测玩家看向实体，不能检测任意两个实体之间的方向关系。
2. **精度问题**：`looking_at` 检测的是玩家视线与实体碰撞箱的交集，不是精确的扇形区域。
3. **性能**：`looking_at` 检测本身开销较低，但需要遍历所有潜在目标。
4. **版本要求**：1.19+（`looking_at` 谓词）

## 方案三：基于 `area_effect_cloud` + 旋转检测（1.13+，高开销）

### 原理

利用 `area_effect_cloud`（AEC）的 `Rotation` 标签，通过命令旋转 AEC 来模拟扇形扫描。但此方案效率极低，仅作为理论参考。

### 实现思路（不推荐）

1. 在检测者位置生成一个 AEC
2. 将 AEC 的 Rotation 设置为检测者的朝向
3. 使用 `execute rotated` 将 AEC 的朝向旋转到扇形边界
4. 检测 AEC 与目标之间的相对位置

### 陷阱

1. **性能极差**：每 tick 生成和操作 AEC 会导致严重的性能问题
2. **精度有限**：无法精确控制扇形角度
3. **不推荐使用**：仅作为理论探讨

## 方案对比

| 方案 | 版本要求 | 性能开销 | 精度 | 适用场景 |
|------|---------|---------|------|---------|
| 方案一：记分板数学运算 | 1.13+ | 中（取决于目标数量） | 高（可调精度） | 通用扇形检测，任意实体间 |
| 方案二：predicate looking_at | 1.19+ | 低 | 中（视线检测） | 仅玩家看向实体 |
| 方案三：AEC 旋转 | 1.13+ | 极高 | 低 | 不推荐 |

## 推荐方案

**方案一**是最通用且可控的方案，虽然实现复杂，但可以精确控制扇形参数（半径、角度、方向），适用于大多数场景。

**方案二**适用于只需要检测玩家是否看向某个实体的场景，实现简单，性能好。

## 进阶优化

对于方案一，可以使用预计算的角度查找表来优化 atan2 计算：

```mcfunction
# 预计算角度表（在 load 中执行）
# 使用 storage 存储角度值
data modify storage namespace:angle_table set value {0:0, 100:1, 200:2, ...}
```

或者使用更简单的近似公式：
```
angle ≈ (target_z - player_z) / (target_x - player_x) * 57.3
```
（乘以 57.3 将弧度转换为度）
