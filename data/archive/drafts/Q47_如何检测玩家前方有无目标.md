# 如何检测玩家前方有无目标

## 问题核心挑战

在 Minecraft 数据包开发中，"检测玩家前方有无目标"是一个高频需求（用于瞄准系统、技能锁定、NPC 交互等）。核心挑战在于：

1. **原版没有直接的"视线检测"谓词或 trigger**——你必须组合多个机制来模拟
2. **方向判断**：需要知道玩家面朝的方向向量，并判断目标是否在该方向上
3. **距离与遮挡**：需要判断目标是否在有效距离内，以及中间是否有方块遮挡
4. **性能**：高频检测（如每 tick）时，穷举所有实体并做向量运算开销较大

## 方案一：基于 `execute` 条件子命令 + 射线检测（推荐，1.20.5+）

### 原理

利用 `execute` 的 `if entity` 条件子命令配合 `distance`、`predicate`（视线方向）和 `anchored eyes` 来模拟射线检测。核心思路：

1. 从玩家眼睛位置出发
2. 沿玩家视线方向，以一定步长（如 0.5 格）向前推进
3. 在每个步长位置检测是否有实体（使用 `@e[distance=..0.5]`）
4. 同时检测该位置是否有方块（使用 `if block` 判断是否被遮挡）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      raycast/
        tick.mcfunction          # 主循环，每 tick 调用
        step.mcfunction          # 单步推进逻辑
        hit.mcfunction           # 命中目标时执行
        miss.mcfunction          # 未命中时执行
    predicates/
      looking_at.json            # 视线方向谓词（可选）
```

#### 1. 主循环（每 tick 调用）

`data/<namespace>/functions/raycast/tick.mcfunction`
```mcfunction
# 初始化射线参数
scoreboard players set @s ray_distance 0
scoreboard players set @s ray_max_distance 64
scoreboard players set @s ray_step 1

# 开始射线检测
execute as @a at @s anchored eyes run function <namespace>:raycast/step
```

#### 2. 单步推进

`data/<namespace>/functions/raycast/step.mcfunction`
```mcfunction
# 检查当前步长是否超过最大距离
execute if score @s ray_distance >= @s ray_max_distance run return run function <namespace>:raycast/miss

# 检查当前位置是否有实体（距离 0.5 格内）
execute if entity @e[distance=..0.5,type=!minecraft:player,limit=1] run return run function <namespace>:raycast/hit

# 检查当前位置是否有方块遮挡（非空气方块）
execute unless block ~ ~ ~ air run return run function <namespace>:raycast/miss

# 沿视线方向前进一个步长
# ⚠️ 需验证：1.20.5+ 中 ^ ^ ^ 的步长单位是格，但方向是局部坐标
# 这里使用 ^ ^ ^0.5 表示沿视线方向前进 0.5 格
execute positioned ^ ^ ^0.5 run function <namespace>:raycast/step
```

#### 3. 命中处理

`data/<namespace>/functions/raycast/hit.mcfunction`
```mcfunction
# 标记命中目标
scoreboard players set @s ray_hit 1

# 获取命中的第一个实体（可选：存储到 storage 供后续使用）
execute as @e[distance=..0.5,type=!minecraft:player,limit=1] run data modify storage <namespace>:raycast hit_entity set from entity @s UUID

# 执行命中逻辑（示例：给目标加 glowing 效果）
effect give @e[distance=..0.5,type=!minecraft:player,limit=1] minecraft:glowing 1 0
```

#### 4. 未命中处理

`data/<namespace>/functions/raycast/miss.mcfunction`
```mcfunction
# 标记未命中
scoreboard players set @s ray_hit 0

# 清除命中实体记录
data remove storage <namespace>:raycast hit_entity
```

### 陷阱与注意事项

1. **步长选择**：步长越小越精确，但性能开销越大。0.5 格是较好的平衡点。步长 0.1 格时，64 格距离需要 640 次递归调用，可能导致性能问题。
2. **递归深度限制**：Minecraft 函数递归深度默认 65536，但实际建议不超过 1000 层。64 格 / 0.5 步长 = 128 层，安全。
3. **实体类型过滤**：`@e[distance=..0.5]` 会检测到玩家自己（因为玩家眼睛位置到自身碰撞箱的距离可能小于 0.5）。必须用 `type=!minecraft:player` 排除。
4. **方块遮挡检测**：`unless block ~ ~ ~ air` 只能检测空气方块。对于玻璃、树叶等透明方块，需要更复杂的检测（如使用 `#minecraft:replaceable` 标签）。
5. **性能**：每 tick 对每个玩家执行 128 次 `if entity` 和 `unless block`，对于 10 个玩家就是 1280 次/ tick。建议只在需要时启用（如玩家手持特定物品时）。

## 方案二：基于 `predicate` + `execute if predicate`（1.19+）

### 原理

利用原版的 `looking_at` 谓词（1.19 引入）检测玩家是否正在注视某个实体。这个谓词基于玩家的视线向量和实体的碰撞箱计算，比手动射线更精确。

### 完整实现

#### 1. 创建谓词

`data/<namespace>/predicates/looking_at.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "type_specific": {
      "type": "minecraft:player",
      "looking_at": {
        "type": "minecraft:entity",
        "predicate": {
          "type": "#minecraft:enemy"
        }
      }
    }
  }
}
```

#### 2. 在 tick 中使用

`data/<namespace>/functions/raycast/tick.mcfunction`
```mcfunction
# 检测玩家是否正在注视敌对生物
execute as @a at @s if predicate <namespace>:looking_at run function <namespace>:raycast/hit
execute as @a at @s unless predicate <namespace>:looking_at run function <namespace>:raycast/miss
```

### 陷阱与注意事项

1. **版本要求**：`looking_at` 谓词在 1.19 引入，1.19.3 之前有 bug（某些情况下不触发），建议 1.19.4+ 使用。
2. **距离限制**：`looking_at` 默认检测距离为 10 格（玩家与目标的距离）。可以通过 `distance` 谓词调整，但无法超过 64 格（硬编码限制）。
3. **遮挡检测**：`looking_at` 会自动检测视线是否被方块遮挡（基于碰撞箱），但透明方块（如玻璃）会被视为遮挡。
4. **性能**：比手动射线好，因为原版内部优化了计算。但每 tick 对所有玩家执行谓词检测，开销中等。
5. **无法自定义步长**：无法控制检测精度，完全由原版算法决定。

## 方案三：基于 `execute` + `facing` 条件 + `distance`（1.13+，低精度）

### 原理

不进行逐格射线，而是直接检测玩家面朝方向与目标之间的角度差。使用 `execute if entity @s[facing=@e[type=...]]` 判断玩家是否面朝某个实体。

### 完整实现

`data/<namespace>/functions/raycast/tick.mcfunction`
```mcfunction
# 检测玩家是否面朝 10 格内的任意敌对生物
execute as @a at @s if entity @s[facing=@e[type=#minecraft:enemy,distance=..10,limit=1]] run function <namespace>:raycast/hit
execute as @a at @s unless entity @s[facing=@e[type=#minecraft:enemy,distance=..10,limit=1]] run function <namespace>:raycast/miss
```

### 陷阱与注意事项

1. **精度极低**：`facing` 条件只检查玩家面朝方向是否大致指向目标（基于玩家位置到目标中心的向量），不检查视线是否被遮挡。即使中间有墙，也会判定为"前方有目标"。
2. **角度容差**：原版 `facing` 的容差是多少？⚠️ 需验证：据社区测试，大约 ±45° 的锥形范围，但具体数值未公开。
3. **性能**：`facing=@e[...]` 会对每个符合条件的实体计算方向，如果实体数量多（如 100+），性能开销较大。
4. **适用场景**：只适合"大致方向"检测（如 NPC 对话触发），不适合精确瞄准。

## 方案对比

| 方案 | 版本要求 | 精度 | 遮挡检测 | 性能 | 适用场景 |
|------|---------|------|---------|------|---------|
| 方案一：手动射线 | 1.13+（`positioned` 1.13+） | 高（可调步长） | 支持（需手动实现） | 中-高（取决于步长和距离） | 精确瞄准、技能锁定 |
| 方案二：`looking_at` 谓词 | 1.19+（推荐 1.19.4+） | 高（原版算法） | 支持（自动） | 中 | 通用视线检测 |
| 方案三：`facing` 条件 | 1.13+ | 低（±45° 锥形） | 不支持 | 低 | 粗略方向检测 |

## 推荐方案

- **1.19.4+ 且需要精确检测**：方案二（`looking_at` 谓词），最简单且精确
- **1.13-1.18 或需要自定义步长/遮挡逻辑**：方案一（手动射线）
- **只需要大致方向**：方案三（`facing` 条件），代码最少

## 进阶技巧：结合方案一和方案二

对于 1.19.4+，可以先用方案二快速筛选出"正在注视"的实体，再用方案一进行精确的逐格检测（只对筛选出的实体执行），大幅减少性能开销。

```mcfunction
# 先用 looking_at 谓词筛选
execute as @a at @s if predicate <namespace>:looking_at run function <namespace>:raycast/refine

# refine 函数中只对筛选出的实体执行精确射线
# 这样可以避免对每个玩家都执行 128 步射线
```
