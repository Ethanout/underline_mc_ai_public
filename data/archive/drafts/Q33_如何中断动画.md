# 如何中断动画

## 核心挑战

在 Minecraft Java Edition 中，玩家执行某些动作（如吃食物、拉弓、使用盾牌、放置方块等）时会触发动画。原版游戏没有提供直接的“取消当前动画”命令。数据包开发者需要利用游戏机制来“欺骗”客户端或服务端，使其提前结束动画状态。

## 方案一：切换物品法（最通用，1.13+）

### 原理

当玩家手持的物品发生变化时，服务端会强制结束当前进行的任何物品使用动画（如吃东西、拉弓、使用盾牌）。通过快速切换主手物品（例如替换为空气或另一个物品），可以中断动画。

### 完整代码

**方案A：替换为空气（1.13+）**

```mcfunction
# 中断玩家 @s 的当前动画
# 将主手物品替换为空气，再恢复原物品
# 注意：这会触发 inventory_changed 进度

# 1. 将主手物品存入 storage
data modify storage <namespace>:temp item set from entity @s Inventory[{Slot:-106b}]

# 2. 清空主手
item replace entity @s weapon.mainhand with air

# 3. 恢复原物品（延迟 1 tick 以避免同一 tick 内检测不到变化）
schedule function <namespace>:restore_item 1
```

```mcfunction
# <namespace>:restore_item
# 从 storage 恢复物品
item replace entity @s weapon.mainhand from storage <namespace>:temp item
```

**方案B：使用物品修改器（1.20.5+，更优雅）**

```mcfunction
# 使用 item modifier 临时修改物品的 custom_data，触发物品变化
# 优点：不需要存储和恢复，副作用更小

item modify entity @s weapon.mainhand <namespace>:interrupt_animation
```

```json
// <namespace>/item_modifier/interrupt_animation.json
{
  "function": "minecraft:set_custom_data",
  "tag": "{<namespace>:{interrupt:1b}}",
  "conditions": []
}
```

然后需要另一个 modifier 来清除这个标记（在下一 tick 执行）：

```mcfunction
# 在下一 tick 清除标记
item modify entity @s weapon.mainhand <namespace>:clear_interrupt
```

```json
// <namespace>/item_modifier/clear_interrupt.json
{
  "function": "minecraft:set_custom_data",
  "tag": "{<namespace>:{interrupt:0b}}",
  "conditions": []
}
```

### 陷阱与注意事项

1. **触发 inventory_changed 进度**：切换物品会触发 `inventory_changed` 进度，如果你的数据包依赖这个进度做其他事情，需要处理递归调用。
2. **创造模式玩家**：在创造模式下，物品替换可能不会按预期工作，因为创造模式玩家可以无限复制物品。
3. **副手物品**：如果动画是由副手物品触发的（如副手持盾牌），需要切换副手物品而不是主手。
4. **1 tick 延迟**：方案A需要至少1 tick的延迟来恢复物品，否则在同一 tick 内服务端可能检测不到变化。
5. **⚠️ 需验证**：在 1.20.5+ 中，`item modify` 是否足以触发动画中断？理论上 `set_custom_data` 会改变物品的组件数据，应该能触发物品变化检测。

## 方案二：使用 advancement 的 `item_used_on_block` 触发器（1.16+）

### 原理

当玩家使用物品（右键点击）时，游戏会触发 `item_used_on_block` 进度触发器。如果我们在进度奖励函数中执行 `clear` 命令或切换物品，可以中断正在进行的动画。

### 完整代码

```json
// <namespace>/advancement/interrupt_animation.json
{
  "criteria": {
    "used_item": {
      "trigger": "minecraft:item_used_on_block",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "<namespace>:on_item_use"
  }
}
```

```mcfunction
# <namespace>:on_item_use
# 中断当前动画
clear @s

# 或者更精确地，只清除特定物品
# clear @s minecraft:apple

# 撤销进度，以便下次触发
advancement revoke @s only <namespace>:interrupt_animation
```

### 陷阱与注意事项

1. **触发条件限制**：这个触发器只在“使用物品于方块上”时触发，不是所有物品使用场景（如吃食物在空中右键也会触发，但拉弓不会）。
2. **副作用**：`clear` 命令会清除所有匹配的物品，可能导致玩家丢失物品。
3. **性能**：每次使用物品都会触发进度，如果数据包中有大量玩家，性能开销较高。
4. **版本要求**：`item_used_on_block` 触发器在 1.16 引入。

## 方案三：使用 `damage` 命令（1.13+，有限场景）

### 原理

当玩家受到伤害时，某些动画（如吃东西、拉弓）会被自动中断。通过 `damage` 命令对玩家造成 0 点伤害（或极小伤害），可以触发动画中断。

### 完整代码

```mcfunction
# 对玩家 @s 造成 0 点伤害，中断动画
# 注意：0 点伤害不会减少生命值，但会触发伤害事件
damage @s 0 minecraft:generic

# 或者使用魔法伤害，避免触发击退
damage @s 0 minecraft:magic
```

### 陷阱与注意事项

1. **伤害免疫**：玩家在受伤后有 0.5 秒的伤害免疫时间，在此期间再次造成伤害不会触发动画中断。
2. **副作用**：即使伤害为 0，仍会触发：
   - 伤害音效（如“咕”声）
   - 玩家抖动效果
   - 触发 `entity_hurt` 进度
   - 可能触发其他数据包的伤害检测逻辑
3. **盔甲和附魔**：某些附魔（如荆棘）可能会在玩家受伤时触发，造成额外效果。
4. **⚠️ 需验证**：`damage @s 0` 在 1.13+ 中是否真的能中断动画？根据社区反馈，0 点伤害在某些版本中可能不会触发动画中断，建议使用 0.5 或 1 点伤害。

## 方案四：使用 `attribute` 修改（1.16+，实验性）

### 原理

修改玩家的 `minecraft:attack_speed` 属性可以强制重置攻击冷却，从而中断某些动画。但这个方法对物品使用动画（如吃东西）无效。

### 完整代码

```mcfunction
# 临时修改攻击速度，强制重置攻击冷却
attribute @s minecraft:generic.attack_speed base set 1000

# 立即重置
attribute @s minecraft:generic.attack_speed base set 4.0
```

### 陷阱与注意事项

1. **仅影响攻击动画**：这个方法只对攻击冷却和攻击动画有效，对吃东西、拉弓等物品使用动画无效。
2. **副作用**：修改攻击速度会影响玩家的实际攻击频率，即使只是瞬间修改。
3. **版本要求**：`attribute` 命令在 1.16 引入。

## 方案对比

| 方案 | 版本要求 | 适用动画 | 副作用 | 性能开销 | 可靠性 |
|------|---------|---------|--------|---------|-------|
| 切换物品法（空气替换） | 1.13+ | 所有物品使用动画 | 触发 inventory_changed | 低 | 高 |
| 切换物品法（item modify） | 1.20.5+ | 所有物品使用动画 | 极小（仅修改 NBT） | 低 | 高 |
| advancement 触发器 | 1.16+ | 物品使用于方块 | 可能清除物品 | 中 | 中 |
| damage 命令 | 1.13+ | 大部分动画 | 伤害音效、抖动 | 低 | 中（需验证） |
| attribute 修改 | 1.16+ | 仅攻击动画 | 影响攻击速度 | 低 | 低 |

## 推荐方案

### 首选：切换物品法（item modify，1.20.5+）

对于 1.20.5+ 版本，使用 `item modify` 修改 `custom_data` 是最优雅的方式，副作用最小。

### 备选：切换物品法（空气替换，1.13+）

对于旧版本，使用空气替换法是最通用的方案，但需要注意 1 tick 延迟和物品恢复。

### 特殊场景：damage 命令

如果你需要中断所有类型的动画（包括非物品使用动画），可以考虑使用 `damage` 命令，但要注意其副作用。

## 总结

中断动画的核心思路是“让服务端认为物品状态发生了变化”，从而强制结束动画。最可靠的方法是切换主手物品，但需要注意副作用和版本兼容性。对于特定场景（如仅中断攻击动画），可以使用更轻量的方法。
