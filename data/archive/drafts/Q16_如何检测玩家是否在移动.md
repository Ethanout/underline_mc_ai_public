# 如何检测玩家是否在移动

## 一、核心挑战

Minecraft 原版数据包中，没有直接的“玩家正在移动”触发器。玩家移动是一个连续状态，而原版触发器（如 `minecraft:location`）只在**位置变化时**触发一次，无法持续检测“正在移动”的状态。此外，玩家可能因多种原因移动（行走、奔跑、飞行、骑乘、被推动等），不同场景需要不同的检测策略。

## 二、方案一：基于 `minecraft:tick` 进度的位置变化检测（推荐，1.13+）

### 原理

利用 `minecraft:tick` 触发器每 tick（1/20秒）触发一次，在触发函数中比较玩家当前位置与上一 tick 存储的位置。如果位置不同，则判定为移动。

### 完整实现

#### 1. 存储结构

使用 `storage` 存储每个玩家的上一 tick 位置：

```mcfunction
# load.mcfunction
scoreboard objectives add <namespace>:pos_x dummy
scoreboard objectives add <namespace>:pos_y dummy
scoreboard objectives add <namespace>:pos_z dummy
```

#### 2. 进度定义

`data/<namespace>/advancement/detect_movement.json`：
```json
{
  "criteria": {
    "tick": {
      "trigger": "minecraft:tick"
    }
  },
  "rewards": {
    "function": "<namespace>:check_movement"
  }
}
```

#### 3. 检测函数

`data/<namespace>/function/check_movement.mcfunction`：
```mcfunction
# 获取当前位置（使用 scoreboard 存储坐标，避免浮点数精度问题）
execute store result score @s <namespace>:pos_x run data get entity @s Pos[0] 1000
execute store result score @s <namespace>:pos_y run data get entity @s Pos[1] 1000
execute store result score @s <namespace>:pos_z run data get entity @s Pos[2] 1000

# 与上一 tick 存储的位置比较
scoreboard players operation @s <namespace>:delta_x = @s <namespace>:pos_x
scoreboard players operation @s <namespace>:delta_x -= @s <namespace>:prev_x
scoreboard players operation @s <namespace>:delta_y = @s <namespace>:pos_y
scoreboard players operation @s <namespace>:delta_y -= @s <namespace>:prev_y
scoreboard players operation @s <namespace>:delta_z = @s <namespace>:pos_z
scoreboard players operation @s <namespace>:delta_z -= @s <namespace>:prev_z

# 如果任一方向有变化，则判定为移动
execute if score @s <namespace>:delta_x matches !0 run function <namespace>:on_move
execute if score @s <namespace>:delta_y matches !0 run function <namespace>:on_move
execute if score @s <namespace>:delta_z matches !0 run function <namespace>:on_move

# 更新上一 tick 位置
scoreboard players operation @s <namespace>:prev_x = @s <namespace>:pos_x
scoreboard players operation @s <namespace>:prev_y = @s <namespace>:pos_y
scoreboard players operation @s <namespace>:prev_z = @s <namespace>:pos_z
```

#### 4. 移动触发函数

`data/<namespace>/function/on_move.mcfunction`：
```mcfunction
# 这里执行移动时的逻辑
# 注意：此函数可能被多次调用（每个方向变化一次），需要去重
# 推荐使用 scoreboard 标记避免重复触发
scoreboard players set @s <namespace>:moved 1
```

#### 5. 去重处理（可选）

在 tick 函数中统一处理：
```mcfunction
# tick.mcfunction
execute as @a[scores={<namespace>:moved=1}] run function <namespace>:on_move_once
scoreboard players set @a <namespace>:moved 0
```

### 陷阱与注意事项

1. **精度问题**：直接比较浮点数 `Pos` 可能因精度问题导致误判。使用 `store result ... 1000` 将坐标放大 1000 倍后转为整数比较，可避免此问题。
2. **首次触发**：玩家首次加入游戏时，`prev_x/y/z` 未初始化，会导致误判为移动。建议在玩家加入时初始化：
   ```mcfunction
   # 在玩家加入事件中
   execute store result score @s <namespace>:prev_x run data get entity @s Pos[0] 1000
   execute store result score @s <namespace>:prev_y run data get entity @s Pos[1] 1000
   execute store result score @s <namespace>:prev_z run data get entity @s Pos[2] 1000
   ```
3. **性能**：每 tick 对每个玩家执行 3 次 `data get` 和 6 次 `scoreboard` 操作，开销较低。对于 20 名玩家，约 180 次操作/秒，对现代服务器影响极小。
4. **版本要求**：1.13+（`minecraft:tick` 触发器在 1.13 引入）。

## 三、方案二：基于 `minecraft:location` 进度的位置变化检测（1.13+）

### 原理

利用 `minecraft:location` 触发器在玩家位置变化时触发。此触发器在玩家坐标变化时自动触发，无需每 tick 轮询。

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/detect_location_change.json`：
```json
{
  "criteria": {
    "location_changed": {
      "trigger": "minecraft:location"
    }
  },
  "rewards": {
    "function": "<namespace>:on_location_change"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_location_change.mcfunction`：
```mcfunction
# 玩家位置已变化，执行移动逻辑
function <namespace>:on_move

# 移除进度，允许下次触发
advancement revoke @s only <namespace>:detect_location_change
```

### 陷阱与注意事项

1. **触发频率**：`minecraft:location` 触发器在位置变化时触发，但**不是每 tick 触发**。实际测试表明，它可能在位置变化后的 1-2 tick 内触发，延迟较低但不如方案一精确。
2. **无法检测静止**：如果玩家停止移动，此触发器不会触发“停止移动”事件。需要结合方案一或超时机制来检测停止。
3. **性能**：触发频率取决于玩家移动频率，通常远低于方案一。但每次触发需要执行 `advancement revoke` 操作，开销较低。
4. **版本要求**：1.13+。

## 四、方案三：基于 `minecraft:player_sleep_in_bed` 的间接检测（1.13+，仅限睡觉场景）

### 原理

玩家在床中无法移动，因此可以通过检测玩家是否离开床来间接判断移动状态。此方案仅适用于与睡觉相关的移动检测。

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/detect_sleep_end.json`：
```json
{
  "criteria": {
    "sleep_end": {
      "trigger": "minecraft:player_sleep_in_bed",
      "conditions": {
        "player": {
          "flags": {
            "is_sleeping": false
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_sleep_end"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_sleep_end.mcfunction`：
```mcfunction
# 玩家离开床，可能开始移动
function <namespace>:on_move

advancement revoke @s only <namespace>:detect_sleep_end
```

### 陷阱与注意事项

1. **适用范围极窄**：仅适用于玩家离开床的场景，无法检测普通移动。
2. **误触发**：玩家在床中醒来但未移动也会触发，需要额外判断。
3. **版本要求**：1.13+。

## 五、方案四：基于 `minecraft:entity_hurt_player` 的间接检测（1.13+，仅限受伤场景）

### 原理

玩家受伤时通常会移动（击退效果），可以通过检测玩家受伤来间接判断移动。此方案仅适用于与战斗相关的移动检测。

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/detect_hurt.json`：
```json
{
  "criteria": {
    "hurt": {
      "trigger": "minecraft:entity_hurt_player"
    }
  },
  "rewards": {
    "function": "<namespace>:on_hurt"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/on_hurt.mcfunction`：
```mcfunction
# 玩家受伤，可能被击退移动
function <namespace>:on_move

advancement revoke @s only <namespace>:detect_hurt
```

### 陷阱与注意事项

1. **不准确**：玩家受伤不一定移动（如抗性提升效果），移动也不一定由受伤引起。
2. **误触发**：玩家在受伤后可能因其他原因停止移动，此方案无法区分。
3. **版本要求**：1.13+。

## 六、方案对比

| 方案 | 版本要求 | 性能开销 | 精确度 | 适用场景 |
|------|---------|---------|--------|---------|
| 方案一：tick 位置比较 | 1.13+ | 低（每 tick 20 次操作/玩家） | 高（每 tick 检测） | 通用移动检测 |
| 方案二：location 触发器 | 1.13+ | 极低（仅位置变化时触发） | 中（有 1-2 tick 延迟） | 低延迟要求不高的场景 |
| 方案三：睡觉检测 | 1.13+ | 极低 | 低（仅限睡觉场景） | 睡眠相关功能 |
| 方案四：受伤检测 | 1.13+ | 极低 | 低（仅限受伤场景） | 战斗相关功能 |

## 七、推荐方案

**首选方案一**：基于 `minecraft:tick` 进度的位置变化检测。它提供了最精确的移动检测，每 tick 更新一次状态，适用于大多数数据包需求。虽然性能开销略高于方案二，但对于 20 名玩家以内的服务器，影响可以忽略不计。

**次选方案二**：如果对实时性要求不高（如统计玩家移动距离），可以使用 `minecraft:location` 触发器，性能更优。

## 八、高级技巧：检测移动方向

如果需要检测玩家移动的方向（前后左右），可以结合玩家的 `Rotation` 和位置变化：

```mcfunction
# 获取玩家朝向
execute store result score @s <namespace>:yaw run data get entity @s Rotation[0] 1000

# 计算移动方向（简化版，仅判断前后）
# 如果玩家沿 Yaw 方向移动，则为前进；反之为后退
# 需要更精确的方向判断请使用三角函数（需借助 scoreboard 模拟）
```

⚠️ 需验证：`Rotation[0]` 在玩家骑乘实体时是否仍代表玩家自身的朝向。

## 九、陷阱总结

1. **首次加入误判**：所有方案在玩家首次加入时都可能误判为移动，需要初始化处理。
2. **骑乘状态**：玩家骑乘实体时，`Pos` 数据反映的是坐骑的位置，移动检测仍然有效，但无法区分是玩家主动移动还是坐骑移动。
3. **飞行状态**：玩家在创造模式飞行时，位置变化检测仍然有效，但需要额外判断飞行状态（通过 `abilities` NBT）。
4. **传送与移动**：使用 `/tp` 或末影珍珠等传送方式也会触发位置变化，需要根据需求决定是否视为“移动”。
