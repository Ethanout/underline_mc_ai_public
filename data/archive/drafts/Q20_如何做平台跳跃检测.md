# 如何做平台跳跃检测

## 问题背景

平台跳跃检测的核心挑战在于：Minecraft 原版没有直接的“玩家是否站在特定方块上”或“玩家是否完成了一次跳跃”的事件触发器。我们需要通过组合不同的原版机制（如统计信息、方块检测、运动状态谓词）来间接推断。

## 方案一：基于 `minecraft:jump` 统计 + 落地检测（推荐）

### 原理

利用 `minecraft:custom:minecraft.jump` 统计值的变化来检测跳跃动作，结合落地检测（`on_ground` 状态变化）来判断一次完整的平台跳跃是否完成。

核心思路：
1. 在 Storage 中存储玩家上一刻的跳跃次数
2. 每 tick 比较当前跳跃次数与存储值，若增加则触发“起跳”事件
3. 检测玩家从 `on_ground=false` 变为 `on_ground=true` 来触发“落地”事件
4. 组合两者即可判断一次完整的跳跃过程

### 完整实现

#### 1. 初始化 (Load)

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 创建用于存储玩家跳跃次数的 storage
scoreboard objectives add <namespace>.jump_count dummy
scoreboard objectives add <namespace>.on_ground dummy

# 初始化所有在线玩家
execute as @a run function <namespace>:player/init
```

`data/<namespace>/function/player/init.mcfunction`
```mcfunction
# 读取当前跳跃次数
execute store result score @s <namespace>.jump_count run data get entity @s player.jump_count
# 读取当前是否在地面
execute store result score @s <namespace>.on_ground run data get entity @s OnGround
```

#### 2. 每 tick 检测

`data/<namespace>/function/tick.mcfunction`
```mcfunction
execute as @a at @s run function <namespace>:player/tick
```

`data/<namespace>/function/player/tick.mcfunction`
```mcfunction
# 检测跳跃次数变化
execute store result score @s <namespace>.jump_count run data get entity @s player.jump_count
execute if score @s <namespace>.jump_count > @s <namespace>.jump_count run function <namespace>:player/on_jump

# 检测落地
execute store result score @s <namespace>.on_ground run data get entity @s OnGround
execute if score @s <namespace>.on_ground = 1 run function <namespace>:player/on_ground
```

#### 3. 起跳和落地事件

`data/<namespace>/function/player/on_jump.mcfunction`
```mcfunction
# 标记玩家正在跳跃
scoreboard players set @s <namespace>.jumping 1
# 记录起跳位置
execute store result score @s <namespace>.jump_x_pos run data get entity @s Pos[0] 1000
execute store result score @s <namespace>.jump_z_pos run data get entity @s Pos[2] 1000
```

`data/<namespace>/function/player/on_ground.mcfunction`
```mcfunction
# 检查玩家是否之前处于跳跃状态
execute if score @s <namespace>.jumping matches 1 run function <namespace>:player/check_platform_jump
# 重置跳跃状态
scoreboard players set @s <namespace>.jumping 0
```

`data/<namespace>/function/player/check_platform_jump.mcfunction`
```mcfunction
# 检查玩家是否在目标平台上落地
# 假设目标平台在 y=64 高度
execute if entity @s[dy=0,y=64] run function <namespace>:player/platform_jump_success
```

### 陷阱与注意事项

1. **跳跃统计的精度问题**：`player.jump_count` 在玩家连续跳跃时可能一次增加多个值（如按住空格键时），导致检测不准确。建议在 `on_jump` 函数中增加冷却时间（如 5 tick）来避免重复触发。

2. **落地检测的延迟**：`OnGround` 状态在玩家接触地面后立即更新，但 `player.jump_count` 的更新可能有 1 tick 延迟。建议在 `on_ground` 函数中延迟 1 tick 再检查跳跃状态。

3. **多平台支持**：如果需要检测多个平台，可以使用 `execute if block` 或 `predicate` 来检查玩家脚下的方块类型。

4. **性能开销**：每 tick 对所有玩家执行两次 `data get` 操作，开销较低。对于 20 名玩家，约 40 次 NBT 读取/tick，对现代服务器影响很小。

## 方案二：基于 `minecraft:location` 触发器 + 谓词检测

### 原理

利用 `minecraft:location` 触发器（1.16+）来检测玩家是否到达特定位置。结合 `minecraft:entity_properties` 谓词中的 `movement` 条件来判断玩家是否在跳跃。

核心思路：
1. 创建一个进度，当玩家在目标平台上方且处于跳跃状态时触发
2. 使用 `movement` 谓词检测玩家的垂直速度（`y` 分量 > 0 表示向上运动）
3. 当玩家落地时（`on_ground=true`）触发另一个进度

### 完整实现

#### 1. 创建跳跃检测进度

`data/<namespace>/advancement/platform_jump_detect.json`
```json
{
  "criteria": {
    "on_platform": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "location": {
                "position": {
                  "y": {
                    "min": 64,
                    "max": 64.5
                  }
                }
              },
              "movement": {
                "y": {
                  "min": 0.1
                }
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:player/on_platform_jump"
  }
}
```

#### 2. 创建落地检测进度

`data/<namespace>/advancement/platform_land_detect.json`
```json
{
  "criteria": {
    "on_ground": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "location": {
                "position": {
                  "y": {
                    "min": 64,
                    "max": 64.5
                  }
                }
              },
              "flags": {
                "on_ground": true
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:player/on_platform_land"
  }
}
```

#### 3. 事件处理函数

`data/<namespace>/function/player/on_platform_jump.mcfunction`
```mcfunction
# 标记玩家正在跳跃
scoreboard players set @s <namespace>.jumping 1
# 撤销进度以便下次触发
advancement revoke @s only <namespace>:platform_jump_detect
```

`data/<namespace>/function/player/on_platform_land.mcfunction`
```mcfunction
# 检查玩家是否之前处于跳跃状态
execute if score @s <namespace>.jumping matches 1 run function <namespace>:player/platform_jump_success
# 重置状态
scoreboard players set @s <namespace>.jumping 0
# 撤销进度以便下次触发
advancement revoke @s only <namespace>:platform_land_detect
```

### 陷阱与注意事项

1. **位置精度问题**：`location` 触发器的位置检测是基于玩家脚部位置（`Pos[1]`），但玩家跳跃时脚部位置会变化。建议使用 `dy` 参数来扩大检测范围。

2. **垂直速度阈值**：`movement.y.min: 0.1` 可能漏掉一些跳跃（如从高处跳下时垂直速度可能为负）。建议根据实际需求调整阈值。

3. **进度撤销时机**：必须在事件处理函数中撤销进度，否则进度只会触发一次。但撤销后到下一次触发之间可能有 1 tick 的延迟。

4. **性能开销**：每个进度每 tick 都会检查条件，开销中等。对于大量玩家，建议使用方案一。

## 方案三：基于方块检测 + 运动状态（1.20.5+）

### 原理

利用 1.20.5 引入的 `minecraft:player_movement` 谓词和 `minecraft:block_interaction` 触发器来检测玩家在特定方块上的跳跃行为。

核心思路：
1. 使用 `minecraft:player_movement` 谓词检测玩家的运动状态（跳跃、下落、行走等）
2. 结合 `minecraft:block_interaction` 触发器检测玩家与目标方块的交互
3. 当玩家在目标方块上跳跃时触发事件

### 完整实现

#### 1. 创建跳跃检测进度

`data/<namespace>/advancement/platform_jump_v2.json`
```json
{
  "criteria": {
    "jump_on_platform": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "location": {
                "block": {
                  "blocks": ["minecraft:stone"]
                },
                "position": {
                  "y": {
                    "min": 64,
                    "max": 65
                  }
                }
              },
              "movement": {
                "y": {
                  "min": 0.2
                }
              },
              "flags": {
                "on_ground": false
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:player/on_platform_jump_v2"
  }
}
```

#### 2. 事件处理函数

`data/<namespace>/function/player/on_platform_jump_v2.mcfunction`
```mcfunction
# 记录跳跃事件
scoreboard players add @s <namespace>.jump_count 1
# 执行自定义逻辑
function <namespace>:player/platform_jump_action
# 撤销进度
advancement revoke @s only <namespace>:platform_jump_v2
```

### 陷阱与注意事项

1. **版本要求**：此方案需要 Minecraft 1.20.5+，因为 `player_movement` 谓词是在此版本引入的。

2. **方块检测精度**：`block` 条件检测的是玩家脚部所在的方块，而不是脚下的方块。如果需要检测脚下的方块，需要使用 `position` 条件配合 `dy` 参数。

3. **运动状态检测**：`movement.y.min: 0.2` 可能漏掉一些跳跃（如从高处跳下时垂直速度可能为负）。建议使用 `movement.y.min: 0.1` 并配合 `on_ground: false` 条件。

4. **性能开销**：每个进度每 tick 都会检查条件，开销中等。对于大量玩家，建议使用方案一。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 精度 | 适用场景 |
|------|---------|---------|------|---------|
| 方案一：统计+落地检测 | 1.13+ | 低 | 高（需处理连续跳跃） | 通用，适合大多数平台跳跃游戏 |
| 方案二：位置触发器 | 1.16+ | 中 | 中（位置精度问题） | 需要精确位置检测的场景 |
| 方案三：方块+运动状态 | 1.20.5+ | 中 | 高（需调整阈值） | 需要检测特定方块上的跳跃 |

## 推荐方案

对于大多数平台跳跃游戏，推荐使用**方案一**，因为它：
- 版本兼容性好（1.13+）
- 性能开销低
- 精度可控（通过调整冷却时间）
- 不依赖特定方块类型

如果需要检测特定方块上的跳跃，可以考虑**方案三**（1.20.5+）或**方案二**（1.16+）。
