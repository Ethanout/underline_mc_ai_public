# 如何做教程提示

## 问题分析

在 Minecraft 数据包中实现"教程提示"的核心挑战是：**原版没有内置的 UI 系统**。你不能像模组那样弹出窗口或显示 HUD 文字。可用的原版机制只有：
1. **聊天栏输出**（`tellraw` / `say`）
2. **Bossbar**（可显示文字和进度）
3. **Title / Subtitle / Actionbar**（屏幕中央/上方/物品栏上方文字）
4. **物品 lore 或名称**（通过物品展示）
5. **粒子效果**（视觉引导）

每种机制都有其适用场景和版本限制。以下按推荐程度排序。

---

## 方案一：Actionbar + 阶段性触发（最推荐）

### 原理

使用 `title @s actionbar {"text":"..."}` 在物品栏上方显示提示文字。配合 `scoreboard` 记录玩家"教程阶段"，只在特定阶段显示一次，避免刷屏。

### 版本要求

- 1.11+（`title actionbar` 引入于 1.11）
- 1.20.5+ 可使用 `return run` 优化性能

### 完整实现

#### 1. 初始化计分板

`data/minecraft/tags/function/load.json`
```json
{
    "values": [
        "tutorial:load"
    ]
}
```

`data/tutorial/function/load.mcfunction`
```mcfunction
scoreboard objectives add tutorial.stage dummy
scoreboard objectives add tutorial.flag dummy
```

#### 2. 玩家加入时设置初始阶段

`data/tutorial/function/join.mcfunction`
```mcfunction
# 仅在首次加入时设置
execute unless score @s tutorial.stage matches 0.. run scoreboard players set @s tutorial.stage 1
```

#### 3. 主循环检测

`data/tutorial/function/tick.mcfunction`
```mcfunction
# 每 tick 检测所有玩家
execute as @a at @s run function tutorial:player/check_stage
```

`data/tutorial/function/player/check_stage.mcfunction`
```mcfunction
# 阶段 1：移动教程
execute if score @s tutorial.stage = @s tutorial.flag run return 0
execute if score @s tutorial.stage matches 1 run function tutorial:player/stage1
execute if score @s tutorial.stage matches 2 run function tutorial:player/stage2
execute if score @s tutorial.stage matches 3 run function tutorial:player/stage3
```

#### 4. 各阶段提示

`data/tutorial/function/player/stage1.mcfunction`
```mcfunction
# 显示移动提示
title @s actionbar {"text":"按 WASD 移动","color":"yellow"}
# 设置 flag 防止重复显示
scoreboard players set @s tutorial.flag 1
```

`data/tutorial/function/player/stage2.mcfunction`
```mcfunction
title @s actionbar {"text":"按空格跳跃","color":"green"}
scoreboard players set @s tutorial.flag 2
```

`data/tutorial/function/player/stage3.mcfunction`
```mcfunction
title @s actionbar {"text":"按 E 打开背包","color":"aqua"}
scoreboard players set @s tutorial.flag 3
```

#### 5. 阶段推进（示例：检测玩家移动后推进到阶段2）

`data/tutorial/function/player/advance_stage.mcfunction`
```mcfunction
# 检测玩家是否移动（通过位置变化）
execute store result score @s tutorial.temp run data get entity @s Pos[0] 1000
execute store result score @s tutorial.temp2 run data get entity @s Pos[2] 1000

# 如果位置变化超过阈值，推进阶段
execute if score @s tutorial.temp != @s tutorial.last_x run scoreboard players set @s tutorial.stage 2
execute if score @s tutorial.temp2 != @s tutorial.last_z run scoreboard players set @s tutorial.stage 2

# 存储当前位置用于下次比较
scoreboard players operation @s tutorial.last_x = @s tutorial.temp
scoreboard players operation @s tutorial.last_z = @s tutorial.temp2
```

### 陷阱与注意事项

1. **Actionbar 会被其他数据包覆盖**：如果多个数据包同时使用 actionbar，只有最后一个生效。建议使用 `tellraw` 作为备选。
2. **性能开销**：每 tick 对所有玩家执行 `title` 命令开销较低（约 0.01ms/玩家），但建议只在阶段变化时触发，而非每 tick 重复。
3. **玩家重进**：`tutorial.stage` 计分板会持久化，但 `tutorial.flag` 也会持久化。如果希望玩家重进后重新显示提示，需要在 join 时重置 flag。
4. **多语言问题**：Actionbar 文字是硬编码的，无法自动适配玩家语言设置。如需多语言，需使用 `tellraw` 配合 `lang` 组件（1.16+）。

## 方案二：Bossbar 教程条（适合持续提示）

### 原理

使用 Bossbar 显示教程文字和进度。Bossbar 可以设置颜色、分段样式，且不会像 actionbar 那样被其他数据包覆盖。

### 版本要求

- 1.11+（Bossbar 引入于 1.11）
- 1.13+ 支持 JSON 格式的 Bossbar 名称

### 完整实现

#### 1. 创建 Bossbar

`data/tutorial/function/load.mcfunction`
```mcfunction
# 创建教程 Bossbar
bossbar add tutorial:guide {"text":"教程提示","color":"yellow"}
bossbar set tutorial:guide color yellow
bossbar set tutorial:guide style progress
bossbar set tutorial:guide max 100
```

#### 2. 玩家加入时显示

`data/tutorial/function/join.mcfunction`
```mcfunction
bossbar set tutorial:guide players @s
```

#### 3. 更新 Bossbar 内容

`data/tutorial/function/player/update_guide.mcfunction`
```mcfunction
# 根据教程阶段更新 Bossbar
execute if score @s tutorial.stage matches 1 run bossbar set tutorial:guide name {"text":"按 WASD 移动","color":"yellow"}
execute if score @s tutorial.stage matches 1 run bossbar set tutorial:guide value 25

execute if score @s tutorial.stage matches 2 run bossbar set tutorial:guide name {"text":"按空格跳跃","color":"green"}
execute if score @s tutorial.stage matches 2 run bossbar set tutorial:guide value 50

execute if score @s tutorial.stage matches 3 run bossbar set tutorial:guide name {"text":"按 E 打开背包","color":"aqua"}
execute if score @s tutorial.stage matches 3 run bossbar set tutorial:guide value 75

execute if score @s tutorial.stage matches 4 run bossbar set tutorial:guide name {"text":"教程完成！","color":"gold"}
execute if score @s tutorial.stage matches 4 run bossbar set tutorial:guide value 100
```

#### 4. 隐藏 Bossbar（教程完成后）

`data/tutorial/function/player/complete.mcfunction`
```mcfunction
bossbar set tutorial:guide players @s
bossbar set tutorial:guide visible false
```

### 陷阱与注意事项

1. **Bossbar 是全局的**：所有玩家看到的是同一个 Bossbar 实例。如果不同玩家处于不同教程阶段，Bossbar 内容会冲突。解决方案：为每个玩家创建独立的 Bossbar（使用 UUID 命名），但管理复杂。
2. **Bossbar 名称长度限制**：Bossbar 名称最长 128 字符（JSON 格式），超出会被截断。
3. **性能开销**：Bossbar 更新开销较低，但每 tick 更新所有玩家的 Bossbar 会累积开销。建议只在阶段变化时更新。
4. **Bossbar 可见性**：`bossbar set ... visible false` 会隐藏 Bossbar，但玩家仍然在 Bossbar 列表中。如需完全移除，需使用 `bossbar remove`。

## 方案三：Tellraw 聊天提示（最通用）

### 原理

使用 `tellraw` 命令向玩家聊天栏发送 JSON 格式消息。支持点击事件、悬浮提示、多语言等高级功能。

### 版本要求

- 1.12+（`tellraw` 支持完整 JSON 组件）
- 1.16+ 支持 `translate` 组件（多语言）

### 完整实现

#### 1. 发送提示

`data/tutorial/function/player/show_tip.mcfunction`
```mcfunction
# 简单文本提示
tellraw @s {"text":"💡 提示：按 WASD 移动","color":"yellow"}

# 带点击事件的提示（点击可关闭）
tellraw @s [{"text":"[关闭提示] ","color":"red","clickEvent":{"action":"run_command","value":"/trigger tutorial.dismiss"}},{"text":"按 WASD 移动","color":"yellow"}]
```

#### 2. 多语言支持（1.16+）

`data/tutorial/function/player/show_tip_lang.mcfunction`
```mcfunction
# 使用 translate 组件，需要语言文件
tellraw @s {"translate":"tutorial.tip.move","color":"yellow"}
```

#### 3. 关闭提示的触发器

`data/tutorial/function/load.mcfunction`
```mcfunction
scoreboard objectives add tutorial.dismiss trigger
```

`data/tutorial/function/player/dismiss.mcfunction`
```mcfunction
# 玩家执行 /trigger tutorial.dismiss 时触发
scoreboard players enable @s tutorial.dismiss
```

### 陷阱与注意事项

1. **聊天栏刷屏**：如果每 tick 都发送 tellraw，会严重干扰玩家。必须使用阶段 flag 控制频率。
2. **点击事件安全性**：`run_command` 点击事件可以执行任意命令，但 `/trigger` 是唯一安全的玩家可执行命令。不要使用 `run_command` 执行 `/op` 等危险命令。
3. **多语言文件**：使用 `translate` 需要创建 `assets/tutorial/lang/zh_cn.json` 等语言文件，且玩家语言设置必须匹配。
4. **性能开销**：`tellraw` 开销较低，但大量文本（如长列表）会略微增加网络传输量。

## 方案四：物品 Lore 提示（适合物品教程）

### 原理

通过 `item modifier` 在物品的 `lore` 中添加教程文字。玩家查看物品时可以看到提示。

### 版本要求

- 1.14+（`item_modifier` 引入于 1.14）
- 1.20.5+ 使用新的组件格式

### 完整实现（1.20.5+）

#### 1. 创建物品修改器

`data/tutorial/item_modifier/add_lore.json`
```json
{
    "function": "minecraft:set_lore",
    "entity": "this",
    "lore": [
        {"text":"💡 教程提示","color":"yellow","italic":false},
        {"text":"右键点击打开教程","color":"gray","italic":false}
    ],
    "mode": "replace_all"
}
```

#### 2. 给玩家物品添加 lore

`data/tutorial/function/player/add_lore.mcfunction`
```mcfunction
# 给主手物品添加教程提示
item modify entity @s weapon.mainhand tutorial:add_lore
```

### 陷阱与注意事项

1. **物品必须存在**：如果玩家主手没有物品，`item modify` 会失败。
2. **Lore 持久化**：添加的 lore 会永久保存在物品上，即使教程结束也不会自动移除。需要额外逻辑清理。
3. **版本差异**：1.20.5 之前使用 `set_lore` 的格式不同（`lore` 字段在 `display` 标签内）。
4. **性能开销**：`item modify` 开销较低，但每 tick 对所有玩家执行会累积。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|---------|------|------|
| Actionbar | 1.11+ | 低 | 简短提示 | 不干扰聊天，视觉突出 | 会被其他数据包覆盖 |
| Bossbar | 1.11+ | 低 | 持续进度提示 | 可显示进度，不会被覆盖 | 全局实例冲突 |
| Tellraw | 1.12+ | 低 | 详细说明 | 支持交互，多语言 | 刷屏风险 |
| 物品 Lore | 1.14+ | 低 | 物品相关教程 | 随物品携带 | 持久化问题 |

---

## 最佳实践建议

1. **组合使用**：Actionbar 显示简短提示，Tellraw 显示详细说明，Bossbar 显示整体进度。
2. **控制频率**：使用 `tutorial.flag` 计分板确保每个提示只显示一次。
3. **玩家控制**：提供 `/trigger tutorial.dismiss` 让玩家关闭提示。
4. **重进处理**：在 `tick.mcfunction` 中检测新玩家（通过 `tutorial.stage` 计分板是否存在）。
