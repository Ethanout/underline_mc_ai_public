# 如何做暂停感

## 核心挑战

在 Minecraft 原版数据包中实现“暂停感”面临两个根本矛盾：
1. **游戏刻不可暂停**：Minecraft 的 tick 循环无法被数据包停止，所有实体、方块实体、生物 AI 都会持续运行
2. **玩家操作不可阻塞**：无法阻止玩家移动、攻击、打开菜单等操作

因此，“暂停感”的本质是**模拟暂停**——通过一系列技巧让玩家和世界看起来像是被暂停了，但底层 tick 仍在运行。

## 方案一：时间冻结法（最推荐）

### 原理

利用 `tick` 函数在每 tick 执行时，将玩家“拉回”到上一 tick 的位置，同时冻结所有实体运动。核心机制：
- 存储玩家上一 tick 的位置和旋转角度
- 每 tick 强制将玩家传送回存储的位置
- 使用 `data modify` 冻结实体运动（设置 Motion 为 [0.0, 0.0, 0.0]）
- 可选：冻结掉落物、箭矢等

### 完整代码

#### 目录结构
```
data/
  <namespace>/
    functions/
      pause/
        init.mcfunction
        tick.mcfunction
        freeze_entities.mcfunction
        unfreeze.mcfunction
      load.mcfunction
    tags/
      functions/
        tick.json
        load.json
```

#### load.mcfunction（初始化）
```mcfunction
# 创建存储玩家位置的 storage
data modify storage <namespace>:pause player_pos set value {x:0.0, y:0.0, z:0.0}
data modify storage <namespace>:pause player_rot set value [0.0, 0.0]
scoreboard objectives add <namespace>.paused dummy
scoreboard players set global <namespace>.paused 0
```

#### tick.json（标签函数）
```json
{
    "values": [
        "<namespace>:pause/tick"
    ]
}
```

#### pause/tick.mcfunction
```mcfunction
# 检查是否处于暂停状态
execute if score global <namespace>.paused matches 0 run return fail

# 冻结所有玩家
execute as @a run function <namespace>:pause/freeze_player

# 冻结所有实体（可选）
execute as @e[type=!player] run function <namespace>:pause/freeze_entities
```

#### pause/freeze_player.mcfunction
```mcfunction
# 将玩家传送回上一 tick 的位置
execute at @s anchored eyes positioned ^ ^ ^ run tp @s ~ ~ ~ ~ ~
# 注意：这里需要更精确的位置存储，下面给出完整实现

# 实际实现：使用 storage 存储位置
execute store result score @s <namespace>.pos_x run data get entity @s Pos[0] 1000
execute store result score @s <namespace>.pos_y run data get entity @s Pos[1] 1000
execute store result score @s <namespace>.pos_z run data get entity @s Pos[2] 1000
execute store result score @s <namespace>.rot_yaw run data get entity @s Rotation[0] 1000
execute store result score @s <namespace>.rot_pitch run data get entity @s Rotation[1] 1000

# 在暂停开始时存储位置
execute if score global <namespace>.paused matches 1 run schedule function <namespace>:pause/store_pos 1t

# 每 tick 强制传送
execute as @s at @s run tp @s @s
# 注意：上面的命令无效，需要精确坐标
```

#### pause/store_pos.mcfunction（存储位置）
```mcfunction
# 存储所有玩家的位置到 storage
execute as @a run function <namespace>:pause/store_single
```

#### pause/store_single.mcfunction
```mcfunction
# 使用 UUID 作为键存储位置
data modify storage <namespace>:pause players.{UUID}.pos set value [0d, 0d, 0d]
execute store result storage <namespace>:pause players.{UUID}.pos[0] double 1 run data get entity @s Pos[0]
execute store result storage <namespace>:pause players.{UUID}.pos[1] double 1 run data get entity @s Pos[1]
execute store result storage <namespace>:pause players.{UUID}.pos[2] double 1 run data get entity @s Pos[2]
execute store result storage <namespace>:pause players.{UUID}.rot[0] float 1 run data get entity @s Rotation[0]
execute store result storage <namespace>:pause players.{UUID}.rot[1] float 1 run data get entity @s Rotation[1]
```

#### pause/freeze_entities.mcfunction
```mcfunction
# 冻结所有非玩家实体的运动
data modify entity @s Motion set value [0.0d, 0.0d, 0.0d]

# 冻结箭矢、投掷物等（可选）
execute if entity @s[type=arrow] run data modify entity @s inGround set value 1b
execute if entity @s[type=trident] run data modify entity @s inGround set value 1b
```

#### pause/unfreeze.mcfunction
```mcfunction
# 解除暂停
scoreboard players set global <namespace>.paused 0

# 清除存储的位置数据
data remove storage <namespace>:pause players
```

### 陷阱与注意事项

1. **位置存储精度问题**：使用 `scoreboard` 存储位置时，由于整数精度限制，玩家位置会逐渐漂移。推荐使用 `storage` 存储 `double` 类型。
2. **玩家旋转角度**：`Rotation` 是 `[float, float]` 类型，存储时需注意精度。
3. **实体冻结不完整**：某些实体（如潜影贝、守卫者）有特殊 AI，冻结 `Motion` 不足以完全停止它们。
4. **掉落物**：掉落物会持续存在，建议使用 `kill @e[type=item]` 或将其传送至虚空。
5. **性能开销**：每 tick 对所有玩家和实体执行 `data modify` 和 `tp`，在 50+ 玩家时可能产生明显延迟。

## 方案二：玩家操作屏蔽法

### 原理

不冻结世界，而是阻止玩家进行任何操作。通过以下方式实现：
- 使用 `effect` 给予玩家 `slowness` 255 级和 `jump_boost` 128 级（负效果）来限制移动
- 使用 `attribute` 修改玩家攻击速度、挖掘速度等
- 使用 `gamemode spectator` 强制玩家进入旁观模式（无法交互）
- 使用 `title` 显示“暂停”界面

### 完整代码

#### pause/activate.mcfunction
```mcfunction
# 设置暂停状态
scoreboard players set global <namespace>.paused 1

# 将所有玩家设为旁观模式
gamemode spectator @a

# 给予负面效果限制移动
effect give @a minecraft:slowness 999999 255 true
effect give @a minecraft:jump_boost 999999 128 true
effect give @a minecraft:weakness 999999 255 true
effect give @a minecraft:mining_fatigue 999999 255 true

# 显示暂停界面
title @a times 0 999999 0
title @a title {"text":"⏸ 暂停","color":"gray"}
title @a subtitle {"text":"按 [暂停键] 继续","color":"dark_gray"}
```

#### pause/deactivate.mcfunction
```mcfunction
# 解除暂停
scoreboard players set global <namespace>.paused 0

# 恢复游戏模式（需要存储原模式）
gamemode survival @a

# 清除效果
effect clear @a

# 清除标题
title @a reset
```

### 陷阱与注意事项

1. **游戏模式恢复问题**：需要存储玩家原来的游戏模式，否则所有玩家都会变成生存模式。
2. **效果无法完全阻止操作**：玩家仍然可以打开菜单、聊天、使用快捷键等。
3. **旁观模式限制**：旁观模式下玩家无法与任何方块/实体交互，但可以穿墙移动。
4. **多人游戏体验**：其他玩家可以看到“暂停”的玩家在旁观模式下移动。

## 方案三：时间膨胀法（Tick 减速）

### 原理

利用 `gamerule randomTickSpeed` 和 `gamerule playersSleepingPercentage` 等规则，结合 `tick` 函数中的条件判断，实现“慢动作”效果。不是真正的暂停，但可以大幅降低游戏速度。

### 完整代码

#### pause/slowmo.mcfunction
```mcfunction
# 设置慢动作模式
scoreboard players set global <namespace>.slowmo 1

# 降低随机刻速度
gamerule randomTickSpeed 0

# 禁用自然生成
gamerule doMobSpawning false

# 禁用方块更新（⚠️ 需验证：1.20.5+ 是否支持）
# gamerule doTileDrops false

# 每 20 tick 只执行一次 tick 函数
schedule function <namespace>:pause/slowmo_tick 20t
```

#### pause/slowmo_tick.mcfunction
```mcfunction
# 每 20 tick 执行一次，模拟 1/20 速度
# 这里可以放置原本在 tick 中执行的逻辑
# 例如：实体 AI、方块更新等

# 重新调度
schedule function <namespace>:pause/slowmo_tick 20t
```

### 陷阱与注意事项

1. **不是真正的暂停**：玩家仍然可以正常移动和操作。
2. **实体 AI 不受影响**：`schedule` 只能控制函数执行频率，无法控制实体 AI 的 tick 频率。
3. **网络延迟**：客户端仍然会收到服务器每 tick 的更新，可能导致视觉上的卡顿。
4. **版本限制**：`gamerule` 的修改在不同版本间可能有差异。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 暂停效果 | 适用场景 |
|------|---------|---------|---------|---------|
| 时间冻结法 | 1.13+ | 中（每 tick 执行） | 完全暂停（玩家+实体） | 单人/小规模多人 |
| 玩家操作屏蔽法 | 1.13+ | 低（仅状态修改） | 仅限制玩家操作 | 需要保留世界动态 |
| 时间膨胀法 | 1.13+ | 低（减少 tick 频率） | 慢动作效果 | 特殊视觉效果 |

## 推荐方案

对于大多数数据包需求，**时间冻结法**是最接近真实暂停的实现。如果需要更精细的控制，可以结合方案一和方案二：冻结世界的同时将玩家设为旁观模式。

## 进阶技巧

### 暂停菜单实现

结合 `inventory_changed` 进度和自定义物品，可以实现暂停菜单：
```json
{
  "criteria": {
    "open_menu": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "items": [{
          "items": ["minecraft:clock"],
          "predicates": {
            "minecraft:custom_data": {"<namespace>": {"pause_menu": true}}
          }
        }]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:pause/open_menu"
  }
}
```
