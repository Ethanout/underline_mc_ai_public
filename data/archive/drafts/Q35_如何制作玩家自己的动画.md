# 如何制作玩家自己的动画

## 一、概述

在 Minecraft Java Edition 数据包开发中，“玩家动画”指的是让玩家实体（Player）执行非原生的动作序列，例如自定义攻击动作、舞蹈、攀爬、受伤反应等。核心挑战在于：**原版没有提供直接控制玩家骨骼动画的接口**（如修改模型、播放自定义关键帧）。所有方案都必须通过间接手段——利用已有的游戏机制（如物品使用、状态效果、实体交互）来模拟动画效果。

本文介绍三种主流方案，按推荐程度排序。

---

## 二、方案一：利用 `use` 进度 + 物品标签 + 动作帧系统

**适用版本**：1.16+（核心机制稳定）  
**原理**：通过 `minecraft:used_item` 或 `minecraft:using_item` 进度监听玩家使用特定物品（如自定义武器、道具），触发函数链，在 tick 中逐帧更新玩家的状态（如位置、旋转、粒子效果、声音），模拟动画帧。

### 2.1 核心架构

```
data/
  <namespace>/
    advancement/
      animation/
        start_attack.json          # 监听使用物品
        tick_attack.json           # 每 tick 检测是否在动画中
    function/
      animation/
        attack/
          start.mcfunction         # 初始化动画状态
          frame_1.mcfunction       # 第1帧
          frame_2.mcfunction       # 第2帧
          ...
          end.mcfunction           # 结束动画
        tick.mcfunction            # 主 tick 调度
    item_modifier/
      animation/
        set_using.json             # 给物品打标记
```

### 2.2 实现步骤

#### 第一步：定义动画物品

创建一个自定义物品（如剑），通过 `item_modifier` 写入 `custom_data` 标记。

`data/<namespace>/item_modifier/animation/set_using.json`
```json
{
  "function": "minecraft:set_custom_data",
  "tag": "{<namespace>:{animation:\"attack\",frame:0}}",
  "conditions": []
}
```

#### 第二步：监听物品使用

`data/<namespace>/advancement/animation/start_attack.json`
```json
{
  "criteria": {
    "used_item": {
      "trigger": "minecraft:using_item",
      "conditions": {
        "item": {
          "items": ["minecraft:iron_sword"],
          "predicates": {
            "minecraft:custom_data": "{<namespace>:{animation:\"attack\"}}"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:animation/attack/start"
  }
}
```

#### 第三步：启动动画

`data/<namespace>/function/animation/attack/start.mcfunction`
```mcfunction
# 设置动画状态
scoreboard players set @s <namespace>.anim_frame 1
scoreboard players set @s <namespace>.anim_total 20  # 20 ticks = 1秒

# 播放起始音效
playsound minecraft:entity.player.attack.crit player @s ~ ~ ~ 1 1

# 显示粒子
particle minecraft:crit ~ ~1.5 ~ 0.5 0.5 0.5 0.1 10

# 撤销进度，防止重复触发
advancement revoke @s only <namespace>:animation/start_attack
```

#### 第四步：每 tick 更新帧

`data/<namespace>/function/animation/tick.mcfunction`
```mcfunction
# 检查是否有玩家在动画中
execute as @a[scores={<namespace>.anim_frame=1..}] run function <namespace>:animation/attack/frame_handler
```

`data/<namespace>/function/animation/attack/frame_handler.mcfunction`
```mcfunction
# 获取当前帧
scoreboard players get @s <namespace>.anim_frame

# 根据帧号执行不同动作
execute if score @s <namespace>.anim_frame matches 1 run function <namespace>:animation/attack/frame_1
execute if score @s <namespace>.anim_frame matches 2 run function <namespace>:animation/attack/frame_2
# ... 更多帧

# 帧递增
scoreboard players add @s <namespace>.anim_frame 1

# 检查是否结束
execute if score @s <namespace>.anim_frame > @s <namespace>.anim_total run function <namespace>:animation/attack/end
```

#### 第五步：定义帧函数示例

`data/<namespace>/function/animation/attack/frame_1.mcfunction`
```mcfunction
# 第1帧：前摇 - 玩家后仰
tp @s ~ ~ ~ ~ ~-10  # 俯视角度
particle minecraft:smoke ~ ~1.6 ~ 0.1 0.1 0.1 0.01 3
```

`data/<namespace>/function/animation/attack/frame_10.mcfunction`
```mcfunction
# 第10帧：挥砍 - 玩家旋转
tp @s ~ ~ ~ ~ ~20
playsound minecraft:entity.player.attack.sweep player @s ~ ~ ~ 0.5 1
particle minecraft:sweep_attack ~ ~1.5 ~ 0.5 0.5 0.5 0.01 5
```

#### 第六步：结束动画

`data/<namespace>/function/animation/attack/end.mcfunction`
```mcfunction
# 重置状态
scoreboard players set @s <namespace>.anim_frame 0
scoreboard players set @s <namespace>.anim_total 0

# 恢复玩家视角（可选）
tp @s ~ ~ ~ ~ ~0

# 播放结束音效
playsound minecraft:entity.player.attack.strong player @s ~ ~ ~ 1 1
```

### 2.3 陷阱与注意事项

1. **视角干扰**：使用 `tp` 修改玩家旋转会覆盖玩家鼠标输入，导致动画期间玩家无法自由转动视角。解决方案：仅在动画关键帧使用 `tp`，或使用 `execute rotated` 临时改变朝向。
2. **物品使用中断**：如果玩家在动画过程中切换物品或受到伤害，`using_item` 进度可能提前结束。需要额外监听 `minecraft:item_durability_changed` 或 `minecraft:inventory_changed` 来检测中断。
3. **多人同步**：每个玩家独立执行动画，但粒子、声音对其他玩家可见。如果需要多人看到同一动画（如团队技能），需使用 `@a` 选择器播放效果。
4. **性能开销**：每 tick 对每个动画中的玩家执行函数，开销较低（约 0.1-0.5 ms/玩家）。但如果同时有大量玩家（>50）在动画中，建议使用 `schedule` 替代每 tick 检测。

## 三、方案二：利用 `entity_interaction` 进度 + 盔甲架傀儡

**适用版本**：1.20.5+（`entity_interaction` 进度引入）  
**原理**：创建一个不可见的盔甲架作为“动画傀儡”，玩家通过交互（右键）触发进度，然后数据包控制盔甲架执行预设的动画（如旋转、移动、粒子），同时将玩家绑定到盔甲架上（通过 `ride` 或 `passenger`），让玩家跟随傀儡运动。

### 3.1 核心架构

```
data/
  <namespace>/
    advancement/
      animation/
        interact_puppet.json       # 监听交互盔甲架
    function/
      animation/
        puppet/
          spawn.mcfunction         # 生成傀儡
          attach.mcfunction        # 绑定玩家
          animate.mcfunction       # 控制傀儡运动
          detach.mcfunction        # 解除绑定
    predicate/
      animation/
        is_puppet.json             # 检测盔甲架标记
```

### 3.2 实现步骤

#### 第一步：生成傀儡盔甲架

`data/<namespace>/function/animation/puppet/spawn.mcfunction`
```mcfunction
# 在玩家位置生成不可见盔甲架
summon minecraft:armor_stand ~ ~ ~ {Invisible:1b,NoGravity:1b,Marker:1b,Tags:["<namespace>.puppet","<namespace>.owner_<UUID>"],CustomName:'{"text":"Puppet"}',CustomNameVisible:0b}

# 存储傀儡 UUID 到 storage
execute store result score @s <namespace>.puppet_id storage <namespace>:temp puppet_id
data modify storage <namespace>:temp puppet set from entity @e[type=minecraft:armor_stand,tag=<namespace>.puppet,limit=1,sort=nearest] UUID
```

#### 第二步：监听交互

`data/<namespace>/advancement/animation/interact_puppet.json`
```json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:entity_interaction",
      "conditions": {
        "entity": {
          "type": "minecraft:armor_stand",
          "nbt": "{Tags:[\"<namespace>.puppet\"]}"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:animation/puppet/attach"
  }
}
```

#### 第三步：绑定玩家到傀儡

`data/<namespace>/function/animation/puppet/attach.mcfunction`
```mcfunction
# 将玩家设为傀儡的乘客
execute as @s at @s run ride @e[type=minecraft:armor_stand,tag=<namespace>.puppet,limit=1,sort=nearest] mount @s

# 撤销进度
advancement revoke @s only <namespace>:animation/interact_puppet

# 启动动画循环
schedule function <namespace>:animation/puppet/animate 1t
```

#### 第四步：控制傀儡运动

`data/<namespace>/function/animation/puppet/animate.mcfunction`
```mcfunction
# 对每个傀儡执行动画
execute as @e[type=minecraft:armor_stand,tag=<namespace>.puppet] at @s run function <namespace>:animation/puppet/frame

# 如果还有乘客，继续调度
execute if entity @e[type=minecraft:armor_stand,tag=<namespace>.puppet,has_passenger=true] run schedule function <namespace>:animation/puppet/animate 1t
```

`data/<namespace>/function/animation/puppet/frame.mcfunction`
```mcfunction
# 示例：旋转动画
tp @s ~ ~ ~ ~ ~5

# 播放粒子
particle minecraft:end_rod ~ ~1.5 ~ 0.2 0.2 0.2 0.01 5

# 播放声音
playsound minecraft:block.beacon.ambient player @a ~ ~ ~ 0.5 1
```

#### 第五步：解除绑定

`data/<namespace>/function/animation/puppet/detach.mcfunction`
```mcfunction
# 解除所有乘客
execute as @e[type=minecraft:armor_stand,tag=<namespace>.puppet] at @s run ride @p dismount

# 移除傀儡
kill @e[type=minecraft:armor_stand,tag=<namespace>.puppet]
```

### 3.3 陷阱与注意事项

1. **玩家控制权**：当玩家骑乘盔甲架时，玩家无法移动或交互（除非使用 `NoGravity` 和 `Marker` 组合）。需要确保动画结束后及时解除绑定。
2. **多人冲突**：如果多个玩家同时交互同一个傀儡，会导致骑乘混乱。建议每个玩家生成独立的傀儡，并通过 `owner_<UUID>` 标签区分。
3. **版本要求**：`entity_interaction` 进度在 1.20.5 引入，1.20.4 及以下版本无法使用此方案。替代方案：使用 `player_interacted_with_entity` 进度（1.16+），但需要玩家手持特定物品。
4. **性能开销**：每 tick 调度函数，开销中等（约 0.5-2 ms/傀儡）。如果同时有大量傀儡，建议使用 `execute as @e[tag=<namespace>.puppet]` 批量处理。

## 四、方案三：利用 `player_animation` 标签 + 资源包

**适用版本**：1.21.2+（`player_animation` 组件引入）  
**原理**：Minecraft 1.21.2 引入了 `minecraft:player_animation` 物品组件，允许通过物品标签触发玩家预设动画（如 `idle`、`walk`、`attack`、`use_item`）。数据包可以给物品添加此组件，玩家手持该物品时自动播放对应动画。

### 4.1 核心架构

```
data/
  <namespace>/
    item_modifier/
      animation/
        set_attack_anim.json       # 添加动画组件
    function/
      animation/
        apply_anim.mcfunction      # 应用动画到物品
```

### 4.2 实现步骤

#### 第一步：创建物品修饰器

`data/<namespace>/item_modifier/animation/set_attack_anim.json`
```json
{
  "function": "minecraft:set_components",
  "components": {
    "minecraft:player_animation": "attack"
  },
  "conditions": []
}
```

#### 第二步：应用动画到物品

`data/<namespace>/function/animation/apply_anim.mcfunction`
```mcfunction
# 给玩家主手物品添加动画组件
item modify entity @s weapon.mainhand <namespace>:animation/set_attack_anim
```

#### 第三步：触发动画

玩家手持该物品时，游戏会自动播放 `attack` 动画。可以通过 `using_item` 进度监听动画开始和结束。

`data/<namespace>/advancement/animation/on_attack_anim.json`
```json
{
  "criteria": {
    "start": {
      "trigger": "minecraft:using_item",
      "conditions": {
        "item": {
          "predicates": {
            "minecraft:components": {
              "minecraft:player_animation": "attack"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:animation/attack_started"
  }
}
```

### 4.3 陷阱与注意事项

1. **动画有限**：目前支持的动画只有 `idle`、`walk`、`attack`、`use_item`、`swim`、`fall`、`sleep` 等预设值，无法自定义骨骼动画。
2. **版本限制**：仅 1.21.2+ 可用，且需要物品组件支持。低版本无法使用。
3. **覆盖问题**：如果物品同时有多个动画组件，游戏可能只播放最后一个。建议每个物品只设置一个动画。
4. **性能开销**：极低（游戏原生渲染，无额外计算）。

## 五、方案对比

| 方案 | 最低版本 | 动画自由度 | 性能开销 | 适用场景 |
|------|----------|------------|----------|----------|
| 方案一：物品使用 + 帧系统 | 1.16 | 高（可控制位置、旋转、粒子、声音） | 低（每 tick 函数调用） | 自定义攻击、技能、舞蹈 |
| 方案二：盔甲架傀儡 | 1.20.5 | 中（可控制实体运动，但玩家被绑定） | 中（每 tick 调度 + 实体更新） | 飞行、翻滚、载具动画 |
| 方案三：player_animation 组件 | 1.21.2 | 低（仅预设动画） | 极低（原生渲染） | 快速添加标准动作 |

---

## 六、总结与建议

- **追求高自由度**：选择方案一，但需处理视角干扰和中断问题。
- **需要玩家跟随运动**：选择方案二，但注意版本要求和多人冲突。
- **快速实现标准动画**：选择方案三，但版本限制较大。
- **混合使用**：可以结合方案一和方案三，例如用方案三触发基础动画，用方案一添加粒子效果。
