# 如何做隐藏区域或解谜

## 一、屏障与隐形方块法（视觉隐藏）

### 原理
利用 `barrier`（屏障方块）或 `light`（光源方块）的隐形特性，配合 `structure_void`（结构空位）或 `command_block` 的隐形，在玩家面前制造"空气墙"或"隐形平台"。玩家无法直接看到这些方块，但可以与之交互（如放置方块、触发红石）。

### 适用版本
1.13+（barrier 在 1.8 引入，但 1.13 后支持数据包）

### 完整代码

#### 1. 放置屏障墙
```mcfunction
# 在坐标 (10, 64, 10) 到 (10, 64, 20) 放置屏障墙
fill 10 64 10 10 64 20 minecraft:barrier
```

#### 2. 配合红石控制开关
```mcfunction
# 当玩家踩到压力板时，移除屏障
execute if entity @p[x=5,y=64,z=5,distance=..1] run fill 10 64 10 10 64 20 air
```

#### 3. 使用结构空位制造"隐形楼梯"
```mcfunction
# 放置结构空位作为隐形平台
fill 10 63 10 20 63 20 minecraft:structure_void
```

### 陷阱与注意事项
- **屏障方块在创造模式下可见**（半透明红色方块），只有生存/冒险模式玩家看不到
- **结构空位在 1.13+ 中默认不可见**，但玩家可以用 F3+B 显示碰撞箱
- **屏障方块会阻挡实体移动**，但不会阻挡视线（玩家可以透过它看到后面）
- **如果玩家使用 F3+N 切换到观察者模式**，所有方块都会可见
- **性能开销**：低（只是方块放置/移除，没有持续计算）

## 二、传送门与坐标变换法（空间隐藏）

### 原理
利用 `/teleport` 命令在玩家进入特定区域时，将其传送到另一个坐标（可以是同一世界的不同位置，也可以是不同维度）。配合 `execute if block` 检测玩家脚下的方块，或使用 `predicate` 检测位置。

### 适用版本
1.13+（`/teleport` 语法在 1.13 重构）

### 完整代码

#### 方案 A：基于位置的传送
```mcfunction
# tick.mcfunction - 每 tick 检测玩家是否在隐藏区域入口
execute as @a at @s if block ~ ~-1 ~ minecraft:stone_pressure_plate run function namespace:enter_hidden

# namespace:enter_hidden.mcfunction
# 将玩家传送到隐藏区域（例如地下 100 格）
teleport @s ~ 10 ~
# 给玩家一个"已进入"标记，防止反复触发
scoreboard players set @s hidden_zone 1
```

#### 方案 B：基于维度的传送（1.16+）
```mcfunction
# 检测玩家是否在特定位置，然后传送到末地/下界
execute as @a at @s if block ~ ~-1 ~ minecraft:light_weighted_pressure_plate run {
  # 保存当前位置
  data modify storage namespace:player_pos set from entity @s Pos
  # 传送到末地
  execute in minecraft:the_end run teleport @s 0 64 0
}
```

#### 方案 C：使用 advancement 检测进入区域
```json
// namespace:advancement/enter_hidden.json
{
  "criteria": {
    "enter": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": {
          "location": {
            "position": {
              "x": 10,
              "y": 64,
              "z": 10
            },
            "distance": {
              "horizontal": 5,
              "vertical": 3
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:enter_hidden"
  }
}
```

### 陷阱与注意事项
- **传送后玩家可能卡在方块中**，需要确保目标位置有足够空间
- **如果使用维度传送**，玩家会看到加载画面，破坏沉浸感
- **基于 advancement 的检测有延迟**（不是每 tick 检测，而是每 20 tick 检测一次位置）
- **玩家可以通过 F3 调试屏幕看到坐标变化**，暴露隐藏区域的存在
- **性能开销**：低（每 tick 执行一次条件检测，或每 20 tick 触发一次 advancement）

## 三、记分板与状态机法（逻辑解谜）

### 原理
利用 `scoreboard` 记录玩家的解谜进度，通过 `execute if score` 条件判断玩家是否满足触发条件。可以配合 `predicate` 检测玩家手持物品、状态效果等。

### 适用版本
1.13+（scoreboard 在 1.13 后支持 `if score` 语法）

### 完整代码

#### 1. 初始化记分板
```mcfunction
# load.mcfunction
scoreboard objectives add puzzle_progress dummy "解谜进度"
scoreboard objectives add puzzle_step dummy "当前步骤"
```

#### 2. 检测玩家放置特定方块
```mcfunction
# tick.mcfunction
execute as @a at @s if block ~ ~-1 ~ minecraft:redstone_block run scoreboard players add @s puzzle_progress 1
execute as @a at @s if block ~ ~-1 ~ minecraft:emerald_block run scoreboard players add @s puzzle_progress 2
execute as @a at @s if block ~ ~-1 ~ minecraft:diamond_block run scoreboard players add @s puzzle_progress 3
```

#### 3. 检测玩家是否完成所有步骤
```mcfunction
# check_puzzle.mcfunction
execute as @a if score @s puzzle_progress matches 6 run {
  # 触发隐藏区域打开
  fill 10 64 10 10 64 20 air
  # 播放音效
  playsound minecraft:block.note_block.chime master @s
  # 重置进度
  scoreboard players set @s puzzle_progress 0
}
```

#### 4. 使用 predicate 检测手持物品
```json
// namespace:predicate/holding_ender_pearl.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "equipment": {
      "mainhand": {
        "items": [
          "minecraft:ender_pearl"
        ]
      }
    }
  }
}
```

```mcfunction
# 检测玩家手持末影珍珠时触发
execute as @a at @s if predicate namespace:holding_ender_pearl run scoreboard players add @s puzzle_step 1
```

### 陷阱与注意事项
- **记分板值不会自动重置**，需要手动管理
- **如果玩家在多个位置触发同一个条件**，记分板会重复增加
- **使用 `if block` 检测时**，如果方块被破坏，条件不再成立，但记分板值不会回退
- **需要处理玩家退出重进的情况**（记分板值会保留，但 advancement 进度可能丢失）
- **性能开销**：低（每 tick 执行几次条件检测）

## 四、实体与交互法（动态隐藏）

### 原理
利用 `marker` 实体（1.17+）或 `area_effect_cloud` 作为"触发器"，配合 `interact` 事件（1.20.5+）检测玩家与特定位置的交互。或者使用 `item_display` 实体（1.19.4+）显示隐藏的物体。

### 适用版本
1.17+（marker 实体），1.20.5+（interact 事件）

### 完整代码

#### 1. 放置 marker 实体作为触发器
```mcfunction
# 在隐藏区域入口放置 marker
summon minecraft:marker 10 64 10 {Tags:["hidden_trigger"]}
```

#### 2. 检测玩家与 marker 的距离
```mcfunction
# tick.mcfunction
execute as @e[tag=hidden_trigger] at @s if entity @p[distance=..2] run function namespace:trigger_hidden
```

#### 3. 使用 interact 事件（1.20.5+）
```json
// namespace:advancement/interact_hidden.json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": {
          "type": "minecraft:marker",
          "nbt": "{Tags:[\"hidden_trigger\"]}"
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:on_interact"
  }
}
```

#### 4. 使用 item_display 显示隐藏物品
```mcfunction
# 在隐藏区域放置一个隐形的物品展示
summon minecraft:item_display 10 64 10 {Tags:["hidden_item"],item:{id:"minecraft:diamond",Count:1},transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[0f,0f,0f]}}
```

### 陷阱与注意事项
- **marker 实体在 1.17+ 中完全不可见**，但可以用 F3+B 显示碰撞箱
- **item_display 的 scale 设为 0 时完全不可见**，但玩家仍然可以与之交互（如果设置了交互区域）
- **interact 事件在 1.20.5+ 中需要玩家右键点击实体**，左键不会触发
- **大量 marker 实体可能影响性能**（每个实体都有 AI 开销，虽然 marker 的 AI 开销很小）
- **性能开销**：中（每 tick 需要遍历实体并检测距离）

## 五、数据包与资源包配合法（视觉欺骗）

### 原理
利用资源包修改方块的模型和纹理，使其在特定条件下显示为透明或不同外观。配合数据包中的 `block_predicate` 或 `item_modifier` 实现动态切换。

### 适用版本
1.13+（资源包支持），1.20.5+（block_predicate 增强）

### 完整代码

#### 1. 资源包中修改方块模型
```json
// assets/minecraft/models/block/stone.json
{
  "parent": "block/cube_all",
  "textures": {
    "all": "minecraft:block/stone"
  },
  "overrides": [
    {
      "predicate": {
        "custom_model_data": 1
      },
      "model": "namespace:block/hidden_stone"
    }
  ]
}
```

#### 2. 数据包中设置方块状态
```mcfunction
# 将特定位置的石头替换为"隐藏"变种
execute if block 10 64 10 minecraft:stone run setblock 10 64 10 minecraft:stone[custom_model_data=1]
```

#### 3. 使用 block_predicate 检测（1.20.5+）
```json
// namespace:predicate/block_is_hidden.json
{
  "condition": "minecraft:block_state_property",
  "block": "minecraft:stone",
  "properties": {
    "custom_model_data": 1
  }
}
```

### 陷阱与注意事项
- **资源包需要玩家手动安装**，或者通过服务器资源包强制推送
- **custom_model_data 在 1.20.5+ 中才支持方块**，之前只支持物品
- **如果玩家没有安装资源包**，看到的仍然是普通石头
- **方块状态变化会触发方块更新**，可能影响红石电路
- **性能开销**：低（只是方块状态变化，没有持续计算）

## 方案对比

| 方案 | 最低版本 | 性能开销 | 隐蔽性 | 适用场景 |
|------|---------|---------|--------|---------|
| 屏障与隐形方块法 | 1.13 | 低 | 中（创造模式可见） | 简单隐藏门、空气墙 |
| 传送门与坐标变换法 | 1.13 | 低 | 高（但坐标暴露） | 大型隐藏区域、维度传送 |
| 记分板与状态机法 | 1.13 | 低 | 高 | 复杂解谜、多步骤触发 |
| 实体与交互法 | 1.17 | 中 | 高 | 动态隐藏、交互式解谜 |
| 数据包与资源包配合法 | 1.13 | 低 | 极高（需资源包） | 视觉欺骗、无缝隐藏 |

## 综合建议

1. **简单隐藏**：使用屏障方块法，配合红石控制开关
2. **复杂解谜**：使用记分板状态机法，配合 predicate 检测
3. **高隐蔽性**：使用数据包+资源包配合法，或传送门法
4. **交互式解谜**：使用实体与交互法（1.20.5+ 推荐使用 interact 事件）
5. **性能敏感**：避免使用大量实体，优先使用方块和记分板
