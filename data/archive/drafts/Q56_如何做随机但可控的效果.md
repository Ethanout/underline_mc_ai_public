# 如何做随机但可控的效果

## 问题背景

在 Minecraft 数据包开发中，“随机”和“可控”是一对矛盾的需求。原版提供了多种随机机制（如 `random` 函数、`scoreboard players random`、战利品表随机池等），但每种机制的可控性（种子、范围、分布）各不相同。核心挑战在于：**如何在保证随机性的同时，让开发者能够复现、调试或限制随机结果**。

## 方案一：基于 `random` 函数的宏 + 谓词（推荐，1.20.5+）

### 原理

1.20.5 引入了 `random` 函数，可以在 `execute` 链中直接生成随机数，并配合宏（`$` 变量）实现可控的随机分支。通过 `execute if random` 可以按概率执行命令，而宏可以传递随机种子或范围参数。

### 完整代码

#### 1. 定义宏函数（接收随机范围参数）

`data/<namespace>/function/random_effect.mcfunction`
```mcfunction
# 宏函数，接收 $min 和 $max 参数
# 生成随机数并存入 storage
$execute store result storage <namespace>:random value int 1 run random value $min..$max

# 根据随机值执行不同效果
execute if score $value <namespace>:random matches 1 run say 触发了效果A
execute if score $value <namespace>:random matches 2 run say 触发了效果B
execute if score $value <namespace>:random matches 3 run say 触发了效果C
```

#### 2. 调用宏（指定范围）

`data/<namespace>/function/call_random.mcfunction`
```mcfunction
# 调用宏，生成 1-3 的随机数
function <namespace>:random_effect {min:1, max:3}
```

#### 3. 使用谓词实现概率分支（更简洁）

`data/<namespace>/predicate/chance_50.json`
```json
{
  "condition": "minecraft:random_chance",
  "chance": 0.5
}
```

`data/<namespace>/function/use_predicate.mcfunction`
```mcfunction
# 50% 概率执行
execute if predicate <namespace>:chance_50 run say 你运气不错！
```

### 陷阱与注意事项

1. **宏参数必须为整数**：`random value` 只支持整数范围，如果需要小数概率，请使用 `random_chance` 谓词。
2. **宏函数不能直接嵌套**：宏函数内部不能再调用另一个宏函数（会报错），需要先展开。
3. **随机种子不可控**：`random` 函数使用世界种子，无法手动指定种子。如果需要可复现的随机，请使用方案二。
4. **性能开销**：较低。`random` 函数是原生的，宏展开在加载时完成。

## 方案二：基于 `scoreboard players random` + 种子控制（1.13+）

### 原理

`scoreboard players random` 可以生成指定范围内的随机整数，并存入记分板。通过控制记分板的值（如使用玩家 UUID 作为种子），可以实现“伪随机但可复现”的效果。

### 完整代码

#### 1. 初始化记分板

`data/<namespace>/function/load.mcfunction`
```mcfunction
scoreboard objectives add <namespace>:random dummy
```

#### 2. 生成随机数（基于玩家 UUID）

`data/<namespace>/function/generate_random.mcfunction`
```mcfunction
# 使用玩家 UUID 作为种子（通过哈希转换）
execute as @a store result score @s <namespace>:random run data get entity @s UUID[0]
# 取模限制范围（1-100）
scoreboard players set @s <namespace>:random 0
scoreboard players random @s <namespace>:random 1 100
```

#### 3. 根据随机值执行效果

`data/<namespace>/function/apply_effect.mcfunction`
```mcfunction
execute if score @s <namespace>:random matches 1..30 run say 效果A（30%概率）
execute if score @s <namespace>:random matches 31..60 run say 效果B（30%概率）
execute if score @s <namespace>:random matches 61..100 run say 效果C（40%概率）
```

#### 4. 实现可复现的随机（使用固定种子）

`data/<namespace>/function/deterministic_random.mcfunction`
```mcfunction
# 使用固定种子（如 42）生成随机数
scoreboard players set #seed <namespace>:random 42
# 通过简单算法生成伪随机（线性同余法）
scoreboard players operation #seed <namespace>:random *= #multiplier <namespace>:random
scoreboard players operation #seed <namespace>:random += #increment <namespace>:random
scoreboard players operation #result <namespace>:random = #seed <namespace>:random
scoreboard players operation #result <namespace>:random %= #modulus <namespace>:random
```

### 陷阱与注意事项

1. **UUID 哈希冲突**：不同玩家的 UUID 可能产生相同种子，但概率极低。
2. **线性同余法需要初始化**：`#multiplier`、`#increment`、`#modulus` 需要预先设置（如 1664525、1013904223、2^31）。
3. **性能开销**：中等。`scoreboard players random` 是 O(1) 操作，但自定义算法需要多个记分板操作。
4. **版本兼容性**：1.13+ 可用，但 1.20.5 之前没有 `random` 函数，此方案是唯一选择。

## 方案三：基于战利品表随机池（1.15+）

### 原理

战利品表（Loot Table）的 `random_chance` 和 `random_chance_with_looting` 条件可以实现概率控制。通过 `loot` 命令执行战利品表，可以触发随机效果。

### 完整代码

#### 1. 定义战利品表（随机掉落物品）

`data/<namespace>/loot_table/random_effect.json`
```json
{
  "pools": [
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "minecraft:paper",
          "weight": 1,
          "functions": [
            {
              "function": "minecraft:set_custom_data",
              "tag": "{<namespace>:{effect:\"A\"}}"
            }
          ]
        },
        {
          "type": "minecraft:item",
          "name": "minecraft:paper",
          "weight": 2,
          "functions": [
            {
              "function": "minecraft:set_custom_data",
              "tag": "{<namespace>:{effect:\"B\"}}"
            }
          ]
        }
      ],
      "conditions": [
        {
          "condition": "minecraft:random_chance",
          "chance": 0.5
        }
      ]
    }
  ]
}
```

#### 2. 执行战利品表并检测结果

`data/<namespace>/function/trigger_loot.mcfunction`
```mcfunction
# 将战利品表结果存入 storage
loot spawn ~ ~ ~ loot <namespace>:random_effect
# 检测掉落物并执行效果
execute as @e[type=item,nbt={Item:{tag:{"<namespace>":{effect:"A"}}}},limit=1] run say 效果A触发
execute as @e[type=item,nbt={Item:{tag:{"<namespace>":{effect:"B"}}}},limit=1] run say 效果B触发
# 清除掉落物
kill @e[type=item,nbt={Item:{tag:{"<namespace>":{effect:"A"}}}},limit=1]
kill @e[type=item,nbt={Item:{tag:{"<namespace>":{effect:"B"}}}},limit=1]
```

### 陷阱与注意事项

1. **掉落物实体开销**：每次执行都会生成实体，高频使用会导致性能问题。
2. **NBT 检测性能**：`nbt=` 选择器参数在大量实体时性能较差，建议使用 `type=item` 限制。
3. **权重计算**：战利品表的权重是整数，概率 = 权重 / 总权重。支持 `quality` 和 `bonus_rolls` 等高级功能。
4. **版本要求**：1.15+ 支持 `loot` 命令，1.16+ 支持 `set_custom_data` 函数。

## 方案四：基于进度触发 + 随机谓词（1.16+）

### 原理

进度（Advancement）的 `tick` 触发器可以每 tick 检测，配合 `random_chance` 谓词实现概率触发。通过 `rewards` 执行函数。

### 完整代码

#### 1. 定义进度（每 tick 检测）

`data/<namespace>/advancement/random_tick.json`
```json
{
  "criteria": {
    "tick": {
      "trigger": "minecraft:tick",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:random_chance",
            "chance": 0.1
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_random_tick"
  }
}
```

#### 2. 执行效果函数

`data/<namespace>/function/on_random_tick.mcfunction`
```mcfunction
# 10% 概率每 tick 触发
say 随机触发了！
# 立即撤销进度，防止重复触发
advancement revoke @s only <namespace>:random_tick
```

### 陷阱与注意事项

1. **每 tick 检测性能**：虽然概率低，但每 tick 都会执行进度检测，对服务器有一定压力。
2. **进度撤销必须及时**：否则玩家会一直触发（因为进度已达成）。
3. **无法控制种子**：`random_chance` 使用世界种子，不可复现。
4. **版本要求**：1.16+ 支持 `tick` 触发器。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 可控性 | 适用场景 |
|------|---------|---------|--------|---------|
| 方案一：`random` 函数 + 宏 | 1.20.5+ | 低 | 中（可指定范围，不可控种子） | 通用随机效果，现代版本首选 |
| 方案二：`scoreboard players random` | 1.13+ | 中 | 高（可自定义种子和算法） | 需要可复现随机、旧版本兼容 |
| 方案三：战利品表随机池 | 1.15+ | 高（生成实体） | 中（权重控制） | 低频随机事件、物品掉落 |
| 方案四：进度 + 随机谓词 | 1.16+ | 中（每 tick 检测） | 低（仅概率控制） | 简单概率触发、无需复杂逻辑 |

## 总结

- **现代版本（1.20.5+）**：优先使用方案一，简洁高效。
- **需要可复现随机**：方案二，通过自定义种子实现确定性随机。
- **低频事件**：方案三，利用战利品表的权重系统。
- **简单概率**：方案四，适合“每 tick 有概率触发”的场景。
