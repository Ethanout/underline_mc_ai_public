# 如何做锁定目标

## 核心挑战

在 Minecraft 数据包开发中，“锁定目标”指的是让玩家或实体锁定一个特定目标，使得攻击、交互或法术效果始终指向该目标，而不受玩家视角或鼠标指向的影响。原版 Minecraft 没有内置的“锁定目标”机制，因此需要通过间接手段实现。

核心挑战：
1. **原版没有“锁定实体”的 API**：无法直接让玩家“锁定”一个实体并自动攻击它。
2. **玩家攻击检测的局限性**：`player_interacted_with_entity` 和 `player_hurt_entity` 进度只能检测玩家主动交互/攻击，无法强制锁定。
3. **视角与瞄准的分离**：`execute as @s at @s anchored eyes facing entity @e[sort=nearest,limit=1] eyes` 可以计算朝向，但无法阻止玩家攻击其他实体。

## 方案一：基于最近实体 + 射线检测的“软锁定”

**适用版本**：1.13+（1.20.5+ 更优，支持 `facing` 子命令的精确控制）

**原理**：在 tick 中持续计算玩家朝向与实体的夹角，选择夹角最小的实体作为“锁定目标”。这本质上是“软锁定”——玩家仍然可以攻击其他实体，但数据包会提供一个“推荐目标”。

### 实现步骤

#### 1. 初始化 Storage 存储锁定状态

`data/<namespace>/functions/lock/init.mcfunction`
```mcfunction
# 初始化全局 storage
data modify storage <namespace>:lock target set value {}
data modify storage <namespace>:lock cooldown set value 0
```

#### 2. 主循环：每 tick 更新锁定目标

`data/<namespace>/functions/lock/tick.mcfunction`
```mcfunction
# 对所有玩家执行
execute as @a at @s run function <namespace>:lock/player_tick
```

`data/<namespace>/functions/lock/player_tick.mcfunction`
```mcfunction
# 1. 获取玩家视线方向向量（使用 scoreboard 存储）
# 注意：1.20.5+ 可以使用 execute store result score 获取朝向
execute store result score @s lock_pitch run data get entity @s Rotation[0] 1000
execute store result score @s lock_yaw run data get entity @s Rotation[1] 1000

# 2. 寻找最近的实体（排除玩家自己、非活体实体等）
# 使用 execute facing 子命令检测视线是否指向实体
# 这里使用一个标记实体作为“射线终点”
summon marker ~ ~ ~ {Tags:["lock_ray"]}
execute as @e[type=marker,tag=lock_ray,limit=1] at @s run function <namespace>:lock/find_target

# 3. 清理标记实体
kill @e[type=marker,tag=lock_ray]
```

`data/<namespace>/functions/lock/find_target.mcfunction`
```mcfunction
# 从玩家位置发射射线，检测最近的实体
# 使用 execute facing 子命令将标记实体朝向最近的实体
execute facing entity @e[type=!player,type=!marker,sort=nearest,limit=1] eyes run function <namespace>:lock/check_angle
```

`data/<namespace>/functions/lock/check_angle.mcfunction`
```mcfunction
# 计算玩家视线方向与标记实体方向的夹角
# 如果夹角小于阈值（例如 30 度），则锁定该实体
# 这里简化处理：直接使用 execute if entity 检测标记实体是否在玩家视线前方 5 格内
execute if entity @s[distance=..5] run function <namespace>:lock/set_target
```

`data/<namespace>/functions/lock/set_target.mcfunction`
```mcfunction
# 将最近的实体设置为锁定目标
execute as @p at @s run data modify storage <namespace>:lock target set from entity @e[type=!player,type=!marker,sort=nearest,limit=1] UUID
# 可选：给目标实体打标记
tag @e[type=!player,type=!marker,sort=nearest,limit=1] add locked_target
```

### 陷阱与注意事项

1. **性能开销**：每 tick 对所有玩家执行射线检测，如果玩家数量多或实体数量多，性能开销较高。建议限制检测频率（如每 5 tick 检测一次）。
2. **精度问题**：`execute facing` 子命令的精度有限，无法精确计算夹角。更精确的方法需要使用 `execute store result score` 和三角函数（需要复杂的 scoreboard 运算）。
3. **多玩家冲突**：多个玩家可能锁定同一个实体，需要为每个玩家独立存储锁定目标。
4. **实体消失**：如果锁定目标被移除（死亡、卸载等），需要及时清除锁定状态。

## 方案二：基于进度触发的“硬锁定”（攻击强制重定向）

**适用版本**：1.16+（需要 `player_hurt_entity` 进度）

**原理**：当玩家攻击实体时，通过进度触发函数，将攻击效果重定向到锁定目标。这需要配合自定义伤害系统（如使用 `effect` 或 `damage` 命令）。

### 实现步骤

#### 1. 创建锁定检测进度

`data/<namespace>/advancements/lock/attack.json`
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "<namespace>:lock/on_attack"
  }
}
```

#### 2. 攻击重定向函数

`data/<namespace>/functions/lock/on_attack.mcfunction`
```mcfunction
# 检查玩家是否有锁定目标
execute if data storage <namespace>:lock target run function <namespace>:lock/redirect_attack

# 撤销进度，以便下次触发
advancement revoke @s only <namespace>:lock/attack
```

`data/<namespace>/functions/lock/redirect_attack.mcfunction`
```mcfunction
# 获取锁定目标的 UUID
data modify storage <namespace>:lock temp set from storage <namespace>:lock target

# 对锁定目标施加伤害（使用 damage 命令，1.20.5+）
# ⚠️ 需验证：damage 命令是否支持通过 UUID 指定实体
execute as @s run damage @e[type=!player,limit=1] 5 minecraft:player_attack

# 可选：取消对原目标的伤害（需要更复杂的逻辑）
# 这里简化处理：直接对锁定目标施加伤害，原目标仍然受到伤害
```

### 陷阱与注意事项

1. **无法取消原伤害**：`player_hurt_entity` 进度在伤害发生后触发，无法阻止原伤害。这意味着玩家攻击实体 A 时，A 仍然会受到伤害，同时锁定目标 B 也会受到额外伤害。
2. **伤害来源问题**：`damage` 命令造成的伤害可能不被视为玩家攻击，影响战利品掉落、经验等。
3. **进度触发频率**：每 tick 只能触发一次进度，如果玩家快速攻击，可能丢失部分攻击事件。
4. **版本限制**：`damage` 命令在 1.20.5 引入，旧版本需要使用 `effect` 或 `data merge` 模拟伤害。

## 方案三：基于记分板 + 实体标签的“目标标记系统”

**适用版本**：1.13+

**原理**：使用记分板记录每个玩家的锁定目标 UUID，通过实体标签标记目标。在攻击检测时，检查攻击目标是否与锁定目标一致。

### 实现步骤

#### 1. 创建记分板

`data/<namespace>/functions/lock/setup.mcfunction`
```mcfunction
scoreboard objectives add lock_target dummy
scoreboard objectives add lock_cooldown dummy
```

#### 2. 锁定目标设置函数

`data/<namespace>/functions/lock/set_target.mcfunction`
```mcfunction
# 参数：@s 为玩家，@s 为要锁定的实体
# 将锁定目标的实体 ID 存储到记分板
execute store result score @s lock_target run data get entity @e[type=!player,limit=1] EntityId 1

# 给目标打标签
tag @e[type=!player,limit=1] add locked_by_@s
```

#### 3. 攻击检测与验证

`data/<namespace>/advancements/lock/attack_check.json`
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "<namespace>:lock/verify_attack"
  }
}
```

`data/<namespace>/functions/lock/verify_attack.mcfunction`
```mcfunction
# 检查攻击的目标是否与锁定目标一致
# 获取被攻击实体的 EntityId
execute store result score @s lock_attacked run data get entity @e[type=!player,limit=1] EntityId 1

# 比较
execute if score @s lock_target = @s lock_attacked run function <namespace>:lock/attack_allowed
execute unless score @s lock_target = @s lock_attacked run function <namespace>:lock/attack_blocked

# 撤销进度
advancement revoke @s only <namespace>:lock/attack_check
```

`data/<namespace>/functions/lock/attack_blocked.mcfunction`
```mcfunction
# 取消伤害（需要自定义伤害系统）
# 这里使用 effect 命令移除伤害效果（不完美）
# ⚠️ 需验证：是否有可靠的方法取消已造成的伤害
say 你不能攻击非锁定目标！
```

### 陷阱与注意事项

1. **无法取消伤害**：与方案二相同，`player_hurt_entity` 在伤害发生后触发，无法阻止伤害。
2. **EntityId 的可靠性**：实体 ID 在实体被移除后可能被重用，导致误判。建议使用 UUID 字符串存储。
3. **多玩家锁定**：需要为每个玩家独立存储锁定目标，标签命名需要包含玩家 UUID 以避免冲突。
4. **性能开销**：每 tick 需要更新记分板，如果玩家数量多，性能开销中等。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 锁定强度 | 适用场景 |
|------|---------|---------|---------|---------|
| 方案一：软锁定 | 1.13+ | 中（每 tick 射线检测） | 弱（仅推荐目标） | RPG 法术系统、辅助瞄准 |
| 方案二：硬锁定 | 1.16+（1.20.5+ 更优） | 低（仅攻击时触发） | 中（可重定向伤害） | 战斗系统、Boss 战 |
| 方案三：目标标记 | 1.13+ | 低（仅攻击时验证） | 弱（无法阻止攻击） | 简单锁定系统、PVP 限制 |

## 推荐方案

对于大多数数据包项目，推荐使用**方案一（软锁定）** 作为基础，配合**方案二（硬锁定）** 实现伤害重定向。这样可以兼顾性能和功能。

### 混合方案示例

1. 使用方案一持续更新“推荐目标”
2. 使用方案二在玩家攻击时，将伤害重定向到推荐目标
3. 使用方案三验证攻击目标是否与推荐目标一致

## 陷阱总结

1. **无法取消原伤害**：所有基于进度触发的方法都无法阻止原始伤害，只能额外施加伤害或效果。
2. **实体引用失效**：锁定目标可能被移除，需要定期检查锁定目标是否仍然存在。
3. **多玩家冲突**：多个玩家锁定同一实体时，需要独立的存储空间。
4. **性能权衡**：高频检测（每 tick）会消耗性能，低频检测（每 5-10 tick）可能错过快速移动的目标。
5. **版本兼容性**：`damage` 命令、`execute facing` 子命令等在不同版本中行为不同，需要根据目标版本调整。
