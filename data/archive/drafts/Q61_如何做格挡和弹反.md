# 如何做格挡和弹反

## 核心挑战

Minecraft 原版没有内置的"格挡"或"弹反"机制。要实现类似效果，核心挑战在于：
1. **检测伤害时机**：需要精确捕捉到玩家受到伤害的瞬间
2. **区分主动格挡与被动受伤**：需要判断玩家是否在受伤前主动执行了某个动作（如右键、潜行、使用物品等）
3. **修改伤害结果**：需要将伤害降低或反弹给攻击者
4. **版本兼容性**：不同版本对伤害处理、物品使用、属性修改的支持差异很大

## 方案一：基于伤害吸收 + 属性修改的格挡（1.20.5+ 推荐）

### 原理

利用 `minecraft:damage` 谓词检测玩家受到伤害的瞬间，结合 `attribute_modifier` 动态修改玩家的 `generic.armor` 或 `generic.armor_toughness` 属性，实现伤害减免。同时通过 `effect` 给予瞬间伤害吸收效果来模拟"格挡成功"的视觉反馈。

核心机制：
1. 玩家按下右键（或潜行）时，通过 `item_modifier` 给玩家添加一个临时属性修饰符，增加护甲值
2. 使用 `damage` 谓词检测伤害事件，判断玩家是否处于"格挡状态"
3. 如果处于格挡状态，触发弹反逻辑（如反弹投射物、给攻击者施加伤害等）
4. 格挡状态持续很短时间（如 5 tick），之后自动移除

### 完整代码

#### 1. 初始化 (load)

```mcfunction
# load.mcfunction
scoreboard objectives add <namespace>:block_timer dummy
scoreboard objectives add <namespace>:blocking dummy
```

#### 2. 玩家右键触发格挡

使用 `used_item` 进度检测玩家使用物品（如盾牌、剑等），进入格挡状态。

```json
// <namespace>/advancement/block_start.json
{
  "criteria": {
    "use_item": {
      "trigger": "minecraft:used_item",
      "conditions": {
        "item": {
          "items": [
            "minecraft:shield",
            "minecraft:sword",
            "minecraft:axe"
          ]
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:block/start"
  }
}
```

```mcfunction
# <namespace>/function/block/start.mcfunction
# 设置格挡状态
scoreboard players set @s <namespace>:blocking 1
scoreboard players set @s <namespace>:block_timer 0

# 添加护甲修饰符（持续 5 tick）
attribute @s minecraft:generic.armor modifier add <namespace>:block_armor "Block Armor" 10.0 add
attribute @s minecraft:generic.armor_toughness modifier add <namespace>:block_toughness "Block Toughness" 5.0 add

# 给予伤害吸收效果（视觉反馈）
effect give @s minecraft:absorption 1 0 true

# 撤销进度，允许下次触发
advancement revoke @s only <namespace>:block_start
```

#### 3. 格挡状态维护 (tick)

```mcfunction
# <namespace>/function/tick.mcfunction
execute as @a[scores={<namespace>:blocking=1}] run function <namespace>:block/tick
```

```mcfunction
# <namespace>/function/block/tick.mcfunction
# 增加计时器
scoreboard players add @s <namespace>:block_timer 1

# 如果超过 5 tick，结束格挡状态
execute if score @s <namespace>:block_timer matches 6.. run function <namespace>:block/end

# 检测玩家是否不再使用物品（松开右键）
# ⚠️ 需验证：如何检测玩家停止使用物品？可以使用 advancement 的 used_item 反向检测，或者检测玩家是否在潜行/使用物品
# 这里使用一个简单的方案：检测玩家是否在潜行（潜行时格挡）
execute unless predicate <namespace>:is_blocking_pose run function <namespace>:block/end
```

```json
// <namespace>/predicate/is_blocking_pose.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "flags": {
      "is_sneaking": true
    }
  }
}
```

#### 4. 格挡结束

```mcfunction
# <namespace>/function/block/end.mcfunction
# 移除格挡状态
scoreboard players set @s <namespace>:blocking 0
scoreboard players set @s <namespace>:block_timer 0

# 移除属性修饰符
attribute @s minecraft:generic.armor modifier remove <namespace>:block_armor
attribute @s minecraft:generic.armor_toughness modifier remove <namespace>:block_toughness

# 移除伤害吸收效果
effect clear @s minecraft:absorption
```

#### 5. 伤害检测与弹反

使用 `damage` 谓词检测玩家受到伤害的瞬间，判断是否处于格挡状态。

```json
// <namespace>/advancement/block_damage.json
{
  "criteria": {
    "damaged": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "source_entity": {
              "type": "#minecraft:enemies"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:block/on_damage"
  }
}
```

```mcfunction
# <namespace>/function/block/on_damage.mcfunction
# 检查是否处于格挡状态
execute if score @s <namespace>:blocking matches 1 run function <namespace>:block/parry

# 撤销进度
advancement revoke @s only <namespace>:block_damage
```

```mcfunction
# <namespace>/function/block/parry.mcfunction
# 弹反逻辑：给攻击者施加伤害
execute on attacker run damage @s 5 minecraft:player_attack

# 或者反弹投射物
execute on attacker run function <namespace>:block/reflect_projectile

# 结束格挡状态
function <namespace>:block/end
```

### 陷阱与注意事项

1. **属性修饰符的持续时间**：`attribute` 命令添加的修饰符是永久的，需要手动移除。如果玩家在格挡期间退出游戏，修饰符会残留，需要在玩家重新加入时清理。
2. **右键检测的局限性**：`used_item` 进度只在玩家**完成**使用物品时触发，而不是按下右键的瞬间。对于剑和斧，使用动作是"挥动"，不会触发 `used_item`。只有盾牌会触发。⚠️ 需验证：剑和斧是否真的不会触发 `used_item`？
3. **潜行检测的替代方案**：如果使用潜行作为格挡触发条件，需要确保玩家在潜行时不会意外触发格挡（如潜行行走时）。
4. **伤害吸收效果的叠加**：如果玩家在格挡期间连续受到伤害，伤害吸收效果会叠加，可能导致意外的无敌时间。
5. **弹反的伤害来源**：使用 `damage @s 5 minecraft:player_attack` 会给攻击者造成玩家攻击类型的伤害，但不会计入攻击者的击杀统计。如果需要更真实的弹反，可以使用 `minecraft:thorns` 附魔效果。

## 方案二：基于物品使用 + 伤害修改的格挡（1.16-1.20.4 兼容方案）

### 原理

在 1.20.5 之前的版本，没有 `attribute` 命令的动态修饰符支持。使用 `item_modifier` 修改玩家手持物品的属性，或者使用 `effect` 给予伤害吸收效果来模拟格挡。

核心机制：
1. 玩家手持特定物品（如剑）时，右键触发格挡状态
2. 使用 `inventory_changed` 进度检测物品使用
3. 通过 `effect` 给予瞬间伤害吸收效果
4. 使用 `damage` 谓词检测伤害，判断是否处于格挡状态

### 完整代码

#### 1. 初始化

```mcfunction
# load.mcfunction
scoreboard objectives add <namespace>:block_timer dummy
scoreboard objectives add <namespace>:blocking dummy
```

#### 2. 物品使用检测

```json
// <namespace>/advancement/block_start.json
{
  "criteria": {
    "use_item": {
      "trigger": "minecraft:used_item",
      "conditions": {
        "item": {
          "items": [
            "minecraft:shield",
            "minecraft:iron_sword",
            "minecraft:diamond_sword"
          ]
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:block/start"
  }
}
```

```mcfunction
# <namespace>/function/block/start.mcfunction
# 设置格挡状态
scoreboard players set @s <namespace>:blocking 1
scoreboard players set @s <namespace>:block_timer 0

# 给予伤害吸收效果（模拟格挡）
effect give @s minecraft:absorption 1 4 true

# 撤销进度
advancement revoke @s only <namespace>:block_start
```

#### 3. 格挡状态维护

```mcfunction
# <namespace>/function/tick.mcfunction
execute as @a[scores={<namespace>:blocking=1}] run function <namespace>:block/tick
```

```mcfunction
# <namespace>/function/block/tick.mcfunction
scoreboard players add @s <namespace>:block_timer 1

# 格挡持续 10 tick（0.5秒）
execute if score @s <namespace>:block_timer matches 11.. run function <namespace>:block/end

# 检测玩家是否还在使用物品
# ⚠️ 需验证：1.16-1.20.4 如何检测玩家是否正在使用物品？
# 可以使用 advancement 的 used_item 反向检测，或者检测玩家是否在潜行
execute unless predicate <namespace>:is_blocking_pose run function <namespace>:block/end
```

#### 4. 伤害检测

```json
// <namespace>/advancement/block_damage.json
{
  "criteria": {
    "damaged": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "source_entity": {
              "type": "#minecraft:enemies"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:block/on_damage"
  }
}
```

```mcfunction
# <namespace>/function/block/on_damage.mcfunction
execute if score @s <namespace>:blocking matches 1 run function <namespace>:block/parry
advancement revoke @s only <namespace>:block_damage
```

```mcfunction
# <namespace>/function/block/parry.mcfunction
# 弹反：给攻击者施加缓慢效果
execute on attacker run effect give @s minecraft:slowness 3 2 true

# 或者反弹伤害（使用荆棘效果模拟）
# ⚠️ 需验证：1.16-1.20.4 如何给攻击者造成伤害？
# 可以使用 damage 命令（1.16+），或者使用 area_effect_cloud
execute on attacker run damage @s 3 minecraft:magic

# 结束格挡
function <namespace>:block/end
```

### 陷阱与注意事项

1. **伤害吸收的局限性**：伤害吸收效果只能吸收固定数值的伤害，无法根据攻击强度动态调整。如果攻击伤害超过吸收值，玩家仍然会受到剩余伤害。
2. **物品使用检测的延迟**：`used_item` 进度在物品使用完成后触发，而不是按下右键的瞬间。对于剑来说，使用动作是"挥动"，不会触发 `used_item`。只有盾牌会触发。
3. **版本差异**：`damage` 命令在 1.16 引入，`attribute` 命令在 1.20.5 引入。1.16 之前的版本无法使用这些命令。
4. **弹反的伤害类型**：使用 `minecraft:magic` 伤害类型可以绕过护甲，但不会触发攻击者的受伤动画。

## 方案三：基于盾牌 + 自定义附魔的格挡（1.16+ 通用方案）

### 原理

利用原版盾牌的格挡机制，通过 `item_modifier` 给盾牌添加自定义附魔（如荆棘），当玩家使用盾牌格挡时，自动触发弹反效果。

核心机制：
1. 给盾牌添加自定义附魔 `minecraft:thorns`
2. 使用 `damage` 谓词检测玩家受到伤害时是否持有盾牌
3. 如果持有盾牌且处于格挡状态，触发弹反逻辑

### 完整代码

#### 1. 给盾牌添加自定义附魔

```json
// <namespace>/item_modifier/shield_enchant.json
{
  "function": "minecraft:set_enchantments",
  "enchantments": {
    "minecraft:thorns": 10
  }
}
```

```mcfunction
# 在玩家获得盾牌时应用
item modify entity @s weapon.mainhand <namespace>:shield_enchant
```

#### 2. 检测盾牌格挡

```json
// <namespace>/advancement/block_damage.json
{
  "criteria": {
    "damaged": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "source_entity": {
              "type": "#minecraft:enemies"
            }
          }
        },
        "player": {
          "equipment": {
            "mainhand": {
              "items": ["minecraft:shield"]
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:block/on_damage"
  }
}
```

```mcfunction
# <namespace>/function/block/on_damage.mcfunction
# 检测玩家是否正在使用盾牌（格挡状态）
# ⚠️ 需验证：如何检测玩家是否正在使用盾牌？
# 可以使用 predicate 检测玩家是否在潜行（使用盾牌时通常需要潜行）
execute if predicate <namespace>:is_blocking run function <namespace>:block/parry
advancement revoke @s only <namespace>:block_damage
```

```json
// <namespace>/predicate/is_blocking.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "flags": {
      "is_sneaking": true
    }
  }
}
```

```mcfunction
# <namespace>/function/block/parry.mcfunction
# 弹反：给攻击者造成额外伤害
execute on attacker run damage @s 5 minecraft:thorns

# 或者反弹投射物
execute on attacker run function <namespace>:block/reflect_projectile
```

### 陷阱与注意事项

1. **盾牌格挡的局限性**：盾牌只能格挡来自前方的攻击，且无法格挡魔法伤害（如药水、龙息等）。
2. **荆棘附魔的触发条件**：荆棘附魔在玩家受到伤害时自动触发，但伤害值固定（取决于附魔等级），无法实现"完美格挡"或"弹反"的精确控制。
3. **潜行检测的误判**：使用潜行作为格挡检测条件，会导致玩家在潜行行走时也被视为"格挡状态"。
4. **盾牌的耐久度**：盾牌格挡会消耗耐久度，需要定期修复或更换。

|------|---------|---------|---------|---------|---------|

| 方案二：伤害吸收 | 1.16-1.20.4 | 低 | 中（固定吸收值） | 支持（可反弹效果） | 兼容旧版本的通用方案 |
| 方案三：盾牌附魔 | 1.16+ | 低 | 低（依赖原版盾牌机制） | 有限（荆棘附魔自动触发） | 快速实现基础格挡功能 |

## 总结

- **推荐方案**：方案一（1.20.5+）提供了最精确的格挡控制和弹反实现，适合现代版本的数据包开发。
- **兼容方案**：方案二适合需要兼容 1.16-1.20.4 版本的项目。
- **快速方案**：方案三适合快速实现基础格挡功能，但控制精度较低。

所有方案都需要注意：
1. 玩家退出游戏时的状态清理（属性修饰符、效果等）
2. 格挡状态的精确检测（避免误判）
3. 弹反伤害的来源和类型（避免无限循环）
