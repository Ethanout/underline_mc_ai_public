# 如何制作拖尾

## 核心挑战

拖尾（Trail）在 Minecraft 数据包开发中指的是：实体移动时，在其经过的路径上留下视觉残留效果（如粒子、掉落物、盔甲架等）。核心挑战在于：

1. **性能**：高频检测实体位置并生成效果，容易造成卡顿
2. **精度**：实体移动速度不同，需要合适的采样频率
3. **清理**：拖尾效果需要自动消失，避免无限堆积

## 方案一：粒子拖尾（推荐，1.13+）

### 原理

利用 `execute positioned` 在实体位置生成粒子，配合 `scoreboard` 控制生成频率。粒子自带生命周期，无需手动清理。

### 完整代码

#### 目录结构
```
data/
  <namespace>/
    functions/
      trail/
        tick.mcfunction
        spawn.mcfunction
        clear.mcfunction
    tags/
      functions/
        tick.json
```

#### 1. 主循环（tick 函数）

`data/<namespace>/functions/trail/tick.mcfunction`
```mcfunction
# 每 tick 检测所有需要拖尾的实体
# 使用 scoreboard 控制生成频率（每 2 tick 生成一次）
scoreboard players add @e[tag=trail_entity] trail_timer 1
execute as @e[tag=trail_entity, scores={trail_timer=2..}] at @s run function <namespace>:trail/spawn
```

#### 2. 生成粒子

`data/<namespace>/functions/trail/spawn.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s trail_timer 0

# 生成粒子（以 end_rod 粒子为例）
particle minecraft:end_rod ~ ~0.5 ~ 0 0 0 0 1 force

# 可选：根据实体朝向生成多个粒子
# 向前方偏移
execute rotated as @s positioned ^ ^ ^0.5 run particle minecraft:end_rod ~ ~0.5 ~ 0 0 0 0 1 force
```

#### 3. 清理函数

`data/<namespace>/functions/trail/clear.mcfunction`
```mcfunction
# 移除所有拖尾实体的 tag 和 scoreboard
scoreboard players reset @e[tag=trail_entity] trail_timer
tag @e[tag=trail_entity] remove trail_entity
```

#### 4. 标签文件

`data/<namespace>/tags/functions/tick.json`
```json
{
    "values": [
        "<namespace>:trail/tick"
    ]
}
```

### 陷阱与注意事项

1. **粒子类型选择**：`force` 模式强制所有玩家看到，`normal` 模式只在 32 格内可见。拖尾建议用 `force`。
2. **频率控制**：每 tick 生成会导致粒子密集，建议每 2-4 tick 生成一次。使用 `scoreboard` 控制。
3. **粒子数量**：`particle` 命令的 count 参数控制每次生成的粒子数，过多会卡顿。
4. **清理机制**：粒子自动消失，无需手动清理，但需要确保实体 tag 被正确移除。

## 方案二：掉落物拖尾（1.13+，适合需要交互的拖尾）

### 原理

在实体位置生成 `item` 实体（掉落物），利用其 `Age` 标签控制消失时间。掉落物可以被玩家拾取或与命令交互。

### 完整代码

#### 目录结构
```
data/
  <namespace>/
    functions/
      trail/
        item/
          tick.mcfunction
          spawn.mcfunction
          cleanup.mcfunction
```

#### 1. 主循环

`data/<namespace>/functions/trail/item/tick.mcfunction`
```mcfunction
# 每 tick 检测
scoreboard players add @e[tag=trail_item] trail_timer 1
execute as @e[tag=trail_item, scores={trail_timer=3..}] at @s run function <namespace>:trail/item/spawn
```

#### 2. 生成掉落物

`data/<namespace>/functions/trail/item/spawn.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s trail_timer 0

# 生成掉落物（使用屏障作为不可见载体）
summon item ~ ~0.5 ~ {Item:{id:"minecraft:barrier",Count:1b},Age:-32768s,Health:5f,PickupDelay:32767s}

# 给掉落物打 tag 以便清理
tag @e[type=item,dx=0,dy=0,dz=0,sort=nearest,limit=1] add trail_particle

# 设置自定义数据（可选）
data merge entity @e[type=item,tag=trail_particle,limit=1,sort=nearest] {Glowing:1b}
```

#### 3. 清理过期掉落物

`data/<namespace>/functions/trail/item/cleanup.mcfunction`
```mcfunction
# 每 5 秒清理一次
schedule function <namespace>:trail/item/cleanup 5s replace

# 移除 Age 大于 100 的拖尾掉落物
kill @e[type=item,tag=trail_particle,nbt={Age:100s..}]
```

### 陷阱与注意事项

1. **掉落物消失时间**：`Age` 标签从 0 开始增加，到 6000（5分钟）自动消失。设置 `Age:-32768s` 可以延迟消失。
2. **拾取延迟**：`PickupDelay:32767s` 防止玩家拾取，但创造模式仍可拾取。
3. **性能开销**：每个掉落物都是一个实体，大量生成会严重影响性能。建议限制最大数量。
4. **清理机制**：必须定期清理，否则会无限堆积。使用 `schedule` 函数定期执行。

## 方案三：盔甲架拖尾（1.13+，适合复杂视觉效果）

### 原理

使用盔甲架作为载体，通过 `data merge` 修改其 NBT 实现视觉效果（如装备物品、标记等）。盔甲架可以精确控制位置和旋转。

### 完整代码

#### 目录结构
```
data/
  <namespace>/
    functions/
      trail/
        armor_stand/
          tick.mcfunction
          spawn.mcfunction
          cleanup.mcfunction
```

#### 1. 主循环

`data/<namespace>/functions/trail/armor_stand/tick.mcfunction`
```mcfunction
# 每 5 tick 生成一个盔甲架
scoreboard players add @e[tag=trail_armor] trail_timer 1
execute as @e[tag=trail_armor, scores={trail_timer=5..}] at @s run function <namespace>:trail/armor_stand/spawn
```

#### 2. 生成盔甲架

`data/<namespace>/functions/trail/armor_stand/spawn.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s trail_timer 0

# 生成不可见盔甲架
summon armor_stand ~ ~0.5 ~ {Invisible:1b,NoGravity:1b,Marker:1b,Small:1b,Invulnerable:1b}

# 打 tag
tag @e[type=armor_stand,dx=0,dy=0,dz=0,sort=nearest,limit=1] add trail_armor_particle

# 设置装备（显示物品）
data merge entity @e[type=armor_stand,tag=trail_armor_particle,limit=1,sort=nearest] {ArmorItems:[{},{},{},{id:"minecraft:diamond",Count:1b}]}
```

#### 3. 清理过期盔甲架

`data/<namespace>/functions/trail/armor_stand/cleanup.mcfunction`
```mcfunction
# 每 10 秒清理一次
schedule function <namespace>:trail/armor_stand/cleanup 10s replace

# 移除存在超过 100 tick 的盔甲架
kill @e[type=armor_stand,tag=trail_armor_particle,nbt={Age:100s..}]
```

### 陷阱与注意事项

1. **盔甲架数量限制**：Minecraft 对实体数量有硬限制（约 2000 个），大量盔甲架会导致游戏崩溃。
2. **性能开销**：每个盔甲架都是一个完整实体，开销远大于粒子。
3. **清理机制**：必须严格清理，否则会迅速达到实体上限。
4. **视觉效果**：盔甲架可以装备物品、设置名称、发光等，视觉效果更丰富。

## 方案四：区域效果云拖尾（1.13+，适合持续伤害/效果区域）

### 原理

使用 `area_effect_cloud` 实体，可以设置药水效果、粒子效果和持续时间。适合制作毒雾、火焰路径等持续效果。

### 完整代码

#### 目录结构
```
data/
  <namespace>/
    functions/
      trail/
        aec/
          tick.mcfunction
          spawn.mcfunction
```

#### 1. 主循环

`data/<namespace>/functions/trail/aec/tick.mcfunction`
```mcfunction
# 每 10 tick 生成一个区域效果云
scoreboard players add @e[tag=trail_aec] trail_timer 1
execute as @e[tag=trail_aec, scores={trail_timer=10..}] at @s run function <namespace>:trail/aec/spawn
```

#### 2. 生成区域效果云

`data/<namespace>/functions/trail/aec/spawn.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s trail_timer 0

# 生成区域效果云（持续 5 秒，半径 1 格）
summon area_effect_cloud ~ ~0.5 ~ {Duration:100,Radius:1f,RadiusPerTick:0f,RadiusOnUse:0f,WaitTime:0,Particle:{type:"minecraft:flame"}}

# 设置药水效果（可选，对进入区域的实体施加效果）
data merge entity @e[type=area_effect_cloud,dx=0,dy=0,dz=0,sort=nearest,limit=1] {Effects:[{Id:19b,Amplifier:0b,Duration:100,ShowParticles:0b}]}
```

### 陷阱与注意事项

1. **持续时间**：`Duration` 以 tick 为单位，100 tick = 5 秒。
2. **粒子效果**：`Particle` 字段可以设置自定义粒子，但格式较复杂。
3. **性能开销**：区域效果云是实体，但比盔甲架轻量。大量生成仍会卡顿。
4. **交互性**：区域效果云可以对进入的实体施加药水效果，适合制作陷阱。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 视觉效果 | 交互性 | 清理难度 | 适用场景 |
|------|---------|---------|---------|-------|---------|---------|
| 粒子拖尾 | 1.13+ | 低 | 好 | 无 | 自动 | 通用拖尾、装饰效果 |
| 掉落物拖尾 | 1.13+ | 中 | 中 | 可拾取 | 需手动 | 可交互拖尾、资源路径 |
| 盔甲架拖尾 | 1.13+ | 高 | 丰富 | 可交互 | 需严格清理 | 复杂视觉效果、装饰 |
| 区域效果云 | 1.13+ | 中 | 中 | 可施加效果 | 自动 | 持续伤害区域、毒雾 |

## 最佳实践建议

1. **优先使用粒子拖尾**：性能最好，无需清理，适合大多数场景。
2. **控制生成频率**：根据实体移动速度调整，慢速实体每 4-5 tick 生成一次，快速实体每 1-2 tick 生成一次。
3. **限制实体数量**：使用 `scoreboard` 或 `tag` 限制同时存在的拖尾实体数量。
4. **使用 schedule 清理**：对于掉落物和盔甲架方案，必须定期清理。
5. **测试性能**：在目标硬件上测试，确保不会造成卡顿。
