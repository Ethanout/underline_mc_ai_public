# 如何让敌人追玩家

## 核心挑战

在 Minecraft 原版数据包中实现"敌人追玩家"面临几个根本限制：
1. **没有原生的寻路 API** — 无法直接命令实体走向某个坐标
2. **实体 AI 系统不可编程** — 无法通过数据包修改行为树或目标选择器
3. **性能与精度的权衡** — 高频移动计算 vs 服务器负载

因此所有方案本质上都是"利用原版已有机制间接实现追踪"，而非真正的 AI 寻路。

---

## 方案一：利用 `minecraft:follow_range` 属性 + 原版 AI 目标

### 原理

Minecraft 原版怪物（如僵尸、骷髅）自带 `follow_range` 属性，控制它们追踪玩家的最大距离。通过修改此属性，可以让任何有攻击 AI 的怪物在更远距离上追踪玩家。

**适用版本**：1.16+（属性系统稳定）

**适用场景**：已有攻击 AI 的怪物（僵尸、骷髅、蜘蛛等），需要扩大追踪范围

### 完整代码

`data/<namespace>/function/enemy/setup.mcfunction`
```mcfunction
# 给目标实体设置更大的追踪范围
# 假设实体标签为 "my_enemy"
execute as @e[tag=my_enemy] run attribute @s minecraft:follow_range base set 64.0
```

`data/<namespace>/function/enemy/init.mcfunction`
```mcfunction
# 在 load 或第一次生成时调用
execute as @e[tag=my_enemy] run function <namespace>:enemy/setup
```

### 陷阱

1. **只对已有攻击 AI 的实体有效** — 猪、牛等被动生物没有攻击目标系统，设置 `follow_range` 无效
2. **不改变行为逻辑** — 怪物仍然需要"看到"玩家（视线检测）才会追击，不会穿墙追踪
3. **属性修改是永久的** — 如果实体被保存到区块，属性会持久化，需要额外清理逻辑
4. **`follow_range` 默认值** — 僵尸默认 35，骷髅默认 16，修改后需测试是否过大导致性能问题

## 方案二：利用 `minecraft:generic.movement_speed` + 路径点标记

### 原理

通过修改实体的移动速度属性，配合 `execute` 的 `at` 和 `facing` 子命令，让实体朝向玩家移动。核心思路：
1. 设置实体的 `NoAI` 为 false（保留基本移动能力）
2. 使用 `tp` 或 `teleport` 命令让实体朝向玩家
3. 利用原版的"被推动"或"随机移动"机制让实体前进

**适用版本**：1.13+（`attribute` 命令引入）

**适用场景**：需要自定义追踪行为，或对无 AI 实体实现追踪

### 完整代码

`data/<namespace>/function/enemy/track.mcfunction`
```mcfunction
# 每 tick 执行，让所有标记的实体朝向最近的玩家
execute as @e[tag=my_enemy] at @s run tp @s ~ ~ ~ facing entity @p

# 增加移动速度，让实体在朝向玩家时自然前进
execute as @e[tag=my_enemy] run attribute @s minecraft:generic.movement_speed base set 0.3
```

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 在 tick 函数中调用
function <namespace>:enemy/track
```

### 陷阱

1. **实体不会主动移动** — 仅设置朝向不会让实体自动前进，需要配合原生的"随机移动"或"被推动"机制
2. **`tp` 朝向会覆盖实体原有朝向** — 如果实体有其他行为（如攻击动画），朝向会被覆盖
3. **性能问题** — 每 tick 对所有实体执行 `tp` 和 `attribute` 操作，大量实体时开销较高
4. **`facing entity` 的精度** — 1.20.5+ 中 `facing entity` 支持更精确的朝向，但旧版本可能略有偏差

## 方案三：利用 `minecraft:generic.movement_speed` + 推动机制

### 原理

利用实体的"被推动"机制（如水流、气泡柱、爆炸等），通过 `execute` 的 `summon` 和 `data` 命令模拟推动效果。更实用的方法是使用 `ride` 或 `passenger` 系统。

**适用版本**：1.13+（`ride` 命令 1.13 引入）

**适用场景**：需要让实体沿直线追踪，不依赖原版 AI

### 完整代码

`data/<namespace>/function/enemy/push.mcfunction`
```mcfunction
# 每 tick 执行，让实体朝向玩家并施加推动
execute as @e[tag=my_enemy] at @s run tp @s ~ ~ ~ facing entity @p

# 使用 motion 组件推动实体（1.20.5+ 语法）
execute as @e[tag=my_enemy] at @s run data modify entity @s Motion[0] set value 0.5
execute as @e[tag=my_enemy] at @s run data modify entity @s Motion[2] set value 0.5
```

`data/<namespace>/function/tick.mcfunction`
```mcfunction
function <namespace>:enemy/push
```

### 陷阱

1. **`Motion` 修改需要精确计算** — 直接设置固定值会导致实体沿世界坐标轴移动，而非朝向玩家方向
2. **需要向量计算** — 正确做法是计算玩家与实体的方向向量，然后归一化后乘以速度
3. **`data modify` 在 1.20.5 前后语法不同** — 旧版本使用 `data merge entity @s {Motion:[0.0,0.0,0.0]}`，新版本使用 `data modify`
4. **实体可能卡在方块中** — 没有碰撞检测，实体可能穿墙或卡住

## 方案四：利用 `minecraft:generic.movement_speed` + 路径点标记（推荐）

### 原理

结合方案二和方案三的优点，使用 `execute` 的 `at` 和 `facing` 子命令让实体朝向玩家，同时利用原版的"随机移动"AI 让实体自然前进。通过修改 `FollowRange` 和 `MovementSpeed` 属性，让实体在朝向玩家时自动追踪。

**适用版本**：1.16+（属性系统稳定）

**适用场景**：需要平衡性能和精度的场景，适合大多数自定义怪物

### 完整代码

`data/<namespace>/function/enemy/track_v2.mcfunction`
```mcfunction
# 每 tick 执行
# 1. 让实体朝向最近的玩家
execute as @e[tag=my_enemy] at @s run tp @s ~ ~ ~ facing entity @p

# 2. 修改移动速度，让实体在朝向玩家时自然前进
execute as @e[tag=my_enemy] run attribute @s minecraft:generic.movement_speed base set 0.35

# 3. 可选：修改追踪范围
execute as @e[tag=my_enemy] run attribute @s minecraft:follow_range base set 64.0
```

`data/<namespace>/function/tick.mcfunction`
```mcfunction

```

### 陷阱

1. **实体需要"看到"玩家** — 原版 AI 需要视线检测，如果玩家在墙后，实体可能停止追踪
2. **`tp` 朝向会覆盖实体原有朝向** — 如果实体有其他行为（如攻击动画），朝向会被覆盖
3. **性能问题** — 每 tick 对所有实体执行 `tp` 和 `attribute` 操作，大量实体时开销较高
4. **`facing entity` 的精度** — 1.20.5+ 中 `facing entity` 支持更精确的朝向，但旧版本可能略有偏差
