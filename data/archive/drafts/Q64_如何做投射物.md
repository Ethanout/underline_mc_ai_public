# 如何做投射物

## 一、核心挑战

在 Minecraft 原版数据包中实现"投射物"（如子弹、箭矢、火球等），核心挑战在于：

1. **原版没有通用的"投射物实体"**——只有有限的几种（箭、雪球、鸡蛋、末影珍珠、三叉戟等），且行为固定
2. **需要自己实现运动、碰撞检测、生命周期管理**
3. **性能开销敏感**——投射物通常需要高频 tick（每 gt 执行），大量投射物会迅速耗尽 MSPT

## 二、方案总览

| 方案 | 版本要求 | 性能 | 适用场景 | 复杂度 |
|------|---------|------|---------|--------|
| 雪球/鸡蛋 + 自定义行为 | 1.13+ | 低 | 简单弹射物，无需复杂轨迹 | 低 |
| 箭 + 自定义状态效果 | 1.13+ | 低 | 需要穿透/弹射的投射物 | 中 |
| 区域效果云 (Area Effect Cloud) | 1.13+ | 中 | 范围伤害/持续效果投射物 | 中 |
| 标记实体 (Marker) + 运动模拟 | 1.20.5+ | 高 | 高性能、高自定义投射物 | 高 |
| 物品展示实体 (Item Display) | 1.19.4+ | 中 | 需要视觉自定义的投射物 | 高 |

## 三、方案详解

### 方案一：雪球/鸡蛋 + 自定义行为（推荐入门）

**原理**：利用原版雪球/鸡蛋实体自带的投掷物理（抛物线、重力、碰撞检测），通过 `player_launch_projectile` 进度监听投掷事件，在 `Projectile` 实体上附加自定义数据，通过 `tick` 函数检测碰撞并执行自定义逻辑。

**适用版本**：1.13+
**优点**：无需自己实现物理和碰撞，性能开销极低
**缺点**：无法修改弹道参数（速度、重力），碰撞检测精度有限

#### 完整实现

**目录结构**：
```
data/
  namespace/
    advancement/
      projectile/throw.json
    function/
      projectile/
        on_throw.mcfunction
        tick.mcfunction
        on_hit.mcfunction
        on_remove.mcfunction
    item_modifier/
      projectile/
        tag.json
```

**1. 监听投掷事件**

`data/namespace/advancement/projectile/throw.json`
```json
{
  "criteria": {
    "throw": {
      "trigger": "minecraft:player_launch_projectile",
      "conditions": {
        "projectile": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "minecraft:snowball"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "namespace:projectile/on_throw"
  }
}
```

**2. 投掷时标记实体**

`data/namespace/function/projectile/on_throw.mcfunction`
```mcfunction
# 给投掷出的雪球打上自定义标签
# 使用 scoreboard 标记，避免 NBT 操作性能开销
scoreboard players set @e[type=minecraft:snowball,dx=0,dy=0,dz=0,sort=nearest,limit=1] namespace.projectile 1

# 设置生命周期（200 tick = 10秒）
schedule function namespace:projectile/on_remove 200t

# 撤销进度，允许下次触发
advancement revoke @s only namespace:projectile/throw
```

**3. 每 tick 检测碰撞**

`data/namespace/function/projectile/tick.mcfunction`
```mcfunction
# 对所有标记的雪球执行检测
execute as @e[type=minecraft:snowball,scores={namespace.projectile=1..}] at @s run function namespace:projectile/check_hit
```

`data/namespace/function/projectile/check_hit.mcfunction`
```mcfunction
# 检测是否撞到方块（inGround 为 true 表示已落地）
execute if entity @s[nbt={inGround:1b}] run function namespace:projectile/on_hit

# 检测是否撞到实体（通过 execute on 检测）
execute on vehicle run function namespace:projectile/on_hit_entity
```

**4. 碰撞处理**

`data/namespace/function/projectile/on_hit.mcfunction`
```mcfunction
# 执行自定义效果（如爆炸、伤害）
particle minecraft:flame ~ ~ ~ 0.5 0.5 0.5 0.1 10
playsound minecraft:entity.generic.explode player @a ~ ~ ~ 1.0 1.0

# 清除实体
kill @s
```

**5. 超时清理**

`data/namespace/function/projectile/on_remove.mcfunction`
```mcfunction
# 清理所有超时的投射物
kill @e[type=minecraft:snowball,scores={namespace.projectile=1..}]
```

#### 陷阱与注意事项

1. **`player_launch_projectile` 进度触发时机**：进度在实体生成后立即触发，此时实体可能还未完全初始化。建议在 `on_throw` 函数中使用 `schedule` 延迟 1 tick 再标记。
2. **雪球碰撞检测精度**：雪球的 `inGround` 标记在落地后立即设置，但可能穿透薄方块（如地毯、雪层）。
3. **多玩家同时投掷**：`@e[sort=nearest,limit=1]` 在多人同时投掷时可能标记错误实体。更可靠的方式是使用 `UUID` 匹配：
   ```mcfunction
   # 在 on_throw 中获取 UUID
   data modify storage namespace:temp uuid set from entity @e[type=minecraft:snowball,dx=0,dy=0,dz=0,sort=nearest,limit=1] UUID
   # 后续通过 UUID 引用
   execute as @e[type=minecraft:snowball,nbt={UUID:[I;...]}] run ...
   ```
4. **性能**：每 tick 遍历所有标记雪球，100 个以内性能可接受，超过 500 个会显著增加 MSPT。

### 方案二：箭 + 自定义状态效果（穿透/弹射）

**原理**：箭实体支持 `PierceLevel`（穿透）和 `damage` 自定义，且自带完整的物理引擎。通过 `item_modifier` 修改箭的 NBT 数据，可以实现穿透、弹射、自定义伤害等效果。

**适用版本**：1.13+（`PierceLevel` 在 1.14+ 可用）
**优点**：物理引擎完善，支持穿透、弹射、附魔效果
**缺点**：箭的视觉固定（无法改变模型），自定义程度有限

#### 完整实现

**1. 自定义箭物品**

`data/namespace/item_modifier/projectile/custom_arrow.json`
```json
{
  "function": "minecraft:set_components",
  "components": {
    "minecraft:custom_data": {
      "namespace": {
        "projectile_type": "piercing_arrow",
        "damage": 10.0
      }
    }
  }
}
```

**2. 发射自定义箭**

`data/namespace/function/projectile/shoot.mcfunction`
```mcfunction
# 给予玩家自定义箭
give @s minecraft:arrow[namespace={projectile_type:"piercing_arrow",damage:10.0}]

# 使用 bow 发射时，箭会继承 custom_data
```

**3. 监听箭命中**

`data/namespace/advancement/projectile/arrow_hit.json`
```json
{
  "criteria": {
    "hit": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "direct_entity": {
              "type": "minecraft:arrow"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:projectile/on_arrow_hit"
  }
}
```

**4. 处理命中逻辑**

`data/namespace/function/projectile/on_arrow_hit.mcfunction`
```mcfunction
# 获取射中玩家的箭实体
execute as @e[type=minecraft:arrow,nbt={inGround:1b},sort=nearest,limit=1] run function namespace:projectile/arrow_effect
```

#### 陷阱与注意事项

1. **箭的 `custom_data` 继承**：从 1.20.5 开始，箭物品的 `custom_data` 会正确传递给射出的箭实体。1.20.5 之前需要使用 `item_modifier` 在发射时手动设置。
2. **穿透箭的碰撞**：`PierceLevel` 使箭可以穿透实体，但不会触发 `entity_hurt_player` 进度。需要使用 `projectile_land` 进度检测箭落地。
3. **箭的回收**：箭落地后默认可回收，如果不想让玩家捡回，可以在 `on_arrow_hit` 中 `kill @s`。

### 方案三：区域效果云 (Area Effect Cloud) —— 范围投射物

**原理**：区域效果云实体可以移动、应用状态效果、且支持自定义粒子效果。通过修改其 `Motion`、`Radius`、`Duration` 等字段，可以实现移动的伤害区域。

**适用版本**：1.13+
**优点**：自带范围检测，支持持续效果，视觉自定义程度高
**缺点**：移动速度有限，碰撞检测不精确

#### 完整实现

**1. 生成投射物**

`data/namespace/function/projectile/spawn_cloud.mcfunction`
```mcfunction
# 生成一个向前移动的区域效果云
summon area_effect_cloud ~ ~1 ~ {Duration:100,Radius:1.0f,RadiusPerTick:0.0f,RadiusOnUse:0.0f,WaitTime:0,Particle:"minecraft:flame",Motion:[0.0,0.0,0.0],Effects:[{Id:6b,Amplifier:0b,Duration:100,ShowParticles:0b}]}

# 设置运动方向（基于玩家朝向）
execute as @p at @s anchored eyes run function namespace:projectile/set_motion
```

**2. 设置运动方向**

`data/namespace/function/projectile/set_motion.mcfunction`
```mcfunction
# 获取玩家朝向向量
data modify storage namespace:temp motion set from entity @s Rotation
# ⚠️ 需验证：Rotation 是 [yaw, pitch]，需要转换为 Motion 向量
# 简化版：直接使用固定方向
data modify entity @e[type=area_effect_cloud,limit=1,sort=nearest] Motion set value [0.5,0.0,0.0]
```

**3. 每 tick 更新位置**

`data/namespace/function/projectile/tick_cloud.mcfunction`
```mcfunction
# 区域效果云会自动根据 Motion 移动，无需手动更新
# 但需要检测碰撞
execute as @e[type=area_effect_cloud,nbt={Duration:100}] at @s run function namespace:projectile/check_cloud_hit
```

**4. 碰撞检测**

`data/namespace/function/projectile/check_cloud_hit.mcfunction`
```mcfunction
# 检测是否撞到方块（通过检测方块碰撞箱）
execute if block ~ ~ ~ air run return fail
# 如果不在空气中，视为撞墙
particle minecraft:explosion ~ ~ ~ 0.5 0.5 0.5 0.1 5
kill @s
```

#### 陷阱与注意事项

1. **区域效果云的移动**：`Motion` 字段控制移动，但移动速度受 `Duration` 影响（每 tick 移动一次）。速度上限约为 0.5 方块/tick。
2. **碰撞检测不精确**：区域效果云没有原生的碰撞检测，需要手动检测方块或实体。
3. **性能**：区域效果云本身性能开销较低，但大量粒子效果会显著影响 FPS。

### 方案四：标记实体 (Marker) + 运动模拟（高性能）

**原理**：使用 `marker` 实体（1.20.5+）作为投射物的逻辑载体，通过 `teleport` 命令手动模拟运动，使用 `predicate` 或 `execute if block` 检测碰撞。

**适用版本**：1.20.5+
**优点**：性能极高（marker 实体无渲染、无碰撞箱），完全自定义运动逻辑
**缺点**：需要自己实现物理、碰撞检测、生命周期管理

#### 完整实现

**1. 生成投射物**

`data/namespace/function/projectile/spawn_marker.mcfunction`
```mcfunction
# 生成标记实体
summon marker ~ ~1 ~ {Tags:["namespace.projectile"]}

# 存储运动参数到 storage
data modify storage namespace:projectile motion set value [0.5,0.0,0.0]
data modify storage namespace:projectile gravity set value -0.05
data modify storage namespace:projectile lifetime set value 200

# 将运动参数复制到实体
execute as @e[type=marker,tag=namespace.projectile,limit=1,sort=nearest] run function namespace:projectile/init_motion
```

**2. 初始化运动参数**

`data/namespace/function/projectile/init_motion.mcfunction`
```mcfunction
# 使用 scoreboard 存储运动参数
scoreboard players set @s namespace.vx 5
scoreboard players set @s namespace.vy 0
scoreboard players set @s namespace.vz 0
scoreboard players set @s namespace.gravity -1
scoreboard players set @s namespace.lifetime 200
```

**3. 每 tick 更新位置**

`data/namespace/function/projectile/tick_marker.mcfunction`
```mcfunction
# 对所有标记实体执行运动更新
execute as @e[type=marker,tag=namespace.projectile] at @s run function namespace:projectile/move
```

`data/namespace/function/projectile/move.mcfunction`
```mcfunction
# 减少生命周期
scoreboard players remove @s namespace.lifetime 1
execute if score @s namespace.lifetime matches ..0 run function namespace:projectile/expire

# 应用重力
scoreboard players add @s namespace.vy @s namespace.gravity

# 获取当前速度（假设速度单位为 0.1 方块/tick）
scoreboard players get @s namespace.vx
scoreboard players get @s namespace.vy
scoreboard players get @s namespace.vz

# 移动实体
execute positioned ~ ~ ~ run tp @s ~$(vx*0.1) ~$(vy*0.1) ~$(vz*0.1)

# 检测碰撞
function namespace:projectile/check_collision
```

**4. 碰撞检测**

`data/namespace/function/projectile/check_collision.mcfunction`
```mcfunction
# 检测方块碰撞
execute if block ~ ~ ~ #minecraft:replaceable run return fail
# 撞到不可替换方块
particle minecraft:explosion ~ ~ ~ 0.5 0.5 0.5 0.1 5
playsound minecraft:entity.generic.explode player @a ~ ~ ~ 1.0 1.0
kill @s

# 检测实体碰撞
execute as @e[type=!marker,distance=..1.5] run function namespace:projectile/hit_entity
```

**5. 超时处理**

`data/namespace/function/projectile/expire.mcfunction`
```mcfunction
# 生命周期结束，消散
particle minecraft:smoke ~ ~ ~ 0.2 0.2 0.2 0.1 3
kill @s
```

#### 陷阱与注意事项

1. **宏变量精度**：`$(vx*0.1)` 中的宏变量是整数运算，`0.1` 会被截断为 0。需要使用 `$(vx)` 并配合 `positioned` 的偏移量，或者使用 `data modify` 直接操作 `Pos`。
2. **碰撞检测精度**：手动碰撞检测无法处理高速穿透（子弹穿过薄方块）。建议每 tick 移动距离不超过 1 方块。
3. **marker 实体的限制**：marker 实体没有 `Motion` 字段，必须使用 `tp` 或 `data modify Pos` 移动。
4. **性能**：marker 实体本身性能极低，但每 tick 的 `execute as @e[type=marker,tag=...]` 遍历开销与实体数量成正比。1000 个投射物约增加 0.5-1 MSPT。

### 方案五：物品展示实体 (Item Display) —— 视觉自定义

**原理**：使用 `item_display` 实体（1.19.4+）作为投射物的视觉载体，配合 `interaction` 实体进行碰撞检测。可以实现任意物品模型的投射物。

**适用版本**：1.19.4+
**优点**：视觉完全自定义，支持物品模型、旋转、缩放
**缺点**：需要两个实体（display + interaction），性能开销较高

# 生成交互实体用于碰撞检测
summon interaction ~ ~1 ~ {Tags:["namespace.project
