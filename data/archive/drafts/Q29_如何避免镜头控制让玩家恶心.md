# 如何避免镜头控制让玩家恶心

## 问题背景

在 Minecraft 数据包开发中，有时需要控制玩家视角（如过场动画、传送、特殊交互），但不当的镜头操作（突然旋转、强制视角、频繁切换）会导致玩家产生晕动症（Motion Sickness）或不适感。核心挑战在于：**原版数据包对玩家视角的控制能力有限，且缺乏平滑过渡机制**。

## 一、使用 `spectate` 命令实现平滑视角跟随（推荐方案）

### 原理

1.20.5+ 版本引入的 `/spectate` 命令可以将玩家视角绑定到某个实体上，实现平滑的视角跟随。当玩家处于旁观模式时，该命令效果最佳。通过控制被跟随实体的运动（如使用 `/tp` 或 `/ride`），可以实现无抖动的镜头移动。

### 完整实现

#### 1. 创建跟随实体（Load）

```mcfunction
# load.mcfunction
summon minecraft:marker ~ ~ ~ {Tags:["camera_target"]}
```

#### 2. 控制镜头移动（Tick）

```mcfunction
# tick.mcfunction
execute as @a[predicate=!<namespace>:in_cutscene] at @s run function <namespace>:camera/start
execute as @a[predicate=<namespace>:in_cutscene] at @s run function <namespace>:camera/tick
```

#### 3. 开始镜头控制

```mcfunction
# <namespace>:camera/start.mcfunction
# 将玩家切换到旁观模式并绑定到标记实体
gamemode spectator @s
spectate @e[tag=camera_target,limit=1] @s
# 设置标记，防止重复触发
scoreboard players set @s <namespace>.camera_active 1
```

#### 4. 平滑移动镜头

```mcfunction
# <namespace>:camera/tick.mcfunction
# 使用 tp 的旋转参数实现平滑旋转（每次旋转不超过 5 度）
execute as @e[tag=camera_target] at @s run tp @s ~ ~ ~ ~<rotation_delta> ~<pitch_delta>
# 或者使用 /ride 实现路径跟随
ride @e[tag=camera_target] mount @e[tag=path_entity,limit=1]
```

#### 5. 结束镜头控制

```mcfunction
# <namespace>:camera/stop.mcfunction
gamemode survival @s
spectate @s
scoreboard players set @s <namespace>.camera_active 0
```

### 陷阱与注意事项

1. **版本要求**：`/spectate` 命令在 1.20.5+ 才可用，且需要玩家处于旁观模式
2. **玩家交互限制**：旁观模式下玩家无法与方块/实体交互，需要设计退出机制
3. **视角抖动**：如果直接使用 `/tp` 旋转，每次旋转角度过大（>10度）会导致明显抖动，建议每次 tick 旋转不超过 5 度
4. **多人兼容**：每个玩家需要独立的跟随实体，否则视角会冲突

## 二、使用 `camera` 命令（1.21.2+ 快照）

### 原理

1.21.2 快照引入了 `/camera` 命令，提供了原生的镜头控制能力，支持平滑过渡、淡入淡出等效果。这是最理想的方案，但目前仍在实验性阶段。

### 完整实现

```mcfunction
# 设置镜头位置和旋转（带平滑过渡）
camera @s set minecraft:fixed 0 64 0 0 0 transition 20
# 参数说明：transition 20 表示 20 tick（1秒）的平滑过渡

# 淡入淡出效果
camera @s fade color 0 0 0 duration 10 20 10
# 参数说明：color 0 0 0 黑色，duration 10 20 10 表示淡入10tick，保持20tick，淡出10tick

# 重置镜头
camera @s clear
```

### 陷阱与注意事项

1. **版本限制**：仅在 1.21.2+ 快照中可用，正式版尚未发布
2. **实验性功能**：命令语法可能在未来版本中变化
3. **玩家控制**：使用 `camera` 后玩家无法控制视角，需要提供退出机制

## 三、使用 `input` 谓词限制玩家输入（1.20+）

### 原理

通过 `input` 谓词检测玩家是否在移动鼠标/键盘，结合 `execute` 条件限制，在特定场景下禁用玩家的视角控制。这种方法不会直接控制镜头，而是通过限制输入来避免玩家主动旋转导致的恶心。

### 完整实现

#### 1. 创建谓词

```json
# <namespace>:predicate/player_input.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "player": {
      "input": {
        "left": true,
        "right": true,
        "forward": true,
        "backward": true,
        "jump": true,
        "sneak": true,
        "sprint": true
      }
    }
  }
}
```

#### 2. 在特定场景中禁用输入

```mcfunction
# <namespace>:camera/disable_input.mcfunction
# 使用 tag 标记需要限制输入的玩家
tag @s add <namespace>.input_locked

# 在 tick 中持续检测并限制
execute as @a[tag=<namespace>.input_locked] at @s run function <namespace>:camera/apply_lock
```

```mcfunction
# <namespace>:camera/apply_lock.mcfunction
# 注意：input 谓词只能检测，不能修改玩家输入
# 这里通过持续设置玩家位置/旋转来抵消玩家操作
execute as @s at @s anchored eyes positioned ^ ^ ^1 facing entity @e[tag=camera_target,limit=1] eyes run tp @s ~ ~ ~ ~ ~
```

### 陷阱与注意事项

1. **只能检测，不能阻止**：`input` 谓词只能检测玩家输入状态，无法直接禁用输入
2. **性能开销**：高频的 `tp` 操作会消耗服务器性能
3. **网络延迟**：在延迟较高时，玩家可能会看到短暂的视角抖动
4. **版本要求**：`input` 谓词在 1.20+ 可用

## 四、使用 `inventory_changed` 进度检测玩家操作（1.20+）

### 原理

通过检测玩家物品栏变化来间接判断玩家是否在进行操作（如切换物品、使用物品），从而在特定场景下暂停镜头控制。这种方法适用于需要玩家主动确认的场景（如过场动画中的选择界面）。

### 完整实现

#### 1. 创建进度

```json
# <namespace>:advancement/camera_interrupt.json
{
  "criteria": {
    "inventory_changed": {
      "trigger": "minecraft:inventory_changed"
    }
  },
  "rewards": {
    "function": "<namespace>:camera/interrupt"
  }
}
```

#### 2. 中断处理

```mcfunction
# <namespace>:camera/interrupt.mcfunction
# 暂停镜头控制
schedule clear <namespace>:camera/continue
# 通知玩家
tellraw @s {"text":"镜头控制已暂停，请确认继续","color":"yellow"}
# 设置等待确认
scoreboard players set @s <namespace>.camera_waiting 1
```

### 陷阱与注意事项

1. **误触发**：任何物品栏变化都会触发，包括自动拾取
2. **延迟**：进度触发有 1 tick 的延迟
3. **版本要求**：1.20+

## 方案对比

| 方案 | 版本要求 | 平滑度 | 性能开销 | 适用场景 |
|------|---------|--------|---------|---------|
| `/spectate` 跟随 | 1.20.5+ | 高（取决于实体移动） | 低 | 过场动画、跟随视角 |
| `/camera` 命令 | 1.21.2+ 快照 | 极高（原生支持） | 极低 | 所有镜头控制场景 |
| `input` 谓词限制 | 1.20+ | 中（需配合 tp） | 中 | 需要限制玩家输入的场景 |
| `inventory_changed` 检测 | 1.20+ | 低（仅检测） | 低 | 需要玩家确认的场景 |

## 最佳实践建议

1. **优先使用 `/camera` 命令**（如果目标版本支持），它提供了最平滑的体验
2. **次选 `/spectate` 跟随**，配合平滑的实体移动算法
3. **避免直接使用 `/tp` 旋转玩家视角**，除非旋转角度很小（<5度/tick）
4. **始终提供退出机制**，让玩家可以随时恢复视角控制
5. **考虑玩家设置**：在开始镜头控制前，检查玩家是否启用了"视角摇晃"等设置
