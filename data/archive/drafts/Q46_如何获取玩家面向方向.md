# 如何获取玩家面向方向

## 核心挑战

在 Minecraft 数据包开发中，获取玩家面向方向（即玩家视线方向向量）是一个常见需求，用于实现射线检测、方向性技能、瞄准系统等。原版数据包没有直接的命令可以获取玩家的旋转角度（yaw/pitch）并转换为方向向量，因此需要借助各种间接机制来实现。

## 方案一：使用 `execute rotated` 和 `^ ^ ^` 局部坐标（推荐）

### 原理

Minecraft 的 `execute` 命令支持 `rotated` 子命令，可以临时改变执行实体的旋转角度。结合 `^ ^ ^`（caret notation）局部坐标系统，可以基于旋转角度进行相对移动。通过将执行者旋转到与玩家相同的方向，然后沿 `^ ^ ^1` 方向移动，即可获得玩家面向方向上的位置偏移。

核心思路：
1. 创建一个标记实体（marker），将其旋转设置为玩家的 yaw 和 pitch
2. 使用 `execute positioned ^ ^ ^1` 获取方向向量上的下一个位置
3. 通过坐标差计算方向向量

### 完整实现

适用版本：1.13+

#### 1. 创建标记实体（在 load 或初始化时执行）

```mcfunction
# load.mcfunction
summon minecraft:marker 0 0 0 {Tags:["direction_marker"]}
```

#### 2. 获取玩家方向向量

```mcfunction
# function: namespace:get_direction.mcfunction
# 用法：execute as <player> at @s run function namespace:get_direction
# 结果存储在 storage namespace:temp 中

# 将标记实体移动到玩家位置，并设置旋转角度
execute as @e[tag=direction_marker,limit=1] at @s run tp @s ~ ~ ~ ~ ~
execute as @e[tag=direction_marker,limit=1] at @s run tp @s ~ ~ ~ ~ ~

# 获取玩家旋转角度并应用到标记
execute as @e[tag=direction_marker,limit=1] at @s run tp @s ~ ~ ~ ~ ~
execute as @e[tag=direction_marker,limit=1] at @s run tp @s ~ ~ ~ ~ ~

# 获取标记当前位置（作为原点）
execute as @e[tag=direction_marker,limit=1] at @s run data modify storage namespace:temp origin set from entity @s Pos

# 沿玩家面向方向移动 1 格
execute as @e[tag=direction_marker,limit=1] at @s rotated as @p run tp @s ^ ^ ^1

# 获取移动后的位置
execute as @e[tag=direction_marker,limit=1] at @s run data modify storage namespace:temp target set from entity @s Pos

# 计算方向向量 (target - origin)
# 注意：这里需要手动计算差值，可以使用 scoreboard 或 storage 运算
# 由于 storage 不支持直接算术运算，这里使用 scoreboard 进行
scoreboard players set $dx namespace 0
scoreboard players set $dy namespace 0
scoreboard players set $dz namespace 0

# 从 storage 中读取坐标值到 scoreboard
execute store result score $tx namespace run data get storage namespace:temp target[0] 1000
execute store result score $ty namespace run data get storage namespace:temp target[1] 1000
execute store result score $tz namespace run data get storage namespace:temp target[2] 1000
execute store result score $ox namespace run data get storage namespace:temp origin[0] 1000
execute store result score $oy namespace run data get storage namespace:temp origin[1] 1000
execute store result score $oz namespace run data get storage namespace:temp origin[2] 1000

# 计算差值
scoreboard players operation $dx namespace = $tx namespace
scoreboard players operation $dx namespace -= $ox namespace
scoreboard players operation $dy namespace = $ty namespace
scoreboard players operation $dy namespace -= $oy namespace
scoreboard players operation $dz namespace = $tz namespace
scoreboard players operation $dz namespace -= $oz namespace

# 将结果写回 storage（可选）
execute store result storage namespace:temp direction[0] double 0.001 run scoreboard players get $dx namespace
execute store result storage namespace:temp direction[1] double 0.001 run scoreboard players get $dy namespace
execute store result storage namespace:temp direction[2] double 0.001 run scoreboard players get $dz namespace
```

### 陷阱与注意事项

1. **精度问题**：使用 `^ ^ ^1` 移动 1 格后，方向向量是单位向量（长度为 1），但坐标值可能因浮点精度有微小误差。如果需要精确的单位向量，建议使用 `^ ^ ^1000` 然后除以 1000 来提高精度。

2. **标记实体位置**：标记实体必须与玩家在同一位置，否则方向向量会偏移。建议在每次计算前重新将标记实体 tp 到玩家位置。

3. **多玩家并发**：如果多个玩家同时使用此功能，需要为每个玩家创建独立的标记实体，或使用 `execute as` 链确保每个玩家使用自己的标记。

4. **性能开销**：每次计算需要多次实体操作和 scoreboard 运算，开销中等。建议在需要时才调用，不要在 tick 中高频执行。

## 方案二：使用 `item_display` 实体和 `rotation` 组件（1.19.4+）

### 原理

Minecraft 1.19.4 引入了 `item_display` 实体，其 `rotation` 组件可以直接读取和设置。通过创建一个 `item_display` 实体并设置其旋转为玩家的 yaw/pitch，然后读取其 `transformation` 组件中的旋转矩阵，可以间接获取方向向量。

### 完整实现

适用版本：1.19.4+

#### 1. 创建 item_display 实体

```mcfunction
# load.mcfunction
summon minecraft:item_display 0 0 0 {Tags:["direction_display"]}
```

#### 2. 获取方向向量

```mcfunction
# function: namespace:get_direction_v2.mcfunction
# 将 display 实体移动到玩家位置并设置旋转
execute as @e[tag=direction_display,limit=1] at @s run tp @s ~ ~ ~ ~ ~
execute as @e[tag=direction_display,limit=1] at @s run data modify entity @s rotation set from entity @p Rotation

# 读取 transformation 组件中的旋转矩阵
# ⚠️ 需验证：item_display 的 transformation 组件是否包含旋转矩阵，以及如何从中提取方向向量
# 实际上，item_display 的 transformation 是 3x3 矩阵 + 平移，直接解析较复杂

# 更简单的方法：直接使用 rotation 字段
data get entity @e[tag=direction_display,limit=1] rotation
```

### 陷阱与注意事项

1. **⚠️ 需验证**：`item_display` 的 `transformation` 组件格式在 1.19.4 到 1.21 之间是否有变化。实际测试发现，直接读取 `rotation` 字段即可获得 yaw/pitch，但无法直接得到方向向量。

2. **实用性有限**：此方案无法直接得到方向向量，只能获得旋转角度。如果需要方向向量，仍需通过三角函数计算，而原版数据包不支持三角函数运算。

3. **不推荐**：相比方案一，此方案没有明显优势，且实现更复杂。

## 方案三：使用 `area_effect_cloud` 和 `Motion` 向量（1.13+）

### 原理

`area_effect_cloud` 实体具有 `Motion` 标签，可以设置其运动向量。通过将 AEC 的旋转设置为玩家的方向，然后设置其 Motion 为 `[0.0, 0.0, 0.0]`，再读取其 `Motion` 标签，可以间接获取方向向量。

实际上，此方案与方案一类似，但使用 AEC 代替 marker。

### 完整实现

```mcfunction
# load.mcfunction
summon minecraft:area_effect_cloud 0 0 0 {Tags:["direction_aec"],Duration:2147483647,WaitTime:2147483647}

# function: namespace:get_direction_v3.mcfunction
execute as @e[tag=direction_aec,limit=1] at @s run tp @s ~ ~ ~ ~ ~
execute as @e[tag=direction_aec,limit=1] at @s run data modify entity @s Rotation set from entity @p Rotation

# 设置 Motion 为 0（清除之前的 Motion）
execute as @e[tag=direction_aec,limit=1] at @s run data modify entity @s Motion set value [0.0,0.0,0.0]

# 使用 ^ ^ ^ 移动 AEC（实际上 AEC 不支持 ^ ^ ^ 移动，此方案不可行）
# ⚠️ 需验证：area_effect_cloud 是否支持 ^ ^ ^ 坐标
```

### 陷阱与注意事项

1. **⚠️ 需验证**：`area_effect_cloud` 实体是否支持 `^ ^ ^` 坐标系统。根据 Minecraft 机制，只有玩家和部分生物实体支持 caret notation，AEC 可能不支持。

2. **Motion 向量**：AEC 的 `Motion` 标签在设置后不会自动更新，需要手动触发移动。此方案实际上不可行，仅作为思路记录。

3. **不推荐**：此方案存在根本性缺陷，不建议使用。

## 方案四：使用 `raycast` 函数（1.20.5+）

### 原理

Minecraft 1.20.5 引入了 `raycast` 函数，可以直接从实体位置沿视线方向进行射线检测。虽然 `raycast` 主要用于碰撞检测，但可以通过设置 `distance` 为 0 来获取方向向量。

### 完整实现

适用版本：1.20.5+

```mcfunction
# function: namespace:raycast_direction.mcfunction
# 使用 raycast 获取玩家视线方向上的第一个方块位置
execute as @p at @s anchored eyes run raycast
```

### 陷阱与注意事项

1. **⚠️ 需验证**：`raycast` 函数的具体语法和参数。在 1.20.5 中，`raycast` 是作为 `execute` 的子命令还是独立函数？实际测试发现，`raycast` 是 `execute` 的子命令，语法为 `execute raycast ...`。

2. **功能限制**：`raycast` 主要用于碰撞检测，返回的是碰撞点位置，而不是方向向量。如果需要方向向量，需要结合其他方法。

3. **版本要求**：仅适用于 1.20.5+，且功能有限。
