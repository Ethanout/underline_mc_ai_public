# 如何让粒子沿某个方向飞

## 核心挑战

Minecraft 原版粒子系统本身不支持"方向"参数——粒子默认向随机方向扩散。要让粒子沿特定方向飞行，必须借助外部机制：要么利用实体运动轨迹，要么通过命令系统在每一 tick 重新生成粒子并手动更新位置。

## 方案一：使用 `particle` 命令的 `delta` 参数（最简单，但效果有限）

### 原理

`particle <name> <pos> <delta> <speed> <count>` 命令中的 `delta` 参数控制粒子生成时的初始速度方向。当 `count=0` 时，`delta` 作为速度向量直接作用于单个粒子；当 `count>0` 时，`delta` 作为扩散范围。

### 适用版本

1.13+（所有现代版本）

### 代码示例

```mcfunction
# 让单个粒子沿 X 正方向飞行（速度 0.5）
particle minecraft:flame ~ ~ ~ 0.5 0 0 0.5 0

# 让单个粒子沿 Y 正方向飞行（速度 1.0）
particle minecraft:flame ~ ~ ~ 0 1 0 1.0 0

# 让单个粒子沿自定义方向（1, 2, 3）飞行
particle minecraft:flame ~ ~ ~ 1 2 3 1.0 0
```

### 陷阱与注意事项

1. **`count=0` 是关键**：只有 `count=0` 时，`delta` 才作为速度向量。`count>0` 时，`delta` 是扩散范围，粒子会随机分布在 `delta` 定义的立方体内。
2. **粒子寿命有限**：每个粒子有固定的生命周期（如 `flame` 约 1 秒），之后自动消失。无法控制粒子持续飞行。
3. **无法控制粒子路径**：粒子生成后不受命令控制，只能通过初始速度决定方向。重力、空气阻力等物理效果由粒子类型决定（如 `minecraft:flame` 不受重力影响，`minecraft:item` 受重力影响）。
4. **速度单位**：`speed` 参数的单位是"米/游戏刻"（1 游戏刻 = 0.05 秒）。`speed=1.0` 表示粒子每秒移动 20 米。

## 方案二：使用 `area_effect_cloud` 实体携带粒子（可控但复杂）

### 原理

`area_effect_cloud`（AEC）实体可以携带粒子效果，并在其位置持续生成粒子。通过控制 AEC 的移动，可以实现粒子沿特定方向飞行。AEC 可以设置 `Particle`、`Radius`、`Duration`、`WaitTime` 等 NBT 字段。

### 适用版本

1.13+（AEC 在 1.13 引入）

### 代码示例

#### 1. 生成一个沿 X 正方向移动的粒子云

```mcfunction
# 生成 AEC，设置粒子为 flame，半径 0.1（点状），持续 100 tick（5 秒）
summon area_effect_cloud ~ ~ ~ {Particle:"minecraft:flame",Radius:0.1f,Duration:100,WaitTime:0}

# 在 tick 函数中让 AEC 沿 X 正方向移动
execute as @e[type=area_effect_cloud,nbt={Particle:"minecraft:flame"}] at @s run tp @s ~0.5 ~ ~
```

#### 2. 更精确的控制：使用 Motion NBT

```mcfunction
# 生成 AEC 并设置初始速度
summon area_effect_cloud ~ ~ ~ {Particle:"minecraft:flame",Radius:0.1f,Duration:100,WaitTime:0,Motion:[0.5d,0.0d,0.0d]}

# 注意：AEC 默认不受重力影响，但 Motion 会每 tick 衰减（类似玩家移动）
# 需要每 tick 重置 Motion 以保持恒定速度
execute as @e[type=area_effect_cloud,nbt={Particle:"minecraft:flame"}] at @s run data merge entity @s {Motion:[0.5d,0.0d,0.0d]}
```

### 陷阱与注意事项

1. **AEC 的 Motion 衰减**：AEC 的 Motion 每 tick 会乘以 0.98（类似其他实体），需要每 tick 重置才能保持恒定速度。
2. **AEC 数量限制**：大量 AEC 会导致性能问题。建议使用 `limit` 和 `sort` 控制数量。
3. **粒子类型限制**：某些粒子（如 `minecraft:block`、`minecraft:item`）需要额外的 `block_state` 或 `item` 参数，AEC 的 `Particle` 字段不支持这些复杂粒子。
4. **AEC 的 Duration**：`Duration` 是 AEC 存在的时间（tick），`WaitTime` 是开始生成粒子前的延迟。`Duration - WaitTime` 才是实际生成粒子的时间。
5. **AEC 的 Radius**：`Radius` 控制粒子生成的范围。`Radius:0.1f` 近似点状，`Radius:1.0f` 会在 1 米半径内随机生成粒子。

## 方案三：使用 `marker` 实体 + 每 tick 重新生成粒子（最灵活，性能开销中等）

### 原理

使用 `marker` 实体（1.17+）作为位置标记，每 tick 在 marker 位置生成粒子，同时移动 marker 沿目标方向。这种方式可以精确控制粒子的位置和轨迹。

### 适用版本

1.17+（marker 实体引入）

### 代码示例

#### 1. 创建 marker 并沿方向移动

```mcfunction
# 初始化：生成 marker
summon marker ~ ~ ~ {Tags:["particle_marker"]}

# tick 函数：移动 marker 并生成粒子
execute as @e[type=marker,tag=particle_marker] at @s run particle minecraft:flame ~ ~ ~ 0 0 0 0 1
execute as @e[type=marker,tag=particle_marker] at @s run tp @s ~0.5 ~ ~
```

#### 2. 使用 scoreboard 实现更精确的移动（支持任意方向）

```mcfunction
# 初始化：设置方向向量
scoreboard objectives add particle_dir dummy
scoreboard players set @e[type=marker,tag=particle_marker] particle_dir 10  # 方向向量分量 * 10

# tick 函数：使用 execute 的 positioned 和 rotated 实现方向移动
# 假设 marker 的 Rotation 已经设置为目标方向
execute as @e[type=marker,tag=particle_marker] at @s run particle minecraft:flame ~ ~ ~ 0 0 0 0 1
execute as @e[type=marker,tag=particle_marker] at @s rotated ~ ~ run tp @s ^ ^ ^0.5
```

### 陷阱与注意事项

1. **marker 实体不可见**：marker 没有碰撞箱，不会触发压力板等机制，适合作为纯位置标记。
2. **每 tick 生成粒子的性能**：每个 marker 每 tick 生成 1 个粒子，100 个 marker 就是 100 粒子/tick，对性能有一定影响。
3. **粒子轨迹不连续**：由于每 tick 只生成一个粒子，粒子之间会有间隔。速度越快，间隔越大。可以通过增加 `count` 参数（如 `count=2`）来填充间隙。
4. **方向计算**：使用 `^ ^ ^` 局部坐标时，需要正确设置实体的 Rotation。可以使用 `data merge entity @s {Rotation:[yaw, pitch]}` 来设置方向。

## 方案四：使用 `item_display` 实体 + 粒子效果（1.19.4+，视觉效果最佳）

### 原理

`item_display` 实体（1.19.4+）可以渲染物品模型，同时可以设置 `billboard` 模式为 `fixed` 或 `center`。通过让 `item_display` 沿方向移动，并在其位置生成粒子，可以实现粒子沿方向飞行的效果。更高级的用法是使用 `text_display` 显示自定义纹理。

### 适用版本

1.19.4+

### 代码示例

#### 1. 使用 item_display 模拟粒子轨迹

```mcfunction
# 生成 item_display，设置物品为火焰弹（视觉效果类似粒子）
summon item_display ~ ~ ~ {item:{id:"minecraft:fire_charge",count:1},transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[0.5f,0.5f,0.5f]},billboard:"center",Tags:["particle_trail"]}

# tick 函数：移动并生成粒子
execute as @e[type=item_display,tag=particle_trail] at @s run particle minecraft:flame ~ ~ ~ 0 0 0 0 1
execute as @e[type=item_display,tag=particle_trail] at @s run tp @s ~0.5 ~ ~
```

#### 2. 使用 text_display 显示粒子纹理（需要资源包）

```mcfunction
# 生成 text_display，显示自定义纹理
summon text_display ~ ~ ~ {text:'{"text":"█"}',background:0,transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[0.1f,0.1f,0.1f]},billboard:"center",Tags:["particle_trail"]}
```

### 陷阱与注意事项

1. **item_display 有碰撞箱**：默认情况下，item_display 有碰撞箱，可能会与玩家或方块交互。可以通过 `data merge entity @s {no_gravity:1b}` 禁用重力，但碰撞箱仍然存在。
2. **性能开销较高**：每个 display 实体都需要渲染，大量 display 会导致 FPS 下降。
3. **需要资源包支持**：text_display 显示自定义纹理需要资源包提供字体定义。
4. **版本限制**：仅 1.19.4+ 可用。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 可控性 | 视觉效果 | 适用场景 |
|------|---------|---------|--------|---------|---------|
| particle 命令 delta | 1.13+ | 极低 | 低（仅初始速度） | 一般 | 简单特效，如火焰轨迹 |
| area_effect_cloud | 1.13+ | 中（每实体） | 中（可控制移动） | 好 | 持续粒子效果，如魔法光环 |
| marker + 每 tick 粒子 | 1.17+ | 中（每 tick 命令） | 高（精确控制） | 好 | 弹道轨迹、激光效果 |
| item_display | 1.19.4+ | 高（渲染开销） | 高 | 极好 | 需要自定义视觉的复杂特效 |

## 推荐方案

### 简单场景（如火焰箭轨迹）：方案一

```mcfunction
# 在箭的位置每 tick 生成粒子
execute as @e[type=arrow] at @s run particle minecraft:flame ~ ~ ~ 0 0 0 0 1
```

### 中等复杂度（如魔法飞弹）：方案三

```mcfunction
# 初始化
summon marker ~ ~ ~ {Tags:["magic_missile"]}
# 设置方向（假设朝向玩家视线方向）
execute as @p at @s anchored eyes run tp @e[type=marker,tag=magic_missile,limit=1] ~ ~ ~
execute as @e[type=marker,tag=magic_missile] at @s run data merge entity @s {Rotation:[0f,0f]}

# tick 函数
execute as @e[type=marker,tag=magic_missile] at @s run particle minecraft:witch ~ ~ ~ 0 0 0 0 1
execute as @e[type=marker,tag=magic_missile] at @s rotated ~ ~ run tp @s ^ ^ ^0.3
```

### 高性能需求（大量粒子）：方案一 + 优化

```mcfunction
# 使用 particle 命令的 count 参数批量生成
# 注意：count>0 时 delta 作为扩散范围，需要特殊处理
# 使用多个 particle 命令模拟方向
particle minecraft:flame ~ ~ ~ 0.5 0 0 0.5 0
particle minecraft:flame ~0.5 ~ ~ 0.5 0 0 0.5 0
particle minecraft:flame ~1.0 ~ ~ 0.5 0 0 0.5 0
```

## 陷阱总结

1. **粒子类型影响物理行为**：`minecraft:flame` 不受重力，`minecraft:item` 受重力，`minecraft:cloud` 会缓慢上升。选择粒子类型时需考虑其默认物理行为。
2. **粒子数量限制**：客户端有粒子数量上限（默认 16384），超过上限的粒子不会显示。大量粒子时需注意控制数量。
3. **多玩家同步**：`particle` 命令默认对所有玩家可见，但 `particle` 命令的 `viewers` 参数（1.20.5+）可以限制可见玩家。
4. **方向计算精度**：使用 `^ ^ ^` 局部坐标时，实体的 Rotation 必须正确设置。`Rotation:[yaw, pitch]` 中 yaw 是水平旋转（0=南，90=西，180=北，270=东），pitch 是垂直旋转（0=水平，90=向下，-90=向上）。
5. **AEC 的 Motion 衰减**：AEC 的 Motion 每 tick 乘以 0.98，需要每 tick 重置才能保持恒定速度。可以使用 `data merge entity @s {Motion:[x,y,z]}` 重置。
