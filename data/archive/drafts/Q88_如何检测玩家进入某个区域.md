# 如何检测玩家进入某个区域

## 一、核心挑战

检测玩家进入区域在数据包开发中看似简单，但存在几个关键难点：
1. **边界判定**：玩家是连续移动的，tick 检测可能漏掉快速穿越
2. **性能开销**：高频检测所有玩家的位置可能造成性能瓶颈
3. **版本兼容**：不同版本提供的检测机制不同（predicate、advancement trigger、execute 条件）
4. **精确度**：需要区分"进入"和"在区域内"两个概念

## 二、方案一：execute positioned + predicate 条件检测（推荐，1.13+）

### 原理

利用 `execute positioned` 改变执行位置，配合 `predicate` 中的 `location_check` 检测玩家是否在指定区域内。通过比较上一 tick 和当前 tick 的状态来判断"进入"。

### 完整实现

#### 1. 定义区域检测 predicate

`data/<namespace>/predicate/in_area.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "location": {
      "position": {
        "x": {
          "min": 100.0,
          "max": 200.0
        },
        "y": {
          "min": 64.0,
          "max": 100.0
        },
        "z": {
          "min": -50.0,
          "max": 50.0
        }
      }
    }
  }
}
```

#### 2. 存储玩家状态

使用 scoreboard 记录每个玩家是否在区域内（1=在区域内，0=不在）。

`data/<namespace>/function/load.mcfunction`
```mcfunction
scoreboard objectives add <namespace>_in_area dummy
```

#### 3. 主检测逻辑

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 对所有玩家执行检测
execute as @a run function <namespace>:check_area
```

`data/<namespace>/function/check_area.mcfunction`
```mcfunction
# 检测当前是否在区域内
execute if predicate <namespace>:in_area run scoreboard players set @s <namespace>_in_area 1
execute unless predicate <namespace>:in_area run scoreboard players set @s <namespace>_in_area 0

# 检测"进入"事件：上一 tick 不在，当前在
execute if score @s <namespace>_in_area matches 1 if score @s <namespace>_prev_in_area matches 0 run function <namespace>:on_enter

# 检测"离开"事件：上一 tick 在，当前不在
execute if score @s <namespace>_in_area matches 0 if score @s <namespace>_prev_in_area matches 1 run function <namespace>:on_exit

# 更新上一 tick 状态
scoreboard players operation @s <namespace>_prev_in_area = @s <namespace>_in_area
```

`data/<namespace>/function/on_enter.mcfunction`
```mcfunction
# 玩家进入区域时执行的操作
say 我进入了区域！
```

`data/<namespace>/function/on_exit.mcfunction`
```mcfunction
# 玩家离开区域时执行的操作
say 我离开了区域！
```

### 陷阱与注意事项

1. **性能问题**：每个 tick 对所有玩家执行 predicate 检测，如果有大量玩家（>50）或区域检测逻辑复杂，性能开销较高。建议使用 `@e[type=player,distance=..100]` 限制检测范围。
2. **边界穿越**：如果玩家速度极快（如鞘翅飞行），可能在一个 tick 内穿越整个区域而未被检测到。这是原版 tick 检测的固有限制。
3. **predicate 版本**：`entity_properties` predicate 在 1.13 引入，1.16+ 支持更复杂的条件组合。
4. **scoreboard 初始化**：首次运行时，`<namespace>_prev_in_area` 未设置，会导致误判。需要在 load 中初始化：
```mcfunction
scoreboard players set @a <namespace>_prev_in_area 0
```

## 三、方案二：advancement location trigger（1.16+，低性能开销）

### 原理

利用 advancement 的 `location` trigger，当玩家位置满足条件时自动触发。这是原版最优雅的检测方式，因为 advancement 系统本身是事件驱动的，不需要每 tick 轮询。

### 完整实现

#### 1. 定义 advancement

`data/<namespace>/advancement/enter_area.json`
```json
{
  "criteria": {
    "in_area": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": {
          "location": {
            "position": {
              "x": {
                "min": 100.0,
                "max": 200.0
              },
              "y": {
                "min": 64.0,
                "max": 100.0
              },
              "z": {
                "min": -50.0,
                "max": 50.0
              }
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_enter"
  }
}
```

#### 2. 触发处理函数

`data/<namespace>/function/on_enter.mcfunction`
```mcfunction
# 玩家进入区域时执行
say 我进入了区域！

# 立即撤销 advancement，以便下次再次触发
advancement revoke @s only <namespace>:enter_area
```

#### 3. 离开区域检测（需要额外实现）

advancement 的 `location` trigger 只能检测"进入"，不能直接检测"离开"。需要配合方案一的 scoreboard 方法或使用第二个 advancement：

`data/<namespace>/advancement/leave_area.json`
```json
{
  "criteria": {
    "not_in_area": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": {
          "location": {
            "position": {
              "x": {
                "min": -30000000,
                "max": 99.999
              },
              "y": {
                "min": -64,
                "max": 63.999
              },
              "z": {
                "min": -30000000,
                "max": -50.001
              }
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:on_exit"
  }
}
```

⚠️ **需验证**：`location` trigger 是否支持多个不连续的区域条件。理论上可以通过多个 criteria 实现，但每个 criteria 是 OR 关系，无法直接表达"不在区域内"。

### 陷阱与注意事项

1. **触发频率**：`location` trigger 不是每 tick 检测，而是由游戏内部的事件系统驱动。实际测试表明，玩家静止时不会触发，移动时大约每 0.5-1 秒检测一次。这意味着快速穿越可能漏检。
2. **advancement 撤销**：必须及时撤销 advancement，否则只会触发一次。但撤销后到下次触发之间可能有延迟。
3. **离开检测复杂**：原版没有"离开区域"的 trigger，需要手动实现反向条件，且边界条件处理复杂。
4. **版本要求**：`location` trigger 在 1.16 引入，1.16.2+ 支持更精确的位置条件。

## 四、方案三：execute if entity distance 条件（1.13+，最简单但最不精确）

### 原理

利用 `execute if entity @s[x=100,y=64,z=-50,distance=..50]` 检测玩家是否在以某点为中心的球形区域内。这是最直接的方法，但只能检测球形区域。

### 完整实现

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 检测进入球形区域（中心点 100,64,-50，半径 50）
execute as @a at @s if entity @s[x=100,y=64,z=-50,distance=..50] unless score @s <namespace>_in_area matches 1 run function <namespace>:on_enter
execute as @a at @s unless entity @s[x=100,y=64,z=-50,distance=..50] if score @s <namespace>_in_area matches 1 run function <namespace>:on_exit

# 更新状态
execute as @a at @s if entity @s[x=100,y=64,z=-50,distance=..50] run scoreboard players set @s <namespace>_in_area 1
execute as @a at @s unless entity @s[x=100,y=64,z=-50,distance=..50] run scoreboard players set @s <namespace>_in_area 0
```

### 陷阱与注意事项

1. **仅支持球形**：`distance` 参数只能检测球形区域，无法检测矩形或自定义形状。
2. **性能**：`execute if entity` 比 predicate 检测更快，但每 tick 对所有玩家执行仍有开销。
3. **精度**：`distance=..50` 是闭区间，边界上的玩家可能被重复触发。

## 五、方案四：利用方块事件检测（1.13+，特殊场景）

### 原理

在区域边界放置特定方块（如压力板、绊线钩），当玩家踩上时触发。这不是纯数据包方案，需要配合地图建造。

### 实现思路

1. 在区域入口放置压力板
2. 使用 `execute if block` 检测压力板被踩下
3. 通过 scoreboard 记录状态，防止重复触发

### 陷阱

1. **需要修改地图**：不是纯数据包方案
2. **容易被绕过**：玩家可以跳跃越过压力板
3. **维护成本高**：每个入口都需要放置方块

## 六、方案对比

| 方案 | 版本要求 | 性能开销 | 精确度 | 适用场景 |
|------|---------|---------|--------|---------|
| predicate + scoreboard | 1.13+ | 中（每 tick 检测） | 高（矩形区域） | 通用，需要精确边界检测 |
| advancement location | 1.16+ | 低（事件驱动） | 中（有检测延迟） | 低性能要求，进入检测为主 |
| execute distance | 1.13+ | 低 | 低（仅球形） | 简单球形区域 |
| 方块事件 | 1.13+ | 极低 | 取决于地图设计 | 配合地图的入口检测 |

## 七、最佳实践建议

1. **通用场景**：使用方案一（predicate + scoreboard），灵活且精确
2. **性能敏感**：使用方案二（advancement location），但需要接受检测延迟
3. **简单球形**：使用方案三（execute distance），实现最简单
4. **配合地图**：使用方案四（方块事件），但需要地图支持

## 八、进阶技巧：多区域检测

如果需要同时检测多个区域，可以使用 scoreboard 存储区域 ID：

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 检测区域1
execute as @a at @s if predicate <namespace>:area1 run scoreboard players set @s <namespace>_current_area 1
# 检测区域2
execute as @a at @s if predicate <namespace>:area2 run scoreboard players set @s <namespace>_current_area 2
# 不在任何区域
execute as @a at @s unless predicate <namespace>:area1 unless predicate <namespace>:area2 run scoreboard players set @s <namespace>_current_area 0

# 检测进入事件
execute as @a if score @s <namespace>_current_area > @s <namespace>_prev_area run function <namespace>:on_enter
execute as @a if score @s <namespace>_current_area < @s <namespace>_prev_area run function <namespace>:on_exit

# 更新状态
scoreboard players operation @s <namespace>_prev_area = @s <namespace>_current_area
```
