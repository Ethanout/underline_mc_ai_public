# 如何做敌人硬直

## 核心挑战

在 Minecraft 原版数据包中实现"敌人硬直"（Stun / Hitstun）面临以下挑战：
1. **没有原生的硬直状态**：Minecraft 的生物 AI 系统没有内置的"受击暂停"机制
2. **AI 控制权有限**：数据包无法直接控制生物的行为树或导航系统
3. **性能与兼容性平衡**：高频 tick 检测可能影响性能，且需要兼容不同版本

## 方案一：基于 `NoAI` 标签的硬直系统（推荐）

### 原理

利用 `NoAI` NBT 标签暂时禁用生物 AI，配合计分板计时器实现可控的硬直时长。当生物受到伤害时，通过 `damage` 进度触发，设置 `NoAI:1b`，并在指定 tick 后恢复。

### 版本要求

- Minecraft 1.13+（`NoAI` 标签）
- 1.20.5+（`damage` 进度触发器的 `source_entity` 字段格式变化）

### 完整实现

#### 目录结构
```
data/

    advancement/

        on_hit.json
    function/
      stun/
        apply.mcfunction
        tick.mcfunction
        recover.mcfunction
        schedule_recover.mcfunction
    predicate/
      stun/

```

#### 1. 检测受击进度

`data/<namespace>/advancement/stun/on_hit.json`
```json
{
  "criteria": {
    "on_hit": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "source_entity": {
            "type": "minecraft:player"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:stun/apply"
  }
}
```

⚠️ **需验证**：`entity_hurt_player` 触发器在 1.20.5+ 中是否仍然可用。如果不可用，需改用 `damage` 触发器：
```json
{
  "criteria": {
    "on_hit": {
      "trigger": "minecraft:damage",
      "conditions": {
        "source_entity": {
          "type": "minecraft:player"
        }
      }
    }
  }
}
```

#### 2. 应用硬直

`data/<namespace>/function/stun/apply.mcfunction`
```mcfunction
# 获取伤害来源（玩家）
advancement revoke @s only <namespace>:stun/on_hit

# 查找最近被玩家攻击的生物（假设玩家攻击范围内只有一个目标）
execute as @e[type=!minecraft:player,distance=..4,sort=nearest,limit=1] run function <namespace>:stun/schedule_recover
```

`data/<namespace>/function/stun/schedule_recover.mcfunction`
```mcfunction
# 设置硬直状态
data merge entity @s {NoAI:1b}

# 设置硬直时长（20 ticks = 1 秒）
scoreboard players set @s stun_timer 20

# 标记为硬直状态
tag @s add stun_active
```

#### 3. 硬直计时与恢复

`data/<namespace>/function/stun/tick.mcfunction`
```mcfunction
# 对所有处于硬直状态的生物计时
execute as @e[tag=stun_active] run function <namespace>:stun/recover
```

`data/<namespace>/function/stun/recover.mcfunction`
```mcfunction
# 减少计时器
scoreboard players remove @s stun_timer 1

# 检查是否到时间
execute if score @s stun_timer matches 0 run function <namespace>:stun/recover_now
```

`data/<namespace>/function/stun/recover_now.mcfunction`
```mcfunction
# 恢复 AI
data merge entity @s {NoAI:0b}

# 清理标记
tag @s remove stun_active
scoreboard players reset @s stun_timer
```

#### 4. 初始化（Load）

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 创建计分板
scoreboard objectives add stun_timer dummy

# 注册 tick 函数
schedule function <namespace>:stun/tick 1t
```

### 陷阱与注意事项

1. **生物选择器精度**：`apply.mcfunction` 中使用 `sort=nearest,limit=1` 可能选错目标（如玩家同时攻击多个生物）。更精确的做法是使用 `damage` 触发器中的 `entity` 条件，但需要 1.20.5+ 的 `damage` 触发器支持。
2. **`NoAI` 副作用**：设置 `NoAI:1b` 会完全禁用生物 AI，包括：
   - 生物不会掉落（但会受重力影响）
   - 生物不会旋转朝向
   - 生物不会受到击退（需额外处理）
3. **多人游戏冲突**：多个玩家同时攻击同一生物时，计时器可能被多次重置。解决方案：在 `apply.mcfunction` 中先检查生物是否已有 `stun_active` 标签，如果有则重置计时器而非叠加。
4. **性能**：每 tick 遍历所有 `stun_active` 生物，开销与硬直生物数量成正比。建议限制最大硬直生物数量（如 50 个）。

## 方案二：基于 `HurtTime` 的视觉硬直（轻量级）

### 原理

利用生物受击时的 `HurtTime` NBT（受击后变红的时间），通过检测 `HurtTime > 0` 来判断生物是否处于"受击硬直"状态。此方案不修改 AI，仅用于检测和触发其他效果。

### 版本要求

- Minecraft 1.13+（`HurtTime` 始终存在）

### 完整实现

#### 1. 检测函数

`data/<namespace>/function/stun/detect_hurt.mcfunction`
```mcfunction
# 检测所有处于受击状态的生物
execute as @e[type=!minecraft:player] if entity @s[nbt={HurtTime:10s}] run function <namespace>:stun/on_hurt
```

#### 2. 受击响应

`data/<namespace>/function/stun/on_hurt.mcfunction`
```mcfunction
# 示例：播放粒子效果
particle minecraft:crit ~ ~1 ~ 0.5 0.5 0.5 0.1 10

# 示例：添加自定义标签
tag @s add recently_hurt

# 设置计时器（HurtTime 最大为 10 ticks）
scoreboard players set @s hurt_cooldown 10
```

#### 3. 计时清理

`data/<namespace>/function/stun/tick_hurt.mcfunction`
```mcfunction
execute as @e[tag=recently_hurt] run function <namespace>:stun/check_hurt_end
```

`data/<namespace>/function/stun/check_hurt_end.mcfunction`
```mcfunction
# 如果 HurtTime 归零，移除标签
execute if entity @s[nbt={HurtTime:0s}] run tag @s remove recently_hurt
```

### 陷阱与注意事项

1. **仅视觉**：此方案不改变生物行为，生物仍会正常移动和攻击。适合用于触发特效或作为其他系统的输入。
2. **`HurtTime` 精度**：`HurtTime` 在受击瞬间设为 10，每 tick 减 1。检测 `HurtTime:10s` 只在受击瞬间触发一次，如需持续检测应使用 `HurtTime:>0s`（但 NBT 选择器不支持大于比较，需用 `execute if entity` 配合 `nbt=`）。
3. **性能**：每 tick 遍历所有生物进行 NBT 检测，开销较高。建议限制检测范围或使用 `@e[type=#<namespace>:stunnable]` 标签。

## 方案三：基于 `Motion` 和 `NoAI` 的物理硬直（进阶）

### 原理

结合 `NoAI` 和 `Motion` 修改，实现受击后生物被击退并短暂定身的"硬直"效果。通过 `data merge entity` 修改生物的 `Motion` 向量，模拟击退。

### 版本要求

- Minecraft 1.13+（`Motion` 和 `NoAI` 均可用）

### 完整实现

#### 1. 应用硬直与击退

`data/<namespace>/function/stun/apply_knockback.mcfunction`
```mcfunction
# 获取攻击者位置（假设通过 advancement 传入）
# 此处简化：假设攻击者在 @s 附近
execute at @p run function <namespace>:stun/calculate_knockback
```

`data/<namespace>/function/stun/calculate_knockback.mcfunction`
```mcfunction
# 计算击退方向（从攻击者指向目标）
# 使用相对坐标计算方向向量
# 注意：此函数需要根据实际位置计算，此处为简化示例

# 设置硬直
data merge entity @s {NoAI:1b}

# 设置击退（假设攻击者在北方向）
data merge entity @s {Motion:[0.0d,0.4d,-0.5d]}

# 设置计时
scoreboard players set @s stun_timer 15
tag @s add stun_active
```

#### 2. 恢复（同方案一）

### 陷阱与注意事项

1. **`Motion` 精度**：`Motion` 是 double 数组，修改后生物会沿该方向移动。但 `NoAI` 禁用 AI 后，生物不会自动减速（摩擦仍起作用），可能导致生物滑行过远。
2. **方向计算复杂**：需要从攻击者位置到目标位置计算单位向量，涉及大量数学运算。建议使用 `execute positioned` 和 `^ ^ ^` 局部坐标简化。
3. **多人游戏**：多个攻击者同时攻击时，`Motion` 会被覆盖，需要合并向量。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 硬直效果 | 适用场景 |
|------|---------|---------|---------|---------|
| 方案一：NoAI 标签 | 1.13+ | 低（仅遍历标记生物） | 完全停止 AI | 需要敌人完全定身的战斗系统 |
| 方案二：HurtTime 检测 | 1.13+ | 中（每 tick NBT 检测） | 仅视觉/触发 | 特效触发、连击计数 |
| 方案三：Motion + NoAI | 1.13+ | 中（需计算向量） | 击退 + 定身 | 需要击退效果的硬直 |

## 最佳实践建议

1. **对于大多数战斗系统**：使用方案一（NoAI 标签），配合 `damage` 触发器精确获取受击实体。
2. **如果需要击退效果**：在方案一的基础上，在 `apply.mcfunction` 中添加 `Motion` 修改。
3. **避免高频 NBT 检测**：方案二的 `HurtTime` 检测应作为辅助手段，不要作为主要硬直判定。
4. **考虑版本兼容**：如果目标版本 < 1.20.5，使用 `entity_hurt_player` 触发器；如果 >= 1.20.5，优先使用 `damage` 触发器。
