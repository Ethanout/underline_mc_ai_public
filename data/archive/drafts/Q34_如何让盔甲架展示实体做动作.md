# 如何让盔甲架展示实体做动作

## 一、核心挑战

盔甲架（Armor Stand）在 Minecraft 中是一个实体，默认状态下是静态的。要让其“做动作”，本质上是**改变其姿态（Pose）NBT 数据**。原版没有直接的“播放动画”API，所有动作都需要通过逐帧修改 NBT 来实现。

主要挑战：
1. **姿态数据格式复杂**：Pose 是一个复合标签，包含 Head、Body、LeftArm、RightArm、LeftLeg、RightLeg 六个部分，每个部分是一个三元素浮点数组 [x, y, z]（角度制）。
2. **平滑过渡**：直接跳变角度会显得生硬，需要插值计算。
3. **性能**：每 tick 修改大量盔甲架的 NBT 可能造成性能瓶颈。

## 二、方案一：逐帧修改 NBT（最通用，1.13+）

### 原理

在 tick 函数中，通过 `data modify` 命令直接修改盔甲架的 `Pose` 标签。通过预定义的关键帧序列，逐帧更新角度值，实现动画效果。

### 完整实现

#### 1. 初始化：创建盔甲架并设置基础数据

```mcfunction

# 初始化动画帧计数器（使用 scoreboard）
```

### 陷阱与注意事项

1. **角度单位**：Pose 使用**角度制**（0-360），不是弧度。负值表示向相反方向旋转。
2. **坐标轴方向**：对于手臂，X 轴旋转控制前后摆动（负值向前），Y 轴控制左右摆动，Z 轴控制扭转。
3. **数据修改频率**：每 tick 修改 NBT 会产生大量数据包，对网络和性能有影响。建议：
   - 动画帧率控制在 5-10 tick/帧（即每秒 2-4 帧）
   - 只对可见的盔甲架执行动画
4. **初始姿态**：盔甲架默认姿态是直立，所有角度为 0。如果 ShowArms 为 false，手臂角度修改无效。
5. **平滑性**：直接跳变角度会产生卡顿感。可以通过线性插值计算中间帧，或使用更复杂的缓动函数。

#### 3. 调用宏

`data/<namespace>/function/anim/update_frame.mcfunction`
```mcfunction
# 获取当前帧号
scoreboard players get @s anim_frame

# 从 storage 中读取帧数据并作为参数传递给宏
# ⚠️ 需验证：execute 中能否直接使用 storage 路径作为宏参数来源
execute store result score #frame_index <namespace> run data get storage <namespace>:anim frames[<score>]
```

### 陷阱与注意事项

1. **宏的版本要求**：宏功能在 1.20.2（23w31a）引入，低于此版本无法使用。
2. **宏参数传递**：宏参数只能通过 `with storage` 或 `with entity` 传递，不能直接传递复杂 NBT 路径。
3. **性能**：宏的执行效率高于逐条命令，但每 tick 调用宏仍然有开销。建议：
   - 将多个盔甲架的动画更新合并到一个宏调用中（如果它们共享同一动画）
   - 使用 `execute as @e[tag=anim_target] at @s run function ...` 批量执行

## 四、方案三：使用进度触发器（1.16+，低性能方案）

### 原理

利用 `minecraft:entity_hurt_player` 或 `minecraft:player_hurt_entity` 等进度触发器，在特定事件发生时触发函数来修改盔甲架姿态。这种方式适合**事件驱动的动作**（如被攻击时播放受伤动画），而不是持续动画。

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancement/armor_stand_hit.json`
```json
{
  "criteria": {
    "hit_armor_stand": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {
        "entity": {
          "type": "minecraft:armor_stand",
          "nbt": "{Tags:[\"anim_target\"]}"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:anim/on_hit"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/anim/on_hit.mcfunction`
```mcfunction
# 被击中的盔甲架执行受伤动画
# 注意：这里需要获取被击中的盔甲架实体
# ⚠️ 需验证：player_hurt_entity 进度中，被击中的实体是否可以通过 @s 获取
advancement revoke @s only <namespace>:armor_stand_hit

# 假设被击中的盔甲架是最近的
execute as @e[type=armor_stand,tag=anim_target,sort=nearest,limit=1] at @s run function <namespace>:anim/hurt_anim
```

`data/<namespace>/function/anim/hurt_anim.mcfunction`
```mcfunction
# 设置受伤姿态（后仰）
data modify entity @s Pose.Body set value [0f,0f,20f]
data modify entity @s Pose.Head set value [0f,0f,0f]

# 延迟恢复（使用 schedule）
schedule function <namespace>:anim/recover 10
```

`data/<namespace>/function/anim/recover.mcfunction`
```mcfunction
# 恢复直立姿态
execute as @e[type=armor_stand,tag=anim_target,sort=nearest,limit=1] at @s run data modify entity @s Pose.Body set value [0f,0f,0f]
```

### 陷阱与注意事项

1. **实体选择**：在进度触发函数中，`@s` 是玩家，不是被击中的盔甲架。需要通过其他方式（如位置、距离）定位到正确的盔甲架。
2. **多实体冲突**：如果多个盔甲架同时被击中，`sort=nearest` 可能选错目标。建议给每个盔甲架分配唯一 ID。
3. **延迟恢复**：使用 `schedule` 实现延迟恢复，但要注意如果玩家在恢复前再次击中，会导致姿态混乱。需要添加状态管理。

## 五、方案对比

| 方案 | 最低版本 | 性能开销 | 平滑度 | 适用场景 |
|------|---------|---------|--------|---------|
