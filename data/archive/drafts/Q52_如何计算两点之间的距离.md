# 如何计算两点之间的距离

在 Minecraft 数据包开发中，计算两点之间的距离是一个常见需求，例如检测玩家是否进入某个区域、判断实体间的相对位置、实现范围攻击等。原版 Minecraft 没有提供直接的数学函数（如平方根），因此需要利用游戏机制间接实现。

核心挑战：
- Minecraft 命令系统不支持浮点数运算和平方根函数
- 距离公式 `d = sqrt((x1-x2)² + (y1-y2)² + (z1-z2)²)` 需要分解为可执行的步骤
- 不同方案在精度、性能、版本兼容性上差异很大

## 方案一：利用 `execute if entity` 的距离检测（最推荐）

### 原理
Minecraft 的 `execute if entity` 命令支持 `distance` 选择器参数，可以直接检测实体间的欧几里得距离。这是原版最高效、最精确的方案，无需任何数学计算。

### 适用版本
1.13+（`distance` 选择器从 1.13 引入）

### 代码示例

#### 检测玩家是否在某个坐标 10 格范围内
```mcfunction
# 检测所有玩家是否在 (100, 64, 200) 的 10 格范围内
execute as @a at @s if entity @s[distance=..10] positioned 100 64 200 run say 我在范围内！
```

#### 检测两个实体之间的距离
```mcfunction
# 检测所有盔甲架是否在玩家 5 格范围内
execute as @e[type=armor_stand] at @s if entity @p[distance=..5] run say 玩家靠近我了！
```

#### 检测精确范围（如 5-10 格之间）
```mcfunction
# 检测玩家是否在 5 到 10 格之间
execute as @a at @s if entity @s[distance=5..10] positioned 100 64 200 run say 我在5-10格范围内
```

### 陷阱与注意事项
1. **`distance` 是欧几里得距离**：它计算的是三维空间中的直线距离，不是曼哈顿距离或水平距离。如果需要水平距离，需要额外处理。
2. **`distance` 不能用于任意两点**：它只能检测执行者与选择器目标之间的距离。如果需要计算两个任意坐标（如两个标记实体）之间的距离，需要将执行者移动到其中一个点。
3. **性能极佳**：这是原生的游戏引擎计算，比任何命令模拟的数学运算都快得多。
4. **精度限制**：`distance` 使用浮点数比较，对于极小距离（<0.01格）可能存在精度问题，但大多数场景下无影响。

## 方案二：利用 `scoreboard` 和 `execute store` 进行数学计算（高精度）

### 原理
通过 `execute store result` 将坐标值存入 scoreboard，然后利用 `scoreboard players operation` 进行加减乘除运算，最后通过比较平方和来判定距离。由于无法直接计算平方根，通常采用比较平方和的方式（即比较 `d²` 而非 `d`）。

### 适用版本
1.13+（`execute store` 从 1.13 引入）

### 代码示例

#### 计算玩家与坐标 (100, 64, 200) 的距离平方
```mcfunction
# 假设我们有一个标记实体 "marker" 在目标位置
# 或者直接使用坐标值

# 步骤1：获取玩家的坐标
execute as @a at @s store result score @s x_pos run data get entity @s Pos[0] 1000
execute as @a at @s store result score @s y_pos run data get entity @s Pos[1] 1000
execute as @a at @s store result score @s z_pos run data get entity @s Pos[2] 1000

# 步骤2：计算差值（目标坐标假设为 100, 64, 200）
scoreboard players set @s target_x 100000  # 100 * 1000
scoreboard players set @s target_y 64000   # 64 * 1000
scoreboard players set @s target_z 200000  # 200 * 1000

scoreboard players operation @s dx = @s x_pos -= @s target_x
scoreboard players operation @s dy = @s y_pos -= @s target_y
scoreboard players operation @s dz = @s z_pos -= @s target_z

# 步骤3：计算平方（注意：Minecraft scoreboard 是整数运算，需要处理负数）
execute store result score @s dx_sq run data get entity @s Pos[0] 1000000
# 更简单的方法：使用绝对值后再平方
scoreboard players operation @s dx_abs = @s dx
execute if score @s dx_abs < 0 run scoreboard players operation @s dx_abs *= -1
scoreboard players operation @s dx_sq = @s dx_abs
scoreboard players operation @s dx_sq *= @s dx_abs

# 对 dy 和 dz 做同样处理...

# 步骤4：计算距离平方和
scoreboard players operation @s dist_sq = @s dx_sq
scoreboard players operation @s dist_sq += @s dy_sq
scoreboard players operation @s dist_sq += @s dz_sq

# 步骤5：比较（例如检测是否在 10 格范围内，即 dist_sq <= 100 * 1000000）
execute if score @s dist_sq <= 100000000 run say 我在10格范围内！
```

### 陷阱与注意事项
1. **精度问题**：由于 scoreboard 是整数运算，需要将坐标乘以一个缩放因子（如 1000）来保留小数精度。缩放因子越大，精度越高，但数值范围也越大（可能溢出）。
2. **性能开销较高**：每个玩家需要执行数十条命令，且涉及多次 `data get` 和 scoreboard 操作。对于大量实体（如 50+ 玩家），性能会显著下降。
3. **无法直接计算平方根**：只能比较平方和，无法得到实际距离值。如果需要实际距离（如显示在 HUD 上），需要额外的近似算法（如牛顿迭代法，但实现复杂）。
4. **坐标获取的版本差异**：1.20.5 之前，`Pos` 是 NBT 路径；1.20.5+ 中，`Pos` 仍然可用，但推荐使用 `data get entity @s Pos[0]` 的格式。⚠️ 需验证：1.20.5 之后 `Pos` 是否仍然作为 NBT 路径可用。

## 方案三：利用 `execute positioned` 和 `distance` 进行相对距离检测（折中方案）

### 原理
通过 `execute positioned` 将执行者移动到目标点，然后使用 `distance` 检测与另一个点的距离。这本质上是方案一的变体，但可以计算任意两点之间的距离。

### 适用版本
1.13+

### 代码示例

#### 计算两个标记实体之间的距离
```mcfunction
# 假设有两个标记实体：marker_a 和 marker_b
# 检测 marker_a 是否在 marker_b 的 10 格范围内

# 方法1：直接使用 distance（如果两个实体都在同一维度）
execute as @e[tag=marker_a] at @s if entity @e[tag=marker_b,distance=..10] run say 两个标记在10格内！

# 方法2：通过 positioned 移动执行者
# 先获取 marker_b 的坐标，然后 positioned 到该坐标
execute as @e[tag=marker_a] at @s run function namespace:check_distance

# namespace:function/check_distance.mcfunction
# 注意：这里需要先获取 marker_b 的坐标，但命令无法直接获取另一个实体的坐标
# 因此需要借助 storage 或 scoreboard 传递坐标
```

#### 更实用的实现：通过 storage 传递坐标
```mcfunction
# 步骤1：将 marker_b 的坐标存入 storage
execute as @e[tag=marker_b] run data modify storage namespace:temp pos set from entity @s Pos

# 步骤2：从 storage 读取坐标并 positioned
execute as @e[tag=marker_a] at @s run function namespace:check_distance

# namespace:function/check_distance.mcfunction
execute positioned 0 0 0 run say 这里需要动态坐标
# 实际上无法直接使用 storage 中的坐标作为 positioned 的参数
# 因为 positioned 只接受字面量坐标
```

### 陷阱与注意事项
1. **`positioned` 不支持动态坐标**：`execute positioned` 只能接受字面量坐标（如 `100 64 200`），无法使用 storage 或 scoreboard 中的值。这使得该方案在计算任意两点距离时受限。
2. **只能用于已知坐标的场景**：如果目标坐标是固定的（如建筑坐标），可以直接使用字面量。如果是动态的（如追踪另一个实体），则需要方案二。
3. **性能中等**：比方案一稍慢（因为需要额外的 `execute` 链），但比方案二快得多。

## 方案四：利用 `predicate` 的 `distance` 条件（声明式检测）

### 原理
在进度或战利品表的 predicate 中使用 `distance` 条件，可以声明式地检测距离。这适用于需要触发特定事件（如进入范围）的场景。

### 适用版本
1.15+（predicate 系统从 1.15 正式引入）

### 代码示例

#### 检测玩家是否在某个坐标 10 格范围内
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "distance": {
      "absolute": {
        "min": 0,
        "max": 10
      }
    },
    "location": {
      "position": {
        "x": 100,
        "y": 64,
        "z": 200
      }
    }
  }
}
```

#### 在进度中使用
```json
{
  "criteria": {
    "enter_range": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "distance": {
                "absolute": {
                  "max": 10
                }
              },
              "location": {
                "position": {
                  "x": 100,
                  "y": 64,
                  "z": 200
                }
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "namespace:enter_range"
  }
}
```

### 陷阱与注意事项
1. **只能用于触发式检测**：predicate 不能用于实时循环检测，只能作为进度或战利品表的条件。
2. **`location.position` 是绝对坐标**：⚠️ 需验证：`location.position` 是否支持相对坐标（如 `~10 ~ ~`）？根据文档，它只接受绝对坐标。
3. **性能极佳**：predicate 是声明式的，由游戏引擎优化处理，几乎无性能开销。
4. **版本要求**：`distance.absolute` 从 1.16 开始支持。1.15 中只有 `distance.horizontal` 和 `distance.vertical`。

## 方案对比

| 方案 | 版本要求 | 精度 | 性能 | 适用场景 |
|------|---------|------|------|---------|
| 方案一：`execute if entity distance` | 1.13+ | 高（浮点） | 极佳 | 检测执行者与选择器目标的距离 |
| 方案二：scoreboard 数学计算 | 1.13+ | 中（整数缩放） | 低 | 需要精确距离值或任意两点距离 |
| 方案三：`execute positioned` + distance | 1.13+ | 高（浮点） | 中 | 固定坐标的距离检测 |
| 方案四：predicate distance | 1.15+ | 高（浮点） | 极佳 | 触发式检测（进度/战利品表） |

## 总结与推荐

1. **大多数场景推荐方案一**：`execute if entity @s[distance=..10]` 是最简单、最高效的方式。如果需要检测玩家与固定点的距离，配合 `positioned` 即可。
2. **需要精确距离值时用方案二**：例如在 HUD 上显示距离，或需要比较两个动态点的距离。注意性能开销，建议只在必要时使用。
3. **触发式检测用方案四**：如进入区域时触发事件，使用 predicate 是最优雅的方式。
4. **避免方案三**：由于 `positioned` 不支持动态坐标，方案三的实际应用场景有限，不如方案一灵活。
