# 如何做敌人的攻击预警

## 核心挑战

在 Minecraft 原版数据包中实现"攻击预警"面临两个核心问题：
1. **缺乏原生的"即将攻击"事件**——原版没有"实体即将执行攻击"的 trigger 或 predicate
2. **需要预测未来状态**——预警本质上是"在伤害发生前告知玩家"，需要提前检测攻击意图

目前可行的方案都基于**检测攻击前摇状态**或**模拟攻击判定**，而非真正的"预测"。

---

## 方案一：基于 `hurt_entity` 进度的"伪预警"（最常用）

### 原理

利用进度系统监听 `minecraft:entity_hurt_you` 或 `minecraft:entity_killed_player` 等 trigger，在玩家**被攻击的瞬间**触发函数。虽然严格来说这不是"预警"（伤害已经发生），但可以通过以下技巧实现"看起来像预警"的效果：

- 在触发函数中**立即执行反击/闪避/减伤逻辑**
- 配合粒子效果和音效，让玩家感觉"预警系统在伤害瞬间生效"
- 如果攻击有前摇（如苦力怕爆炸、骷髅射箭），可以在前摇阶段通过其他机制检测

### 完整代码

**文件路径：** `data/<namespace>/advancement/attack_warning.json`
```json
{
  "criteria": {
    "hurt": {
      "trigger": "minecraft:entity_hurt_player"
    }
  },
  "rewards": {
    "function": "<namespace>:warning/on_hurt"
  }
}
```

**文件路径：** `data/<namespace>/function/warning/on_hurt.mcfunction`
```mcfunction
# 触发预警效果
particle minecraft:sonic_explosion ~ ~1 ~ 0.5 0.5 0.5 0.1 10 force @a
playsound minecraft:entity.wither.hurt player @a ~ ~ ~ 1 0.5

# 执行反击逻辑（示例：给攻击者施加缓慢效果）
effect give @s minecraft:slowness 3 2 true

# 移除进度以便下次触发
advancement revoke @s only <namespace>:attack_warning
```

### 陷阱与注意事项

1. **这不是真正的预警**——伤害已经发生，玩家已经掉血。只能用于"受伤后反击"或"减伤"场景
2. **`entity_hurt_player` 在 1.16+ 可用**，但 `entity_hurt_you` 在 1.20.5+ 才引入
3. **高频触发问题**——如果玩家被连续攻击（如骷髅连射），进度会反复触发，需确保函数幂等
4. **无法区分攻击类型**——无法知道是近战、远程还是爆炸，除非在函数内进一步检测

## 方案二：基于 `player_hurt_entity` 进度的"攻击前摇检测"（1.20.5+）

### 原理

利用 `minecraft:player_hurt_entity` trigger 检测**玩家攻击实体**的事件。虽然这是玩家攻击敌人，但可以反向利用：当玩家攻击敌人时，触发预警系统检查**周围其他敌人**是否即将攻击玩家。

核心思路：
1. 玩家攻击任意实体 → 触发进度
2. 在触发函数中，检查玩家周围是否有正在"蓄力"或"瞄准"的敌人
3. 如果有，触发预警效果

### 完整代码

**文件路径：** `data/<namespace>/advancement/player_attack_warning.json`
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:player_hurt_entity"
    }
  },
  "rewards": {
    "function": "<namespace>:warning/on_player_attack"
  }
}
```

**文件路径：** `data/<namespace>/function/warning/on_player_attack.mcfunction`
```mcfunction
# 检查周围是否有正在攻击的敌人（示例：检测苦力怕的 fuse 状态）
execute as @e[type=minecraft:creeper,distance=..10,nbt={ignited:1b}] at @s run function <namespace>:warning/creeper_alert

# 检查是否有骷髅正在拉弓
execute as @e[type=minecraft:skeleton,distance=..15,nbt={HandItems:[{id:"minecraft:bow"}],AttackTime:20s}] at @s run function <namespace>:warning/skeleton_alert

# 移除进度
advancement revoke @s only <namespace>:player_attack_warning
```

**文件路径：** `data/<namespace>/function/warning/creeper_alert.mcfunction`
```mcfunction
# 对玩家触发预警
particle minecraft:explosion ~ ~1 ~ 1 1 1 0.1 50 force @a[distance=..10]
playsound minecraft:entity.creeper.primed player @a[distance=..10] ~ ~ ~ 1 1
title @a[distance=..10] actionbar {"text":"⚠ 苦力怕即将爆炸！","color":"red"}
```

### 陷阱与注意事项

1. **依赖玩家主动攻击**——如果玩家不攻击任何实体，预警系统不会触发
2. **NBT 检测性能问题**——`nbt={...}` 选择器参数在高频使用时有性能开销，建议限制检测范围（`distance=..15`）
3. **`AttackTime` 字段**——[需验证] 骷髅的 `AttackTime` 在 1.20.5+ 是否仍存在？可能已被 `attack_time` 组件替代
4. **无法检测所有敌人**——只有特定实体有可检测的"前摇"状态（苦力怕的 `ignited`、骷髅的 `AttackTime`、掠夺者的 `AttackTime`）

## 方案三：基于 `tick` 函数的"持续扫描预警"（最灵活，性能开销最高）

### 原理

在每 tick 执行的函数中，扫描玩家周围的所有敌对实体，检查它们是否处于"即将攻击"的状态。通过以下方式判断：

- **苦力怕**：`nbt={ignited:1b}` 或 `nbt={Fuse:1s}`（Fuse 值小于某个阈值）
- **骷髅/掠夺者**：`nbt={AttackTime:20s}`（正在拉弓）
- **卫道士/僵尸**：`nbt={AttackTime:10s}`（正在挥砍）
- **幻翼**：`nbt={AttackTime:20s}`（俯冲攻击）
- **唤魔者**：`nbt={AttackTime:20s}`（召唤尖牙）

### 完整代码

**文件路径：** `data/<namespace>/function/tick.mcfunction`
```mcfunction
# 每 tick 对所有玩家执行预警扫描
execute as @a at @s run function <namespace>:warning/scan
```

**文件路径：** `data/<namespace>/function/warning/scan.mcfunction`
```mcfunction
# 检测苦力怕（Fuse <= 20 表示即将爆炸）
execute as @e[type=minecraft:creeper,distance=..10,nbt={Fuse:20s..}] at @s run function <namespace>:warning/creeper_alert

# 检测骷髅（AttackTime >= 15 表示正在拉弓）
execute as @e[type=minecraft:skeleton,distance=..15,nbt={AttackTime:15s..}] at @s run function <namespace>:warning/skeleton_alert

# 检测卫道士（AttackTime >= 5 表示正在攻击）
execute as @e[type=minecraft:vindicator,distance=..8,nbt={AttackTime:5s..}] at @s run function <namespace>:warning/vindicator_alert

# 检测唤魔者（AttackTime >= 10 表示正在施法）
execute as @e[type=minecraft:evoker,distance=..12,nbt={AttackTime:10s..}] at @s run function <namespace>:warning/evoker_alert
```

**文件路径：** `data/<namespace>/function/warning/creeper_alert.mcfunction`
```mcfunction
# 对最近的玩家触发预警
execute at @s run particle minecraft:explosion ~ ~1 ~ 1 1 1 0.1 30 force @a[distance=..10]
execute at @s run playsound minecraft:entity.creeper.primed player @a[distance=..10] ~ ~ ~ 1 1
execute at @s run title @a[distance=..10] actionbar {"text":"⚠ 苦力怕即将爆炸！","color":"red"}
```

**文件路径：** `data/<namespace>/function/warning/skeleton_alert.mcfunction`
```mcfunction
execute at @s run particle minecraft:arrow ~ ~1 ~ 0.5 0.5 0.5 0.1 10 force @a[distance=..15]
execute at @s run playsound minecraft:entity.skeleton.shoot player @a[distance=..15] ~ ~ ~ 1 0.5
execute at @s run title @a[distance=..15] actionbar {"text":"⚠ 骷髅正在瞄准！","color":"yellow"}
```

### 陷阱与注意事项

1. **性能开销高**——每 tick 对所有玩家执行 NBT 扫描，如果玩家数量多或实体数量多，可能导致 TPS 下降
2. **NBT 选择器限制**——`nbt=` 选择器参数在 1.20.5+ 已被标记为"不推荐"，建议使用 `predicate` 替代
3. **`AttackTime` 字段的版本兼容性**——[需验证] 1.20.5+ 后，`AttackTime` 可能已被 `attack_time` 组件替代，且格式可能变化
4. **误报问题**——如果实体处于"攻击冷却"状态但目标不是玩家，也会触发预警
5. **无法检测所有攻击**——如蜘蛛的跳跃攻击、蠹虫的钻地攻击等没有可检测的 NBT 字段

## 方案四：基于 `predicate` 的"条件检测预警"（1.20.5+，推荐）

### 原理

利用 1.20.5+ 引入的 `minecraft:entity_properties` predicate 和 `minecraft:entity_components` predicate，通过 `execute if predicate` 检测实体是否处于"攻击状态"。相比 NBT 扫描，predicate 更高效且更稳定。

### 完整代码

**文件路径：** `data/<namespace>/predicate/creeper_primed.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "type": "minecraft:creeper",
    "nbt": "{ignited:1b}"
  }
}
```

**文件路径：** `data/<namespace>/predicate/skeleton_attacking.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "type": "minecraft:skeleton",
    "nbt": "{AttackTime:15s..}"
  }
}
```

**文件路径：** `data/<namespace>/function/tick.mcfunction`
```mcfunction
execute as @a at @s run function <namespace>:warning/scan_predicate
```

**文件路径：** `data/<namespace>/function/warning/scan_predicate.mcfunction`
```mcfunction
# 使用 predicate 检测
execute as @e[type=minecraft:creeper,distance=..10] if predicate <namespace>:creeper_primed at @s run function <namespace>:warning/creeper_alert
execute as @e[type=minecraft:skeleton,distance=..15] if predicate <namespace>:skeleton_attacking at @s run function <namespace>:warning/skeleton_alert
```

### 陷阱与注意事项

1. **predicate 中的 NBT 检测**——虽然 predicate 比选择器中的 `nbt=` 更高效，但本质上仍是 NBT 匹配，性能开销依然存在
2. **版本要求**——`entity_properties` predicate 在 1.16+ 可用，但 `entity_components` predicate 需要 1.20.5+
3. **predicate 文件数量**——每个实体类型需要单独的 predicate 文件，管理起来较繁琐
4. **`AttackTime` 字段的版本兼容性**——同上，[需验证] 1.20.5+ 后的字段名和格式

## 方案对比

| 方案 | 版本要求 | 性能开销 | 预警准确性 | 适用场景 |
|------|---------|---------|-----------|---------|
| 方案一：`hurt_entity` 进度 | 1.16+ | 极低 | 低（伤害已发生） | 受伤后反击/减伤 |
| 方案二：`player_hurt_entity` 进度 | 1.20.5+ | 低 | 中（依赖玩家攻击） | 玩家主动战斗时的预警 |
| 方案三：tick 扫描 NBT | 1.13+ | 高 | 高（可检测前摇） | 需要实时预警的硬核地图 |
| 方案四：tick 扫描 predicate | 1.16+ | 中 | 高（可检测前摇） | 推荐方案，平衡性能与功能 |

---

## 最佳实践建议

1. **对于大多数地图**：使用**方案一**作为基础预警（受伤后触发效果），配合**方案四**对特定敌人（苦力怕、骷髅）做额外扫描
2. **对于硬核生存地图**：使用**方案三**或**方案四**，但限制扫描频率（每 5 tick 扫描一次，而非每 tick）
3. **对于性能敏感场景**：仅使用**方案一**，通过 `entity_hurt_player` 触发，不做持续扫描
4. **避免使用 `nbt=` 选择器参数**（1.20.5+ 已不推荐），改用 predicate 或 `execute if data`
