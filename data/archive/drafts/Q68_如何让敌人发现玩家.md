# 如何让敌人发现玩家

## 核心挑战

在 Minecraft 原版数据包中实现"敌人发现玩家"的机制，核心挑战在于：
1. 原版没有内置的"仇恨系统"或"感知系统"
2. 需要模拟视觉、听觉、距离等多种感知维度
3. 性能开销必须可控，不能每 tick 对所有实体进行复杂计算
4. 需要处理遮挡、隐身、潜行等特殊情况

## 方案一：基于距离和视线的简单检测（推荐，1.13+）

### 原理

使用 `execute` 命令的条件子命令链，依次检查：
1. 距离条件：玩家与实体在指定范围内
2. 视线条件：实体看向玩家方向（通过旋转角度计算）
3. 遮挡条件：检查路径上是否有方块阻挡

### 完整实现

### 陷阱与注意事项

1. **性能问题**：每 tick 对所有敌人进行射线检测开销较大。建议降低检测频率（每 5-10 tick 检测一次）
2. **FOV 计算**：predicate 中的 `fov` 字段在 1.19+ 才支持，早期版本需要手动计算角度差
3. **遮挡检测精度**：简单的步进射线检测可能漏过薄墙或小缝隙
4. **潜行检测**：玩家潜行时，原版怪物检测距离减半，需要额外处理

## 方案二：基于进度和谓词的被动检测（1.16+）

### 原理

利用 `player_killed_entity` 或 `player_hurt_entity` 进度，在玩家攻击实体时触发检测。结合 `location` 谓词检查距离和视线。

### 完整实现

```mcfunction
# 检查敌人是否"发现"了玩家
```


### 陷阱与注意事项

1. **触发时机**：只有在玩家攻击时才会检测，无法检测到玩家靠近
2. **多实体问题**：`sort=nearest,limit=1` 可能选错目标，需要更精确的选择器
3. **进度撤销**：必须及时撤销进度，否则只能触发一次
4. **版本兼容**：`player_hurt_entity` 在 1.16 引入

### 原理

使用记分板记录检测间隔，每 N tick 对所有敌人进行一次扫描。结合 `execute` 的条件链实现距离、视线、遮挡检测。

### 陷阱与注意事项

1. **射线步进次数**：需要根据距离动态调整步进次数，或者使用固定次数（如 32 次）
2. **精度问题**：步进间隔越小越精确，但性能开销越大
3. **边界情况**：玩家在墙后但部分身体暴露时，检测可能不准确
4. **多玩家处理**：需要检测所有玩家，而不仅仅是最近的

## 最佳实践建议

1. **组合使用**：将方案一（距离检测）作为快速筛选，方案四（定时扫描）作为精确检测
2. **频率控制**：根据敌人数量和场景复杂度调整检测频率
3. **缓存结果**：检测到玩家后，设置一个"警觉"状态，减少后续检测频率
4. **潜行处理**：玩家潜行时，检测距离减半，且不产生振动

## 陷阱总结

1. **性能陷阱**：每 tick 对所有敌人进行完整检测会导致严重卡顿
2. **精度陷阱**：简单的射线检测可能漏过薄墙或小缝隙
3. **多玩家陷阱**：需要检测所有玩家，而不仅仅是最近的
4. **状态管理**：检测到玩家后需要设置状态，避免重复触发
5. **版本兼容**：不同版本的 predicate 和命令语法有差异
