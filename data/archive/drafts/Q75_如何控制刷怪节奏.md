# 如何控制刷怪节奏

## 核心挑战

Minecraft 原版的刷怪机制由游戏规则 `doMobSpawning` 统一控制，要么全开要么全关。数据包开发者需要更精细的控制：限制特定区域的刷怪频率、实现波次刷怪、或根据玩家行为动态调整刷怪速率。原版没有直接的"刷怪计时器"API，需要利用游戏机制间接实现。

## 方案一：基于 `spawner` 的计时器 + 条件刷怪（推荐）

### 原理

利用刷怪笼（Spawner）的 `SpawnCount`、`SpawnRange`、`Delay` 等 NBT 字段控制刷怪节奏。通过 `data merge entity` 动态修改刷怪笼的 `Delay` 和 `SpawnData`，实现精确的刷怪间隔控制。

### 版本要求

1.16+（`data merge entity` 可用），1.20.5+ 支持更丰富的 NBT 操作

### 完整实现

#### 1. 放置刷怪笼（手动或通过命令）

```mcfunction
# 在目标位置放置一个刷怪笼
setblock ~ ~1 ~ minecraft:spawner
```

#### 2. 初始化刷怪笼 NBT

`data/spawner/load.mcfunction`
```mcfunction
# 设置刷怪笼参数
data merge entity @e[type=minecraft:spawner,limit=1,distance=..5] {
  SpawnCount: 3,          # 每次刷怪数量
  SpawnRange: 8,          # 刷怪范围
  Delay: 100,             # 初始延迟（tick）
  MinSpawnDelay: 40,      # 最小延迟
  MaxSpawnDelay: 200,     # 最大延迟
  SpawnData: {
    entity: {
      id: "minecraft:zombie",
      CustomName: '{"text":"波次僵尸"}',
      PersistenceRequired: 1b
    }
  },
  SpawnPotentials: []     # 清空其他刷怪选项
}
```

#### 3. 动态控制刷怪节奏

`data/spawner/tick.mcfunction`
```mcfunction
# 每 tick 检查刷怪笼状态，根据条件调整延迟
execute if score #wave_count <namespace> matches 1..10 run data merge entity @e[type=minecraft:spawner,limit=1] {
  MinSpawnDelay: 20,
  MaxSpawnDelay: 60
}

# 当玩家远离时降低刷怪频率
execute if entity @p[distance=..10] run data merge entity @e[type=minecraft:spawner,limit=1] {
  MinSpawnDelay: 100,
  MaxSpawnDelay: 300
}
```

#### 4. 重置刷怪笼

`data/spawner/reset.mcfunction`
```mcfunction
# 强制重置刷怪笼延迟
data merge entity @e[type=minecraft:spawner,limit=1] {
  Delay: 0,
  SpawnCount: 5
}
```

### 陷阱与注意事项

1. **刷怪笼激活条件**：刷怪笼需要玩家在 16 格内才会激活。如果玩家距离过远，刷怪笼会暂停工作，导致计时器失效。
2. **性能开销**：每个刷怪笼每 tick 都会检查一次，大量刷怪笼（>50）可能导致性能问题。开销中等。
3. **NBT 合并限制**：`data merge entity` 会覆盖整个 NBT 结构，如果同时有其他数据包修改同一个刷怪笼，可能产生冲突。
4. **刷怪笼数量限制**：每个区块最多 1 个自然生成的刷怪笼，但通过命令放置的没有限制。

## 方案二：基于 `scoreboard` 计时器 + `summon` 命令

### 原理

使用 `scoreboard` 的 `dummy` 目标作为计时器，每 tick 递减，当计时器归零时执行 `summon` 命令生成实体。通过调整计时器初始值和递减速度控制刷怪节奏。

### 版本要求

1.13+（`scoreboard` 和 `summon` 命令可用）

### 完整实现

#### 1. 初始化计时器

`data/timer/load.mcfunction`
```mcfunction
# 创建计时器目标
scoreboard objectives add spawn_timer dummy

# 初始化全局计时器（使用假玩家）
scoreboard players set #global_spawn_timer spawn_timer 0
```

#### 2. 主循环

`data/timer/tick.mcfunction`
```mcfunction
# 每 tick 执行一次
execute if score #global_spawn_timer spawn_timer matches 0 run function data:timer/spawn_wave
execute if score #global_spawn_timer spawn_timer matches 1.. run scoreboard players remove #global_spawn_timer spawn_timer 1
```

#### 3. 刷怪逻辑

`data/timer/spawn_wave.mcfunction`
```mcfunction
# 重置计时器（随机间隔 100-200 tick）
scoreboard players set #global_spawn_timer spawn_timer 100
execute if score #random_seed spawn_timer matches 0.. run scoreboard players add #global_spawn_timer spawn_timer 100

# 在玩家附近刷怪
execute as @a at @s run function data:timer/spawn_at_player
```

`data/timer/spawn_at_player.mcfunction`
```mcfunction
# 在玩家周围 5-15 格随机位置生成僵尸
summon minecraft:zombie ~ ~ ~ {CustomName:'{"text":"计时器僵尸"}',PersistenceRequired:1b}
```

#### 4. 动态调整节奏

`data/timer/adjust.mcfunction`
```mcfunction
# 根据玩家数量调整刷怪间隔
execute if entity @a[limit=5] run scoreboard players set #global_spawn_timer spawn_timer 60
execute if entity @a[limit=10] run scoreboard players set #global_spawn_timer spawn_timer 30
```

### 陷阱与注意事项

1. **性能开销**：每 tick 执行 `scoreboard players remove` 和条件判断，开销较低。但大量 `summon` 命令（>100/秒）可能导致实体数量爆炸。
2. **随机性控制**：使用 `scoreboard` 的随机数需要额外实现（如利用 `random` 函数或 `@r` 选择器）。
3. **多区域支持**：如果需要多个独立的刷怪计时器，需要为每个区域创建独立的假玩家或使用 `storage`。
4. **服务器重启**：`scoreboard` 数据会持久化，但假玩家的值在重启后保留，需要确保初始化逻辑正确处理。

## 方案三：基于 `advancement` + `schedule` 的波次刷怪

### 原理

利用 `advancement` 的 `tick` 触发器作为计时器，结合 `schedule` 命令实现延迟执行。当玩家满足特定条件（如进入区域、击杀怪物）时触发刷怪波次。

### 版本要求

1.13+（`schedule` 命令 1.14+ 可用）

### 完整实现

#### 1. 创建波次触发器

`data/wave/advancement/trigger.json`
```json
{
  "criteria": {
    "tick": {
      "trigger": "minecraft:tick"
    }
  },
  "rewards": {
    "function": "data:wave/check"
  }
}
```

#### 2. 检查条件并触发波次

`data/wave/check.mcfunction`
```mcfunction
# 检查是否满足波次条件
execute if entity @a[scores={wave_cooldown=0}] run function data:wave/start_wave

# 移除进度，防止重复触发
advancement revoke @s only data:wave/trigger
```

#### 3. 启动波次

`data/wave/start_wave.mcfunction`
```mcfunction
# 设置冷却时间
scoreboard players set @a wave_cooldown 600

# 生成第一波怪物
summon minecraft:zombie ~ ~ ~
summon minecraft:skeleton ~ ~ ~

# 安排第二波（延迟 100 tick）
schedule function data:wave/second_wave 100
```

`data/wave/second_wave.mcfunction`
```mcfunction
# 第二波刷怪
summon minecraft:zombie ~ ~ ~
summon minecraft:zombie ~ ~ ~
summon minecraft:spider ~ ~ ~
```

### 陷阱与注意事项

1. **`schedule` 限制**：`schedule` 命令只能安排函数在未来的某个 tick 执行，不能循环。需要手动重新安排。
2. **玩家离线处理**：如果触发波次的玩家离线，`schedule` 仍然会执行，可能导致怪物在无人区域生成。
3. **性能开销**：`advancement` 的 `tick` 触发器每 tick 都会检查所有在线玩家，开销较低。但大量 `schedule` 命令（>100）可能导致性能问题。
4. **版本兼容性**：`schedule` 命令在 1.14 之前不可用，1.13 需要使用其他方法（如 `scoreboard` 计时器）。

## 方案四：基于 `predicate` + `random` 的概率刷怪

### 原理

利用 `predicate` 的 `random_chance` 或 `random_chance_with_looting` 实现概率刷怪。每 tick 检查随机条件，满足时执行刷怪命令。

### 版本要求

1.15+（`predicate` 系统引入）

### 完整实现

#### 1. 创建概率谓词

`data/predicate/spawn_chance.json`
```json
{
  "condition": "minecraft:random_chance",
  "chance": 0.01
}
```

#### 2. 主循环

`data/spawn/tick.mcfunction`
```mcfunction
# 每 tick 检查概率
execute as @a at @s if predicate data:spawn_chance run function data:spawn/do_spawn
```

#### 3. 刷怪逻辑

`data/spawn/do_spawn.mcfunction`
```mcfunction
# 在玩家周围生成怪物
summon minecraft:zombie ~ ~ ~
summon minecraft:skeleton ~ ~ ~
```

### 陷阱与注意事项

1. **概率控制**：`random_chance` 是全局概率，无法根据玩家或区域动态调整。如需动态调整，需要使用 `random_chance_with_looting` 或自定义 `scoreboard` 逻辑。
2. **性能开销**：每 tick 对每个玩家执行一次谓词检查，开销较低。但大量玩家（>50）可能导致性能下降。
3. **刷怪密度控制**：概率刷怪无法控制单位时间内的刷怪数量上限，可能导致怪物数量爆炸。需要额外实现计数器。
4. **版本兼容性**：`predicate` 在 1.15 之前不可用，1.14 及以下版本需要使用其他方法。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|---------|------|------|
| 刷怪笼计时器 | 1.16+ | 中 | 固定区域刷怪、波次刷怪 | 原生支持、精确控制 | 需要放置实体、玩家距离限制 |
| scoreboard 计时器 | 1.13+ | 低 | 全局刷怪、动态节奏 | 灵活、无实体依赖 | 需要手动管理计时器 |
| advancement + schedule | 1.14+ | 低 | 波次刷怪、事件触发 | 延迟执行、条件触发 | 需要手动安排、玩家离线问题 |
| predicate 概率刷怪 | 1.15+ | 低 | 随机刷怪、低密度场景 | 简单、原生支持 | 无法精确控制频率 |

## 最佳实践建议

1. **固定区域刷怪**：优先使用刷怪笼方案，利用原生机制减少性能开销。
2. **全局动态节奏**：使用 scoreboard 计时器，配合条件判断实现自适应刷怪。
3. **波次刷怪**：使用 advancement + schedule 方案，实现精确的波次间隔。
4. **随机刷怪**：使用 predicate 概率方案，但需要配合计数器防止怪物数量失控。

## 陷阱总结

1. **刷怪笼激活距离**：刷怪笼需要玩家在 16 格内，否则停止工作。
2. **实体数量控制**：所有方案都需要考虑实体数量上限，防止服务器卡顿。
3. **多玩家场景**：多个玩家同时触发刷怪时，需要确保刷怪逻辑不会重复执行。
4. **服务器重启**：`schedule` 命令在服务器重启后会丢失，需要重新安排。
5. **版本兼容性**：不同 Minecraft 版本对 NBT 格式和命令语法有差异，需要根据目标版本调整。
