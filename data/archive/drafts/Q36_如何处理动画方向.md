# 如何处理动画方向

## 问题概述

在 Minecraft 数据包开发中，"动画方向"通常指：
1. **实体朝向**：玩家/生物看向的方向（yaw/pitch）
2. **动画播放方向**：如盔甲架旋转、粒子发射方向、物品展示实体朝向
3. **相对方向**：玩家相对于某个方块或实体的方向

核心挑战在于：原版数据包没有直接的"方向动画"API，需要通过实体旋转、粒子参数、展示实体变换等机制间接实现。

---

## 方案一：利用展示实体（Display Entity）实现平滑旋转动画

**适用版本**：1.19.4+（展示实体引入）
**原理**：使用 `item_display`、`block_display` 或 `text_display` 实体，通过修改其 `rotation` NBT 或使用 `data modify` 实现方向变化。结合 `tick` 函数逐帧更新，可实现平滑旋转动画。

### 实现步骤

#### 1. 创建展示实体（初始化）

`data/<namespace>/function/animation/spawn_display.mcfunction`
```mcfunction
# 在玩家位置生成一个物品展示实体，显示钻石块
summon item_display ~ ~ ~ {item:{id:"minecraft:diamond_block",count:1},rotation:[0f,0f,0f],interpolation_duration:1,start_interpolation:0}
# 存储实体UUID以便后续操作
tag @e[type=item_display,limit=1,sort=nearest] add rotating_display
```

#### 2. 逐帧更新旋转（tick 函数）

`data/<namespace>/function/animation/rotate.mcfunction`
```mcfunction
# 每 tick 增加 yaw 旋转 5 度（每秒 100 度）
execute as @e[tag=rotating_display] run data modify entity @s rotation[0] set value 5f
# 注意：这里直接设置固定值，实际应使用 scoreboard 累加
```

**更精确的累加方式**（使用 scoreboard）：

`data/<namespace>/function/animation/init_scoreboard.mcfunction`
```mcfunction
scoreboard objectives add anim_angle dummy
scoreboard objectives add anim_speed dummy
scoreboard players set @e[tag=rotating_display] anim_speed 5
```

`data/<namespace>/function/animation/rotate_accumulate.mcfunction`
```mcfunction
# 累加角度
scoreboard players add @e[tag=rotating_display] anim_angle 5
# 将角度写入实体 rotation
execute as @e[tag=rotating_display] store result entity @s rotation[0] float 1.0 run scoreboard players get @s anim_angle
```

### 陷阱与注意事项

1. **插值问题**：展示实体支持 `interpolation_duration` 和 `start_interpolation`，但直接修改 `rotation` 时，如果 `interpolation_duration` 不为 0，实体会自动插值到新值。这可能导致"跳跃"而非平滑旋转。建议设置 `interpolation_duration:0` 或使用 `teleport` 强制更新。
2. **性能开销**：每 tick 修改大量展示实体的 NBT 可能造成性能下降。建议限制同时存在的动画实体数量（如不超过 50 个）。
3. **方向基准**：展示实体的 `rotation` 是 [yaw, pitch] 格式，yaw 为 0 时朝向正南（+Z），顺时针增加。这与玩家的 yaw 系统一致。

## 方案二：利用粒子系统实现方向性动画

**适用版本**：1.17+（粒子参数系统完善）
**原理**：某些粒子（如 `minecraft:arrow`、`minecraft:item`）支持方向参数。通过 `particle` 命令的 `delta` 参数或 `block_marker` 粒子的朝向，可以模拟方向动画。

### 实现步骤

#### 1. 发射方向性粒子

`data/<namespace>/function/animation/directional_particle.mcfunction`
```mcfunction
# 发射一个朝向东方的箭头粒子（delta 表示速度/方向向量）
particle minecraft:arrow ~ ~ ~ 1 0 0 0.5 1
# 参数解释：x y z dx dy dz speed count
# dx=1, dy=0, dz=0 表示粒子沿 X 轴正方向运动
```

#### 2. 使用 item 粒子展示旋转物品

```mcfunction
# 发射一个旋转的钻石粒子（通过 delta 模拟旋转效果）
particle minecraft:item diamond ~ ~ ~ 0.5 0 0 0.1 1
```

### 陷阱与注意事项

1. **粒子方向有限**：粒子系统的方向控制非常粗糙，只能通过 `delta` 参数控制运动方向，无法精确控制朝向。
2. **粒子生命周期**：粒子默认在 1-2 秒内消失，无法实现持续动画。
3. **性能开销**：大量粒子（>1000）会显著降低帧率。
4. **版本差异**：1.20.5 后粒子系统有较大改动，部分粒子类型被移除或合并。

## 方案三：利用盔甲架（Armor Stand）实现方向动画

**适用版本**：所有版本（1.8+）
**原理**：盔甲架支持 `Rotation` NBT 和 `Pose` NBT，通过逐帧修改这些值可以实现方向动画。这是最传统的方法。

### 实现步骤

#### 1. 创建盔甲架

`data/<namespace>/function/animation/spawn_armorstand.mcfunction`
```mcfunction
# 生成一个不可见的盔甲架，手持剑，朝向北方
summon armor_stand ~ ~ ~ {Invisible:1b,NoGravity:1b,ShowArms:1b,Rotation:[0f,0f],HandItems:[{id:"minecraft:iron_sword",count:1},{}]}
tag @e[type=armor_stand,limit=1,sort=nearest] add animated_stand
```

#### 2. 逐帧旋转

`data/<namespace>/function/animation/rotate_stand.mcfunction`
```mcfunction
# 使用 scoreboard 累加角度
scoreboard players add @e[tag=animated_stand] anim_angle 5
# 写入 Rotation
execute as @e[tag=animated_stand] store result entity @s Rotation[0] float 1.0 run scoreboard players get @s anim_angle
```

### 陷阱与注意事项

1. **盔甲架碰撞箱**：盔甲架默认有碰撞箱，可能干扰玩家移动。建议设置 `Marker:1b` 使其无碰撞，但标记盔甲架无法手持物品。
2. **Pose 与 Rotation 的区别**：`Rotation` 控制整体朝向，`Pose` 控制肢体角度。两者可以结合使用。
3. **性能开销**：每 tick 修改 NBT 的开销与方案一类似，但盔甲架实体本身比展示实体更轻量（无渲染插值）。
4. **版本兼容性**：盔甲架在所有版本中行为一致，是最稳定的方案。

## 方案四：利用玩家朝向（Player Rotation）实现视角动画

**适用版本**：1.13+（`execute as` 和 `at` 完善）
**原理**：通过修改玩家的 `Rotation` NBT 或使用 `teleport` 改变玩家朝向，实现第一人称视角动画。常用于过场动画或自动瞄准。

### 实现步骤

#### 1. 强制改变玩家朝向

`data/<namespace>/function/animation/look_at.mcfunction`
```mcfunction
# 让玩家看向某个坐标（例如看向 0 64 0）
execute as @a at @s run tp @s ~ ~ ~ facing 0 64 0
```

#### 2. 平滑旋转（逐帧微调）

`data/<namespace>/function/animation/smooth_look.mcfunction`
```mcfunction
# 每 tick 增加玩家 yaw 1 度
execute as @a at @s run data modify entity @s Rotation[0] set value 1f
# ⚠️ 需验证：直接修改玩家 Rotation 是否会被客户端覆盖？
# 实际测试表明：服务端修改 Rotation 后，客户端会立即同步，但玩家移动鼠标会覆盖。
```

### 陷阱与注意事项

1. **客户端覆盖**：玩家可以随时移动鼠标覆盖服务端设置的朝向。因此此方案仅适用于强制控制（如过场动画）或配合 `spectator` 模式使用。
2. **多人同步**：修改玩家朝向会立即同步到所有客户端，但可能造成晕眩感。
3. **性能开销**：极低，仅修改 NBT 无额外计算。
4. **版本要求**：1.13+ 支持 `data modify entity` 修改玩家 NBT。

## 推荐方案

### 首选：展示实体（1.19.4+）

**理由**：
- 原生支持插值动画（`interpolation_duration`）
- 可显示物品、方块、文本，灵活性最高
- 无碰撞箱干扰

**完整示例**：平滑旋转 360 度

`data/<namespace>/function/animation/init.mcfunction`
```mcfunction
# 创建展示实体
summon item_display ~ ~1 ~ {item:{id:"minecraft:compass",count:1},rotation:[0f,0f,0f],interpolation_duration:0,start_interpolation:0,tags:["rotating_compass"]}
# 初始化角度
scoreboard players set @e[tag=rotating_compass] anim_angle 0
```

`data/<namespace>/function/animation/tick.mcfunction`
```mcfunction
# 每 tick 增加 2 度（每秒 40 度，9 秒转一圈）
execute as @e[tag=rotating_compass] run scoreboard players add @s anim_angle 2
# 写入 rotation
execute as @e[tag=rotating_compass] store result entity @s rotation[0] float 1.0 run scoreboard players get @s anim_angle
# 重置角度（避免溢出）
execute as @e[tag=rotating_compass] if score @s anim_angle >= 360 run scoreboard players set @s anim_angle 0
```

### 备选：盔甲架（兼容旧版本）

**理由**：支持 1.8+，行为稳定，适合需要兼容旧版本的数据包。

## 陷阱总结

1. **插值与直接修改的冲突**：展示实体的 `interpolation_duration` 如果 > 0，直接修改 `rotation` 会导致插值跳跃。解决方案：设置 `interpolation_duration:0` 或使用 `teleport` 强制更新。
2. **玩家朝向被覆盖**：修改玩家 `Rotation` 后，客户端鼠标移动会覆盖。解决方案：仅在 `spectator` 模式或配合 `input` 禁用时使用。
3. **粒子方向精度不足**：粒子系统的 `delta` 参数只能控制运动方向，无法精确控制朝向。解决方案：使用展示实体或盔甲架。
4. **性能瓶颈**：每 tick 修改大量实体的 NBT 可能导致 TPS 下降。解决方案：限制动画实体数量，或使用 `schedule` 降低更新频率。
5. **版本兼容性**：展示实体是 1.19.4 新增，粒子系统在 1.20.5 有重大改动。解决方案：明确标注最低版本要求。
