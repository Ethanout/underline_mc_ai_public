# 如何制作交互提示

## 核心挑战

在 Minecraft 原版数据包中制作交互提示（即玩家靠近某个方块或实体时显示可交互的提示信息），主要面临以下挑战：

1. **没有原生的 UI 系统**：无法直接创建 GUI 按钮或提示框
2. **玩家位置检测精度**：需要精确检测玩家与交互点的距离和视线方向
3. **提示信息的显示方式**：只能通过 Title/Actionbar/Bossbar 等有限方式显示
4. **性能开销**：高频检测可能影响服务器性能

## 方案一：基于距离检测的 Actionbar 提示（最常用）

### 原理

通过 `execute` 命令检测玩家与特定位置的距离，当玩家进入指定范围时，通过 `title` 命令在 Actionbar 显示提示信息。

### 适用版本
1.13+（所有支持数据包的版本）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      load.mcfunction
      tick.mcfunction
      interact/
        check.mcfunction
        show_prompt.mcfunction
        hide_prompt.mcfunction
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建用于标记玩家状态的 scoreboard
scoreboard objectives add <namespace>.interact dummy
scoreboard objectives add <namespace>.interact_cooldown dummy

# 设置交互点（示例：在坐标 100 64 100 处）
scoreboard players set <namespace>.interact_x <namespace> 100
scoreboard players set <namespace>.interact_y <namespace> 64
scoreboard players set <namespace>.interact_z <namespace> 100
```

#### 2. 主循环 (tick.mcfunction)
```mcfunction
# 每 tick 检测所有玩家
execute as @a at @s run function <namespace>:interact/check
```

#### 3. 检测逻辑 (interact/check.mcfunction)
```mcfunction
# 计算玩家与交互点的距离
execute store result score @s <namespace>.interact_x run data get entity @s Pos[0] 1000
execute store result score @s <namespace>.interact_y run data get entity @s Pos[1] 1000
execute store result score @s <namespace>.interact_z run data get entity @s Pos[2] 1000

# 计算差值（注意：这里简化了距离计算，实际需要三维距离）
scoreboard players operation @s <namespace>.interact_x -= <namespace>.interact_x <namespace>
scoreboard players operation @s <namespace>.interact_y -= <namespace>.interact_y <namespace>
scoreboard players operation @s <namespace>.interact_z -= <namespace>.interact_z <namespace>

# 检查是否在范围内（简化版：每个轴距离 < 2 格）
execute if score @s <namespace>.interact_x matches -2..2 if score @s <namespace>.interact_y matches -2..2 if score @s <namespace>.interact_z matches -2..2 run function <namespace>:interact/show_prompt
execute unless score @s <namespace>.interact_x matches -2..2 unless score @s <namespace>.interact_y matches -2..2 unless score @s <namespace>.interact_z matches -2..2 run function <namespace>:interact/hide_prompt
```

#### 4. 显示提示 (interact/show_prompt.mcfunction)
```mcfunction
# 检查是否已经显示提示（避免重复发送）
execute unless score @s <namespace>.interact = 1 run title @s actionbar {"text":"按 [右键] 交互","color":"green"}
scoreboard players set @s <namespace>.interact 1
```

#### 5. 隐藏提示 (interact/hide_prompt.mcfunction)
```mcfunction
# 清除提示
execute if score @s <namespace>.interact = 1 run title @s actionbar {"text":""}
scoreboard players set @s <namespace>.interact 0
```

### 陷阱与注意事项

1. **距离计算不精确**：上述示例使用简化的曼哈顿距离，实际应使用欧几里得距离。更精确的方法：
   ```mcfunction
   # 使用 execute positioned 和 distance 谓词
   execute as @a at @s if entity @s[distance=..2] run function <namespace>:interact/show_prompt
   ```

2. **性能开销**：每 tick 对所有玩家执行距离计算，当玩家数量多时开销较大。建议：
   - 降低检测频率（每 2-3 tick 检测一次）
   - 使用 `@a[distance=..10]` 先过滤远距离玩家

3. **Actionbar 冲突**：如果其他数据包或模组也使用 Actionbar，会互相覆盖。考虑使用 Bossbar 或 Title 作为替代。

## 方案二：基于视线检测的精准交互提示

### 原理

除了距离检测外，还检测玩家的视线方向是否对准交互点，实现类似"准星对准时显示提示"的效果。

### 适用版本
1.13+（需要 `execute facing` 和 `anchored eyes` 支持）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      load.mcfunction
      tick.mcfunction
      interact/
        check.mcfunction
        raycast.mcfunction
        show_prompt.mcfunction
        hide_prompt.mcfunction
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建交互点标记实体（使用 armor_stand）
summon minecraft:armor_stand 100 64 100 {Marker:1b,Invisible:1b,NoGravity:1b,Tags:["<namespace>.interact_point"]}

# 设置交互范围
scoreboard objectives add <namespace>.interact_distance dummy
scoreboard objectives add <namespace>.interact_angle dummy
```

#### 2. 主循环 (tick.mcfunction)
```mcfunction
# 每 tick 检测所有玩家
execute as @a at @s run function <namespace>:interact/check
```

#### 3. 检测逻辑 (interact/check.mcfunction)
```mcfunction
# 检查距离（使用实体选择器）
execute if entity @e[tag=<namespace>.interact_point,distance=..3] run function <namespace>:interact/raycast
execute unless entity @e[tag=<namespace>.interact_point,distance=..3] run function <namespace>:interact/hide_prompt
```

#### 4. 视线检测 (interact/raycast.mcfunction)
```mcfunction
# 使用 execute facing 检测玩家是否面向交互点
# ⚠️ 需验证：以下命令在 1.13+ 是否有效
execute as @s at @s anchored eyes facing entity @e[tag=<namespace>.interact_point,limit=1] feet run function <namespace>:interact/check_angle

# 简化版：直接检测玩家是否在交互点附近且面向大致方向
execute if entity @s[ry=45,rym=-45] run function <namespace>:interact/show_prompt
```

#### 5. 显示/隐藏提示 (interact/show_prompt.mcfunction, interact/hide_prompt.mcfunction)
```mcfunction
# show_prompt.mcfunction
execute unless score @s <namespace>.interact = 1 run title @s actionbar {"text":"按 [右键] 打开箱子","color":"yellow"}
scoreboard players set @s <namespace>.interact 1

# hide_prompt.mcfunction
execute if score @s <namespace>.interact = 1 run title @s actionbar {"text":""}
scoreboard players set @s <namespace>.interact 0
```

### 陷阱与注意事项

1. **视线检测精度有限**：原版没有精确的射线检测，只能通过角度近似判断。对于小目标（如按钮）可能不准确。

2. **性能开销较高**：每 tick 对每个玩家执行视线计算，建议：
   - 先做距离过滤（只检测 5 格内的玩家）
   - 降低检测频率

3. **多交互点冲突**：如果有多个交互点，需要为每个点创建独立的标记实体，并分别检测。

## 方案三：基于进度触发的交互提示（1.20.5+）

### 原理

利用 1.20.5 新增的 `player_interacted_with_entity` 进度触发器，在玩家与特定实体交互时触发提示。这种方式不需要每 tick 检测，性能最优。

### 适用版本
1.20.5+

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancements/
      interact/
        prompt.json
    functions/
      interact/
        on_interact.mcfunction
        show_prompt.mcfunction
```

#### 1. 进度定义 (advancements/interact/prompt.json)
```json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": {
          "type": "minecraft:armor_stand",
          "nbt": "{Tags:[\"<namespace>.interact_point\"]}"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:interact/on_interact"
  }
}
```

#### 2. 交互处理 (functions/interact/on_interact.mcfunction)
```mcfunction
# 显示交互提示
title @s actionbar {"text":"你与交互点进行了交互！","color":"green"}

# 执行交互逻辑（示例：给玩家一个物品）
give @s minecraft:diamond 1

# 撤销进度，以便下次再次触发
advancement revoke @s only <namespace>:interact/prompt
```

#### 3. 初始化 (load.mcfunction)
```mcfunction
# 创建交互点
summon minecraft:armor_stand 100 64 100 {Marker:1b,Invisible:1b,NoGravity:1b,Tags:["<namespace>.interact_point"]}

# 为所有玩家撤销进度（防止旧存档残留）
advancement revoke @a only <namespace>:interact/prompt
```

### 陷阱与注意事项

1. **仅支持实体交互**：无法直接检测玩家与方块的交互。如果需要与方块交互，需要将 armor_stand 放在方块位置。

2. **进度触发延迟**：进度触发有 1 tick 的延迟，不适合需要即时响应的场景。

3. **玩家必须右键点击实体**：玩家需要主动右键点击 armor_stand 才能触发，无法实现"靠近自动显示"的效果。

## 方案对比

| 特性 | 方案一：距离检测 | 方案二：视线检测 | 方案三：进度触发 |
|------|-----------------|-----------------|-----------------|
| **最低版本** | 1.13 | 1.13 | 1.20.5 |
| **性能开销** | 中（每 tick 计算距离） | 高（每 tick 计算视线） | 低（仅触发时执行） |
| **精度** | 低（仅距离） | 中（距离+大致方向） | 高（精确交互） |
| **实时性** | 高（每 tick 更新） | 高（每 tick 更新） | 低（触发后更新） |
| **实现复杂度** | 低 | 中 | 低 |
| **适用场景** | 大范围提示（如区域入口） | 精准交互提示（如按钮） | 点击交互（如 NPC 对话） |

## 推荐方案

- **通用场景**：方案一（距离检测），实现简单，性能可接受
- **需要精准交互**：方案二（视线检测），但注意性能优化
- **1.20.5+ 且需要点击交互**：方案三（进度触发），性能最优

## 进阶技巧

### 使用 Bossbar 显示提示
```mcfunction
# 创建 Bossbar
bossbar add <namespace>:interact {"text":"按 [右键] 交互","color":"green"}
bossbar set <namespace>:interact max 100
bossbar set <namespace>:interact visible false

# 显示
bossbar set <namespace>:interact visible true
bossbar set <namespace>:interact players @s

# 隐藏
bossbar set <namespace>:interact visible false
```

### 多语言支持
```json
{
  "text": "Press [Right Click] to interact",
  "translate": "interact.prompt",
  "with": []
}
```

### 冷却机制（防止刷屏）
```mcfunction
# 在 show_prompt 中设置冷却
scoreboard players set @s <namespace>.interact_cooldown 20

# 在 check 中检查冷却
execute if score @s <namespace>.interact_cooldown matches 0 run function <namespace>:interact/show_prompt
execute if score @s <namespace>.interact_cooldown matches 1.. run scoreboard players remove @s <namespace>.interact_cooldown 1
```
