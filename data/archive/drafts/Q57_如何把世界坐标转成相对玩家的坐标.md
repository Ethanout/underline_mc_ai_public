# 如何把世界坐标转成相对玩家的坐标

## 问题背景

在 Minecraft 数据包开发中，经常需要将世界坐标（绝对坐标）转换为相对于某个玩家的坐标（相对坐标）。例如：在玩家周围生成结构、计算玩家与某个位置的偏移、实现自定义传送系统等。

核心挑战：原版命令系统没有直接的“世界坐标 → 相对坐标”转换函数。`execute positioned` 和 `execute at` 只能改变执行位置，但不能直接输出坐标差值。我们需要通过间接手段实现这一转换。

## 方案一：使用 `execute store` + 记分板（最通用，推荐）

### 原理

利用 `execute store` 将实体的坐标存储到记分板，然后通过 `execute positioned` 改变执行位置，再次存储坐标，最后计算差值。

核心思路：
1. 在玩家位置执行 `execute store result score ... run data get entity @s Pos[0]` 获取玩家 X 坐标
2. 在世界坐标位置执行同样的操作获取目标 X 坐标
3. 计算差值：目标坐标 - 玩家坐标 = 相对坐标

### 完整代码

#### 1. 初始化记分板（load 函数）

```mcfunction
# load.mcfunction
scoreboard objectives add coord_x dummy
scoreboard objectives add coord_y dummy
scoreboard objectives add coord_z dummy
scoreboard objectives add temp dummy
```

#### 2. 转换函数（假设要计算世界坐标 (100, 64, 200) 相对于玩家 @p 的坐标）

```mcfunction
# function example:convert_to_relative.mcfunction
# 输入：世界坐标 (100, 64, 200)，玩家 @p
# 输出：记分板 coord_x/y/z 存储相对坐标

# 步骤1：获取玩家坐标
execute as @p at @s run function example:get_player_coords

# 步骤2：获取世界坐标
execute positioned 100 64 200 run function example:get_world_coords

# 步骤3：计算相对坐标（世界坐标 - 玩家坐标）
scoreboard players operation #relative_x coord_x = #world_x coord_x
scoreboard players operation #relative_x coord_x -= #player_x coord_x

scoreboard players operation #relative_y coord_y = #world_y coord_y
scoreboard players operation #relative_y coord_y -= #player_y coord_y

scoreboard players operation #relative_z coord_z = #world_z coord_z
scoreboard players operation #relative_z coord_z -= #player_z coord_z

# 可选：将结果输出到聊天
tellraw @a [{"text":"相对坐标: ","color":"gold"},{"score":{"name":"#relative_x","objective":"coord_x"}},{"text":", "},{"score":{"name":"#relative_y","objective":"coord_y"}},{"text":", "},{"score":{"name":"#relative_z","objective":"coord_z"}}]
```

```mcfunction
# function example:get_player_coords.mcfunction
# 获取当前执行位置的坐标（玩家位置）
execute store result score #player_x coord_x run data get entity @s Pos[0] 1
execute store result score #player_y coord_y run data get entity @s Pos[1] 1
execute store result score #player_z coord_z run data get entity @s Pos[2] 1
```

```mcfunction
# function example:get_world_coords.mcfunction
# 获取当前执行位置的坐标（世界坐标位置）
execute store result score #world_x coord_x run data get entity @s Pos[0] 1
execute store result score #world_y coord_y run data get entity @s Pos[1] 1
execute store result score #world_z coord_z run data get entity @s Pos[2] 1
```

### 陷阱与注意事项

1. **精度问题**：`data get` 默认返回 double 类型，`store result` 会截断为整数。如果需要小数精度，可以使用 `scale` 参数（如 `data get entity @s Pos[0] 100` 将坐标放大100倍存储），但记分板只能存储整数。

2. **执行上下文**：`get_world_coords.mcfunction` 中的 `@s` 在 `execute positioned` 后指向的是该位置的虚拟实体（实际上是命令执行者本身，但位置已改变）。⚠️ 需验证：在 `execute positioned` 后，`@s` 是否仍然指向原实体？实际上，`execute positioned` 只改变执行位置，不改变执行者。所以 `@s` 仍然是原来的玩家实体，但 `data get entity @s Pos` 获取的是玩家当前的实际位置，而不是 `positioned` 设置的位置。**这是一个常见误区！**

   **修正方案**：使用 `execute at @s` 配合 `summon` 创建一个临时标记实体在世界坐标位置，然后获取该实体的坐标。

#### 修正后的代码

```mcfunction
# function example:convert_to_relative_fixed.mcfunction
# 输入：世界坐标 (100, 64, 200)，玩家 @p
# 输出：记分板 coord_x/y/z 存储相对坐标

# 步骤1：获取玩家坐标
execute as @p at @s run function example:get_player_coords

# 步骤2：在世界坐标位置生成临时标记实体
summon minecraft:marker 100 64 200 {Tags:["temp_marker"]}

# 步骤3：获取标记实体的坐标
execute as @e[type=minecraft:marker,tag=temp_marker,limit=1] run function example:get_marker_coords

# 步骤4：计算相对坐标
scoreboard players operation #relative_x coord_x = #marker_x coord_x
scoreboard players operation #relative_x coord_x -= #player_x coord_x

scoreboard players operation #relative_y coord_y = #marker_y coord_y
scoreboard players operation #relative_y coord_y -= #player_y coord_y

scoreboard players operation #relative_z coord_z = #marker_z coord_z
scoreboard players operation #relative_z coord_z -= #player_z coord_z

# 步骤5：清理标记实体
kill @e[type=minecraft:marker,tag=temp_marker,limit=1]

# 输出结果
tellraw @a [{"text":"相对坐标: ","color":"gold"},{"score":{"name":"#relative_x","objective":"coord_x"}},{"text":", "},{"score":{"name":"#relative_y","objective":"coord_y"}},{"text":", "},{"score":{"name":"#relative_z","objective":"coord_z"}}]
```

```mcfunction
# function example:get_marker_coords.mcfunction
execute store result score #marker_x coord_x run data get entity @s Pos[0] 1
execute store result score #marker_y coord_y run data get entity @s Pos[1] 1
execute store result score #marker_z coord_z run data get entity @s Pos[2] 1
```

3. **性能开销**：每次转换需要生成和销毁一个 marker 实体，开销较低（约 0.1ms 级）。如果高频调用（每 tick 多次），建议复用 marker 实体。

## 方案二：使用 `execute store` + `storage`（1.20.5+，无实体开销）

### 原理

利用 `execute store result storage` 将坐标存储到 storage 中，然后通过 `data modify` 进行数学运算。1.20.5 引入了 `data modify` 的算术运算功能，可以直接在 storage 中计算差值。

### 完整代码

#### 1. 初始化 storage（load 函数）

```mcfunction
# load.mcfunction
# 创建一个 storage 用于存储坐标数据
data modify storage example:coords player set value [0.0,0.0,0.0]
data modify storage example:coords world set value [0.0,0.0,0.0]
data modify storage example:coords relative set value [0.0,0.0,0.0]
```

#### 2. 转换函数

```mcfunction
# function example:convert_to_relative_storage.mcfunction
# 输入：世界坐标 (100, 64, 200)，玩家 @p
# 输出：storage example:coords relative 存储相对坐标

# 步骤1：获取玩家坐标并存入 storage
execute as @p at @s run function example:store_player_coords

# 步骤2：在世界坐标位置生成临时标记并获取坐标
summon minecraft:marker 100 64 200 {Tags:["temp_marker"]}
execute as @e[type=minecraft:marker,tag=temp_marker,limit=1] run function example:store_world_coords

# 步骤3：计算相对坐标（world - player）
# 注意：data modify 的算术运算在 1.20.5+ 可用
data modify storage example:coords relative set from storage example:coords world
data modify storage example:coords relative[0] -= storage example:coords player[0]
data modify storage example:coords relative[1] -= storage example:coords player[1]
data modify storage example:coords relative[2] -= storage example:coords player[2]

# 步骤4：清理
kill @e[type=minecraft:marker,tag=temp_marker,limit=1]

# 输出结果
tellraw @a [{"text":"相对坐标: ","color":"gold"},{"nbt":"relative[0]","storage":"example:coords","interpret":true},{"text":", "},{"nbt":"relative[1]","storage":"example:coords","interpret":true},{"text":", "},{"nbt":"relative[2]","storage":"example:coords","interpret":true}]
```

```mcfunction
# function example:store_player_coords.mcfunction
execute store result storage example:coords player[0] double 1 run data get entity @s Pos[0]
execute store result storage example:coords player[1] double 1 run data get entity @s Pos[1]
execute store result storage example:coords player[2] double 1 run data get entity @s Pos[2]
```

```mcfunction
# function example:store_world_coords.mcfunction
execute store result storage example:coords world[0] double 1 run data get entity @s Pos[0]
execute store result storage example:coords world[1] double 1 run data get entity @s Pos[1]
execute store result storage example:coords world[2] double 1 run data get entity @s Pos[2]
```

### 陷阱与注意事项

1. **版本要求**：`data modify ... -=` 算术运算需要 Minecraft 1.20.5+。在 1.20.4 及以下版本，只能使用方案一（记分板）或方案三（手动计算）。

2. **精度**：storage 可以存储 double 类型，因此可以保留小数精度。但 `data get` 默认返回 double，`store result` 的 scale 参数可以控制精度。

3. **storage 初始化**：需要确保 storage 中的数组已正确初始化，否则 `data modify` 可能失败。

## 方案三：使用 `execute positioned` + `distance` 谓词（仅限距离计算）

### 原理

如果只需要计算距离（而非具体坐标差值），可以使用 `execute positioned` 配合 `distance` 谓词来检测玩家与某个位置的距离范围。但这只能得到距离，不能得到方向。

### 完整代码

```mcfunction
# 检测玩家是否在世界坐标 (100, 64, 200) 的 5 格范围内
execute as @p at @s positioned 100 64 200 if entity @s[distance=..5] run say 我在目标位置附近！
```

### 陷阱与注意事项

1. **局限性**：只能检测距离范围，无法获取具体的 X/Y/Z 偏移量。
2. **适用场景**：适合简单的范围检测，如玩家是否到达某个区域。

## 方案对比

| 方案 | 版本要求 | 精度 | 性能开销 | 适用场景 |
|------|---------|------|---------|---------|
| 方案一（记分板） | 1.13+ | 整数（可放大） | 低（需生成 marker） | 通用，需要整数坐标的场景 |
| 方案二（storage） | 1.20.5+ | 浮点数（高精度） | 低（需生成 marker） | 需要高精度浮点坐标的场景 |
| 方案三（distance） | 1.13+ | 仅距离范围 | 极低 | 仅需检测距离范围的简单场景 |

## 总结

- **推荐方案一**：兼容性最好，适用于绝大多数版本和场景。虽然只能存储整数，但可以通过 scale 参数放大精度。
- **方案二**：如果项目目标版本是 1.20.5+，且需要高精度浮点坐标，推荐使用。
- **方案三**：仅适用于简单的距离检测，不能替代完整的坐标转换。

所有方案都需要生成临时 marker 实体来获取世界坐标位置的精确坐标，这是原版命令系统的限制。如果项目对性能要求极高，可以考虑复用 marker 实体（如使用 `tp` 移动 marker 而非每次生成销毁）。
