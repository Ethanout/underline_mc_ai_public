# 如何做命中反馈

## 一、核心挑战

在 Minecraft 原版数据包中实现“命中反馈”（即玩家攻击实体时触发自定义效果，如粒子、音效、伤害加成等）面临以下挑战：

1. **缺乏直接的“攻击命中”触发器**：原版进度系统没有 `player_hits_entity` 这样的 trigger，只有 `player_killed_entity`（击杀时触发）
2. **需要区分攻击与交互**：玩家右键交互实体也会触发某些检测，需要过滤
3. **版本差异大**：不同版本可用的检测机制完全不同（1.16 vs 1.20.5+）

## 二、方案一：基于伤害统计的轮询检测（1.13+，推荐）

### 原理

利用 `scoreboard` 的 `statistic` 类型追踪 `damage_dealt`（造成伤害）统计值。每个 tick 记录玩家的当前伤害值，与上一 tick 的值比较，若增加则判定为命中。

### 完整实现

#### 1. 初始化 (load.mcfunction)

```mcfunction
# 创建计分板
scoreboard objectives add hit_statistic minecraft.custom:minecraft.damage_dealt
scoreboard objectives add hit_previous dummy
scoreboard objectives add hit_flag dummy

# 初始化所有玩家的上一 tick 值
execute as @a run scoreboard players operation @s hit_previous = @s hit_statistic
```

#### 2. 每 tick 检测 (tick.mcfunction)

```mcfunction
# 对所有在线玩家执行检测
execute as @a run function namespace:hit/check
```

#### 3. 检测函数 (namespace:function/hit/check.mcfunction)

```mcfunction
# 计算当前伤害值 - 上一 tick 伤害值
scoreboard players operation @s hit_flag = @s hit_statistic
scoreboard players operation @s hit_flag -= @s hit_previous

# 如果差值 > 0，说明造成了伤害（命中了实体）
execute if score @s hit_flag matches 1.. run function namespace:hit/on_hit

# 更新上一 tick 值
scoreboard players operation @s hit_previous = @s hit_statistic
```

#### 4. 命中回调函数 (namespace:function/hit/on_hit.mcfunction)

```mcfunction
# 示例：在玩家位置生成粒子
particle minecraft:crit ~ ~1 ~ 0.5 0.5 0.5 0.1 10

# 示例：播放音效
playsound minecraft:entity.player.attack.crit player @s ~ ~ ~ 1 1

# 示例：对最近被攻击的实体施加效果（需配合其他检测）
# 注意：这里无法直接获取被攻击的实体，需要额外方案
```

### 陷阱与注意事项

1. **无法获取被攻击的实体**：此方案只能知道玩家造成了伤害，但不知道打中了谁。如果需要针对特定实体做反馈（如对目标施加药水效果），需要配合其他检测（如方案二或三）
2. **延迟问题**：伤害统计值在 tick 结束时更新，因此检测有 1 tick 的延迟
3. **多段伤害**：如果一次攻击造成多次伤害（如横扫之刃），`hit_flag` 可能大于 1，需要根据需求处理
4. **远程攻击**：弓箭、三叉戟等远程武器也会增加 `damage_dealt` 统计，如果需要区分近战/远程，需要额外判断
5. **创造模式**：创造模式下攻击实体不会造成伤害，因此此方案在创造模式下无效

## 三、方案二：基于实体交互的进度检测（1.16+，可获取目标实体）

### 原理

利用进度系统监听 `player_interacted_with_entity` 触发器和 `player_hurt_entity` 触发器（⚠️ 需验证：`player_hurt_entity` 是 1.16 引入的？实际测试发现 1.16.5 中不存在此 trigger，1.17+ 才可用）。

**注意**：`player_interacted_with_entity` 在右键交互时也会触发，需要过滤。

### 完整实现

#### 1. 进度定义 (namespace:advancement/hit_detect.json)

```json
{
  "criteria": {
    "hit_entity": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {
        "entity": {
          "type": "#minecraft:enemy"
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:hit/on_hit"
  }
}
```

#### 2. 命中回调函数 (namespace:function/hit/on_hit.mcfunction)

```mcfunction
# 此函数在玩家命中实体时自动执行
# 可以通过 advancement 的 conditions 获取实体信息

# 示例：在目标实体位置生成粒子
execute at @e[type=#minecraft:enemy,sort=nearest,limit=1] run particle minecraft:crit ~ ~1 ~ 0.5 0.5 0.5 0.1 10

# 示例：对目标施加效果
effect give @e[type=#minecraft:enemy,sort=nearest,limit=1] minecraft:slowness 3 1

# 撤销进度以便下次触发
advancement revoke @s only namespace:hit_detect
```

### 陷阱与注意事项

1. **`player_hurt_entity` 的版本问题**：此 trigger 在 1.16.5 中不存在，1.17+ 才可用。如果需要在 1.16 中使用，请使用方案一
2. **无法精确获取目标**：进度触发时无法直接通过 `@s` 获取被攻击的实体，只能通过 `@e[sort=nearest]` 近似获取，在多实体场景下可能不准确
3. **右键交互误触**：`player_interacted_with_entity` 在右键交互时也会触发，需要额外过滤（如检测玩家主手物品是否为武器）
4. **性能开销**：每次命中都触发进度，如果频率很高（如快速攻击），可能造成性能压力

## 四、方案三：基于伤害吸收实体的精确检测（1.20.5+，最精确）

### 原理

利用 1.20.5 引入的 `damage` 组件和 `area_effect_cloud` 实体。在玩家攻击时生成一个临时的 AEC，AEC 的 `damage` 组件会检测实体受伤事件，从而实现精确的命中反馈。

### 完整实现

#### 1. 玩家攻击检测（通过方案一或二检测到攻击时触发）

```mcfunction
# 在玩家位置生成一个 AEC，用于检测伤害
execute at @s run summon minecraft:area_effect_cloud ~ ~ ~ {Duration:1,Radius:0f,WaitTime:0}
```

#### 2. AEC 的伤害检测（通过 advancement 监听）

```json
{
  "criteria": {
    "entity_hurt": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "direct_entity": {
              "type": "minecraft:area_effect_cloud"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:hit/on_hit_precise"
  }
}
```

### 陷阱与注意事项

1. **版本要求严格**：此方案仅适用于 1.20.5+，且需要理解 `damage` 组件的新机制
2. **AEC 的生存时间**：AEC 的 `Duration` 和 `WaitTime` 需要精确控制，否则可能检测不到或误检测
3. **复杂度高**：相比前两种方案，此方案实现复杂，且需要处理 AEC 的清理
4. **⚠️ 需验证**：`entity_hurt_player` trigger 是否能检测到 AEC 造成的伤害？实际测试中可能需要使用 `entity_hurt_entity` 或其他 trigger

## 五、方案对比

| 方案 | 版本要求 | 可获取目标实体 | 延迟 | 性能开销 | 适用场景 |
|------|---------|---------------|------|---------|---------|
| 方案一：伤害统计轮询 | 1.13+ | ❌ | 1 tick | 低 | 通用命中反馈，不需要知道打中谁 |
| 方案二：进度检测 | 1.17+ | ⚠️ 近似 | 0 tick | 中 | 需要知道目标类型，可接受近似定位 |
| 方案三：AEC 伤害检测 | 1.20.5+ | ✅ 精确 | 0 tick | 高 | 需要精确获取被攻击实体 |

## 六、最佳实践建议

1. **通用场景**：使用方案一（伤害统计轮询），配合 `@e[sort=nearest,limit=1]` 近似获取目标
2. **需要精确目标**：使用方案二（进度检测），但注意版本限制
3. **1.20.5+ 且需要极高精度**：尝试方案三（AEC 检测），但需充分测试
4. **性能优化**：将检测频率降低到每 2-3 tick 一次，或使用 `schedule` 延迟处理

## 七、完整示例：综合方案（1.17+）

结合方案一和方案二，实现既能检测命中又能获取目标的系统：

### 1. 初始化 (load.mcfunction)

```mcfunction
scoreboard objectives add hit_statistic minecraft.custom:minecraft.damage_dealt
scoreboard objectives add hit_previous dummy
scoreboard objectives add hit_flag dummy
execute as @a run scoreboard players operation @s hit_previous = @s hit_statistic
```

### 2. 进度定义 (namespace:advancement/hit_detect.json)

```json
{
  "criteria": {
    "hit_entity": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "namespace:hit/on_hit_advancement"
  }
}
```

### 3. 命中回调 (namespace:function/hit/on_hit_advancement.mcfunction)

```mcfunction
# 存储被攻击实体的 UUID 到 storage
execute store result storage namespace:hit target_id int 1 run data get entity @e[type=!minecraft:player,sort=nearest,limit=1] UUID[0]

# 执行通用命中反馈
function namespace:hit/on_hit_common

# 撤销进度
advancement revoke @s only namespace:hit_detect
```

### 4. 通用命中反馈 (namespace:function/hit/on_hit_common.mcfunction)

```mcfunction
# 粒子效果
particle minecraft:crit ~ ~1 ~ 0.5 0.5 0.5 0.1 10

# 音效
playsound minecraft:entity.player.attack.crit player @s ~ ~ ~ 1 1

# 对目标施加效果（如果有存储的 UUID）
execute if data storage namespace:hit {target_id:1} run effect give @e[type=!minecraft:player,sort=nearest,limit=1] minecraft:slowness 3 1
```

### 5. 每 tick 检测 (tick.mcfunction)

```mcfunction
execute as @a run function namespace:hit/check
```

### 6. 统计检测 (namespace:function/hit/check.mcfunction)

```mcfunction
scoreboard players operation @s hit_flag = @s hit_statistic
scoreboard players operation @s hit_flag -= @s hit_previous
execute if score @s hit_flag matches 1.. run function namespace:hit/on_hit_statistic
scoreboard players operation @s hit_previous = @s hit_statistic
```

### 7. 统计命中回调 (namespace:function/hit/on_hit_statistic.mcfunction)

```mcfunction
# 清除 storage 中的目标 ID（因为统计检测无法获取目标）
data remove storage namespace:hit target_id

# 执行通用命中反馈
function namespace:hit/on_hit_common
```

## 八、陷阱总结

1. **版本兼容性**：`player_hurt_entity` trigger 在 1.16.5 中不存在，1.17+ 才可用
2. **目标获取不精确**：使用 `@e[sort=nearest]` 在多实体场景下可能获取到错误的目标
3. **创造模式无效**：方案一在创造模式下无法工作
4. **远程攻击混淆**：方案一无法区分近战和远程攻击
5. **性能开销**：高频攻击时，进度触发和函数调用可能造成性能压力
6. **AEC 清理**：方案三需要确保 AEC 被及时清理，否则会残留
