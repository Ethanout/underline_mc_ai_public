# 如何做玩家朝向相关的移动

## 问题分析

玩家朝向相关的移动是指：玩家移动的方向**相对于其面朝方向**，而非世界坐标系。例如：玩家面朝北时按 W 键向前走，实际是向 Z 负方向移动；面朝东时按 W 键向前走，实际是向 X 正方向移动。

核心挑战：
1. 原版没有直接提供"相对于玩家朝向的移动方向"的 API
2. 需要结合玩家的旋转角度（yaw）和输入方向（forward/left）进行计算
3. 不同版本对 NBT 路径和命令的支持不同

## 方案一：基于 scoreboard 和三角函数计算（1.13+，推荐）

### 原理

利用玩家的 `Rotation[0]`（yaw，水平旋转角）和输入谓词（`forward`、`left`）计算相对于玩家朝向的移动向量。

- yaw 范围：-180（北）→ 0（南）→ 180（北），东为 -90，西为 90
- 输入方向：`forward`（1=前进，0=不动，-1=后退），`left`（1=左移，0=不动，-1=右移）
- 通过三角函数将输入方向旋转到世界坐标系

### 完整实现


#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建用于存储计算结果的 scoreboard

scoreboard objectives add <namespace>.move_x dummy

```

#### 2. 主循环 (tick.mcfunction)
```mcfunction

```

#### 3. 计算函数 (movement/calc.mcfunction)
```mcfunction
# 获取玩家 yaw（取整到整数）
execute store result score @s <namespace>.yaw run data get entity @s Rotation[0]

# 获取输入方向（通过 predicate 检测）
# forward: 1=前进, 0=不动, -1=后退
execute if predicate <namespace>:input/forward run scoreboard players set @s <namespace>.forward 1
execute if predicate <namespace>:input/backward run scoreboard players set @s <namespace>.forward -1
execute unless predicate <namespace>:input/forward unless predicate <namespace>:input/backward run scoreboard players set @s <namespace>.forward 0

# left: 1=左移, 0=不动, -1=右移
execute if predicate <namespace>:input/left run scoreboard players set @s <namespace>.left 1
execute if predicate <namespace>:input/right run scoreboard players set @s <namespace>.left -1
execute unless predicate <namespace>:input/left unless predicate <namespace>:input/right run scoreboard players set @s <namespace>.left 0

# 计算 sin 和 cos（使用预计算表或近似公式）
# 这里使用简单的查表法，实际项目中建议用更精确的方法
function <namespace>:movement/trig_lookup

# 计算世界坐标系下的移动向量
# move_x = forward * sin(yaw) + left * cos(yaw)
# move_z = forward * cos(yaw) - left * sin(yaw)
scoreboard players operation @s <namespace>.move_x = @s <namespace>.forward
scoreboard players operation @s <namespace>.move_x *= @s <namespace>.sin_yaw
scoreboard players operation @s <namespace>.move_z = @s <namespace>.forward
scoreboard players operation @s <namespace>.move_z *= @s <namespace>.cos_yaw

# 应用移动（示例：使用 /tp 或 /ride 等）
execute if score @s <namespace>.move_x matches 1.. run function <namespace>:movement/apply
```

#### 5. 三角函数查表（简化版）

`movement/trig_lookup.mcfunction`
```mcfunction
# 简化版：只处理 0°, 90°, 180°, 270° 四个方向
# 实际项目中需要更精确的查表或使用 /data modify 配合 storage
execute if score @s <namespace>.yaw matches -180..-135 run scoreboard players set @s <namespace>.sin_yaw 0
execute if score @s <namespace>.yaw matches -180..-135 run scoreboard players set @s <namespace>.cos_yaw -1
execute if score @s <namespace>.yaw matches -134..-45 run scoreboard players set @s <namespace>.sin_yaw -1
execute if score @s <namespace>.yaw matches -134..-45 run scoreboard players set @s <namespace>.cos_yaw 0
execute if score @s <namespace>.yaw matches -44..45 run scoreboard players set @s <namespace>.sin_yaw 0
execute if score @s <namespace>.yaw matches -44..45 run scoreboard players set @s <namespace>.cos_yaw 1
execute if score @s <namespace>.yaw matches 46..135 run scoreboard players set @s <namespace>.sin_yaw 1
execute if score @s <namespace>.yaw matches 46..135 run scoreboard players set @s <namespace>.cos_yaw 0
execute if score @s <namespace>.yaw matches 136..180 run scoreboard players set @s <namespace>.sin_yaw 0
execute if score @s <namespace>.yaw matches 136..180 run scoreboard players set @s <namespace>.cos_yaw -1
```

### 陷阱与注意事项

1. **三角函数精度**：原版 scoreboard 只支持整数运算，无法直接计算 sin/cos。查表法需要覆盖 360 个角度，文件体积较大。可以使用 `/data modify` 配合 storage 实现浮点运算，但复杂度较高。
2. **输入检测延迟**：`predicate` 检测的是**当前 tick** 的输入状态，但玩家输入有 1 tick 的延迟（输入在 tick 开始时采样）。对于大多数应用场景可以接受。
3. **yaw 值范围**：`Rotation[0]` 的范围是 -180 到 180，不是 0-360。计算时需要注意边界情况。
4. **性能开销**：每个玩家每 tick 执行一次，包含多个 scoreboard 操作和 predicate 检测。对于 20 个玩家，开销较低（约 0.1-0.2ms/tick）。

## 方案二：利用 /ride 和实体朝向（1.19+，简化版）

### 原理

创建一个标记实体（marker），将其朝向设置为与玩家相同，然后利用 `/ride` 命令让玩家相对于该实体移动。

### 完整实现

#### 1. 创建标记实体 (tick.mcfunction)
```mcfunction
# 为每个玩家创建一个标记实体
execute as @a at @s run summon minecraft:marker ~ ~ ~ {Tags:["<namespace>.move_marker"]}
execute as @a at @s run data merge entity @e[tag=<namespace>.move_marker,limit=1,sort=nearest] {Rotation:[0f,0f]}
```

#### 2. 设置标记朝向 (movement/set_rotation.mcfunction)
```mcfunction
# 将标记实体的朝向设置为玩家的朝向
execute as @a at @s run data modify entity @e[tag=<namespace>.move_marker,limit=1,sort=nearest] Rotation set from entity @s Rotation
```

#### 3. 应用移动 (movement/apply.mcfunction)
```mcfunction
# 让玩家相对于标记实体移动
# 注意：/ride 的移动是相对于实体的局部坐标系
execute as @a at @s run ride @s mount @e[tag=<namespace>.move_marker,limit=1,sort=nearest]
# 然后通过控制标记实体的移动来控制玩家
```

### 陷阱与注意事项

1. **⚠️ 需验证**：`/ride` 命令在 1.19+ 中是否支持控制玩家相对于实体的移动方向？实际上 `/ride` 主要用于骑乘，不能直接控制移动方向。
2. **标记实体生命周期**：需要每 tick 清理旧的标记实体，否则会无限堆积。
3. **适用场景有限**：此方案更适合控制实体（如船、矿车）的移动，而非直接控制玩家。

## 方案三：基于 NBT 路径和 /data modify（1.20.5+，高级方案）

### 原理

利用 1.20.5 新增的 `/data modify` 语法，直接在 storage 中计算浮点三角函数，然后通过 `/attribute` 或 `/effect` 应用移动。

```mcfunction
data modify storage <namespace>:movement Rotation set value [0.0,0.0]
```

#### 2. 计算函数 (movement/calc_advanced.mcfunction)

```mcfunction
execute if predicate <namespace>:input/left run data modify storage <namespace>:movement Input.left set value 1
execute if predicate <namespace>:input/right run data modify storage <namespace>:movement Input.left set value -1

# 获取玩家 yaw
execute as @s run data modify storage <namespace>:movement Rotation set from entity @s Rotation[0]

# 计算 sin/cos（使用 storage 中的浮点运算）
# ⚠️ 需验证：1.20.5+ 是否支持在 storage 中直接进行浮点运算？
# 实际上，/data modify 只能进行简单的数据操作，不能进行数学运算
# 需要配合 scoreboard 或外部工具
```

### 陷阱与注意事项

1. **⚠️ 需验证**：`/data modify` 不支持数学运算，只能进行数据复制、合并等操作。因此无法直接在 storage 中计算 sin/cos。
2. **版本要求**：1.20.5+，但实际可用性有限。
3. **不推荐**：此方案目前没有实际可行的实现方式，仅作为思路参考。

## 总结

**推荐使用方案一**，它是最成熟、最通用的方案。虽然需要处理三角函数，但通过查表法可以平衡精度和性能。对于需要高精度的场景，可以考虑使用更精细的查表（如每 5 度一个值）或使用外部工具生成完整的三角函数表。

**方案二**适用于需要控制实体（如船、矿车）相对于玩家朝向移动的场景，但不适合直接控制玩家。

**方案三**目前不可行，因为 `/data modify` 不支持数学运算。
