# 如何制作血条能量条耐力条

## 核心挑战

Minecraft 原版没有内置的 HUD 扩展系统，无法直接绘制自定义 UI 元素。制作血条/能量条/耐力条的核心挑战在于：

1. **无原生 UI 支持**：原版只能通过 bossbar、经验条、副手物品提示等有限渠道显示数值
2. **实时性要求**：血条需要每 tick 更新，对性能敏感
3. **视觉反馈**：需要让玩家直观感知数值变化，不能只靠记分板数字

## 方案一：Bossbar 血条（推荐，1.11+）

### 原理

利用 `bossbar` 系统创建自定义血条。每个玩家可以拥有独立的 bossbar，通过 `minecraft:bossbar` 命名空间管理。Bossbar 支持设置最大/当前值、颜色、分段样式，且客户端渲染开销极低。

### 完整实现

#### 1. 初始化（load 函数）

```mcfunction
# load.mcfunction
# 为每个玩家创建独立的 bossbar
scoreboard objectives add health_dummy dummy
scoreboard objectives add max_health dummy

# 创建 bossbar 模板（实际使用时动态设置）
bossbar add <namespace>:health "❤️ 生命值"
bossbar set <namespace>:health color red
bossbar set <namespace>:health style notched_10
bossbar set <namespace>:health max 100
```

#### 2. 每 tick 更新（tick.mcfunction）

```mcfunction
# tick.mcfunction
execute as @a run function <namespace>:player/update_health
```

#### 3. 玩家更新函数

```mcfunction
# <namespace>/function/player/update_health.mcfunction
# 获取玩家当前生命值（0-20，但可以扩展）
execute store result score @s health_dummy run data get entity @s Health 100

# 将生命值映射到 bossbar（假设 max=100）
bossbar set <namespace>:health value @s health_dummy

# 显示给对应玩家
bossbar set <namespace>:health players @s
```

#### 4. 扩展为能量条（示例：耐力值）

```mcfunction
# 创建耐力值记分板
scoreboard objectives add stamina dummy
scoreboard objectives add max_stamina dummy

# 初始化耐力值
scoreboard players set @a stamina 100
scoreboard players set @a max_stamina 100

# 创建耐力 bossbar
bossbar add <namespace>:stamina "⚡ 耐力"
bossbar set <namespace>:stamina color yellow
bossbar set <namespace>:stamina style notched_6
bossbar set <namespace>:stamina max 100
```

```mcfunction
# 每 tick 更新耐力
# <namespace>/function/player/update_stamina.mcfunction
bossbar set <namespace>:stamina value @s stamina
bossbar set <namespace>:stamina players @s
```

### 陷阱与注意事项

1. **Bossbar 数量限制**：每个玩家同时可见的 bossbar 数量有限（约 10 个），超过后新 bossbar 不会显示
2. **Bossbar 名称**：名称会显示在 bossbar 上方，如果不想显示文字，可以设置为空格（`" "`），但会占用一行空间
3. **多玩家场景**：每个玩家需要独立的 bossbar ID，否则所有玩家共享同一个 bossbar
4. **性能**：每 tick 更新 bossbar 的开销极低（约 0.01ms/玩家），适合高频使用
5. **版本兼容**：bossbar 系统从 1.11 引入，所有现代版本都支持

## 方案二：经验条血条（1.0+）

### 原理

利用原版经验条（Experience Bar）显示自定义数值。通过修改玩家的 `XpLevel` 和 `XpProgress` 来控制经验条的显示。经验条有 18 个分段，适合显示 0-18 的数值。

### 完整实现

#### 1. 初始化

```mcfunction
# load.mcfunction
scoreboard objectives add xp_display dummy
scoreboard objectives add xp_max dummy

# 设置经验等级上限（控制分段数量）
scoreboard players set @a xp_max 10
```

#### 2. 每 tick 更新

```mcfunction
# tick.mcfunction
execute as @a run function <namespace>:player/update_xp_bar
```

```mcfunction
# <namespace>/function/player/update_xp_bar.mcfunction
# 假设血量为 0-20，映射到 0-10 级
scoreboard players operation @s xp_display = @s health_dummy
scoreboard players operation @s xp_display /= @s xp_max

# 设置经验等级
xp set @s levels @s xp_display

# 设置经验进度（小数部分，控制分段填充）
# 注意：xp progress 范围 0.0-1.0
execute store result score @s xp_progress run data get entity @s Health 10
# 这里需要更复杂的映射，略
```

### 陷阱与注意事项

1. **经验条被占用**：如果玩家同时需要显示真实经验值（如附魔），此方案会冲突
2. **视觉精度低**：经验条只有 18 个分段，无法精确显示 0-100 的数值
3. **等级音效**：每次升级会播放音效，需要禁用（通过 `gamerule doLimitedCrafting` 无法阻止）
4. **版本兼容**：所有版本都支持，但 1.20.5 后 `xp` 命令语法有变化

## 方案三：副手物品耐久条（1.9+）

### 原理

利用副手物品的耐久度显示。当玩家副手持有一个可损坏物品时，物品栏会显示该物品的耐久条。通过修改物品的 `Damage` 组件来控制耐久条显示。

### 完整实现

#### 1. 给副手物品设置自定义耐久

```mcfunction
# 给玩家副手一个自定义物品（如木剑），并设置耐久
give @s minecraft:wooden_sword{<namespace>:{stamina:1}} 1

# 或者使用 item modifier 修改现有物品
# <namespace>/item_modifier/set_stamina_bar.json
{
    "function": "minecraft:set_components",
    "components": {
        "minecraft:max_damage": 100,
        "minecraft:damage": 0,
        "minecraft:custom_data": {
            "<namespace>": {
                "is_stamina_bar": true
            }
        }
    }
}
```

#### 2. 每 tick 更新耐久值

```mcfunction
# tick.mcfunction
execute as @a at @s run function <namespace>:player/update_stamina_bar
```

```mcfunction
# <namespace>/function/player/update_stamina_bar.mcfunction
# 假设 stamina 记分板值为 0-100
# 计算 damage = max_damage - stamina
scoreboard players operation @s stamina_damage = @s max_stamina
scoreboard players operation @s stamina_damage -= @s stamina

# 更新副手物品的 damage 组件
item modify entity @s weapon.offhand <namespace>:set_stamina_damage
```

```json
// <namespace>/item_modifier/set_stamina_damage.json
{
    "function": "minecraft:set_components",
    "components": {
        "minecraft:damage": {
            "type": "minecraft:score",
            "target": "this",
            "score": "stamina_damage"
        }
    }
}
```

### 陷阱与注意事项

1. **物品必须可损坏**：只有具有 `max_damage` 组件的物品才能显示耐久条
2. **副手物品被占用**：玩家无法同时使用副手物品（如盾牌）
3. **耐久条颜色固定**：无法自定义颜色，始终为灰白渐变
4. **物品消失风险**：当 `damage >= max_damage` 时物品会损坏消失，需要特殊处理
5. **版本要求**：1.20.5+ 才支持 `set_components` 函数，旧版本需要使用 NBT 修改

## 方案四：Actionbar 文本显示（1.0+）

### 原理

利用 `/title` 命令的 `actionbar` 子命令，在玩家屏幕底部显示文本。可以配合 Unicode 字符（如 ██）制作简单的进度条。

### 完整实现

#### 1. 每 tick 更新 actionbar

```mcfunction
# tick.mcfunction
execute as @a run function <namespace>:player/update_actionbar
```

```mcfunction
# <namespace>/function/player/update_actionbar.mcfunction
# 假设 health 记分板值为 0-20
# 生成进度条文本（10 格）
scoreboard players operation @s health_bar = @s health_dummy
scoreboard players operation @s health_bar *= @s ten_const
scoreboard players operation @s health_bar /= @s max_health

# 使用 tellraw 或 title 显示
# 注意：actionbar 文本长度有限制（约 30 字符）
title @s actionbar [{"text":"❤️ ","color":"red"},{"text":"██████████","color":"dark_red","font":"minecraft:uniform"}]
```

#### 2. 使用 Unicode 字符制作进度条

```mcfunction
# 更精确的进度条（使用 Unicode 块字符）
# █ = U+2588, ▉ = U+2589, ... ▏ = U+258F
# 可以精确到 1/8 格

# 示例：显示 75% 血量的进度条
# 需要复杂的字符串拼接，建议使用 storage 和 data modify
data modify storage <namespace>:actionbar text set value '[{"text":"❤️ ","color":"red"},{"text":"████████","color":"dark_red"},{"text":"██","color":"gray"}]'
title @s actionbar @s <namespace>:actionbar.text
```

### 陷阱与注意事项

1. **文本长度限制**：Actionbar 最多显示约 30 个字符，超出会被截断
2. **性能开销**：每 tick 执行 `title` 命令的开销中等（约 0.05ms/玩家）
3. **视觉干扰**：会覆盖其他插件/模组的 actionbar 信息
4. **Unicode 兼容性**：部分字体可能不显示块字符，建议使用 `minecraft:uniform` 字体
5. **版本兼容**：所有版本都支持，但 1.20.5 后 JSON 文本格式有变化

## 方案对比

| 方案 | 版本要求 | 性能开销 | 视觉精度 | 适用场景 | 主要缺点 |
|------|---------|---------|---------|---------|---------|
| Bossbar | 1.11+ | 极低 | 高（6/10/12段） | 主血条、能量条 | 数量有限，占用屏幕空间 |
| 经验条 | 1.0+ | 低 | 低（18段） | 简单数值显示 | 与真实经验冲突，有音效 |
| 副手耐久 | 1.9+（1.20.5+最佳） | 低 | 中（0-100） | 耐力条、护盾值 | 占用副手，物品可能损坏 |
| Actionbar | 1.0+ | 中 | 高（自定义） | 临时提示、精确数值 | 文本长度限制，覆盖其他信息 |

## 推荐组合方案

对于完整的血条+能量条+耐力条系统，推荐：

1. **主血条**：Bossbar（红色，notched_10）
2. **能量条**：Bossbar（蓝色，notched_6）或 Actionbar（节省 bossbar 数量）
3. **耐力条**：副手物品耐久条（如果玩家不需要副手）或 Actionbar

## 陷阱总结

1. **Bossbar 数量限制**：每个玩家最多可见约 10 个 bossbar，超过后不显示
2. **经验条音效**：无法完全禁用升级音效，建议使用 `gamerule doMobLoot false` 无效
3. **副手物品损坏**：当 `damage >= max_damage` 时物品消失，需要设置 `max_damage` 为足够大
4. **Actionbar 覆盖**：多个数据包同时使用 actionbar 会互相覆盖
5. **性能权衡**：每 tick 更新所有玩家的所有条，100 玩家时可能达到 1ms+，建议使用 `schedule` 降低频率
