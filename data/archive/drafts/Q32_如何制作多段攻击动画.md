# 如何制作多段攻击动画

## 核心挑战

在 Minecraft 原版数据包中制作多段攻击动画（如：轻击→重击→突刺，每段有不同伤害、特效和冷却时间）面临以下挑战：

1. **原版没有“攻击阶段”概念**——玩家攻击只有“开始攻击”和“攻击结束”两个状态
2. **攻击冷却机制**——1.9+ 的攻击冷却系统会重置攻击动画
3. **玩家输入检测有限**——无法直接检测“攻击键按下”事件，只能通过 `player_hurt_entity` 等触发器间接判断
4. **动画帧同步**——多段攻击需要精确的计时和状态机管理

## 方案一：基于计分板状态机 + 攻击触发器（推荐，1.16+）

### 原理

利用 `player_hurt_entity` 进度作为攻击触发信号，配合计分板维护攻击阶段状态机。每次攻击推进一个阶段，通过 `schedule` 或 `tick` 函数控制阶段超时重置。

### 完整实现

#### 目录结构
```
data/
  namespace/
    advancement/
      attack_detect.json
    function/
      attack/
        init.mcfunction
        tick.mcfunction
        stage_1.mcfunction
        stage_2.mcfunction
        stage_3.mcfunction
        reset.mcfunction
      load.mcfunction
    predicate/
      is_attacking.json
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建计分板
scoreboard objectives add attack_stage dummy
scoreboard objectives add attack_cooldown dummy

# 初始化所有玩家
execute as @a run function namespace:attack/init
```

#### 2. 玩家初始化 (attack/init.mcfunction)
```mcfunction
# 设置初始阶段为0（未攻击）
scoreboard players set @s attack_stage 0
scoreboard players set @s attack_cooldown 0
```

#### 3. 攻击检测进度 (advancement/attack_detect.json)
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:player_hurt_entity",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "namespace:attack/tick"
  }
}
```

#### 4. 攻击状态机 (attack/tick.mcfunction)
```mcfunction
# 检查当前阶段并推进
execute if score @s attack_stage matches 0 run function namespace:attack/stage_1
execute if score @s attack_stage matches 1 run function namespace:attack/stage_2
execute if score @s attack_stage matches 2 run function namespace:attack/stage_3

# 重置进度以便下次触发
advancement revoke @s only namespace:attack_detect
```

#### 5. 各阶段函数

**stage_1.mcfunction**（轻击）
```mcfunction
# 设置阶段
scoreboard players set @s attack_stage 1

# 设置冷却时间（20 ticks = 1秒）
scoreboard players set @s attack_cooldown 20

# 执行轻击效果
particle minecraft:crit @s ~ ~1 ~ 0.5 0.5 0.5 0.1 10
playsound minecraft:entity.player.attack.knockback player @a ~ ~ ~ 1 1.5

# 伤害逻辑（通过属性修饰符或直接伤害）
execute as @e[type=!player,distance=..3,limit=1] at @s run damage @s 4 minecraft:player_attack by @p
```

**stage_2.mcfunction**（重击）
```mcfunction
# 设置阶段
scoreboard players set @s attack_stage 2

# 设置冷却时间（30 ticks = 1.5秒）
scoreboard players set @s attack_cooldown 30

# 执行重击效果
particle minecraft:explosion @s ~ ~1 ~ 1 1 1 0.1 20
playsound minecraft:entity.player.attack.crit player @a ~ ~ ~ 1 0.8

# 伤害逻辑
execute as @e[type=!player,distance=..4,limit=1] at @s run damage @s 8 minecraft:player_attack by @p
```

**stage_3.mcfunction**（突刺）
```mcfunction
# 设置阶段
scoreboard players set @s attack_stage 3

# 设置冷却时间（40 ticks = 2秒）
scoreboard players set @s attack_cooldown 40

# 执行突刺效果
particle minecraft:sweep_attack @s ~ ~1 ~ 2 0.5 2 0.1 30
playsound minecraft:entity.player.attack.sweep player @a ~ ~ ~ 1 0.6

# 伤害逻辑（范围伤害）
execute as @e[type=!player,distance=..5,limit=3] at @s run damage @s 12 minecraft:player_attack by @p

# 突刺后重置到阶段0
scoreboard players set @s attack_stage 0
```

#### 6. 冷却计时 (tick.mcfunction)
```mcfunction
# 每秒执行一次（在服务器tick函数中调用）
scoreboard players remove @a[scores={attack_cooldown=1..}] attack_cooldown 1

# 冷却结束后重置阶段
execute as @a[scores={attack_cooldown=0}] run scoreboard players set @s attack_stage 0
```

#### 7. 重置函数 (attack/reset.mcfunction)
```mcfunction
# 强制重置攻击状态
scoreboard players set @s attack_stage 0
scoreboard players set @s attack_cooldown 0
```

### 陷阱与注意事项

1. **攻击检测延迟**：`player_hurt_entity` 在攻击命中时触发，不是攻击键按下时。如果玩家挥空（未命中实体），不会触发进度，导致攻击阶段无法推进。
   - **解决方案**：配合 `minecraft:entity_hurt_player` 进度检测被攻击，或使用 `inventory_changed` 检测攻击冷却变化（1.20.5+）

2. **多实体攻击**：如果一次攻击命中多个实体，进度会触发多次，导致阶段跳跃。
   - **解决方案**：在 `attack/tick.mcfunction` 开头添加阶段锁定检查：
   ```mcfunction
   # 如果冷却未结束，不推进阶段
   execute if score @s attack_cooldown matches 1.. run return
   ```

3. **攻击冷却重置**：原版攻击冷却系统会重置攻击动画，可能导致阶段显示异常。
   - **解决方案**：使用 `attribute @s minecraft:attack_speed base set 1024` 禁用原版攻击冷却（1.16+），完全由数据包控制

4. **玩家死亡/重生**：死亡后计分板状态保留，但攻击进度被撤销。
   - **解决方案**：在 `minecraft:entity_died` 进度中调用 `attack/reset.mcfunction`

## 方案二：基于攻击冷却检测（1.20.5+，更精确）

### 原理

1.20.5 引入了 `minecraft:attack` 组件，可以通过 `inventory_changed` 进度检测玩家攻击冷却的变化。攻击冷却在攻击后重置为 0，然后逐渐恢复。通过检测冷却值的变化可以精确判断攻击事件。

### 完整实现

#### 1. 攻击冷却检测进度 (advancement/attack_cool_detect.json)
```json
{
  "criteria": {
    "attack": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "player": {
          "nbt": "{AttackCool:0f}"
        }
      }
    }
  },
  "rewards": {
    "function": "namespace:attack/on_attack"
  }
}
```

⚠️ **需验证**：`AttackCool` NBT 路径在 1.20.5+ 中是否可被 `inventory_changed` 检测到。根据 Minecraft Wiki，`AttackCool` 是玩家 NBT 的一部分，但 `inventory_changed` 触发器可能不检测玩家 NBT 变化。

#### 2. 攻击处理函数 (attack/on_attack.mcfunction)
```mcfunction
# 推进攻击阶段
execute if score @s attack_stage matches 0 run function namespace:attack/stage_1
execute if score @s attack_stage matches 1 run function namespace:attack/stage_2
execute if score @s attack_stage matches 2 run function namespace:attack/stage_3

# 重置进度
advancement revoke @s only namespace:attack_cool_detect
```

### 陷阱与注意事项

1. **NBT 检测可靠性**：`AttackCool` 在玩家攻击后立即变为 0，但 `inventory_changed` 触发条件可能不包含玩家 NBT 变化。如果无效，请回退到方案一。

2. **版本要求**：仅 1.20.5+，且需要验证 `AttackCool` 的可检测性。

## 方案三：基于计时器 + 玩家动作谓词（1.19.4+，无实体依赖）

### 原理

使用 `minecraft:tick` 函数每 tick 检测玩家的攻击状态。通过 `predicate` 中的 `player` 条件检测玩家是否正在攻击（`attacking` 字段），结合计时器实现多段攻击。

### 完整实现

#### 1. 攻击状态谓词 (predicate/is_attacking.json)
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "player": {
      "attacking": true
    }
  }
}
```

⚠️ **需验证**：`player.attacking` 字段在 1.19.4+ 中是否可用。根据 Minecraft Wiki，该字段在 `player` 谓词中存在，但实际行为可能不如预期。

#### 2. 主 tick 函数 (tick.mcfunction)
```mcfunction
# 每 tick 检测所有玩家
execute as @a at @s run function namespace:attack/check
```

#### 3. 攻击检测函数 (attack/check.mcfunction)
```mcfunction
# 检测是否正在攻击
execute if predicate namespace:is_attacking run function namespace:attack/on_attack
```

#### 4. 攻击处理 (attack/on_attack.mcfunction)
```mcfunction
# 防止同一 tick 内多次触发
execute if score @s attack_cooldown matches 1.. run return

# 推进阶段
execute if score @s attack_stage matches 0 run function namespace:attack/stage_1
execute if score @s attack_stage matches 1 run function namespace:attack/stage_2
execute if score @s attack_stage matches 2 run function namespace:attack/stage_3

# 设置冷却（防止同一 tick 内重复触发）
scoreboard players set @s attack_cooldown 1
```

### 陷阱与注意事项

1. **性能开销**：每 tick 对所有玩家执行谓词检测，性能开销中等。建议限制检测范围（如 `@a[scores={attack_stage=0..}]`）。

2. **攻击状态延迟**：`attacking` 字段可能在攻击动画开始后才有变化，存在 1-2 tick 的延迟。

3. **空手攻击**：空手攻击时 `attacking` 字段可能不更新，需要额外检测。

## 方案对比

## 进阶技巧

### 1. 攻击动画同步

使用 `item_modifier` 修改玩家手持物品的 `custom_model_data` 来实现视觉反馈：
```json
{
  "function": "minecraft:set_components",
  "components": {
    "minecraft:custom_model_data": 1
  }
}
```

### 2. 多段攻击冷却管理

使用 `scoreboard` 实现复杂的冷却系统：
```mcfunction
# 阶段1冷却：10 ticks
# 阶段2冷却：15 ticks
# 阶段3冷却：20 ticks

# 在 stage_1.mcfunction 中
scoreboard players set @s attack_cooldown 10

# 在 tick.mcfunction 中
scoreboard players remove @a[scores={attack_cooldown=1..}] attack_cooldown 1
execute as @a[scores={attack_cooldown=0,attack_stage=1..}] run scoreboard players set @s attack_stage 0
```

### 3. 攻击组合技

通过检测攻击间隔实现组合技（如：快速点击3次触发特殊攻击）：
```mcfunction
# 在 attack/tick.mcfunction 中
# 记录上次攻击时间
scoreboard players operation @s last_attack_time = @s attack_time

# 更新攻击时间
scoreboard players set @s attack_time 0

# 检测连续攻击
execute if score @s combo_count matches 2 run function namespace:attack/combo_finish
```

## 总结

- **推荐方案一**：基于状态机 + 攻击触发器，兼容性好，性能开销低
- **方案二**：1.20.5+ 专用，需要验证 NBT 检测可靠性
- **方案三**：无实体依赖，但性能开销中等

核心要点：
1. 使用 `player_hurt_entity` 作为攻击触发信号
2. 用计分板维护攻击阶段状态机
3. 通过 `schedule` 或 `tick` 函数控制阶段超时
4. 考虑空手攻击和挥空攻击
