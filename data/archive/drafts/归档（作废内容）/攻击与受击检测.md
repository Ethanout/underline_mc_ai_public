# 攻击与受击检测

## 进度法（检测玩家受伤）

文件：`data/<namespace>/advancement/<path>.json`

```json
{
  "criteria": {
    "a": {
      "trigger": "minecraft:entity_hurt_player"
    }
  },
  "requirements": [["a"]],
  "rewards": {
    "function": "namespace:atk/player_hurted"
  }
}
```

函数：
```mcfunction
execute at @s run particle explosion
say 我受伤了！
execute on attacker run say 哈哈，是我打的！
advancement revoke @s only namespace:atk/player_hurted
```

### 注意事项
- `execute on attacker` 有约 5 秒（100gt）的记忆残留：先被僵尸打再踩仙人掌，攻击者仍判定为僵尸
- 必须 `advancement revoke`，否则只触发一次
- `@s` 是受害者，`on attacker` 切换到攻击者

## 附魔检测法（检测任意实体受伤/攻击）

利用鞍槽位给实体装自定义附魔作为"攻击传感器"。

### 附魔定义
`data/<namespace>/enchantment/atk/entity_hurted.json`
```json
{
  "effects": {
    "minecraft:post_attack": [
      {
        "affected": "victim",
        "enchanted": "victim",
        "effect": {
          "type": "minecraft:all_of",
          "effects": [
            { "type": "minecraft:run_function", "function": "namespace:atk/entity_hurted" }
          ]
        }
      }
    ]
  },
  "primary_items": "minecraft:saddle",
  "slots": ["any"],
  "supported_items": "minecraft:saddle"
}
```
关键：`enchanted: victim`（受害者身上有附魔时触发），`affected: victim`（对受害者运行函数）

### 实体初始化
```mcfunction
# data/<namespace>/function/atk/setup_mob.mcfunction
data modify entity @s drop_chances.saddle set value 0f
item replace entity @s saddle with saddle[enchantments={"namespace:atk/entity_hurted":1}]
tag @s add has_saddle
```

### tick 给新实体上鞍
```mcfunction
execute as @e[type=!player,tag=!has_saddle] run function namespace:atk/setup_mob
```

### 调试
```mcfunction
tag @e remove has_saddle
item replace entity @e[type=!player] saddle with air
data get entity @n[type=!player] equipment.saddle
```

> 附魔定义不可热重载，需重进世界。

## 高效濒死检测（Hit Match 方案）

> 发现者：picarrow (Hit Match v1.8.0)。对任意活体实体进行高效死亡检测，不依赖进度/标记。

核心思路：在 storage 中用 UUID 追踪实体，按轮询频率分 tick 检查是否即将死亡。实体死亡动画持续 20 tick，因此 20 tick 是最优最大轮询间隔。

```mcfunction
# 注册实体（按需设置轮询频率，默认20t）
data modify storage hitmatch:registry.<uuid> set value {frequency:20,tick:0}

# tick 循环（简化示意）
execute if data storage hitmatch:registry.<uuid> run function hitmatch:poll
```

### 特性
- 可指定不同轮询频率（1~20 tick），实现灵活性与性能平衡
- 负载均衡：不同实体的轮询分散到不同 tick 上
- 支持在濒死实体身份执行命令（在死亡位置执行）
- 支持伤害链中精确选中所有相关实体（伤害来源/直接实体/受害者）
- 自动回收无效 UUID，无内存泄漏

参考：[Hit Match on GitHub](https://github.com/picarrow/hit-match)
