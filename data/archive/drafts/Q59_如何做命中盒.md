# 如何做命中盒（Hitbox / 碰撞箱检测）

## 核心挑战

在 Minecraft 原版数据包中，没有直接的“检测实体A是否与实体B发生碰撞”的 API。命中盒检测的核心挑战在于：

1. **没有碰撞事件**：原版不提供 `on_collision` 或 `on_hit` 触发器
2. **坐标精度问题**：实体位置更新频率（20 tick/s）与碰撞检测精度之间的矛盾
3. **性能开销**：穷举检测所有实体对的开销随实体数量平方增长
4. **版本差异**：1.20.5 前后的 NBT 路径和命令语法有变化

---

## 方案一：基于 `@e` 选择器 + `distance` 的球形检测（最常用）

### 原理

利用 `@e` 选择器的 `distance` 参数，检测以某点为中心、指定半径范围内的实体。这是一种**近似检测**，将实体视为球体（以实体脚部位置为球心）。

### 适用版本
1.13+（所有版本通用）

### 完整代码

#### 1. 检测玩家周围 2 格内的所有实体

```mcfunction
# 检测玩家周围 2 格内的所有实体（不包括玩家自己）
execute as @a at @s run function namespace:hitbox/check
```

`namespace:function/hitbox/check.mcfunction`
```mcfunction
# 检测半径 2 格内的实体
execute as @e[type=!minecraft:player,distance=..2] at @s run function namespace:hitbox/on_hit
```

`namespace:function/hitbox/on_hit.mcfunction`
```mcfunction
# 命中后的逻辑
say 我被命中了！
```

#### 2. 更精确的检测：考虑实体碰撞箱大小

```mcfunction
# 检测玩家周围，半径 = 玩家碰撞箱半宽 + 目标碰撞箱半宽 + 容忍误差
# 玩家碰撞箱：宽 0.6，半宽 0.3
# 目标实体（如僵尸）：宽 0.6，半宽 0.3
# 容忍误差：0.1
# 总半径 = 0.3 + 0.3 + 0.1 = 0.7

execute as @a at @s run function namespace:hitbox/check_precise
```

`namespace:function/hitbox/check_precise.mcfunction`
```mcfunction
# 先存储玩家位置
data modify storage namespace:hitbox player_pos set from entity @s Pos

# 检测半径 0.7 内的实体
execute as @e[type=!minecraft:player,distance=..0.7] at @s run function namespace:hitbox/on_hit_precise
```

### 陷阱与注意事项

1. **精度问题**：`distance` 检测的是**脚部位置**的距离，不是碰撞箱表面的距离。对于大型实体（如铁傀儡，宽 1.4），误差较大。
2. **Y轴问题**：`distance` 是三维距离，但实体脚部位置在 Y 轴上的差异会导致误判。例如：玩家站在地面，目标实体在头顶 2 格处，`distance=..2` 会误判为命中。
3. **性能问题**：`@e[type=!minecraft:player,distance=..2]` 会遍历所有实体，如果实体数量多（>50），性能开销较高。
4. **无法区分命中部位**：无法检测是“头部命中”还是“身体命中”。

## 方案二：基于 `predicate` + `position` 的精确碰撞箱检测（1.20.5+）

### 原理

利用 1.20.5 引入的 `position` predicate，可以检测实体在特定坐标范围内的位置。结合 `execute if predicate` 可以实现更精确的碰撞箱检测。

### 适用版本
1.20.5+

### 完整代码

#### 1. 创建 predicate 文件

`data/namespace/predicate/hitbox/player_hitbox.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "position": {
      "x": {
        "min": -0.3,
        "max": 0.3
      },
      "y": {
        "min": 0.0,
        "max": 1.8
      },
      "z": {
        "min": -0.3,
        "max": 0.3
      }
    }
  }
}
```

#### 2. 检测函数

```mcfunction
# 检测玩家周围 3 格内的实体，并检查是否在玩家碰撞箱内
execute as @a at @s run function namespace:hitbox/check_predicate
```

`namespace:function/hitbox/check_predicate.mcfunction`
```mcfunction
# 存储玩家位置
data modify storage namespace:hitbox/player_pos set from entity @s Pos

# 检测周围实体
execute as @e[type=!minecraft:player,distance=..3] at @s run function namespace:hitbox/check_relative
```

`namespace:function/hitbox/check_relative.mcfunction`
```mcfunction
# 计算相对位置
execute store result score @s hitbox_x run data get entity @s Pos[0]
execute store result score @s hitbox_y run data get entity @s Pos[1]
execute store result score @s hitbox_z run data get entity @s Pos[2]

# 减去玩家位置（假设玩家位置已存储在 scoreboard 中）
scoreboard players operation @s hitbox_x -= @p hitbox_x
scoreboard players operation @s hitbox_y -= @p hitbox_y
scoreboard players operation @s hitbox_z -= @p hitbox_z

# 检查是否在玩家碰撞箱内（简化版：检查相对坐标是否在 [-0.3, 0.3] 范围内）
execute if score @s hitbox_x matches -0.3..0.3 if score @s hitbox_z matches -0.3..0.3 if score @s hitbox_y matches 0..1.8 run function namespace:hitbox/on_hit
```

### 陷阱与注意事项

1. **坐标精度**：`scoreboard` 只能存储整数，无法精确表示小数。需要使用 `data get` 的 scale 参数（如 `data get entity @s Pos[0] 100`）来保留两位小数。
2. **性能开销**：每个 tick 都要计算相对位置，对于大量实体性能开销较大。
3. **版本限制**：仅 1.20.5+ 可用。
4. **碰撞箱形状**：predicate 的 `position` 检测的是**点**是否在范围内，不是碰撞箱重叠。对于大型实体，需要调整检测范围。

## 方案三：基于 `area_effect_cloud` + `execute on` 的精确碰撞检测（1.19+）

### 原理

利用 `area_effect_cloud`（AEC）实体的 `Radius` 属性和 `execute on` 子命令，可以实现精确的碰撞箱检测。AEC 的碰撞箱是球体，通过调整半径可以模拟不同大小的碰撞箱。

### 适用版本
1.19+（`execute on` 在 1.19 引入）

### 完整代码

#### 1. 创建 AEC 并检测碰撞

```mcfunction
# 在玩家位置生成一个 AEC，半径等于玩家碰撞箱半宽
execute as @a at @s run function namespace:hitbox/spawn_aec
```

`namespace:function/hitbox/spawn_aec.mcfunction`
```mcfunction
# 生成 AEC，半径 0.3（玩家半宽），持续时间 1 tick
summon area_effect_cloud ~ ~ ~ {Radius:0.3f, Duration:1, WaitTime:0, Particle:"minecraft:barrier"}

# 检测 AEC 是否与其他实体碰撞
execute as @e[type=area_effect_cloud,tag=!checked] at @s on origin run function namespace:hitbox/check_collision
```

`namespace:function/hitbox/check_collision.mcfunction`
```mcfunction
# 检测 AEC 位置是否有其他实体
execute as @e[type=!area_effect_cloud,distance=..0.3] at @s run function namespace:hitbox/on_hit

# 标记 AEC 已检查
tag @s add checked
```

#### 2. 清理 AEC

```mcfunction
# 每个 tick 清理过期的 AEC
kill @e[type=area_effect_cloud,tag=checked]
```

### 陷阱与注意事项

1. **AEC 数量**：每个玩家每个 tick 生成一个 AEC，如果玩家数量多，AEC 数量会线性增长。
2. **碰撞检测精度**：AEC 的碰撞检测是基于**球体**的，对于非球体碰撞箱（如玩家是长方体），精度有限。
3. **粒子效果**：`Particle:"minecraft:barrier"` 会产生可见粒子，如果不想让玩家看到，可以设置为 `"minecraft:block_marker"` 或空粒子（`"minecraft:effect"` 并设置颜色为透明）。
4. **性能开销**：AEC 的碰撞检测由游戏引擎处理，性能较好，但生成和销毁 AEC 本身有开销。

## 方案四：基于 `raycast` 的视线检测（1.19.4+）

### 原理

利用 `execute if entity` 的 `raycast` 功能（1.19.4+），检测从玩家视线方向发射的射线是否命中实体。这适用于“玩家看向某个实体”的场景，而不是物理碰撞。

### 适用版本
1.19.4+

### 完整代码

#### 1. 射线检测

```mcfunction
# 检测玩家视线方向 10 格内的第一个实体
execute as @a at @s anchored eyes run function namespace:hitbox/raycast
```

`namespace:function/hitbox/raycast.mcfunction`
```mcfunction
# 从玩家眼睛位置发射射线，检测 10 格内的实体
execute facing entity @e[type=!minecraft:player,distance=..10,sort=nearest,limit=1] eyes positioned ^ ^ ^1 run function namespace:hitbox/check_raycast
```

`namespace:function/hitbox/check_raycast.mcfunction`
```mcfunction
# 检测射线是否命中实体
execute if entity @e[type=!minecraft:player,distance=..0.5] run function namespace:hitbox/on_hit
```

### 陷阱与注意事项

1. **视线方向**：检测的是玩家**看向**的方向，不是物理碰撞。如果玩家背对实体，即使实体在碰撞箱内也不会触发。
2. **精度问题**：`raycast` 的精度受限于 `^ ^ ^1` 的步长，步长越小精度越高，但性能开销越大。
3. **多实体检测**：只能检测到最近的实体，无法检测多个实体同时被命中。
4. **版本限制**：仅 1.19.4+ 可用。

## 推荐方案

### 对于大多数近战攻击检测（推荐）

使用**方案一：球形检测**，并调整半径以匹配实际碰撞箱：

```mcfunction
# 玩家攻击检测（半径 2.5 格）
execute as @a at @s if entity @e[type=!minecraft:player,distance=..2.5,limit=1] run function namespace:combat/attack
```

### 对于需要精确碰撞箱的场景（1.20.5+）

使用**方案二：Predicate 精确检测**，配合 `data get` 的 scale 参数提高精度：

```mcfunction
# 存储玩家位置（保留两位小数）
execute store result score @s hitbox_x run data get entity @s Pos[0] 100
execute store result score @s hitbox_y run data get entity @s Pos[1] 100
execute store result score @s hitbox_z run data get entity @s Pos[2] 100
```

### 对于物理碰撞模拟（1.19+）

使用**方案三：AEC 碰撞检测**，注意控制 AEC 数量：

```mcfunction
# 限制每 tick 生成的 AEC 数量
execute as @a[limit=10] at @s run function namespace:hitbox/spawn_aec
```

## 陷阱总结

1. **Y轴检测**：所有方案都需要考虑 Y 轴差异。玩家站在地面，目标在头顶 2 格处，`distance=..2` 会误判。建议增加 Y 轴范围限制。
2. **实体类型过滤**：记得排除 `area_effect_cloud`、`marker`、`item` 等非碰撞实体。
3. **性能优化**：对于大量实体，使用 `limit=1` 限制检测数量，或使用 `sort=nearest` 优先检测最近的实体。
4. **版本兼容**：不同版本的 NBT 路径和命令语法不同，注意检查目标版本。
