# 如何制作菜单

## 概述

在 Minecraft 原版数据包中制作菜单（GUI 交互界面）的核心挑战是：**原版没有原生的 GUI 框架**。所有菜单都必须通过间接手段实现，常见方案包括：

1. **物品栏标题欺骗法**（利用 `minecraft:item` 容器 + 自定义标题）
2. **物品交互检测法**（利用 `inventory_changed` 进度监听点击）
3. **聊天组件交互法**（利用 `tellraw` + `clickEvent`）
4. **实体交互法**（利用盔甲架等实体 + 交互组件）

每种方案在版本支持、交互方式、性能开销上差异显著。

---

## 方案一：物品栏标题欺骗法（推荐，1.16+）

### 原理

利用 `minecraft:item` 容器（如箱子、漏斗、发射器）的 `CustomName` 组件，通过 `data merge` 或 `data modify` 修改容器的标题，使其看起来像一个菜单界面。玩家打开容器后，通过 `inventory_changed` 进度监听物品栏变化，检测玩家点击了哪个槽位。

### 完整实现

#### 1. 创建菜单容器

```mcfunction
# 在玩家位置生成一个箱子，并设置自定义标题
# 文件：data/<namespace>/function/menu/open.mcfunction

# 生成箱子实体
summon minecraft:chest ~ ~ ~ {CustomName:'{"text":"§6§l菜单","color":"gold"}',LootTable:"<namespace>:menu/items"}

# 将箱子标记为菜单
data merge entity @e[type=minecraft:chest,limit=1,sort=nearest] {Tags:["menu_chest"]}

# 打开箱子（玩家需要右键点击箱子，或者使用 /trigger 触发）
# 这里使用 /trigger 方式
scoreboard objectives add menu_trigger minecraft:trigger
scoreboard players enable @s menu_trigger
```

#### 2. 菜单物品配置（战利品表）

```json
// 文件：data/<namespace>/loot_table/menu/items.json
{
  "pools": [
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "minecraft:paper",
          "functions": [
            {
              "function": "minecraft:set_name",
              "name": {"text":"§a选项一","italic":false}
            },
            {
              "function": "minecraft:set_lore",
              "lore": [
                {"text":"点击执行功能A","color":"gray","italic":false}
              ]
            },
            {
              "function": "minecraft:set_custom_data",
              "tag": "{menu:{id:1}}"
            }
          ]
        },
        {
          "type": "minecraft:item",
          "name": "minecraft:paper",
          "functions": [
            {
              "function": "minecraft:set_name",
              "name": {"text":"§c选项二","italic":false}
            },
            {
              "function": "minecraft:set_lore",
              "lore": [
                {"text":"点击执行功能B","color":"gray","italic":false}
              ]
            },
            {
              "function": "minecraft:set_custom_data",
              "tag": "{menu:{id:2}}"
            }
          ]
        }
      ]
    }
  ]
}
```

#### 3. 监听物品栏变化

```json
// 文件：data/<namespace>/advancement/menu/click.json
{
  "criteria": {
    "clicked": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "nbt": "{Inventory:[{tag:{menu:{id:1..2}}}]}"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:menu/handle_click"
  }
}
```

#### 4. 处理点击事件

```mcfunction
# 文件：data/<namespace>/function/menu/handle_click.mcfunction

# 检测玩家背包中是否有菜单物品
execute if items entity @s inventory.* *[custom_data~{menu:{id:1}}] run function <namespace>:menu/option_a
execute if items entity @s inventory.* *[custom_data~{menu:{id:2}}] run function <namespace>:menu/option_b

# 清除菜单物品（防止重复触发）
clear @s minecraft:paper{menu:{id:1}} 1
clear @s minecraft:paper{menu:{id:2}} 1

# 撤销进度
advancement revoke @s only <namespace>:menu/click
```

### 陷阱与注意事项

1. **物品栏标题仅在 1.16+ 支持**：1.15 及以下版本无法修改容器标题。
2. **玩家必须手动关闭容器**：`inventory_changed` 进度在容器关闭时触发，不是点击瞬间。
3. **物品堆叠问题**：如果菜单物品可以堆叠，玩家可能通过合并物品绕过检测。建议使用不可堆叠物品（如纸、命名牌）。
4. **创造模式玩家**：创造模式下玩家可以复制菜单物品，导致无限触发。建议在 `handle_click` 中增加 `gamemode` 检测。
5. **性能开销**：每次物品栏变化都会触发进度检测，如果玩家频繁操作物品栏，性能开销中等。

## 方案二：聊天组件交互法（1.12+，轻量级）

### 原理

利用 `tellraw` 命令输出带 `clickEvent` 的聊天消息，玩家点击后执行命令。这是最轻量的菜单方案，但交互方式受限（只能点击文本，不能拖拽物品）。

### 完整实现

#### 1. 显示菜单

```mcfunction
# 文件：data/<namespace>/function/menu/show.mcfunction

tellraw @s [
  {"text":"\n§6§l=== 菜单 ===\n","bold":true},
  {"text":"\n"},
  {"text":"§a[选项一] ","clickEvent":{"action":"run_command","value":"/function <namespace>:menu/option_a"}},
  {"text":"§c[选项二] ","clickEvent":{"action":"run_command","value":"/function <namespace>:menu/option_b"}},
  {"text":"\n"},
  {"text":"§7[关闭] ","clickEvent":{"action":"run_command","value":"/function <namespace>:menu/close"}}
]
```

#### 2. 处理选项

```mcfunction
# 文件：data/<namespace>/function/menu/option_a.mcfunction
tellraw @s {"text":"§a你选择了选项一","color":"green"}
# 执行功能A逻辑...

# 文件：data/<namespace>/function/menu/option_b.mcfunction
tellraw @s {"text":"§c你选择了选项二","color":"red"}
# 执行功能B逻辑...

# 文件：data/<namespace>/function/menu/close.mcfunction
tellraw @s {"text":"§7菜单已关闭","color":"gray"}
```

### 陷阱与注意事项

1. **命令权限**：`run_command` 需要玩家有对应命令权限。在服务器中，普通玩家默认没有 `/function` 权限，需要设置 `minecraft:function` 权限等级。
2. **聊天栏污染**：每次点击都会在聊天栏显示执行的命令（除非使用 `/gamerule sendCommandFeedback false`）。
3. **无法拖拽**：不能像物品栏那样拖拽物品，交互方式单一。
4. **版本兼容性**：`clickEvent` 从 1.12 开始支持，1.12 以下版本无法使用。

## 方案三：实体交互法（1.19+，沉浸式）

### 原理

利用 1.19 引入的交互实体（`interaction`）和玩家交互事件（`minecraft:player_interacted_with_entity` 进度），在玩家右键点击实体时触发菜单逻辑。可以结合盔甲架、展示实体等制作可视化按钮。

### 完整实现

#### 1. 创建交互实体

```mcfunction
# 文件：data/<namespace>/function/menu/spawn_buttons.mcfunction

# 生成交互实体作为按钮
summon minecraft:interaction ~ ~1 ~ {width:1.0f,height:1.0f,response:true,Tags:["menu_button","menu_button_1"]}
summon minecraft:interaction ~2 ~1 ~ {width:1.0f,height:1.0f,response:true,Tags:["menu_button","menu_button_2"]}

# 可选：在交互实体位置生成盔甲架作为视觉装饰
summon minecraft:armor_stand ~ ~1 ~ {Invisible:true,NoGravity:true,Small:true,Tags:["menu_visual"],ArmorItems:[{},{},{},{id:"minecraft:player_head",Count:1b,tag:{SkullOwner:{Id:[I;0,0,0,0],Properties:{textures:[{Value:"eyJ0ZXh0dXJlcyI6eyJTS0lOIjp7InVybCI6Imh0dHA6Ly90ZXh0dXJlcy5taW5lY3JhZnQubmV0L3RleHR1cmUvZjg0ZjU5NzFjZDFkZmI4YWNkMjA5OTg0ZGQ5YTYyYjJjMjQ4Zjc1YjY5MjEzYzYzZjc0ZTM0YzQzYjQifX19"}]}}}]}
```

#### 2. 监听交互事件

```json

    "clicked_button_1": {

        "entity": [
          {

              "type": "minecraft:interaction",
              "nbt": "{Tags:[\"menu_button_1\"]}"
            }
          }
        ]
      }
    },
    "clicked_button_2": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "type": "minecraft:interaction",
              "nbt": "{Tags:[\"menu_button_2\"]}"
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:menu/handle_interact"
  }

```

#### 3. 处理交互

```mcfunction
# 文件：data/<namespace>/function/menu/handle_interact.mcfunction

# 检测玩家交互了哪个按钮
execute if predicate <namespace>:menu/interacted_with_button_1 run function <namespace>:menu/option_a
execute if predicate <namespace>:menu/interacted_with_button_2 run function <namespace>:menu/option_b

# 撤销进度
advancement revoke @s only <namespace>:menu/interact
```

```json
// 文件：data/<namespace>/predicate/menu/interacted_with_button_1.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "type": "minecraft:interaction",
    "nbt": "{Tags:[\"menu_button_1\"]}"
  }
}
```

### 陷阱与注意事项

1. **交互实体仅在 1.19+ 可用**：1.18 及以下版本没有 `interaction` 实体。
2. **视觉反馈**：交互实体本身不可见，需要配合盔甲架、展示实体或粒子效果提供视觉反馈。
3. **交互范围**：交互实体的 `width` 和 `height` 决定了可点击区域，需要合理设置。
4. **多玩家冲突**：多个玩家同时点击同一个交互实体时，进度可能只触发一次。建议每个玩家使用独立的交互实体。
5. **性能开销**：每个交互实体都需要 tick 检测，大量实体时性能开销中等。

## 方案对比

| 方案 | 最低版本 | 交互方式 | 视觉表现 | 性能开销 | 适用场景 |
|------|----------|----------|----------|----------|----------|
| 物品栏标题欺骗法 | 1.16 | 点击物品 | 好（可自定义物品图标和名称） | 中 | 复杂菜单，需要多选项和图标 |
| 聊天组件交互法 | 1.12 | 点击文本 | 差（纯文本） | 低 | 简单菜单，快速交互 |
| 实体交互法 | 1.19 | 右键点击实体 | 好（可搭配盔甲架/展示实体） | 中 | 沉浸式菜单，需要空间定位 |

---

## 综合建议

- **1.16+ 服务器**：优先使用物品栏标题欺骗法，功能最完整，用户体验最好。
- **1.12-1.15 服务器**：只能使用聊天组件交互法，注意权限设置。
- **1.19+ 且需要空间交互**：实体交互法适合制作"按钮墙"或"3D 菜单"。
- **轻量级需求**：聊天组件交互法性能最好，适合作为辅助菜单（如设置菜单）。
