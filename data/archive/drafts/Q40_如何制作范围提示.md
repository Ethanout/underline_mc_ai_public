# 如何制作范围提示

## 一、问题概述

范围提示（Range Indicator）在 Minecraft 数据包开发中常见于以下场景：
- 显示玩家与某个实体/位置的距离
- 显示某个区域的范围边界（如圆形、方形）
- 显示玩家是否在某个距离阈值内

核心挑战在于：**原版没有直接的"距离显示"机制**，需要利用粒子、实体、计分板等系统间接实现。

## 二、方案一：粒子边界环（圆形范围提示）

### 原理
在指定半径的圆周上生成粒子，形成可视化的范围边界。通过数学计算圆周上的点坐标，使用 `particle` 命令在每一帧生成粒子。

### 适用版本
1.13+（粒子系统稳定）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      range_indicator/
        circle.mcfunction
        circle_tick.mcfunction
        circle_clear.mcfunction
```

#### 核心函数：`circle.mcfunction`
```mcfunction
# 参数：半径（通过 scoreboard 传入）
# 使用：execute as @a at @s run function <namespace>:range_indicator/circle_tick
# 注意：此函数需要每 tick 执行

# 设置粒子数量（根据半径动态调整）
scoreboard players set #particle_count <namespace> 0

# 计算粒子数量：半径 * 2（保证密度）
scoreboard players operation #particle_count <namespace> = #radius <namespace>
scoreboard players operation #particle_count <namespace> *= #2 <namespace>

# 如果半径小于1，至少显示4个粒子
execute if score #radius <namespace> matches ..0 run scoreboard players set #particle_count <namespace> 4

# 循环生成粒子（使用递归或循环函数）
# 这里使用递归方式，每次生成一个粒子
scoreboard players set #index <namespace> 0
function <namespace>:range_indicator/circle_loop
```

#### 循环生成函数：`circle_loop.mcfunction`
```mcfunction
# 检查是否完成
execute if score #index <namespace> >= #particle_count <namespace> run return fail

# 计算角度：index / count * 2π
# 使用计分板模拟浮点运算（近似）
# 实际项目中建议使用宏（1.20.2+）或预计算

# 简化方案：使用预定义的粒子位置（适用于固定半径）
# 对于动态半径，可以使用宏或实体标记

# 示例：生成一个粒子在圆周上
# 注意：这里使用简化计算，实际需要更精确的三角函数
# 替代方案：使用 armor stand 旋转

# 生成粒子
particle minecraft:end_rod ^ ^1 ^ 0 0 0 0 1

# 递增索引
scoreboard players add #index <namespace> 1

# 递归调用
function <namespace>:range_indicator/circle_loop
```

### 陷阱与注意事项
1. **性能问题**：每 tick 生成大量粒子会导致客户端卡顿。建议：
   - 粒子数量控制在 20-50 个
   - 使用 `dust` 粒子（性能更好）
   - 只在玩家附近生成（使用 `distance` 选择器过滤）
2. **粒子可见性**：粒子只在玩家 32 格内可见（默认），需要调整 `particle` 命令的视距参数
3. **数学计算**：原版计分板不支持三角函数，需要使用近似方法或预计算

## 三、方案二：实体标记法（动态范围提示）

### 原理
使用 armor stand 或 marker 实体作为"标记点"，围绕目标实体排列成圆形/方形。通过 `tp` 命令和 `execute rotated` 实现圆周运动。

### 适用版本
1.13+（marker 实体在 1.17+ 可用）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      range_indicator/
        spawn_markers.mcfunction
        update_markers.mcfunction
        remove_markers.mcfunction
```

#### 生成标记实体：`spawn_markers.mcfunction`
```mcfunction
# 在目标位置生成一圈 armor stand
# 参数：半径（通过 scoreboard 传入）

# 清除旧标记
execute as @e[tag=<namespace>.range_marker] run kill @s

# 生成 16 个标记（固定数量）
summon minecraft:armor_stand ~ ~ ~ {Tags:["<namespace>.range_marker"],Invisible:1b,NoGravity:1b,Marker:1b}
# ... 重复 15 次，或使用循环函数

# 初始化角度
scoreboard players set #angle <namespace> 0
function <namespace>:range_indicator/spawn_loop
```

#### 更新位置：`update_markers.mcfunction`
```mcfunction
# 每 tick 执行，更新标记位置
# 使用 execute rotated 实现圆周运动

# 示例：更新第一个标记
execute as @e[tag=<namespace>.range_marker,limit=1,sort=nearest] at @s run tp @s ^ ^ ^<radius>

# 旋转角度
execute as @e[tag=<namespace>.range_marker] at @s run tp @s ~ ~ ~ ~22.5 ~

# 实际实现需要更复杂的角度计算
# 建议使用宏（1.20.2+）或预计算角度
```

### 陷阱与注意事项
1. **实体数量**：每个标记都是一个实体，大量实体影响性能。建议控制在 8-16 个
2. **同步问题**：多个标记需要同步旋转，否则会散开
3. **玩家跟随**：如果标记跟随玩家，需要每 tick 重新定位
4. **版本差异**：`Marker:1b` 在 1.17+ 可用，旧版本使用 `Invisible:1b` 和 `NoGravity:1b`

## 四、方案三：计分板距离显示（数值提示）

### 原理
使用计分板计算玩家与目标之间的距离，通过 `title` 或 `bossbar` 显示数值。

### 适用版本
1.13+（计分板系统稳定）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      range_indicator/
        distance_calc.mcfunction
        display_distance.mcfunction
```

#### 距离计算：`distance_calc.mcfunction`
```mcfunction
# 计算玩家与目标实体的距离
# 使用 execute store 存储坐标

# 存储玩家坐标
execute as @a at @s store result score @s <namespace>.x_pos run data get entity @s Pos[0] 1000
execute as @a at @s store result score @s <namespace>.y_pos run data get entity @s Pos[1] 1000
execute as @a at @s store result score @s <namespace>.z_pos run data get entity @s Pos[2] 1000

# 存储目标坐标（假设目标有 tag "target"）
execute as @e[tag=target,limit=1] store result score #target_x <namespace> run data get entity @s Pos[0] 1000
execute as @e[tag=target,limit=1] store result score #target_y <namespace> run data get entity @s Pos[1] 1000
execute as @e[tag=target,limit=1] store result score #target_z <namespace> run data get entity @s Pos[2] 1000

# 计算差值
scoreboard players operation @s <namespace>.dx = @s <namespace>.x_pos
scoreboard players operation @s <namespace>.dx -= #target_x <namespace>

scoreboard players operation @s <namespace>.dy = @s <namespace>.y_pos
scoreboard players operation @s <namespace>.dy -= #target_y <namespace>

scoreboard players operation @s <namespace>.dz = @s <namespace>.z_pos
scoreboard players operation @s <namespace>.dz -= #target_z <namespace>

# 平方
scoreboard players operation @s <namespace>.dx2 = @s <namespace>.dx
scoreboard players operation @s <namespace>.dx2 *= @s <namespace>.dx

scoreboard players operation @s <namespace>.dy2 = @s <namespace>.dy
scoreboard players operation @s <namespace>.dy2 *= @s <namespace>.dy

scoreboard players operation @s <namespace>.dz2 = @s <namespace>.dz
scoreboard players operation @s <namespace>.dz2 *= @s <namespace>.dz

# 求和
scoreboard players operation @s <namespace>.dist_sq = @s <namespace>.dx2
scoreboard players operation @s <namespace>.dist_sq += @s <namespace>.dy2
scoreboard players operation @s <namespace>.dist_sq += @s <namespace>.dz2

# 开平方（近似）
# 使用牛顿迭代法或预计算表
function <namespace>:range_indicator/sqrt
```

#### 显示距离：`display_distance.mcfunction`
```mcfunction
# 显示距离到 actionbar
execute as @a run title @s actionbar [{"text":"距离: ","color":"white"},{"score":{"name":"@s","objective":"<namespace>.dist"}}]
```

### 陷阱与注意事项
1. **开平方运算**：原版计分板不支持开平方，需要实现近似算法或使用预计算表
2. **精度问题**：坐标存储时乘以 1000 再运算，最后除以 1000 恢复精度
3. **性能开销**：每 tick 计算所有玩家的距离，开销中等
4. **多目标**：如果有多个目标，需要为每个目标单独计算

## 五、方案四：粒子路径追踪（射线提示）

### 原理
从玩家位置向目标方向发射粒子，形成可见的"连线"，直观显示距离和方向。

### 适用版本
1.13+（粒子系统）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      range_indicator/
        ray_tick.mcfunction
        ray_particle.mcfunction
```

#### 每 tick 执行：`ray_tick.mcfunction`
```mcfunction
# 为每个玩家生成射线粒子
execute as @a at @s run function <namespace>:range_indicator/ray_particle
```

#### 生成粒子：`ray_particle.mcfunction`
```mcfunction
# 从玩家位置向目标方向生成粒子
# 使用 execute facing 和 ^ ^ ^ 相对坐标

# 生成第一个粒子（玩家位置）
particle minecraft:end_rod ^ ^ ^ 0 0 0 0 1

# 向目标方向移动并生成粒子
execute facing entity @e[tag=target,limit=1] feet run particle minecraft:end_rod ^ ^ ^0.5 0 0 0 0 1
execute facing entity @e[tag=target,limit=1] feet run particle minecraft:end_rod ^ ^ ^1.0 0 0 0 0 1
# ... 重复直到目标位置

# 实际实现需要动态计算步数
# 可以使用循环函数或宏
```

### 陷阱与注意事项
1. **粒子数量**：距离越远，需要的粒子越多，性能开销线性增长
2. **方向计算**：`execute facing` 只能指向实体，不能指向坐标
3. **遮挡问题**：粒子会被方块遮挡，不适合复杂地形
4. **客户端性能**：大量粒子可能导致客户端卡顿

## 六、方案对比

| 方案 | 版本要求 | 性能开销 | 视觉效果 | 适用场景 |
|------|---------|---------|---------|---------|

## 七、推荐方案

### 简单场景（固定半径圆形范围）
推荐方案一（粒子边界环），配合预计算粒子位置，性能可控。

### 复杂场景（动态半径、多形状）
推荐方案二（实体标记法），使用 marker 实体（1.17+）减少性能开销。

### 精确数值需求
推荐方案三（计分板距离显示），配合 bossbar 或 actionbar 显示。

## 八、高级技巧：使用宏（1.20.2+）

### 原理
利用 1.20.2 引入的宏功能，动态生成粒子位置，避免预计算和大量实体。

### 示例
```mcfunction
# 使用宏生成圆周上的粒子
# 参数：$(radius) $(count)

# 循环生成粒子
for $(i) from 0 to $(count)-1:
  # 计算角度
  $(angle) = $(i) * 360 / $(count)
  # 生成粒子（需要三角函数支持）
  particle minecraft:end_rod ^ $(radius)*sin($(angle)) ^ $(radius)*cos($(angle))
```

### 陷阱
1. 宏不支持三角函数，需要预计算或使用近似
2. 宏的循环次数有限制（约 10000 次）
3. 需要 1.20.2+ 版本

## 九、总结

范围提示的实现取决于具体需求：
- **视觉范围**：粒子或实体标记
- **数值范围**：计分板计算
- **动态范围**：实体标记法或宏
- **简单固定**：粒子边界环

建议根据版本、性能要求和视觉效果选择合适的方案。
