# 如何制作惯性或滑行

## 核心挑战

在 Minecraft 原版数据包中实现惯性或滑行，核心挑战在于：
1. **原版没有直接的"速度衰减"机制**——玩家的移动速度由游戏引擎直接控制，数据包无法直接修改玩家的运动属性（如 `Motion` 标签对玩家无效）
2. **需要模拟"松开按键后继续移动"的效果**——这通常需要持续施加一个方向的速度，并逐步衰减
3. **不同版本的能力边界不同**——1.20.5 之前的 `Motion` 标签对玩家无效，1.20.5+ 引入了 `movement` 组件但限制严格

## 方案一：基于 `Motion` 的实体滑行（推荐，1.13+）

### 原理

玩家本身无法直接修改 `Motion`，但可以**生成一个标记实体（如 `minecraft:marker` 或 `minecraft:armor_stand`）**，让这个实体携带玩家的运动状态，然后通过 `tp` 或 `ride` 机制让玩家跟随实体移动。

核心思路：
1. 检测玩家输入方向（WASD）
2. 计算方向向量并施加到标记实体上
3. 标记实体每 tick 衰减速度（模拟摩擦力）
4. 玩家骑乘或跟随标记实体移动

### 完整实现（1.13+，推荐使用 `marker` 实体，1.17+）

#### 目录结构
```
data/
  namespace/
    functions/
      load.mcfunction
      tick.mcfunction
      player/
        init.mcfunction
        apply_velocity.mcfunction
        decay.mcfunction
        move_player.mcfunction
      entity/
        spawn_marker.mcfunction
        apply_motion.mcfunction
    predicates/
      is_moving.json
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建用于存储玩家运动状态的 storage
data modify storage namespace:player Motion set value [0.0, 0.0, 0.0]
scoreboard objectives add namespace:input dummy
scoreboard objectives add namespace:decay dummy

# 为每个在线玩家创建标记实体
execute as @a run function namespace:player/init
```

#### 2. 玩家初始化 (player/init.mcfunction)
```mcfunction
# 为每个玩家生成一个标记实体，并建立关联
# 使用 UUID 或自定义标签关联
summon marker ~ ~ ~ {Tags:["namespace.slider","namespace.pending"]}
# ⚠️ 需验证：1.17+ marker 实体是否支持 Tags
# 将标记实体的 UUID 存储到玩家的 storage 中
execute store result score @s namespace:input run data get entity @s UUID[0]
```

#### 3. 每 tick 处理 (tick.mcfunction)
```mcfunction
# 对所有玩家执行
execute as @a at @s run function namespace:player/apply_velocity
execute as @a at @s run function namespace:player/decay
execute as @a at @s run function namespace:player/move_player
```

#### 4. 检测输入并施加速度 (player/apply_velocity.mcfunction)
```mcfunction
# 检测玩家是否在移动（WASD 按键）
# 使用 predicate 检测输入
execute if predicate namespace:is_moving run function namespace:player/apply_motion

# 如果玩家在移动，重置衰减计数器
execute if predicate namespace:is_moving run scoreboard players set @s namespace:decay 0
```

#### 5. 输入检测谓词 (predicates/is_moving.json)
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "input": {
      "forward": true,
      "left": true,
      "right": true,
      "backward": true
    }
  }
}
```
> **注意**：这个谓词检测的是**任意方向**的输入。如果需要区分方向，需要更复杂的实现。

#### 6. 施加运动 (player/apply_motion.mcfunction)
```mcfunction
# 获取玩家的朝向向量
# 注意：这里简化处理，实际需要根据输入方向计算
execute store result score @s namespace:input run data get entity @s Motion[0]
# ⚠️ 需验证：1.20.5+ 玩家 Motion 是否可读

# 向标记实体施加速度
# 假设标记实体通过 tag 关联
execute as @e[tag=namespace.slider,limit=1] at @s run function namespace:entity/apply_motion
```

#### 7. 标记实体速度处理 (entity/apply_motion.mcfunction)
```mcfunction
# 给标记实体施加一个初始速度
data modify entity @s Motion set value [0.5, 0.0, 0.0]
# 实际需要根据玩家输入方向计算
```

#### 8. 速度衰减 (player/decay.mcfunction)
```mcfunction
# 每 tick 增加衰减计数器
scoreboard players add @s namespace:decay 1

# 当衰减达到阈值时，减少标记实体的速度
execute if score @s namespace:decay matches 10.. run function namespace:player/apply_decay
```

#### 9. 移动玩家 (player/move_player.mcfunction)
```mcfunction
# 将玩家传送到标记实体的位置
execute as @e[tag=namespace.slider,limit=1] at @s run tp @p ~ ~ ~
```

### 陷阱与注意事项

1. **标记实体的生命周期**：标记实体需要与玩家一一对应，玩家退出时需要清理
2. **速度计算复杂**：实际实现中，需要根据玩家的朝向和输入方向计算三维向量，这需要三角函数（可以通过查表法实现）
3. **传送闪烁**：使用 `tp` 移动玩家会导致视觉闪烁，建议使用 `ride` 机制（1.13+）
4. **性能开销**：每个玩家需要维护一个标记实体，对于大量玩家（>20）性能开销较高
5. **版本兼容性**：`marker` 实体在 1.17 引入，1.13-1.16 需要使用 `armor_stand`

## 方案二：基于 `ride` 的实体滑行（推荐，1.13+）

### 原理

利用 Minecraft 的骑乘机制：让玩家骑乘一个实体，然后控制该实体的运动。玩家会跟随实体移动，且不会产生传送闪烁。

### 完整实现

#### 目录结构
```
data/
  namespace/
    functions/
      load.mcfunction
      tick.mcfunction
      player/
        mount.mcfunction
        dismount.mcfunction
        apply_velocity.mcfunction
      entity/
        spawn_boat.mcfunction
        move_boat.mcfunction
```

#### 1. 初始化 (load.mcfunction)
```mcfunction
# 创建计分板
scoreboard objectives add namespace:velocity dummy
scoreboard objectives add namespace:direction dummy
```

#### 2. 生成载具 (entity/spawn_boat.mcfunction)
```mcfunction
# 生成一个不可见的船作为载具
summon minecraft:boat ~ ~ ~ {Tags:["namespace.vehicle"],Invulnerable:1b,NoGravity:1b}
# ⚠️ 需验证：1.13+ 船是否支持 NoGravity
```

#### 3. 玩家骑乘 (player/mount.mcfunction)
```mcfunction
# 让玩家骑乘载具
execute as @e[tag=namespace.vehicle,limit=1] at @s run ride @p mount @s
# ⚠️ 需验证：ride 命令语法在 1.13+ 是否一致
```

#### 4. 每 tick 处理 (tick.mcfunction)
```mcfunction
# 控制载具运动
execute as @e[tag=namespace.vehicle] at @s run function namespace:entity/move_boat
```

#### 5. 载具运动 (entity/move_boat.mcfunction)
```mcfunction
# 获取骑乘玩家的输入
execute store result score @s namespace:velocity run data get entity @s Motion[0]

# 施加速度（简化示例）
data modify entity @s Motion set value [0.3, 0.0, 0.0]

# 衰减速度
execute store result score @s namespace:velocity run data get entity @s Motion[0]
scoreboard players remove @s namespace:velocity 1
execute store result entity @s Motion[0] double 0.0001 run scoreboard players get @s namespace:velocity
```

### 陷阱与注意事项

1. **载具类型选择**：船在陆地上移动困难，建议使用 `minecraft:marker` 或 `minecraft:armor_stand`
2. **骑乘状态管理**：玩家死亡、退出或主动下船时需要重新处理
3. **速度控制**：`Motion` 对载具实体的控制是直接的，但需要精确计算衰减系数
4. **碰撞检测**：载具实体可能会卡在方块中，需要额外的碰撞处理

## 方案三：基于 `attribute` 的移动速度修改（1.16+）

### 原理

直接修改玩家的 `movement_speed` 属性，配合 `effect` 或 `attribute modifier` 实现速度变化。但这种方法**无法实现真正的惯性**，只能模拟"加速/减速"效果。

### 完整实现

#### 1. 初始化 (load.mcfunction)
```mcfunction
scoreboard objectives add namespace:speed dummy
```

#### 2. 每 tick 处理 (tick.mcfunction)
```mcfunction
# 检测玩家输入
execute as @a at @s if predicate namespace:is_moving run function namespace:player/accelerate
execute as @a at @s unless predicate namespace:is_moving run function namespace:player/decelerate
```

#### 3. 加速 (player/accelerate.mcfunction)
```mcfunction
# 增加速度属性
attribute @s minecraft:movement_speed modifier add namespace:speed_bonus 0.1 add
```

#### 4. 减速 (player/decelerate.mcfunction)
```mcfunction
# 移除速度加成
attribute @s minecraft:movement_speed modifier remove namespace:speed_bonus
```

### 陷阱与注意事项

1. **不是真正的惯性**：这只是修改了移动速度，松开按键后玩家会立即减速到基础速度
2. **属性叠加问题**：多次添加 modifier 会导致速度异常
3. **版本限制**：`attribute` 命令在 1.16 引入

## 方案对比

| 方案 | 版本要求 | 性能开销 | 惯性效果 | 实现复杂度 | 适用场景 |
|------|---------|---------|---------|-----------|---------|
| Motion 实体滑行 | 1.13+ (marker 需 1.17+) | 中 | 真实惯性 | 高 | 需要真实物理效果的场景 |
| Ride 实体滑行 | 1.13+ | 中 | 真实惯性 | 中 | 需要平滑移动的场景 |
| Attribute 速度修改 | 1.16+ | 低 | 伪惯性 | 低 | 简单加速/减速效果 |

## 推荐方案

对于大多数数据包项目，推荐使用**方案二（Ride 实体滑行）**，因为：
1. 实现相对简单
2. 移动平滑，无传送闪烁
3. 性能开销可控
4. 兼容性较好（1.13+）

如果需要更精确的物理模拟（如冰面滑行），推荐**方案一（Motion 实体滑行）**，但需要处理更复杂的向量计算。

## 完整示例：冰面滑行效果（基于 Ride 方案）

### 核心函数

#### 1. 检测冰面 (predicates/on_ice.json)
```json
{
  "condition": "minecraft:location_check",
  "predicate": {
    "block": {
      "blocks": [
        "minecraft:ice",
        "minecraft:packed_ice",
        "minecraft:blue_ice",
        "minecraft:frosted_ice"
      ]
    }
  }
}
```

#### 2. 滑行逻辑 (tick.mcfunction)
```mcfunction
# 检测玩家是否在冰面上
execute as @a at @s if predicate namespace:on_ice run function namespace:player/slide
execute as @a at @s unless predicate namespace:on_ice run function namespace:player/normal
```

#### 3. 滑行处理 (player/slide.mcfunction)
```mcfunction
# 降低摩擦力（减少衰减）
scoreboard players set @s namespace:friction 5

# 如果玩家在移动，增加速度
execute if predicate namespace:is_moving run function namespace:player/add_speed

# 应用衰减
function namespace:player/apply_friction
```

#### 4. 速度衰减 (player/apply_friction.mcfunction)
```mcfunction
# 根据摩擦力衰减速度
execute store result score @s namespace:speed run data get entity @e[tag=namespace.vehicle,limit=1] Motion[0]
scoreboard players remove @s namespace:speed 1
execute store result entity @e[tag=namespace.vehicle,limit=1] Motion[0] double 0.0001 run scoreboard players get @s namespace:speed
```

### 陷阱

1. **冰面检测**：`location_check` 检测的是玩家脚部位置，需要确保玩家确实站在冰面上
2. **速度上限**：需要设置速度上限，防止玩家无限加速
3. **方向控制**：滑行时玩家应该能控制方向，但惯性会保留原有方向分量
