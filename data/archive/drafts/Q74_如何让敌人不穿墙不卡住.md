# 如何让敌人不穿墙不卡住

## 问题核心

在 Minecraft 原版数据包开发中，让生物（如僵尸、骷髅等）不穿墙、不卡住的核心挑战在于：**原版寻路 AI 本身存在缺陷**。生物在遇到复杂地形（如 1x1 通道、转角、栅栏、活板门）时，即使目标路径存在，也可能因寻路节点计算错误而卡住或穿墙。数据包无法直接修改寻路算法，但可以通过**环境改造、路径引导、强制传送**等间接手段解决。

## 方案一：路径块引导法（推荐，1.13+）

### 原理

利用 `minecraft:path` 标签的方块（如 `minecraft:light_weighted_pressure_plate`、`minecraft:stone_pressure_plate` 等）对生物寻路的影响。生物在寻路时会优先选择路径块上的路径，通过在地面上放置路径块，可以强制生物沿指定路线移动，避免穿墙或卡住。

### 完整实现

#### 1. 创建路径块系统

在数据包中定义路径块，使用 `#minecraft:pressure_plates` 标签（包含所有压力板）作为路径标记。

`data/<namespace>/tags/blocks/path_blocks.json`
```json
{
    "values": [
        "minecraft:light_weighted_pressure_plate",
        "minecraft:heavy_weighted_pressure_plate",
        "minecraft:stone_pressure_plate",
        "minecraft:oak_pressure_plate",
        "minecraft:spruce_pressure_plate",
        "minecraft:birch_pressure_plate",
        "minecraft:jungle_pressure_plate",
        "minecraft:acacia_pressure_plate",
        "minecraft:dark_oak_pressure_plate",
        "minecraft:mangrove_pressure_plate",
        "minecraft:cherry_pressure_plate",
        "minecraft:bamboo_pressure_plate",
        "minecraft:crimson_pressure_plate",
        "minecraft:warped_pressure_plate"
    ]
}
```

#### 2. 检测生物是否偏离路径

每 tick 检测生物脚下的方块，如果不是路径块，则强制将其传送到最近的路径块上。

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 检测所有目标生物
execute as @e[type=#<namespace>:enemies] at @s run function <namespace>:enemy/path_check
```

`data/<namespace>/functions/enemy/path_check.mcfunction`
```mcfunction
# 检测脚下方块
execute unless block ~ ~-0.5 ~ #<namespace>:path_blocks run function <namespace>:enemy/teleport_to_path
```

#### 3. 强制传送回路径

需要预先在路径块位置放置标记实体（如 `minecraft:marker`）来记录路径点。

`data/<namespace>/functions/enemy/teleport_to_path.mcfunction`
```mcfunction
# 寻找最近的路径标记
execute as @e[type=minecraft:marker,tag=path_point,sort=nearest,limit=1] at @s run tp @p ~ ~0.5 ~
```

#### 4. 初始化路径标记

在 load 函数中创建路径标记。

`data/<namespace>/functions/load.mcfunction`
```mcfunction
# 示例：在坐标 (100, 64, 100) 放置路径标记
summon minecraft:marker 100 64 100 {Tags:["path_point"]}
```

### 陷阱与注意事项

1. **路径块高度问题**：压力板只有 0.5 格高，生物可能从侧面绕过。建议在路径块下方放置完整方块（如石头）来抬高地面。
2. **标记实体数量**：路径标记过多会影响性能。建议每 5-10 格放置一个标记。
3. **传送抖动**：生物被强制传送时可能出现视觉抖动。可以通过 `tp` 命令的旋转参数（如 `tp @s ~ ~0.5 ~ ~ ~`）保持生物朝向。
4. **1.20.5+ 版本**：`minecraft:marker` 实体在 1.20.5 中仍然可用，但 `Tags` 字段已改为 `tags`（数组格式）⚠️ 需验证。

## 方案二：屏障墙法（1.13+）

### 原理

在生物可能穿墙的位置放置 `minecraft:barrier`（屏障）或 `minecraft:structure_void`（结构空位），物理上阻挡生物移动。屏障对玩家不可见，但生物无法穿过。

### 完整实现

#### 1. 创建屏障墙

在数据包中定义需要放置屏障的位置。

`data/<namespace>/functions/setup_barriers.mcfunction`
```mcfunction
# 示例：在坐标 (100, 64, 100) 到 (100, 64, 110) 之间放置屏障墙
fill 100 64 100 100 64 110 minecraft:barrier
```

#### 2. 动态检测并修复穿墙

每 tick 检测生物是否在墙内，如果是则强制传送。

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 检测生物是否在屏障内
execute as @e[type=#<namespace>:enemies] at @s if block ~ ~ ~ minecraft:barrier run function <namespace>:enemy/fix_wall
```

`data/<namespace>/functions/enemy/fix_wall.mcfunction`
```mcfunction
# 将生物传送到最近的屏障外
execute positioned ~ ~ ~ run tp @s ^ ^ ^5
```

### 陷阱与注意事项

1. **屏障可见性**：屏障在创造模式下可见，且玩家手持屏障时会显示。如果不想让玩家看到，可以使用 `minecraft:structure_void`，但结构空位对生物寻路的影响较小。
2. **性能开销**：每 tick 检测所有生物是否在屏障内，如果生物数量多（>50），性能开销较高。建议使用 `predicate` 或 `advancement` 来减少检测频率。
3. **传送方向**：`^ ^ ^5` 是相对生物朝向的前方 5 格。如果生物朝向墙内，可能传送到更深处。建议使用绝对坐标或 `@p` 选择器。

## 方案三：寻路目标重置法（1.13+）

### 原理

生物卡住通常是因为寻路目标被阻挡或计算错误。通过定期重置生物的寻路目标（如 `Owner`、`Target`、`Leash` 等），强制生物重新计算路径。

### 完整实现

#### 1. 检测生物是否卡住

使用 `predicate` 检测生物在短时间内位置是否变化。

`data/<namespace>/predicate/is_stuck.json`
```json
{
    "condition": "minecraft:entity_properties",
    "entity": "this",
    "predicate": {
        "movement": {
            "x": 0,
            "y": 0,
            "z": 0
        }
    }
}
```

#### 2. 重置寻路目标

每 5 tick 检测一次，如果生物卡住则重置目标。

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 5 tick 执行一次
execute if score $tick_counter <namespace> matches ..0 run function <namespace>:enemy/reset_path
scoreboard players add $tick_counter <namespace> 1
```

`data/<namespace>/functions/enemy/reset_path.mcfunction`
```mcfunction
# 检测所有生物是否卡住
execute as @e[type=#<namespace>:enemies] at @s if predicate <namespace>:is_stuck run function <namespace>:enemy/force_move
```

`data/<namespace>/functions/enemy/force_move.mcfunction`
```mcfunction
# 强制生物向玩家移动
execute as @p at @s run tp @s ~ ~ ~
# 或者设置生物的目标为最近的玩家
execute as @e[type=#<namespace>:enemies,sort=nearest,limit=1] at @s run data merge entity @s {Target:0}
```

### 陷阱与注意事项

1. **`movement` 谓词**：`movement` 字段在 1.16+ 中可用，但检测的是生物的速度向量，不是位置变化。如果生物在移动但被墙挡住，速度可能不为 0，导致误判。
2. **`Target` 字段**：`Target` 是生物的攻击目标，设置为 0 会清除目标。但生物可能立即重新选择目标，导致循环。
3. **性能开销**：每 5 tick 检测一次，性能开销较低。但如果生物数量多，`predicate` 检测仍有一定开销。

## 方案四：路径点传送法（1.13+）

### 原理

在关键位置（如转角、门口）放置路径点标记，当生物到达路径点时，强制将其传送到下一个路径点。这种方法完全绕过寻路 AI，直接控制生物移动。

### 完整实现

#### 1. 创建路径点链

使用 `minecraft:marker` 实体作为路径点，每个标记有 `next_point` 标签指向下一个标记的 UUID。

`data/<namespace>/functions/setup_path.mcfunction`
```mcfunction
# 创建路径点链
summon minecraft:marker 100 64 100 {Tags:["path_point","point_1"],CustomName:'{"text":"Point 1"}'}
summon minecraft:marker 110 64 100 {Tags:["path_point","point_2"],CustomName:'{"text":"Point 2"}'}
summon minecraft:marker 110 64 110 {Tags:["path_point","point_3"],CustomName:'{"text":"Point 3"}'}
```

#### 2. 检测生物到达路径点

每 tick 检测生物是否在路径点附近。

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
execute as @e[type=#<namespace>:enemies] at @s run function <namespace>:enemy/check_path_point
```

`data/<namespace>/functions/enemy/check_path_point.mcfunction`
```mcfunction
# 检测生物是否在路径点 1 附近
execute if entity @s[distance=..2] at @e[type=minecraft:marker,tag=point_1,limit=1] run function <namespace>:enemy/teleport_to_point_2
```

`data/<namespace>/functions/enemy/teleport_to_point_2.mcfunction`
```mcfunction
# 传送到路径点 2
execute at @e[type=minecraft:marker,tag=point_2,limit=1] run tp @s ~ ~0.5 ~
```

### 陷阱与注意事项

1. **路径点密度**：路径点间距过大会导致生物移动不自然，过小则性能开销大。建议间距 5-10 格。
2. **多生物同步**：多个生物同时到达同一路径点时，传送顺序可能导致重叠。可以使用 `sort=nearest` 或 `limit=1` 控制。
3. **路径点循环**：如果路径点形成循环，生物会无限循环。需要设计终点（如玩家位置）来结束循环。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|----------|----------|----------|------|------|
| 路径块引导法 | 1.13+ | 低 | 固定路线、迷宫、走廊 | 自然移动，无传送抖动 | 需要预先铺设路径块 |
| 屏障墙法 | 1.13+ | 中 | 防止穿墙、边界保护 | 物理阻挡，无需修改寻路 | 屏障可见性，性能开销随生物数量增加 |
| 寻路目标重置法 | 1.16+ | 低 | 通用场景，临时修复 | 无需修改地图 | 可能误判，生物可能反复卡住 |
| 路径点传送法 | 1.13+ | 中 | 精确控制、复杂地形 | 完全控制生物移动 | 传送抖动，路径点维护复杂 |

## 推荐方案

- **固定路线**：路径块引导法（方案一），性能最好，移动自然。
- **防止穿墙**：屏障墙法（方案二），物理阻挡最可靠。
- **通用修复**：寻路目标重置法（方案三），适合作为补充方案。
- **精确控制**：路径点传送法（方案四），适合需要精确路径的场景。

## 陷阱总结

1. **版本兼容性**：`minecraft:marker` 在 1.17+ 中可用，1.13-1.16 可以使用 `minecraft:armor_stand` 替代（设置 `Marker:1b`）。
2. **性能优化**：避免每 tick 检测所有生物，可以使用 `schedule` 或 `scoreboard` 分帧处理。
3. **生物类型**：不同生物（如蜘蛛、末影人）的寻路行为不同，需要针对性调整。
4. **多人游戏**：多个玩家时，生物的目标选择可能导致混乱。建议使用 `@p` 或 `@r` 选择器。
