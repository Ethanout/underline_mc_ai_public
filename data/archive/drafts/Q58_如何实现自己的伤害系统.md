# 如何实现自己的伤害系统

## 核心挑战

Minecraft 原版伤害系统是硬编码的，数据包无法直接修改伤害计算逻辑（如护甲减伤、附魔保护、伤害类型免疫等）。要实现自定义伤害系统，核心挑战在于：

1. **拦截原版伤害**：在实体受到伤害时获取控制权
2. **自定义伤害计算**：实现自己的伤害公式（如基于属性、状态效果、距离等）
3. **应用自定义伤害**：将计算后的伤害施加给目标
4. **处理死亡逻辑**：确保自定义伤害能正确触发死亡动画、掉落物等

## 方案一：基于 `entity_hurt_player` 进度的伤害拦截 + 自定义伤害应用

**适用版本**：1.16+（`entity_hurt_player` trigger 于 1.16 引入）
**推荐程度**：⭐⭐⭐⭐（最通用，但无法拦截所有伤害来源）

### 原理

1. 使用 `entity_hurt_player` 进度监听玩家被伤害的事件
2. 在进度奖励函数中，通过 `data modify` 获取伤害值，存入 storage
3. 使用 `attribute` 命令修改玩家的属性（如 `generic.armor`、`generic.armor_toughness`）来影响原版伤害计算
4. 或者：先通过 `effect give` 给予瞬间伤害效果来应用自定义伤害，再通过 `attribute` 将原版护甲设为 0 让原版伤害无效化

### 完整代码

#### 1. 进度定义

`data/<namespace>/advancement/custom_damage/hurt_player.json`
```json
{
  "criteria": {
    "on_hurt": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "damage": {
          "type": {
            "source_entity": {
              "type": "minecraft:player"
            }
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:custom_damage/on_hurt"
  }
}
```

#### 2. 伤害处理函数

`data/<namespace>/function/custom_damage/on_hurt.mcfunction`
```mcfunction
# 存储伤害值到 storage（⚠️ 需验证：entity_hurt_player 的 damage 条件是否能通过 advancement 的 damage 字段获取具体数值）
# 实际上，advancement 的 damage 条件只能做范围判断，无法获取精确数值
# 因此需要另一种方式获取伤害值

# 方案：使用 scoreboard 记录生命值变化
# 在 tick 中记录上一 tick 的生命值
scoreboard players operation @s <namespace>.prev_health = @s minecraft:health

# 在 on_hurt 函数中计算差值
scoreboard players operation @s <namespace>.damage_taken = @s minecraft:health
scoreboard players operation @s <namespace>.damage_taken -= @s <namespace>.prev_health
scoreboard players set @s <namespace>.damage_taken 0 - @s <namespace>.damage_taken

# 应用自定义伤害减免（示例：减少 50% 伤害）
scoreboard players operation @s <namespace>.custom_damage = @s <namespace>.damage_taken
scoreboard players operation @s <namespace>.custom_damage /= 2

# 将原版伤害设为 0（通过修改护甲属性）
attribute @s minecraft:generic.armor base set 1000

# 应用自定义伤害（使用 instant_damage 效果）
execute if score @s <namespace>.custom_damage matches 1.. run effect give @s minecraft:instant_damage 1 0

# 恢复护甲
attribute @s minecraft:generic.armor base set 0
```

#### 3. Tick 函数（记录生命值）

`data/<namespace>/function/tick.mcfunction`
```mcfunction
execute as @a run function <namespace>:custom_damage/record_health
```

`data/<namespace>/function/custom_damage/record_health.mcfunction`
```mcfunction
scoreboard players operation @s <namespace>.prev_health = @s minecraft:health
```

### 陷阱与注意事项

1. **无法获取精确伤害值**：`entity_hurt_player` 进度的 `damage` 条件只能做范围判断（如 `dealt` 字段），无法获取具体数值。上述方案通过生命值差值间接计算，但存在以下问题：
   - 如果玩家同时受到多个伤害源（如多个箭矢同时命中），差值无法区分
   - 瞬间治疗效果（如瞬间治疗药水）会干扰计算
   - 生命值变化可能由其他原因引起（如饥饿、窒息）

2. **`instant_damage` 效果的限制**：
   - 该效果无视护甲和附魔保护，直接造成魔法伤害
   - 无法精确控制伤害值（效果等级 0 对应 6 点伤害，等级 1 对应 12 点，以此类推）
   - 无法区分伤害类型（如火焰、爆炸、弹射物等）

3. **属性修改的副作用**：
   - 修改 `generic.armor` 会影响所有伤害，包括环境伤害（如摔落、溺水）
   - 需要确保在 tick 结束时恢复属性，否则其他系统会受影响

4. **性能开销**：中等。每个玩家每 tick 需要执行一次 scoreboard 操作，加上伤害触发时的额外计算。

## 方案二：基于 `damage` 命令 + 自定义伤害类型（1.20.5+）

**适用版本**：1.20.5+（`damage` 命令和自定义伤害类型系统于 1.20.5 引入）
**推荐程度**：⭐⭐⭐⭐⭐（最灵活，支持自定义伤害类型和伤害计算）

### 原理

1. 使用 `damage` 命令直接对实体造成伤害，支持自定义伤害类型
2. 通过自定义伤害类型 JSON 文件定义伤害行为（如是否无视护甲、是否触发附魔等）
3. 结合 `execute if predicate` 和 scoreboard 实现复杂的伤害计算逻辑
4. 完全绕过原版伤害系统，实现完全自定义的伤害流程

### 完整代码

#### 1. 自定义伤害类型定义

`data/<namespace>/damage_type/custom_physical.json`
```json
{
  "exhaustion": 0.1,
  "message_id": "custom.physical",
  "scaling": "never",
  "effects": "hurt",
  "death_message_type": "default"
}
```

`data/<namespace>/damage_type/custom_magic.json`
```json
{
  "exhaustion": 0.0,
  "message_id": "custom.magic",
  "scaling": "never",
  "effects": "magic",
  "death_message_type": "default"
}
```

#### 2. 伤害计算函数

`data/<namespace>/function/custom_damage/apply.mcfunction`
```mcfunction
# 用法：execute as <attacker> at @s run function <namespace>:custom_damage/apply {target: "<UUID>", base_damage: <float>}
# 参数通过宏传入

# 获取基础伤害
$scoreboard players set @s <namespace>.base_damage $(base_damage)

# 计算攻击者属性加成（示例：每级力量增加 50% 伤害）
execute store result score @s <namespace>.strength_level if entity @s[nbt={ActiveEffects:[{Id:5b}]}]
scoreboard players operation @s <namespace>.strength_level *= 50
scoreboard players operation @s <namespace>.strength_level /= 100
scoreboard players operation @s <namespace>.final_damage = @s <namespace>.base_damage
scoreboard players operation @s <namespace>.final_damage += @s <namespace>.strength_level

# 计算目标护甲减伤（示例：每点护甲减少 4% 伤害）
execute store result score @s <namespace>.target_armor as $(target) run attribute @s minecraft:generic.armor get
scoreboard players operation @s <namespace>.armor_reduction = @s <namespace>.target_armor
scoreboard players operation @s <namespace>.armor_reduction *= 4
scoreboard players operation @s <namespace>.final_damage *= @s <namespace>.armor_reduction
scoreboard players operation @s <namespace>.final_damage /= 100

# 应用伤害
$execute as $(target) run damage @s <namespace>.final_damage <namespace>:custom_physical by @s
```

#### 3. 调用示例

```mcfunction
# 玩家对目标造成 10 点基础伤害
execute as @p at @s run function <namespace>:custom_damage/apply {target: "@e[type=minecraft:zombie,limit=1,sort=nearest]", base_damage: 10}
```

### 陷阱与注意事项

1. **宏参数限制**：宏参数必须是字符串，UUID 需要以字符串形式传入。对于实体选择器，需要确保在函数执行时选择器有效。

2. **伤害类型 JSON 的 `scaling` 字段**：
   - `"never"`：伤害值不随难度缩放
   - `"when_caused_by_living_non_player"`：当伤害来源是非玩家生物时缩放
   - `"when_caused_by_player"`：当伤害来源是玩家时缩放
   - 需要根据需求选择合适的缩放策略

3. **`damage` 命令的伤害来源**：
   - `by @s`：伤害来源是执行者自己
   - `from @s`：伤害来源是执行者，但伤害类型不同（如弹射物）
   - 需要根据实际场景选择合适的来源

4. **性能开销**：较低。`damage` 命令是原生的伤害应用方式，效率高。但复杂的 scoreboard 计算会增加开销。

## 方案三：基于 `execute on` + 实体交互的伤害模拟（1.19+）

**适用版本**：1.19+（`execute on` 于 1.19 引入）
**推荐程度**：⭐⭐⭐（适用于特殊场景，如区域伤害、持续伤害）

### 原理

1. 使用 `execute on` 在实体位置执行命令
2. 通过 `effect give` 给予瞬间伤害效果来模拟伤害
3. 结合 `predicate` 和 `scoreboard` 实现条件判断
4. 适用于范围伤害、持续伤害等场景

### 完整代码

#### 1. 范围伤害函数

`data/<namespace>/function/custom_damage/area_damage.mcfunction`
```mcfunction
# 用法：在目标位置执行，对半径 5 格内的所有实体造成伤害
# 参数：$(damage) - 伤害值，$(radius) - 半径

# 获取范围内的所有实体
$execute as @e[distance=..$(radius),type=!minecraft:player] at @s run function <namespace>:custom_damage/apply_to_entity {damage: $(damage)}

# 对玩家单独处理（避免误伤）
$execute as @a[distance=..$(radius)] at @s run function <namespace>:custom_damage/apply_to_player {damage: $(damage)}
```

`data/<namespace>/function/custom_damage/apply_to_entity.mcfunction`
```mcfunction
# 对非玩家实体应用伤害
$effect give @s minecraft:instant_damage 1 0
```

`data/<namespace>/function/custom_damage/apply_to_player.mcfunction`
```mcfunction
# 对玩家应用伤害（使用 damage 命令以获得更好的控制）
$damage @s $(damage) minecraft:generic
```

#### 2. 持续伤害区域

`data/<namespace>/function/custom_damage/poison_zone.mcfunction`
```mcfunction
# 每 tick 执行，对区域内的实体造成持续伤害

# 在区域中心放置一个 marker 实体
execute positioned <x> <y> <z> run function <namespace>:custom_damage/area_damage {damage: 1, radius: 3}
```

### 陷阱与注意事项

1. **`instant_damage` 对非玩家实体的限制**：
   - 对亡灵生物（僵尸、骷髅等）是治疗效果
   - 对末影龙、凋灵等 Boss 生物无效
   - 无法精确控制伤害值（只能按等级递增）

2. **`damage` 命令对非玩家实体的限制**：
   - 1.20.5+ 的 `damage` 命令可以应用于任何实体
   - 但需要确保伤害类型 JSON 已定义

3. **性能开销**：中高。每 tick 对范围内所有实体执行命令，范围越大开销越高。

## 方案对比

| 特性 | 方案一（entity_hurt_player） | 方案二（damage 命令） | 方案三（execute on） |
|------|------------------------------|----------------------|---------------------|
| 最低版本 | 1.16 | 1.20.5 | 1.19 |
| 伤害精确控制 | 低（无法获取精确值） | 高（完全可控） | 中（受效果限制） |
| 自定义伤害类型 | 否 | 是 | 否（仅原版类型） |
| 伤害来源追踪 | 有限 | 完整 | 有限 |
| 性能开销 | 中 | 低 | 中高 |
| 适用场景 | 玩家伤害拦截 | 完整自定义伤害系统 | 范围/持续伤害 |
| 复杂度 | 中 | 高 | 低 |

## 推荐方案

- **1.20.5+ 新项目**：方案二（damage 命令 + 自定义伤害类型），最灵活、性能最好
- **1.16-1.20.4 兼容项目**：方案一（entity_hurt_player），但需要接受伤害值控制的局限性
- **简单范围伤害**：方案三（execute on），实现简单，但控制力有限

## 进阶技巧

### 伤害免疫帧处理

原版实体有伤害免疫帧（0.5 秒内不会重复受到伤害），自定义伤害系统需要处理这个问题：

```mcfunction
# 在应用伤害前，先清除目标的伤害免疫
# ⚠️ 需验证：1.20.5+ 是否支持通过 data modify 清除 hurtTimestamp
data modify entity @s HurtTimestamp set value 0
```

### 伤害日志记录

```mcfunction
# 记录伤害事件到 storage
$data modify storage <namespace>:damage_log list append value {attacker: "$(attacker)", target: "$(target)", damage: $(damage), type: "$(type)"}
```

### 伤害类型免疫

```mcfunction
# 检查目标是否免疫某种伤害类型
$execute if predicate <namespace>:immune_to_fire run return fail
```
