# 如何做镜头震动

## 一、核心挑战

Minecraft 原版数据包无法直接控制玩家视角（Camera）的位置或旋转。镜头震动（Screen Shake）在数据包层面只能通过**间接手段**模拟，无法像模组那样直接修改渲染矩阵。所有方案本质上都是“欺骗”玩家的感知，而非真正移动摄像机。

## 二、方案一：使用 `/camera` 命令（1.21.2+）

### 原理

1.21.2 版本引入了 `/camera` 命令，可以设置玩家的摄像机视角。通过 `minecraft:follow_orbit` 预设（preset），可以创建一个围绕目标实体旋转的摄像机，并利用其 `offset` 参数实现震动效果。

### 完整代码

#### 1. 创建震动预设（数据包内）

`<namespace>/camera_preset/screen_shake.json`
```json
{
  "type": "minecraft:follow_orbit",
  "name": {
    "text": "Screen Shake",
    "color": "gray"
  },
  "arguments": {
    "target": {
      "type": "minecraft:entity",
      "entity": "this"
    },
    "offset": {
      "x": 0.0,
      "y": 0.0,
      "z": 0.0
    },
    "radius": 0.0,
    "rotation": {
      "x": 0.0,
      "y": 0.0
    },
    "speed": 1.0
  },
  "effects": {
    "minecraft:shaking": {
      "intensity": 0.5,
      "frequency": 10.0
    }
  }
}
```

#### 2. 触发震动（mcfunction）

```mcfunction
# 对指定玩家应用震动预设
camera @p set minecraft:follow_orbit <namespace>:screen_shake

# 如果需要持续震动，可以在 tick 中不断更新 offset
# 例如：每 tick 随机偏移
execute as @a[predicate=<namespace>:is_shaking] at @s run function <namespace>:shake_tick
```

`<namespace>/function/shake_tick.mcfunction`
```mcfunction
# 生成随机偏移（使用 scoreboard 随机数）
scoreboard players random @s shake_x -2 2
scoreboard players random @s shake_y -2 2
scoreboard players random @s shake_z -2 2

# 将分数转换为浮点数并应用到 camera
execute store result storage <namespace>:temp shake_x double 0.1 run scoreboard players get @s shake_x
execute store result storage <namespace>:temp shake_y double 0.1 run scoreboard players get @s shake_y
execute store result storage <namespace>:temp shake_z double 0.1 run scoreboard players get @s shake_z

# 更新 camera 的 offset
camera @s modify offset <namespace>:temp.shake_x <namespace>:temp.shake_y <namespace>:temp.shake_z
```

#### 3. 停止震动

```mcfunction
# 重置为默认视角
camera @p reset
```

### 陷阱与注意事项

1. **版本限制**：`/camera` 命令仅在 1.21.2+ 可用，且 `follow_orbit` 预设的 `shaking` 效果是 1.21.4 才加入的 ⚠️ 需验证。如果使用 1.21.2-1.21.3，只能通过手动更新 offset 模拟震动。
2. **性能开销**：每 tick 更新 offset 会产生中等开销（约 0.1-0.3ms/玩家），建议仅在需要时启用，不要全局 tick。
3. **玩家控制**：使用 `follow_orbit` 预设会锁定玩家视角，玩家无法自由旋转镜头。需要配合 `allow_movement` 参数（如果存在）或手动处理。
4. **多人同步**：每个玩家独立应用 camera，震动效果不会同步，这是正常行为。

## 三、方案二：使用实体旋转 + 玩家视角绑定（1.16+）

### 原理

通过创建一个隐形的标记实体（marker），让玩家持续看向该实体（使用 `/execute as @p at @s facing entity <marker>`），然后让标记实体做随机运动，从而带动玩家视角晃动。

### 完整代码

#### 1. 创建震动标记实体

`<namespace>/function/shake/start.mcfunction`
```mcfunction
# 在玩家位置生成标记实体
summon marker ~ ~ ~ {Tags:["shake_marker","shake_<UUID>"]}

# 将标记实体与玩家绑定（通过 UUID 或记分板）
scoreboard players set @e[tag=shake_marker,limit=1] shake_target <player_id>

# 开始 tick 循环
schedule function <namespace>:shake/tick 1t replace
```

#### 2. 每 tick 更新标记位置并让玩家看向它

`<namespace>/function/shake/tick.mcfunction`
```mcfunction
# 获取所有活跃的震动标记
execute as @e[tag=shake_marker] at @s run function <namespace>:shake/move_marker

# 让绑定的玩家看向标记
execute as @p[scores={shake_id=..}] at @s run function <namespace>:shake/look_at

# 继续循环（直到停止）
schedule function <namespace>:shake/tick 1t replace
```

`<namespace>/function/shake/move_marker.mcfunction`
```mcfunction
# 生成随机偏移（使用 scoreboard）
scoreboard players random @s shake_dx -3 3
scoreboard players random @s shake_dy -3 3
scoreboard players random @s shake_dz -3 3

# 应用偏移（相对移动）
execute store result entity @s Pos[0] double 0.1 run scoreboard players get @s shake_dx
execute store result entity @s Pos[1] double 0.1 run scoreboard players get @s shake_dy
execute store result entity @s Pos[2] double 0.1 run scoreboard players get @s shake_dz

# 注意：这里需要相对移动，但直接设置 Pos 是绝对坐标
# 正确做法：使用 /tp 相对移动
tp @s ~0.3 ~0.3 ~0.3
```

`<namespace>/function/shake/look_at.mcfunction`
```mcfunction
# 让玩家看向对应的标记实体
execute as @p at @s facing entity @e[tag=shake_marker,scores={shake_target=<player_id>},limit=1] eyes run tp @s ~ ~ ~
```

#### 3. 停止震动

`<namespace>/function/shake/stop.mcfunction`
```mcfunction
# 移除标记实体
kill @e[tag=shake_marker]

# 取消循环
schedule clear <namespace>:shake/tick
```

### 陷阱与注意事项

1. **视角锁定**：玩家会被强制看向标记实体，无法自由转动视角。这通常不可接受，除非是过场动画场景。
2. **性能开销**：每 tick 执行 `facing entity` 和 `tp` 命令，开销较高（约 0.5-1ms/玩家），且会干扰玩家输入。
3. **平滑度问题**：随机移动会导致视角抖动不自然，需要额外的插值逻辑。
4. **版本兼容**：1.16+ 可用，但 marker 实体在 1.17 才引入，1.16 可使用 area_effect_cloud 替代。
5. **多人同步**：每个玩家独立绑定标记，互不干扰。

## 四、方案三：使用资源包 + 着色器（1.17+）

### 原理

通过资源包自定义着色器（shader），在渲染层面添加屏幕扭曲效果。数据包负责触发资源包的切换或着色器的启用/禁用。

### 完整代码

#### 1. 资源包结构

```
resources/
├── assets/
│   └── minecraft/
│       └── shaders/
│           ├── post/
│           │   └── screen_shake.json
│           └── program/
│               └── screen_shake.json
```

`assets/minecraft/shaders/post/screen_shake.json`
```json
{
  "targets": [
    "swap",
    "main"
  ],
  "passes": [
    {
      "name": "screen_shake",
      "intarget": "main",
      "outtarget": "swap",
      "uniforms": [
        {
          "name": "ShakeIntensity",
          "values": [0.05, 0.05]
        },
        {
          "name": "ShakeFrequency",
          "values": [10.0]
        }
      ]
    },
    {
      "name": "blit",
      "intarget": "swap",
      "outtarget": "main"
    }
  ]
}
```

`assets/minecraft/shaders/program/screen_shake.json`
```json
{
  "blend": {
    "func": "add",
    "srcrgb": "srcalpha",
    "dstrgb": "1-srcalpha"
  },
  "vertex": "blobscreen",
  "fragment": "screen_shake",
  "attributes": ["Position"],
  "samplers": ["DiffuseSampler"],
  "uniforms": [
    {
      "name": "ShakeIntensity",
      "type": "float",
      "count": 2,
      "values": [0.05, 0.05]
    },
    {
      "name": "ShakeFrequency",
      "type": "float",
      "count": 1,
      "values": [10.0]
    }
  ]
}
```

`assets/minecraft/shaders/program/screen_shake.fsh`（GLSL 片段着色器）
```glsl
#version 150

uniform sampler2D DiffuseSampler;
uniform float Time;
uniform vec2 ShakeIntensity;
uniform float ShakeFrequency;

in vec2 texCoord;
out vec4 fragColor;

void main() {
    vec2 offset = vec2(
        sin(Time * ShakeFrequency) * ShakeIntensity.x,
        cos(Time * ShakeFrequency * 1.3) * ShakeIntensity.y
    );
    vec2 distortedCoord = texCoord + offset;
    fragColor = texture(DiffuseSampler, distortedCoord);
}
```

#### 2. 数据包触发

```mcfunction
# 启用着色器（需要玩家使用对应资源包）
execute as @a run function <namespace>:shader/enable
```

`<namespace>/function/shader/enable.mcfunction`
```mcfunction
# 通过 /shader 命令启用（1.17+）
shader enable minecraft:post/screen_shake
```

```mcfunction
# 禁用着色器
shader disable
```

### 陷阱与注意事项

1. **资源包依赖**：玩家必须加载包含着色器的资源包，否则无效。数据包无法强制玩家使用资源包。
2. **版本限制**：`/shader` 命令在 1.17 引入，但着色器系统在 1.19.4 有重大改动 ⚠️ 需验证。
3. **性能开销**：着色器在 GPU 上运行，开销极低（<0.01ms），但启用/禁用时有短暂卡顿。
4. **多人同步**：每个客户端独立渲染，无需同步。
5. **着色器复杂度**：复杂的着色器可能导致低端设备掉帧，建议保持简单。

## 五、方案对比

| 方案 | 最低版本 | 性能开销 | 效果真实度 | 玩家控制影响 | 适用场景 |
|------|----------|----------|------------|--------------|----------|
| `/camera` 命令 | 1.21.2 | 低-中 | 高 | 锁定视角 | 过场动画、爆炸冲击 |
| 实体旋转绑定 | 1.16 | 中-高 | 中 | 锁定视角 | 简单震动（不推荐） |
| 资源包着色器 | 1.17 | 极低 | 高 | 无影响 | 持续环境震动 |

## 六、推荐方案

**首选：`/camera` 命令（1.21.2+）**
- 官方支持，效果最好
- 性能开销可控
- 可精细控制震动参数

**备选：资源包着色器（1.17+）**
- 不影响玩家操作
- 性能最优
- 需要资源包配合

**不推荐：实体旋转绑定**
- 锁定玩家视角，体验差
- 性能开销高
- 仅作为无其他方案时的最后选择
