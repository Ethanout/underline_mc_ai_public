# 玩家数据持久化与同步

## Player ID 系统

给每个玩家分配唯一计分板 ID，用于索引 Storage 数据库中的玩家数据：

```mcfunction
# load
scoreboard objectives add <namespace> dummy
scoreboard objectives add <namespace>.id dummy
execute unless score id <namespace> matches -2147483648.. run scoreboard players set id <namespace> 0

# 首次加入分配 ID（懒加载触发，要用的时候运行）
# function first_join
execute unless score @s <namespace>.id matches -2147483648.. store result score @s <namespace>.id run scoreboard players add <namespace> id 1
```

## Storage 数据库模式

用 Storage 存储所有玩家数据的通用方案：

```json
{
  "player": [
    { "id": 1, "data": { "职业": "战士", "等级": 10 } },
    { "id": 2, "data": { "职业": "法师", "等级": 5 } }
  ]
}
```

顶层用 `player` 数组而非 `data`，避免与临时操作 Storage 重名。

### NBT 路径列表筛选

```mcfunction
# 按 ID 查找并修改
data modify storage <namespace>:data player[{id:2}].data.职业 set value "法师"
```

## 标准访问模式（读取-操作-写回，性能优化）

采用“读取-操作-写回”模式。原则：**尽量避免直接读写玩家实体 NBT**（性能开销大），转而利用宏将玩家数据从持久化 Storage 数组读取到临时 IO 空间，在 IO 空间完成复杂逻辑后再写回持久化 Storage。

### 读取到临时空间（宏）

`<namespace>:data/open.mcfunction`
```mcfunction
$data modify storage <namespace>:io player set from storage <namespace>:data player[{id:$(id)}]
```

### 操作临时空间（普通函数，无宏）

```mcfunction
# 例如：更新职业
data modify storage <namespace>:io player.data.职业 set value "弓箭手"
```

### 写回持久 Storage（宏）

`<namespace>:data/close.mcfunction`
```mcfunction
$data modify storage <namespace>:data player[{id:$(id)}] set from storage <namespace>:io player
```

### 调用示例

```mcfunction
# 入口
execute store result storage <namespace>:io id int 1 run scoreboard players get @s <namespace>.id
function <namespace>:data/open with storage <namespace>:io

# 此时 io player 包含该玩家完整数据，直接操作
data modify storage <namespace>:io player.data.职业 set value "弓箭手"

# 写回
function <namespace>:data/close with storage <namespace>:io
```

## 宏：路径参数化

如果需要动态指定操作路径（而非固定的修改），使用双层宏：

### 写入入口

`<namespace>:data/modify.mcfunction`
```mcfunction
# 自动分配 ID（如果还没有）
execute unless score @s <namespace>.id matches -2147483648.. store result score @s <namespace>.id run scoreboard players add <namespace> id 1
execute store result storage <namespace>:io id int 1 run scoreboard players get @s <namespace>.id
function <namespace>:data/modify/macro with storage <namespace>:io
```

### 宏函数

`<namespace>:data/modify/macro.mcfunction`
```mcfunction
$data modify storage <namespace>:data player[{id:$(id)}].$(op)
```

### 调用写入

```mcfunction
data modify storage <namespace>:io op set value "data.inv set from entity @s Inventory"
function <namespace>:data/modify
```

### 导出宏

`<namespace>:data/export/macro.mcfunction`
```mcfunction
$data modify $(op) from storage <namespace>:data player[{id:$(id)}].$(path)
```

### 调用导出

```mcfunction
data modify storage <namespace>:io op set value "storage <namespace>:io output set"
data modify storage <namespace>:io path set value "data.inv"
function <namespace>:data/export
```

## 初始化（Load）

在数据包加载时，需要初始化计分板、强加载区块以及必要的技术性实体：

```mcfunction
# load.mcfunction
# 1. 创建核心计分项
scoreboard objectives add <namespace> dummy
scoreboard objectives add <namespace>.id dummy

# 2. 强加载区块用于放置寄存器实体
execute in overworld run forceload add -1 -1 1 1

# 3. 检查并生成寄存器实体（用于物品物理交换等场景）
execute if entity a-b-c-d-2 run return 0
execute in overworld run return run summon item_display 0 0 0 {Tags:["<namespace>.persistent"],UUID:uuid("a-b-c-d-2"),view_range:0}
```

## 实战：背包自动同步

### 进度监听

`data/<namespace>/advancement/inv_changed.json`
```json
{
  "criteria": {
    "a": { "trigger": "minecraft:inventory_changed" }
  },
  "requirements": [["a"]],
  "rewards": { "function": "<namespace>:inv_sync" }
}
```

### 同步函数（open/close 模式）

```mcfunction
# inv_sync.mcfunction
execute store result storage <namespace>:io id int 1 run scoreboard players get @s <namespace>.id
function <namespace>:data/open with storage <namespace>:io

# 将玩家背包写入临时空间
data modify storage <namespace>:io player.data.inv set from entity @s Inventory

# 写回持久 Storage
function <namespace>:data/close with storage <namespace>:io

advancement revoke @s only <namespace>:inv_changed
```

## 宏易错点
1. `$` 必须在行首：`$data ...` 不是 `data $...`
2. `function ... with storage ...` 传的是整个花括号：`with storage <namespace>:io`（不是 `<namespace>:io id`）
3. `$()` 里只能写键名，不能写路径：`$(id)` 正确，`$(data.id)` 错误
