# 如何避免玩家破坏关卡

## 核心挑战

在 Minecraft 数据包开发的关卡/地图中，防止玩家破坏方块是保护建筑完整性的基本需求。核心挑战在于：
1. 原版没有直接的"禁止破坏"游戏规则（`mobGriefing` 只影响生物）
2. 需要区分"玩家"和"其他破坏来源"（如爆炸、水流、末影人）
3. 不同版本（1.16.5 / 1.20.5+）的可用机制差异较大
4. 需要平衡"保护强度"和"性能开销"

## 方案一：基于 `player_break_block` 进度的即时回滚（推荐，1.20.5+）

### 原理

利用 1.20.5 新增的 `player_break_block` 进度触发器，在玩家破坏方块的**瞬间**触发函数，通过 `setblock` 或 `fill` 命令立即恢复方块。该触发器在方块被破坏前触发，因此可以做到"看起来没被破坏过"。

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancement/
      anti_break.json
    function/
      anti_break/
        on_break.mcfunction
        restore.mcfunction
      load.mcfunction
      tick.mcfunction
```

#### 1. 进度定义
`data/<namespace>/advancement/anti_break.json`
```json
{
  "criteria": {
    "break_block": {
      "trigger": "minecraft:player_break_block",
      "conditions": {
        "player": {
          "location": {
            "dimension": "minecraft:overworld"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:anti_break/on_break"
  }
}
```

#### 2. 破坏处理函数
`data/<namespace>/function/anti_break/on_break.mcfunction`
```mcfunction
# 获取破坏的方块位置（通过 advancement 的 location 条件）
# 注意：player_break_block 触发时，方块已被标记为"即将破坏"，但尚未实际移除
# 我们可以通过存储玩家位置来获取破坏位置

# 方案A：使用 execute store 存储玩家位置
execute store result score #x <namespace>.var run data get entity @s Pos[0] 1000
execute store result score #y <namespace>.var run data get entity @s Pos[1] 1000
execute store result score #z <namespace>.var run data get entity @s Pos[2] 1000

# 方案B：使用 advancement 的 location 条件（更精确）
# 在 advancement 中已经限制了维度，这里直接使用玩家位置

# 恢复方块（需要知道被破坏的方块是什么）
# 这里假设我们有一个预定义的"保护方块列表"
# 实际应用中，可以在 load 时用 storage 存储所有受保护方块的坐标和类型

# 示例：恢复为石头
execute positioned as @s run setblock ~ ~ ~ minecraft:stone

# 撤销进度，以便下次触发

```

#### 3. 更完善的版本（使用 storage 记录受保护区域）
`data/<namespace>/function/anti_break/restore.mcfunction`
```mcfunction
# 从 storage 中读取受保护方块列表
# 假设 storage <namespace>:protected_blocks 中存储了所有受保护方块的坐标和类型

# 遍历所有受保护方块
execute store result score #i <namespace>.var run data get storage <namespace>:protected_blocks blocks
scoreboard players set #index <namespace>.var 0

# 循环恢复（需要递归函数或循环）
execute if score #index <namespace>.var < #i <namespace>.var run function <namespace>:anti_break/restore_loop
```

### 陷阱与注意事项

1. **版本要求**：`player_break_block` 触发器在 1.20.5 才引入，1.20.4 及以下版本不可用
2. **触发时机**：该触发器在方块被破坏**前**触发，但如果你在函数中执行 `setblock`，可能会与破坏逻辑冲突。建议使用 `schedule` 延迟 1 tick 恢复
3. **性能开销**：每次破坏都触发函数，如果玩家连续破坏，性能开销较高。建议配合 `gamemode` 检测，只对冒险模式玩家生效
4. **无法阻止破坏动画**：客户端会播放破坏动画，但方块会立即恢复，看起来像"闪烁了一下"
5. **创造模式玩家**：创造模式玩家不会触发此进度，需要额外处理

## 方案二：基于游戏规则和命令方块的全局保护（1.16.5+）

### 原理

利用 `gamerule doTileDrops false` 和 `gamerule mobGriefing false` 减少破坏来源，配合 `fill` 命令定期修复受保护区域。这是最古老但兼容性最好的方案。

### 完整实现

#### 1. 设置游戏规则
`data/<namespace>/function/load.mcfunction`
```mcfunction
gamerule doTileDrops false
gamerule mobGriefing false
gamerule doFireTick false
gamerule doMobLoot false
```

#### 2. 定期修复函数
`data/<namespace>/function/anti_break/repair.mcfunction`
```mcfunction
# 使用 fill 命令恢复受保护区域
# 注意：fill 命令会覆盖所有方块，包括玩家放置的
# 因此只适用于"完全禁止修改"的场景

# 示例：恢复坐标 (100, 64, 100) 到 (120, 80, 120) 为石头
fill 100 64 100 120 80 120 minecraft:stone replace minecraft:air
fill 100 64 100 120 80 120 minecraft:stone replace minecraft:cave_air
fill 100 64 100 120 80 120 minecraft:stone replace minecraft:void_air

# 也可以使用 replace 参数只替换特定方块
fill 100 64 100 120 80 120 minecraft:stone replace minecraft:dirt
```

#### 3. 定时执行
`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 每 20 tick（1秒）执行一次修复
schedule function <namespace>:anti_break/repair 20
```

### 陷阱与注意事项

1. **延迟修复**：方块被破坏后需要等待修复周期，玩家会看到"被破坏→恢复"的过程
2. **覆盖玩家放置**：如果玩家在受保护区域内放置方块，也会被覆盖
3. **性能开销**：`fill` 命令在大范围区域执行时性能开销较大，建议分区域、分 tick 执行
4. **无法阻止爆炸**：爆炸会破坏方块，但修复命令可以恢复。爆炸产生的掉落物会被 `doTileDrops false` 阻止
5. **无法阻止水流/岩浆**：水流和岩浆会破坏受保护区域，需要额外处理

## 方案三：基于 `player_interacted_with_entity` 的间接保护（1.16.5+）

### 原理

对于"玩家通过交互破坏方块"的场景（如使用斧头破坏木头、使用锄头耕地），可以通过检测玩家交互事件并取消交互效果来实现。但此方案**无法**阻止直接左键破坏。

### 完整实现

#### 1. 检测玩家交互
`data/<namespace>/advancement/anti_interact.json`
```json
{
  "criteria": {
    "interact": {
      "trigger": "minecraft:player_interacted_with_entity",
      "conditions": {
        "entity": {
          "type": "minecraft:item_frame"
        }
      }
    }
  },
  "rewards": {
    "function": "<namespace>:anti_break/on_interact"
  }
}
```

#### 2. 处理交互
`data/<namespace>/function/anti_break/on_interact.mcfunction`
```mcfunction
# 取消交互效果（例如：移除物品展示框中的物品）
execute as @e[type=minecraft:item_frame,distance=..5] run data remove entity @s Item

# 撤销进度
advancement revoke @s only <namespace>:anti_interact
```

### 陷阱与注意事项

1. **局限性**：只能阻止特定类型的交互破坏，无法阻止直接左键破坏
2. **版本差异**：`player_interacted_with_entity` 在 1.16.5 可用，但某些实体类型在不同版本中行为不同
3. **性能开销**：较低，只在交互时触发

## 方案四：基于 `player_break_block` 的预存储恢复（1.20.5+，推荐）

### 原理

在 load 时，将受保护区域的方块信息存储到 storage 中。当玩家破坏方块时，从 storage 中读取原始方块类型并恢复。这样可以精确恢复被破坏的方块，而不是统一恢复为一种方块。

### 完整实现

#### 1. 存储受保护区域
`data/<namespace>/function/load.mcfunction`
```mcfunction
# 使用 data modify 命令将受保护区域的方块数据存储到 storage
# 注意：这需要预先知道受保护区域的坐标

# 示例：存储一个 3x3x3 区域
data modify storage <namespace>:protected_blocks blocks set value []
data modify storage <namespace>:protected_blocks blocks append value {x:100,y:64,z:100,block:"minecraft:stone"}
data modify storage <namespace>:protected_blocks blocks append value {x:101,y:64,z:100,block:"minecraft:oak_planks"}
# ... 更多方块
```

#### 2. 破坏检测与恢复
`data/<namespace>/function/anti_break/on_break.mcfunction`
```mcfunction
# 获取破坏位置
execute store result score #x <namespace>.var run data get entity @s Pos[0] 1000
execute store result score #y <namespace>.var run data get entity @s Pos[1] 1000
execute store result score #z <namespace>.var run data get entity @s Pos[2] 1000

# 从 storage 中查找对应位置的方块
# 这里简化处理：直接使用预定义的恢复函数
function <namespace>:anti_break/restore_block

# 撤销进度
advancement revoke @s only <namespace>:anti_break
```

`data/<namespace>/function/anti_break/restore_block.mcfunction`
```mcfunction
# 根据坐标恢复方块
# 注意：这里需要根据实际存储的数据来写
# 示例：如果坐标在 (100,64,100) 则恢复为石头
execute if score #x <namespace>.var matches 100 if score #y <namespace>.var matches 64 if score #z <namespace>.var matches 100 run setblock 100 64 100 minecraft:stone
execute if score #x <namespace>.var matches 101 if score #y <namespace>.var matches 64 if score #z <namespace>.var matches 100 run setblock 101 64 100 minecraft:oak_planks
# ... 更多条件
```

### 陷阱与注意事项

1. **存储开销**：如果受保护区域很大，storage 中的数据量会很大，影响加载性能
2. **坐标精度**：使用 `Pos` 获取玩家位置时，需要转换为整数坐标。建议使用 `execute positioned` 配合 `~ ~ ~` 相对坐标
3. **多维度支持**：需要确保只在受保护维度生效
4. **⚠️ 需验证**：`player_break_block` 触发时，`@s` 的位置是否精确到破坏的方块位置？还是玩家身体位置？根据文档，该触发器在方块被破坏前触发，位置应该是玩家位置而非方块位置

## 方案对比

| 方案 | 版本要求 | 性能开销 | 保护强度 | 适用场景 |
|------|---------|---------|---------|---------|
| 方案一：player_break_block 即时回滚 | 1.20.5+ | 中（每次破坏触发） | 高（即时恢复） | 需要精确保护特定方块 |
| 方案二：游戏规则+定期修复 | 1.16.5+ | 高（定期执行 fill） | 中（有延迟） | 全局保护，不介意延迟 |
| 方案三：交互检测 | 1.16.5+ | 低 | 低（仅限交互破坏） | 保护物品展示框等实体 |
| 方案四：预存储恢复 | 1.20.5+ | 中高（存储+恢复） | 高（精确恢复） | 需要精确恢复不同方块类型 |

## 最佳实践建议

1. **对于新版本（1.20.5+）**：使用方案一或方案四，配合 `gamemode` 检测，只对冒险模式玩家生效
2. **对于旧版本（1.16.5-1.20.4）**：使用方案二，配合 `fill` 命令定期修复
3. **混合使用**：方案一 + 方案二，方案一处理即时破坏，方案二作为兜底修复
4. **性能优化**：
   - 将受保护区域分成多个小区域，每个 tick 只修复一个区域
   - 使用 `execute if block` 先检测方块是否被破坏，再执行修复
   - 避免在 tick 函数中执行大量 `fill` 命令

## 陷阱总结

1. **创造模式玩家**：所有方案都无法阻止创造模式玩家破坏方块。需要在 load 时设置 `defaultgamemode adventure`，并在 tick 中检测玩家模式
2. **爆炸破坏**：方案一无法阻止爆炸破坏，需要配合 `gamerule mobGriefing false`
3. **水流/岩浆**：需要额外处理，例如在受保护区域周围放置屏障
4. **红石破坏**：活塞推动、TNT 爆炸等红石机制可能绕过保护
5. **性能陷阱**：不要在 tick 函数中对大范围执行 `fill` 命令，会导致严重卡顿
