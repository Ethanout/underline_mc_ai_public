# 如何做组合输入

## 核心挑战

组合输入（如 Shift+W、Ctrl+Q、同时按下多个键）在原版 Minecraft 数据包中面临两个根本限制：

1. **原版输入谓词只支持单键检测**：`InputPredicate` 只能检测 `forward`、`backward`、`left`、`right`、`jump`、`sneak`、`sprint` 这 7 个键的按下状态，无法检测组合（如同时按 W 和 Shift）。
2. **没有"按键事件"系统**：Minecraft 没有提供"按下 A 键时触发"的机制，只能通过持续检测状态变化来推断按键事件。

因此，组合输入的核心思路是：**分别检测每个键的状态，然后通过逻辑组合判断是否同时按下**。

---

## 方案一：基于 `InputPredicate` 的持续状态检测（推荐）

### 原理

利用进度（advancement）的 `tick` 触发条件，配合 `InputPredicate` 检测玩家当前帧的按键状态。通过比较前后帧的状态变化，可以判断"某个键是否被按下"以及"多个键是否同时被按下"。

核心机制：
- 使用 `minecraft:tick` 触发器每 tick（1/20 秒）检测一次
- 在 `InputPredicate` 中指定需要检测的按键组合
- 通过 storage 存储上一帧的状态，比较后触发事件

### 适用版本

1.20.5+（`InputPredicate` 在 1.20.5 引入）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancement/
      input/
        shift_forward.json      # 检测 Shift+W
        shift_jump.json         # 检测 Shift+Space
    function/
      input/
        tick.mcfunction         # 每 tick 执行
        on_shift_forward.mcfunction  # 触发事件
        on_shift_jump.mcfunction     # 触发事件
      load.mcfunction           # 初始化
```

#### 1. 进度文件：检测 Shift+W

`data/<namespace>/advancement/input/shift_forward.json`
```json
{
  "criteria": {

      "trigger": "minecraft:tick",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",

}
```

#### 3. 触发函数：Shift+W 按下

`data/<namespace>/function/input/on_shift_forward.mcfunction`
```mcfunction
# 检查是否已经触发过（防止每 tick 重复触发）
scoreboard players get @s <namespace>.input_cooldown
execute if score @s <namespace>.input_cooldown matches 1.. run return

# 设置冷却（1 tick 后重置，确保只触发一次）
scoreboard players set @s <namespace>.input_cooldown 1

# 执行组合输入逻辑
say 我按下了 Shift+W！

# 撤销进度，防止下次 tick 再次触发（因为进度已达成）
advancement revoke @s only <namespace>:input/shift_forward
```

#### 4. 冷却重置函数（每 tick 执行）

`data/<namespace>/function/input/tick.mcfunction`
```mcfunction
# 减少冷却值
scoreboard players remove @a[scores={<namespace>.input_cooldown=1..}] <namespace>.input_cooldown 1

# 重新授予进度（使下次 tick 可以再次触发）
advancement grant @a only <namespace>:input/shift_forward
advancement grant @a only <namespace>:input/shift_jump
```

#### 5. 初始化

`data/<namespace>/function/load.mcfunction`
```mcfunction
scoreboard objectives add <namespace>.input_cooldown dummy
```

### 陷阱与注意事项

1. **每 tick 触发问题**：进度达成后，如果不撤销，每次 tick 都会触发。必须使用冷却机制或撤销进度来确保只触发一次。
2. **性能开销**：每个组合输入需要独立的进度文件。如果有 10 种组合，就需要 10 个进度，每 tick 检查 10 次。开销中等。
3. **无法检测"按下瞬间"**：`tick` 触发器检测的是"当前帧的状态"，无法区分"刚按下"和"持续按住"。如果需要检测"按下事件"（而非"按住状态"），需要结合 storage 存储上一帧状态进行比较。
4. **版本限制**：仅 1.20.5+ 可用。

## 方案二：基于 `inventory_changed` 的间接检测（备选）

### 原理

利用物品栏变化作为触发点，结合 `InputPredicate` 在触发时检测按键状态。适用于"玩家打开背包时按特定键"的场景（如 Ctrl+Q 丢弃物品）。

核心机制：
- 使用 `minecraft:inventory_changed` 触发器
- 在触发条件中通过 `InputPredicate` 检测按键组合
- 当物品栏变化且按键组合满足时触发

### 适用版本

1.20.5+（`InputPredicate` 要求）

### 完整实现

#### 检测 Ctrl+Q 丢弃物品

`data/<namespace>/advancement/input/ctrl_q_drop.json`
```json
{
  "criteria": {
    "check_drop": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "input": {
                "sneak": false,
                "forward": false,
                "backward": false,
                "left": false,
                "right": false,
                "jump": false,
                "sprint": false
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:input/on_ctrl_q"
  }
}
```

`data/<namespace>/function/input/on_ctrl_q.mcfunction`
```mcfunction
# 注意：Ctrl+Q 在 Minecraft 中默认是"丢弃整组物品"
# 这个进度会在丢弃物品时触发，但无法区分是 Q 还是 Ctrl+Q
# 需要额外逻辑判断

say 检测到物品丢弃（可能是 Q 或 Ctrl+Q）

# 撤销进度
advancement revoke @s only <namespace>:input/ctrl_q_drop
```

### 陷阱与注意事项

1. **无法区分 Q 和 Ctrl+Q**：`InputPredicate` 只能检测 7 个键，Ctrl 键不在其中。因此无法直接区分普通 Q 和 Ctrl+Q。
2. **触发时机**：`inventory_changed` 在物品栏变化后触发，此时按键可能已经释放，导致 `InputPredicate` 检测失败。
3. **性能开销**：物品栏变化频率较低，性能开销小。
4. **适用场景有限**：只适用于与物品栏操作相关的组合输入。

## 方案三：基于 `effects_changed` 的间接检测（实验性）

### 原理

利用状态效果变化作为触发点，结合 `InputPredicate` 检测按键。适用于"玩家喝药水时按特定键"等场景。

### 适用版本

1.20.5+

### 完整实现

`data/<namespace>/advancement/input/drink_with_shift.json`
```json
{
  "criteria": {
    "check_drink": {
      "trigger": "minecraft:effects_changed",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "input": {
                "sneak": true
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:input/on_drink_shift"
  }
}
```

### 陷阱与注意事项

1. **触发条件苛刻**：需要玩家同时喝药水并按住 Shift，实际使用场景极少。
2. **性能开销**：低。
3. **不推荐用于通用组合输入**。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|---------|------|------|
| 方案一：`tick` + `InputPredicate` | 1.20.5+ | 中（每 tick 检查） | 通用组合输入（Shift+W、Shift+Space 等） | 实时检测，精度高 | 需要冷却机制防止重复触发 |
| 方案二：`inventory_changed` + `InputPredicate` | 1.20.5+ | 低 | 物品栏操作相关组合 | 触发频率低，性能好 | 无法区分 Ctrl 键，触发时机可能滞后 |
| 方案三：`effects_changed` + `InputPredicate` | 1.20.5+ | 低 | 状态效果相关组合 | 触发频率极低 | 适用场景极其有限 |

---

## 总结

- **推荐方案一**：对于大多数组合输入需求（如 Shift+W 奔跑、Shift+Space 跳跃），使用 `tick` + `InputPredicate` 是最直接有效的方法。
- **方案二和方案三**：仅适用于特定场景，不推荐作为通用方案。
- **版本限制**：所有方案都依赖 1.20.5+ 引入的 `InputPredicate`，旧版本无法实现原版组合输入检测。
