# 如何做敌人死亡流程

## 核心挑战

在 Minecraft 原版数据包中实现"敌人死亡流程"面临几个核心问题：
1. **原版没有"实体死亡事件"**——你不能直接监听一个实体何时死亡
2. **死亡动画与掉落物生成是原版机制**——数据包无法阻止或修改原版死亡动画
3. **需要区分"玩家击杀"与"环境死亡"**——不同来源需要不同处理
4. **性能开销**——高频 tick 检测所有敌人可能造成卡顿

## 方案一：基于 `player_killed_entity` 进度的击杀检测（推荐）

### 原理

利用原版进度触发器 `player_killed_entity`，当玩家杀死指定实体时自动触发。这是最直接、性能最好的方案，因为它是事件驱动的，不需要 tick 循环检测。

### 版本要求

- `player_killed_entity`：1.16+ 引入
- `entity_properties` 谓词（用于精确匹配 NBT）：1.15+
- `check_tag` 谓词（用于检测自定义标签）：1.20.5+

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    advancement/
      kill_enemy.json
    function/
      enemy/
        on_death.mcfunction
        on_death_by_player.mcfunction
        on_death_by_environment.mcfunction
      load.mcfunction
    predicate/
      is_custom_enemy.json
```

#### 1. 定义自定义敌人标记

在生成敌人时，给实体添加自定义标签（Scoreboard tag 或 NBT tag）：

```mcfunction
# function: <namespace>:spawn/enemy.mcfunction
summon minecraft:zombie ~ ~ ~ {Tags:["<namespace>.enemy"],Health:20f}
```

#### 2. 创建检测谓词

`data/<namespace>/predicate/is_custom_enemy.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "nbt": "{Tags:[\"<namespace>.enemy\"]}"
  }
}
```

⚠️ **需验证**：`entity_properties` 中的 `nbt` 字段在 1.20.5+ 是否仍然支持。如果使用 1.20.5+，建议改用 `check_tag` 谓词：

`data/<namespace>/predicate/is_custom_enemy_tag.json` (1.20.5+)
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "type_specific": {
      "type": "any",
      "check_tag": "<namespace>.enemy"
    }
  }
}
```

#### 3. 创建击杀进度

`data/<namespace>/advancement/kill_enemy.json`
```json
{

    "kill_custom_enemy": {
      "trigger": "minecraft:player_killed_entity",
      "conditions": {
        "entity": [
          {
            "condition": "minecraft:reference",
            "name": "<namespace>:is_custom_enemy"
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:enemy/on_death"
  }
}
```

#### 4. 死亡处理函数

`data/<namespace>/function/enemy/on_death.mcfunction`
```mcfunction
# 此时 @s 是击杀者（玩家），被杀死的实体已经死亡
# 我们需要通过 advancement 的 context 获取被杀死的实体信息

# 方案A：使用 advancement 的 entity 上下文（1.20+）
# 在 advancement 中，entity 上下文指向被杀死的实体
# 但实体已经死亡，无法直接操作

# 方案B：在击杀前标记实体（推荐）
# 在生成敌人时，给实体绑定一个"死亡标记"的 advancement
# 或者使用 scoreboard 记录

# 实际常用做法：在 tick 中检测实体死亡
# 见方案二

# 这里只做简单的奖励发放
give @s minecraft:emerald 1
```

### 陷阱与注意事项

1. **实体已死亡**：当进度触发时，被杀死的实体已经消失，无法直接操作其掉落物或位置
2. **无法区分击杀来源**：`player_killed_entity` 只能检测玩家击杀，无法检测环境死亡（摔落、岩浆等）
3. **进度重复触发**：同一个实体被多次击杀不会重复触发（实体已死），但不同实体可以
4. **进度需要 revoke**：如果玩家已经获得该进度，后续击杀不会再次触发，需要在奖励函数中 revoke

```mcfunction
# 在 on_death.mcfunction 末尾添加
advancement revoke @s only <namespace>:kill_enemy
```

## 方案二：基于 Tick 循环检测实体死亡（通用方案）

### 原理

在每一 tick 中遍历所有自定义敌人，检查其 `Health` 是否 ≤ 0，或者检查 `DeathTime` 是否 > 0（表示正在播放死亡动画）。这是最通用的方案，可以处理任何死亡原因。

### 版本要求

- 1.13+（函数系统）
- 1.20.5+ 的 `execute if entity` 支持更精确的 NBT 匹配

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    function/
      tick.mcfunction
      enemy/
        check_death.mcfunction
        on_death.mcfunction
        on_death_by_player.mcfunction
        on_death_by_environment.mcfunction
      load.mcfunction
```

#### 1. 注册 tick 函数

`data/minecraft/tags/function/tick.json`
```json
{
  "values": [
    "<namespace>:tick"
  ]
}
```

#### 2. 主 tick 函数

`data/<namespace>/function/tick.mcfunction`
```mcfunction
# 每 tick 检测所有自定义敌人
execute as @e[tag=<namespace>.enemy] at @s run function <namespace>:enemy/check_death
```

#### 3. 死亡检测函数

`data/<namespace>/function/enemy/check_death.mcfunction`
```mcfunction
# 检查实体是否死亡（Health <= 0 或 DeathTime > 0）
# 使用 DeathTime > 0 更可靠，因为 Health 可能在死亡瞬间被修改

# 方法1：检测 DeathTime（1.13+）
execute if entity @s[nbt={DeathTime:0s}] run return fail
# 如果 DeathTime > 0，说明实体正在死亡动画中

# 方法2：检测 Health（1.13+）
# execute if entity @s[nbt={Health:0f}] run ...

# 标记为"正在死亡"，防止重复触发
tag @s add <namespace>.dying

# 执行死亡逻辑
function <namespace>:enemy/on_death
```

#### 4. 死亡处理函数

`data/<namespace>/function/enemy/on_death.mcfunction`
```mcfunction
# @s 是正在死亡的实体
# 此时实体还在世界中（死亡动画中），可以获取位置等信息

# 记录死亡位置
execute store result score $death_x <namespace> run data get entity @s Pos[0] 1000
execute store result score $death_y <namespace> run data get entity @s Pos[1] 1000
execute store result score $death_z <namespace> run data get entity @s Pos[2] 1000

# 判断击杀来源
# 检查 last_damage 的 attacker（1.20.5+）
execute if entity @s[nbt={HurtByTimestamp:0s}] run function <namespace>:enemy/on_death_by_environment
execute if entity @s[nbt={HurtByTimestamp:0s}] run return fail

# 获取最近伤害来源（1.20.5+）
data get entity @s LastDamageSource

# 如果是玩家击杀
execute if entity @s[nbt={LastDamageSource:{IsPlayer:1b}}] run function <namespace>:enemy/on_death_by_player

# 清除标记（实体死亡后会自动消失，但为了保险）
tag @s remove <namespace>.enemy
tag @s remove <namespace>.dying
```

#### 5. 玩家击杀处理

`data/<namespace>/function/enemy/on_death_by_player.mcfunction`
```mcfunction

# 需要找到击杀者

# 方法1：通过 scoreboard 记录最近伤害者（需要额外设置）
# 在伤害事件中记录

# 方法2：通过 advancement 配合（见方案一）

# 方法3：使用 LastDamageSource 获取（1.20.5+）
# ⚠️ 需验证：LastDamageSource 在实体死亡后是否仍然可用
execute store result score $attacker_id <namespace> run data get entity @s LastDamageSource.SourceEntityId

# 通过 ID 找到实体
execute if score $attacker_id <namespace> matches 0.. run function <namespace>:enemy/find_attacker

### 陷阱与注意事项

1. **性能开销**：每 tick 遍历所有敌人，如果有大量敌人（>100），可能造成性能问题。建议：
   - 限制检测频率（每 2-5 tick 检测一次）
   - 使用 `@e[tag=<namespace>.enemy,limit=50]` 分批处理

2. **死亡动画期间**：实体在 `DeathTime` > 0 时仍然存在，但无法交互。如果需要在死亡动画期间执行操作（如播放粒子），需要额外处理。

3. **重复触发**：`DeathTime` 会从 0 增加到 20（1秒），如果不加标记，会在 20 tick 内重复触发。必须使用 tag 标记已处理的实体。

4. **实体消失**：死亡动画结束后实体自动消失，无法在之后获取其数据。

## 方案三：基于伤害事件的死亡检测（1.20.5+）

### 原理

利用 1.20.5 引入的 `minecraft:entity_hurt_player` 和 `minecraft:player_hurt_entity` 进度触发器，在伤害发生时预判死亡。结合 `execute on` 上下文获取伤害来源。

### 版本要求

- 1.20.5+（需要 `player_hurt_entity` 触发器和 `execute on` 上下文）

### 陷阱与注意事项

1. **版本限制**：仅 1.20.5+ 可用
2. **伤害瞬间检测**：在伤害应用后立即检测，此时实体可能还没进入死亡动画
3. **多次伤害**：如果实体被多次伤害，每次都会触发进度，需要避免重复处理
4. **环境伤害**：无法检测非玩家造成的伤害（摔落、岩浆等）

## 方案对比

| 方案 | 版本要求 | 性能 | 适用场景 | 优点 | 缺点 |
|------|---------|------|---------|------|------|
| 方案一：player_killed_entity | 1.16+ | 极低（事件驱动） | 仅需玩家击杀奖励 | 性能最好，原生支持 | 无法处理环境死亡，实体已消失 |
| 方案二：Tick 循环检测 | 1.13+ | 中（每 tick 遍历） | 需要完整死亡流程控制 | 通用性强，可处理所有死亡原因 | 性能开销随敌人数量增加 |
| 方案三：伤害事件预判 | 1.20.5+ | 低（事件驱动） | 需要精确的击杀来源 | 性能好，可获取伤害来源 | 版本限制，需要额外处理未死亡情况 |

## 最佳实践建议

### 小型项目（< 50 个敌人同时存在）
使用方案二（Tick 循环），配合方案一（player_killed_entity）做玩家击杀奖励。

### 大型项目（> 100 个敌人同时存在）
使用方案一（player_killed_entity）处理玩家击杀，方案二（Tick 循环）每 5 tick 检测一次处理环境死亡。

### 1.20.5+ 项目
优先使用方案三（伤害事件预判），配合方案二做兜底检测。

## 常见问题

### Q: 如何防止实体死亡后掉落物？
A: 无法完全阻止原版掉落物，但可以通过以下方式减少：
- 使用 `DeathLootTable: "minecraft:empty"` 设置空战利品表
- 在死亡检测函数中立即清除掉落物（`kill @e[type=item,distance=..1]`）

### Q: 如何实现死亡动画？
A: 原版实体有内置死亡动画（`DeathTime` 从 0 到 20）。如果需要自定义动画：
- 在 `DeathTime` 为 1 时设置 `NoGravity:1b` 防止掉落
- 使用 `data merge entity @s {DeathTime:0s}` 延长动画时间
- 播放粒子效果

### Q: 如何区分不同种类的敌人？
A: 使用不同的 tag 或 NBT 标记：
```mcfunction
# 生成不同种类
summon zombie ~ ~ ~ {Tags:["<namespace>.enemy","<namespace>.boss"]}
summon skeleton ~ ~ ~ {Tags:["<namespace>.enemy","<namespace>.minion"]}

# 在死亡检测中区分
execute if entity @s[tag=<namespace>.boss] run ...
execute if entity @s[tag=<namespace>.minion]
