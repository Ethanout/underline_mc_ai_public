# 如何判断实体是否在圆形范围内

## 核心挑战

Minecraft 原版没有直接的"圆形范围检测"命令或谓词。`@e[distance=..N]` 检测的是**球形**范围（三维），而 `@e[x=X,z=Z,distance=..R]` 同样是球形。要实现**平面圆形**（忽略 Y 轴差异），需要利用数学计算或间接手段。

---

## 方案一：利用 `distance` 谓词 + Y 轴限制（推荐，1.13+）

### 原理

`distance` 检测的是**三维欧几里得距离**。要将其限制为平面圆形，需要：
1. 将实体投影到同一 Y 高度（通过 `execute positioned` 或 `execute at` 配合 `anchored`）
2. 使用 `distance` 检测水平距离

但 `distance` 本身无法忽略 Y 轴。因此需要**先统一 Y 坐标**，再检测距离。

### 实现方式

#### 方法 A：`execute positioned` 临时改变检测位置（1.13+）

```mcfunction
# 检测以 (0, 64, 0) 为中心，半径 10 的圆形范围内的所有玩家
# 将检测位置固定在 Y=64，忽略玩家实际 Y 坐标
execute as @a at @s positioned 0 64 0 if entity @s[distance=..10] run say 我在圆形范围内
```

**原理**：`positioned` 临时改变执行位置，但 `@s` 的坐标仍为实体实际位置。`distance` 计算的是**执行位置**与**实体位置**的差值。因此 `positioned 0 64 0` 后，`distance=..10` 检测的是实体到 (0,64,0) 的距离——这恰好是水平距离（因为 Y 固定为 64）。

**陷阱**：
- 如果实体 Y 坐标与 64 相差很大，`distance` 计算的是三维距离，但 Y 轴固定后，实际计算的是 `sqrt((x-0)^2 + (z-0)^2 + (y-64)^2)`。只有当实体 Y 接近 64 时，结果才近似水平距离。
- **正确做法**：使用 `anchored eyes` 或 `anchored feet` 配合 `positioned` 来消除 Y 轴影响？不，`positioned` 改变的是执行位置，`anchored` 改变的是基准点。更好的方案是方法 B。

#### 方法 B：使用 `execute store` 计算水平距离（1.13+，精确）

**原理**：将实体的 X 和 Z 坐标存入 scoreboard，手动计算 `sqrt(x^2 + z^2)`。

```mcfunction
# 初始化 scoreboard
scoreboard objectives add xPos dummy
scoreboard objectives add zPos dummy
scoreboard objectives add distSq dummy

# 每 tick 计算
execute as @a run function namespace:calc_distance
```

`namespace:function/calc_distance.mcfunction`:
```mcfunction
# 存储玩家相对于中心 (0,0) 的坐标差
execute store result score @s xPos run data get entity @s Pos[0] 1
execute store result score @s zPos run data get entity @s Pos[2] 1

# 计算平方和 (x^2 + z^2)
scoreboard players operation @s distSq = @s xPos
scoreboard players operation @s distSq *= @s xPos
scoreboard players operation @s temp = @s zPos
scoreboard players operation @s temp *= @s zPos
scoreboard players operation @s distSq += @s temp

# 判断是否在半径 10 内 (10^2 = 100)
execute if score @s distSq <= 100 run say 我在圆形范围内
```

**陷阱**：
- `data get entity @s Pos[0]` 返回的是 double 类型，`store result` 会截断为整数。对于小数坐标，精度丢失严重。
- **改进**：使用 `data get entity @s Pos[0] 100` 放大 100 倍，计算平方后再缩小。但 scoreboard 最大值为 2^31-1，放大后可能溢出。
- 更精确的做法：使用 `execute store result score @s xPos run data get entity @s Pos[0] 1000`，然后计算平方时注意溢出。

#### 方法 C：利用 `predicate` 中的 `distance` + `y` 范围限制（1.15+）

**原理**：在 predicate 中同时使用 `distance` 和 `y` 范围，将 Y 轴限制在一个很窄的范围内，从而近似平面圆形。

```json
// namespace:predicate/in_circle.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "location": {
      "position": {
        "x": 0,
        "z": 0,
        "y": {
          "min": 63.5,
          "max": 64.5
        }
      },
      "distance": {
        "max": 10.0
      }
    }
  }
}
```

```mcfunction
# 使用 predicate
execute as @a at @s if predicate namespace:in_circle run say 我在圆形范围内
```

**陷阱**：
- 这**不是真正的平面圆形**，而是"在 Y=64 附近 ±0.5 且水平距离 ≤10"的圆柱体切片。
- 如果实体 Y 坐标超出范围，即使水平距离符合也会被排除。
- 适用于 Y 轴变化不大的场景（如地面检测）。

## 方案二：利用 `area_effect_cloud` 标记点（1.13+，低精度但简单）

### 原理

在圆心位置生成一个 `area_effect_cloud`（AEC），利用其 `Radius` 属性（默认是球形范围）来检测实体。但 AEC 的 `Radius` 是**球形**的，不是平面圆形。

**改进**：将 AEC 的 Y 坐标与目标实体对齐，然后检测 `distance`。

### 实现

```mcfunction
# 在圆心 (0, 64, 0) 生成 AEC，半径 10
summon area_effect_cloud 0 64 0 {Radius:10f, Duration:1, Tags:["circle_center"]}

# 每 tick 检测
execute as @a at @s positioned 0 64 0 if entity @s[distance=..10] run say 我在圆形范围内
```

**陷阱**：
- AEC 的 `Radius` 是球形，不是平面圆形。上述代码实际上等同于方案一方法 A。
- AEC 本身有实体数量限制，大量使用可能影响性能。
- 不推荐此方案，因为方案一更直接。

---

## 方案三：利用 `raycast` 配合 `distance`（1.16+，高精度但复杂）

### 原理

从圆心向实体方向发射一条射线，检测射线长度是否 ≤ 半径。但 raycast 主要用于方块碰撞检测，不直接支持"点到点距离"。

**替代**：使用 `execute if entity` 配合 `distance` 本身就是最直接的距离检测，无需 raycast。

---

## 方案四：利用 `predicate` 中的 `distance` + `y` 忽略（1.20.5+，最优雅）

### 原理

从 1.20.5 开始，`location` predicate 支持 `dimension` 字段，但 `distance` 仍然是三维的。不过，可以通过 `position` 中的 `y` 字段设置为 `{min: -inf, max: inf}` 来忽略 Y 轴？**不行**，`y` 字段不能忽略，必须指定范围。

**真正优雅的方案**：使用 `execute positioned` 配合 `anchored` 将检测点固定在实体所在 Y 高度。

```mcfunction
# 检测以 (0, 0) 为中心，半径 10 的圆形范围内的实体
# 将检测位置设置为 (0, <实体Y>, 0)，然后检测 distance
execute as @a at @s positioned 0 ~ 0 if entity @s[distance=..10] run say 我在圆形范围内
```

**注意**：`positioned 0 ~ 0` 中的 `~` 表示相对坐标，但 `positioned` 中的 `~` 是相对于**执行位置**的。`at @s` 将执行位置设为实体位置，然后 `positioned 0 ~ 0` 将执行位置的 X 和 Z 改为 0，Y 保持不变。此时 `distance` 计算的是实体到 (0, 实体Y, 0) 的距离，即水平距离。

**这是最简洁、最精确的方案**。

## 最终推荐方案

### 方案四：`positioned 0 ~ 0` + `distance`（1.13+）

**原理**：利用 `positioned` 的相对坐标 `~` 保留 Y 轴，将 X 和 Z 固定为圆心坐标，从而检测水平距离。

```mcfunction
# 检测以 (100, 64) 为中心，半径 15 的圆形范围内的所有实体
execute as @e at @s positioned 100 ~ 64 if entity @s[distance=..15] run tag @s add in_circle
```

**陷阱**：
- `positioned 100 ~ 64` 中的 `~` 是相对于执行位置的。`at @s` 将执行位置设为实体位置，然后 `positioned` 将 X 改为 100，Z 改为 64，Y 保持不变。因此 `distance` 计算的是实体到 (100, 实体Y, 64) 的距离。
- 如果圆心 Y 坐标不重要（即忽略 Y 轴），可以写成 `positioned 100 ~ 64`。如果圆心 Y 坐标固定（如地面高度），可以写成 `positioned 100 64 64`，但这样会变成三维距离。
- **关键**：`~` 在 `positioned` 中表示"保持当前执行位置的该坐标不变"。因此 `positioned 100 ~ 64` 表示 X=100, Y=不变, Z=64。

### 完整示例：检测玩家是否在圆形区域内并执行动作

```mcfunction
# 每 tick 执行
execute as @a at @s positioned 0 ~ 0 if entity @s[distance=..10] run function namespace:in_circle_action
```

```mcfunction
# namespace:function/in_circle_action.mcfunction
say 我在以 (0,0) 为中心，半径 10 的圆形范围内！
```

### 陷阱与注意事项

1. **`positioned` 中的 `~` 行为**：`positioned 0 ~ 0` 中的 `~` 是相对于**执行位置**的。如果执行位置是实体位置，则 `~` 保留实体的 Y 坐标。如果执行位置是其他位置（如 `positioned 0 0 0` 后），则 `~` 保留的是那个位置的 Y 坐标。务必理解执行上下文。

2. **`distance` 的单位**：`distance` 的单位是米（方块），与游戏内距离一致。

3. **性能**：单条 `execute` 命令即可完成检测，性能开销极低。每 tick 对每个实体执行一次，复杂度 O(n)。

4. **版本兼容性**：此方案在 1.13+ 所有版本中均有效。`positioned` 和 `distance` 都是 1.13 引入的。

5. **与 `predicate` 结合**：可以将检测逻辑封装到 predicate 中，便于复用。

```json
// namespace:predicate/in_circle.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "location": {
      "position": {
        "x": 0,
        "z": 0
      },
      "distance": {
        "max": 10.0
      }
    }
  }
}
```

```mcfunction
# 使用 predicate（注意：predicate 中的 distance 仍然是三维的！）
# 因此需要配合 positioned 使用
execute as @a at @s positioned 0 ~ 0 if predicate namespace:in_circle run say 我在圆形范围内
```

**注意**：predicate 中的 `position` 只指定了 X 和 Z，没有指定 Y。此时 `distance` 计算的是实体到 (0, 实体Y, 0) 的距离——这正是水平距离。但前提是 `execute` 的执行位置 Y 与实体 Y 一致。上述命令中 `at @s` 已经将执行位置设为实体位置，`positioned 0 ~ 0` 保留了 Y，因此 predicate 中的 `distance` 计算的是水平距离。
