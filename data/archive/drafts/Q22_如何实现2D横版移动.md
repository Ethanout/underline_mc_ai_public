# 如何实现2D横版移动

## 核心挑战

Minecraft 原版是3D游戏，玩家移动默认在三维空间中进行。实现2D横版移动的核心挑战在于：
1. **限制Z轴移动**：玩家默认可以沿X、Y、Z三个方向移动，需要将Z轴锁定
2. **视角与移动方向解耦**：横版游戏中，玩家左右移动应始终对应屏幕的左右方向，而非根据视角方向变化
3. **重力与跳跃**：需要保留Y轴的重力和跳跃机制，但限制Z轴位移

## 方案一：基于谓词和传送的纯数据包方案（推荐）

### 原理

利用 `predicate` 检测玩家的移动输入，结合 `execute` 命令和 `tp` 命令，在每一 tick 将玩家的Z轴坐标强制锁定到固定值，同时根据输入方向在X轴上移动。

核心机制：
- 使用 `input` 谓词检测玩家是否按下了 `left` 或 `right` 键
- 使用 `movement` 谓词检测玩家是否在Z轴方向上有移动
- 每 tick 执行传送，将玩家的Z坐标固定，并在X轴上根据输入方向移动

### 版本要求

1.20.5+（使用了 `predicate` 的 `input` 字段，该字段在1.20.5中正式稳定）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      load.mcfunction
      tick.mcfunction
      player/
        tick.mcfunction
        move.mcfunction
        reset_z.mcfunction
    predicates/
      input_left.json
      input_right.json
      moving_z.json
```

#### 1. 加载函数

`data/<namespace>/functions/load.mcfunction`
```mcfunction
# 初始化计分板
scoreboard objectives add <namespace>.move_x dummy
scoreboard objectives add <namespace>.move_z dummy

# 设置全局标记
scoreboard players set #initialized <namespace>.move_x 1

# 设置所有玩家的初始Z坐标（根据地图需求调整）
execute as @a run scoreboard players set @s <namespace>.move_z -100
```

#### 2. 主循环

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 处理所有玩家
execute as @a at @s run function <namespace>:player/tick
```

#### 3. 玩家处理

`data/<namespace>/functions/player/tick.mcfunction`
```mcfunction
# 检测移动输入并执行移动
function <namespace>:player/move

# 强制锁定Z轴
function <namespace>:player/reset_z
```

#### 4. 移动逻辑

`data/<namespace>/functions/player/move.mcfunction`
```mcfunction
# 检测左移输入
execute if predicate <namespace>:input_left run scoreboard players add @s <namespace>.move_x -1
# 检测右移输入
execute if predicate <namespace>:input_right run scoreboard players add @s <namespace>.move_x 1

# 检测Z轴移动（防止玩家通过其他方式移动Z轴）
execute if predicate <namespace>:moving_z run scoreboard players set @s <namespace>.move_z 0

# 执行X轴移动（每 tick 移动0.2格，可根据需要调整速度）
execute store result score #speed <namespace>.move_x run data get entity @s Motion[0] 100
scoreboard players operation #speed <namespace>.move_x += @s <namespace>.move_x
execute store result entity @s Motion[0] double 0.01 run scoreboard players get #speed <namespace>.move_x

# 重置移动输入计分板
scoreboard players set @s <namespace>.move_x 0
```

#### 5. Z轴锁定

`data/<namespace>/functions/player/reset_z.mcfunction`
```mcfunction
# 将玩家的Z坐标锁定到固定值（这里使用-100，可根据地图调整）
execute store result score #z_pos <namespace>.move_z run data get entity @s Pos[2] 100
scoreboard players operation #z_pos <namespace>.move_z -= @s <namespace>.move_z
execute if score #z_pos <namespace>.move_z matches 0 run tp @s ~ ~ -100
```

#### 6. 谓词文件

`data/<namespace>/predicates/input_left.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "input": {
      "left": true
    }
  }
}
```

`data/<namespace>/predicates/input_right.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "input": {
      "right": true
    }
  }
}
```

`data/<namespace>/predicates/moving_z.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "movement": {
      "z": {
        "min": 0.001
      }
    }
  }
}
```

### 陷阱与注意事项

1. **传送闪烁**：每 tick 强制传送可能导致玩家看到轻微的闪烁，尤其是在网络延迟较高时。可以通过在 `reset_z` 函数中使用 `tp @s ~ ~ -100` 而不是 `tp @s ~ ~ ~` 来减少闪烁（因为只改变Z坐标）。
2. **跳跃高度**：由于我们只锁定Z轴，Y轴的重力和跳跃不受影响，玩家可以正常跳跃。
3. **视角方向**：玩家仍然可以自由旋转视角，但左右移动始终对应X轴的正负方向，与视角无关。如果需要视角与移动方向绑定（如经典横版游戏），需要额外处理。
4. **性能开销**：每 tick 对每个玩家执行3次谓词检测和1次传送，开销较低。对于20人以下的服务器，性能影响可以忽略。
5. **与碰撞箱的交互**：如果地图中有Z轴方向的墙壁或障碍物，玩家可能会卡住。建议将地图设计为Z轴方向只有一层方块。

## 方案二：基于记分板和运动矢量控制的方案

### 原理

直接控制玩家的 `Motion` NBT 数据，通过修改 `Motion[2]`（Z轴速度）为0来阻止Z轴移动，同时通过修改 `Motion[0]`（X轴速度）来实现左右移动。

### 版本要求

1.13+（`data get/merge entity` 命令支持）

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      load.mcfunction
      tick.mcfunction
      player/
        tick.mcfunction
        control_motion.mcfunction
```

#### 1. 加载函数

`data/<namespace>/functions/load.mcfunction`
```mcfunction
scoreboard objectives add <namespace>.move_x dummy
scoreboard objectives add <namespace>.move_z dummy
```

#### 2. 主循环

`data/<namespace>/functions/tick.mcfunction`
```mcfunction
execute as @a at @s run function <namespace>:player/tick
```

#### 3. 玩家处理

`data/<namespace>/functions/player/tick.mcfunction`
```mcfunction
function <namespace>:player/control_motion
```

#### 4. 运动控制

`data/<namespace>/functions/player/control_motion.mcfunction`
```mcfunction
# 获取当前运动状态
execute store result score @s <namespace>.move_x run data get entity @s Motion[0] 1000
execute store result score @s <namespace>.move_z run data get entity @s Motion[2] 1000

# 检测输入并修改X轴速度
execute if predicate <namespace>:input_left run scoreboard players remove @s <namespace>.move_x 200
execute if predicate <namespace>:input_right run scoreboard players add @s <namespace>.move_x 200

# 限制X轴速度范围（防止加速过快）
execute if score @s <namespace>.move_x matches 1000.. run scoreboard players set @s <namespace>.move_x 1000
execute if score @s <namespace>.move_x matches ..-1000 run scoreboard players set @s <namespace>.move_x -1000

# 将Z轴速度设为0
scoreboard players set @s <namespace>.move_z 0

# 写回运动数据
execute store result entity @s Motion[0] double 0.001 run scoreboard players get @s <namespace>.move_x
execute store result entity @s Motion[1] double 0.001 run scoreboard players get @s <namespace>.move_z
```

### 陷阱与注意事项

1. **运动数据精度**：`Motion` 使用浮点数，通过记分板存储时会有精度损失。使用 `1000` 作为缩放因子可以保留3位小数精度。
2. **重力影响**：`Motion[1]`（Y轴速度）不受影响，玩家可以正常受重力影响下落和跳跃。
3. **碰撞检测**：直接修改 `Motion` 可能导致玩家穿过方块，因为Minecraft的碰撞检测是在运动更新后进行的。建议配合 `tp` 命令进行位置校正。
4. **版本兼容性**：`data get entity @s Motion[0]` 在1.13+可用，但 `execute store result entity` 的精度处理在不同版本间可能有差异。

## 方案三：基于命令方块和红石的简易方案（不推荐）

### 原理

使用命令方块每 tick 执行 `tp @p ~ ~ ~` 来锁定Z轴，同时使用红石比较器检测玩家的位置变化来触发移动。

### 版本要求

1.8+（所有版本）

### 实现

```mcfunction
# 命令方块1（循环，无条件，保持开启）
tp @a[x=0,y=0,z=-100,dx=100,dy=100,dz=0] ~ ~ -100

# 命令方块2（循环，无条件，保持开启）
execute as @a at @s if predicate <namespace>:input_left run tp @s ~-0.2 ~ ~
execute as @a at @s if predicate <namespace>:input_right run tp @s ~0.2 ~ ~
```

### 陷阱与注意事项

1. **性能极差**：每 tick 对所有玩家执行多次 `tp` 命令，且没有优化。
2. **无法处理跳跃**：`tp` 命令会覆盖玩家的Y轴位置，导致无法跳跃。
3. **碰撞检测问题**：直接 `tp` 可能导致玩家穿过方块。
4. **不推荐用于任何实际项目**。

## 进阶优化

### 1. 视角锁定

如果需要将玩家视角锁定为横版视角（始终看向固定方向），可以在 `tick` 函数中添加：
```mcfunction
# 锁定视角为水平方向（看向X轴正方向）
execute as @a at @s run tp @s ~ ~ ~ 0 0
```

### 2. 跳跃检测

如果需要自定义跳跃行为（如二段跳），可以检测 `jump` 输入：
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "input": {
      "jump": true
    }
  }
}
```

### 3. 移动平滑

使用 `Motion` 控制可以实现更平滑的移动，配合 `friction` 和 `acceleration` 参数可以实现类似平台游戏的物理效果。
