# 如何做第三人称或固定视角

## 一、核心挑战

Minecraft 原版数据包无法直接控制玩家的摄像机视角模式（第一人称/第三人称/第三人称正面）。视角切换是客户端行为，服务端没有直接设置玩家视角的指令或 NBT。因此，所有方案都是**间接实现**，通过强制玩家进入特定状态来"迫使"客户端切换到目标视角。

## 二、方案一：使用 `spectate` 命令强制第三人称（1.20+）

### 原理

`/spectate` 命令可以让玩家以旁观者模式跟随一个实体。当玩家使用此命令跟随实体时，客户端会自动切换到第三人称视角（且无法手动切换回第一人称，除非停止旁观）。利用这个特性，可以让玩家跟随一个**隐形的、无敌的、与玩家位置同步的实体**，从而实现"固定第三人称"效果。

### 完整实现

#### 1. 创建跟随实体（Load）

```mcfunction
# load.mcfunction
# 为每个在线玩家创建一个标记实体用于跟随
execute as @a run function namespace:thirdperson/create_follow_entity
```

```mcfunction
# namespace:thirdperson/create_follow_entity.mcfunction
# 使用 marker 实体（1.17+），它没有碰撞箱、不可见、无敌
summon marker ~ ~ ~ {Tags:["follow_target","<namespace>_follow"],CustomName:'"Follow Target"'}
# 将实体 UUID 存储到玩家的 storage 中，方便后续引用
data modify storage <namespace>:player_data <player_uuid>.follow_entity set from entity @e[tag=<namespace>_follow,limit=1,sort=nearest] UUID
```

#### 2. 每 tick 同步位置

```mcfunction
# tick.mcfunction
execute as @a run function namespace:thirdperson/sync_position
```

```mcfunction
# namespace:thirdperson/sync_position.mcfunction
# 获取玩家对应的跟随实体
# ⚠️ 需验证：如何高效地从 storage 中读取 UUID 并定位实体
# 这里使用 tag 方式简化：每个玩家有一个唯一标记的实体
execute as @e[tag=<namespace>_follow] at @p[tag=<namespace>_player] run tp @s ~ ~ ~
```

#### 3. 触发跟随

```mcfunction
# 玩家执行此函数后进入第三人称
# namespace:thirdperson/enable.mcfunction
# 获取玩家对应的跟随实体
execute as @e[tag=<namespace>_follow] at @s run spectate @s @p
```

#### 4. 退出跟随

```mcfunction
# namespace:thirdperson/disable.mcfunction
spectate
```

### 陷阱与注意事项

1. **玩家必须处于旁观者模式**：`/spectate` 命令只在旁观者模式下生效。如果玩家处于生存模式，命令会失败。因此需要先切换游戏模式：
   ```mcfunction
   gamemode spectator @s
   ```
   但这会带来副作用：玩家无法交互、无敌、穿墙等。

2. **实体数量管理**：每个玩家需要一个独立的跟随实体。玩家退出时需要清理实体，否则会堆积。

3. **视角锁定**：玩家在旁观模式下跟随实体时，视角会锁定在实体位置。如果实体与玩家位置完全重合，视角会卡在玩家身体内部。建议将实体放置在玩家**头部上方 0.5 格**或**前方 1 格**位置，以获得更好的第三人称体验。

4. **版本要求**：`/spectate` 命令在 1.20 中引入。1.19.4 及以下版本无法使用此方案。

## 三、方案二：使用 `camera` 命令（1.21.2+）

### 原理

1.21.2 版本引入了 `/camera` 命令，可以设置玩家的摄像机视角。虽然该命令主要用于自定义摄像机位置和旋转，但可以通过设置 `minecraft:follow_orbit` 摄像机预设来实现第三人称效果。

### 完整实现

#### 1. 设置第三人称视角

```mcfunction
# namespace:thirdperson/enable.mcfunction
camera @s set minecraft:follow_orbit
```

#### 2. 恢复默认视角

```mcfunction
# namespace:thirdperson/disable.mcfunction
camera @s set minecraft:free
```

### 陷阱与注意事项

1. **版本限制**：`/camera` 命令在 1.21.2 快照中引入，正式版需要 1.21.2+。1.21.1 及以下版本无法使用。

2. **预设行为不确定**：`minecraft:follow_orbit` 预设的具体行为（是否允许玩家手动切换视角、是否锁定视角等）取决于 Mojang 的实现。⚠️ 需验证：该预设是否真的能实现"固定第三人称"效果，还是只是一个可拖动的轨道摄像机。

3. **无法完全锁定**：即使使用 `camera` 命令，玩家可能仍然可以通过 F5 键切换视角模式。需要结合其他机制（如禁用 F5 键）来强制锁定。

## 四、方案三：利用矿车/船等实体强制视角（1.13+）

### 原理

当玩家乘坐某些实体（如矿车、船）时，客户端会自动切换到第三人称视角（如果玩家当前是第一人称）。利用这个特性，可以让玩家乘坐一个**隐形的、与玩家位置同步的实体**，从而强制第三人称。

### 完整实现

#### 1. 创建乘坐实体

```mcfunction
# load.mcfunction
execute as @a run function namespace:thirdperson/create_vehicle
```

```mcfunction
# namespace:thirdperson/create_vehicle.mcfunction
# 使用 minecart，因为它可以设置为不可见
summon minecart ~ ~ ~ {Tags:["<namespace>_vehicle"],Invisible:1b,NoGravity:1b,Silent:1b}
```

#### 2. 每 tick 同步位置

```mcfunction
# tick.mcfunction
execute as @a run function namespace:thirdperson/sync_vehicle
```

```mcfunction
# namespace:thirdperson/sync_vehicle.mcfunction
# 将矿车传送到玩家位置
execute as @e[tag=<namespace>_vehicle] at @p run tp @s ~ ~ ~
```

#### 3. 让玩家上车

```mcfunction
# namespace:thirdperson/enable.mcfunction
# 将玩家传送到矿车上（自动乘坐）
execute as @e[tag=<namespace>_vehicle] at @s run tp @p ~ ~ ~
```

#### 4. 让玩家下车

```mcfunction
# namespace:thirdperson/disable.mcfunction
# 将玩家从实体上踢下来
ride @s dismiss
```

### 陷阱与注意事项

1. **矿车有碰撞箱**：即使设置为 `Invisible:1b`，矿车仍然有碰撞箱，可能会影响玩家移动。可以使用 `marker` 实体替代，但 marker 实体不支持乘坐。

2. **乘坐状态下的移动**：玩家乘坐矿车时，移动方式会变成矿车移动（受轨道影响），而不是正常行走。需要禁用矿车的物理特性：
   ```mcfunction
   data merge entity @e[tag=<namespace>_vehicle,limit=1] {NoGravity:1b}
   ```
   但即使如此，玩家仍然无法自由移动。

3. **视角切换**：玩家乘坐实体后，客户端会自动切换到第三人称。但玩家仍然可以按 F5 切换回第一人称（虽然会卡在实体内部）。无法完全锁定。

4. **版本兼容性**：此方案在 1.13+ 版本中均可使用，但 `ride` 命令在 1.19+ 中才引入。1.18 及以下版本需要使用 `tp @p ~ ~ ~` 来让玩家下车（但效果不稳定）。

## 五、方案四：利用 `input` 谓词检测 + 强制切换（1.16+）

### 原理

通过检测玩家是否按下了 F5 键（视角切换键），然后立即强制切换回目标视角。虽然无法直接设置视角，但可以通过**高频检测 + 强制切换**来"锁定"视角。

### 完整实现

#### 1. 检测 F5 键

F5 键不在 `input` 谓词支持的字段中（只支持 `forward, backward, left, right, jump, sneak, sprint`）。因此无法直接检测 F5 键。

#### 2. 替代方案：检测视角变化

虽然没有直接检测视角的方法，但可以通过检测玩家是否处于"旁观模式"来判断视角是否被切换（因为 F5 在旁观模式下会切换视角模式）。

```mcfunction
# tick.mcfunction
# 检测玩家是否处于旁观模式
execute as @a[predicate=namespace:is_spectator] run function namespace:thirdperson/force_thirdperson
```

```json
# predicate/namespace:is_spectator.json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "player": {
      "gamemode": "spectator"
    }
  }
}
```

#### 3. 强制切换视角

```mcfunction
# namespace:thirdperson/force_thirdperson.mcfunction
# 使用 camera 命令强制设置视角（1.21.2+）
camera @s set minecraft:follow_orbit
```

### 陷阱与注意事项

1. **无法检测 F5**：原版数据包无法检测 F5 键，因此无法在玩家按下 F5 的瞬间做出反应。只能通过其他间接方式（如检测视角状态变化）来触发。

2. **视角状态不可读**：Minecraft 没有提供读取玩家当前视角模式的命令或 NBT。无法知道玩家当前是第一人称还是第三人称。

3. **此方案不完整**：由于无法检测视角状态，此方案实际上无法实现"固定视角"的功能。仅作为思路参考。

## 六、方案对比

| 方案 | 最低版本 | 视角锁定效果 | 副作用 | 性能开销 | 推荐场景 |
|------|---------|-------------|--------|---------|---------|
| spectate 跟随 | 1.20 | 完全锁定（旁观模式） | 玩家无敌、穿墙、无法交互 | 低（每 tick 一次 tp） | 需要完全锁定视角的过场动画 |
| camera 命令 | 1.21.2+ | 部分锁定（取决于预设） | 可能仍可手动切换 | 极低（仅一次命令） | 简单视角设置 |
| 乘坐实体 | 1.13+ | 部分锁定（可 F5 切回） | 移动受限、有碰撞箱 | 中（每 tick tp + 状态管理） | 兼容旧版本的方案 |
| 输入检测 | 1.16+ | 无法实现 | 无 | 低 | 仅作为思路参考 |

## 七、总结与推荐

1. **1.21.2+ 版本**：优先使用 `camera` 命令方案，最简单且无副作用。但需要验证 `follow_orbit` 预设的具体行为。

2. **1.20 - 1.21.1 版本**：使用 `spectate` 方案，虽然需要切换到旁观模式，但视角锁定效果最好。适合过场动画、剧情演出等场景。

3. **1.13 - 1.19 版本**：使用乘坐实体方案，但需要接受移动受限的副作用。适合静态场景或简单演示。

4. **所有方案都无法完全避免玩家手动切换视角**（除非使用 `spectate` 强制旁观模式）。如果需要完全锁定视角，必须接受旁观模式的副作用。
