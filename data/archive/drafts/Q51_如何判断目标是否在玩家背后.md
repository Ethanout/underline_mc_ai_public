# 如何判断目标是否在玩家背后

## 核心挑战

Minecraft 原版数据包没有直接的“方向向量”或“角度比较”机制。判断“背后”需要利用已有的坐标、旋转角度数据，通过数学计算或实体选择器间接实现。主要难点在于：
1. 玩家视角方向（yaw/pitch）与目标相对位置向量的夹角计算
2. 原版命令系统缺乏三角函数支持，需要变通方案
3. 不同版本对实体旋转数据的访问方式不同

## 方案一：利用 `@s` 选择器的 `x_rotation` 和 `y_rotation` 配合坐标计算（推荐，1.13+）

### 原理

通过 `execute positioned` 和 `execute rotated` 将执行上下文移动到玩家位置和朝向，然后使用 `@s` 选择器的 `distance` 和 `x_rotation`/`y_rotation` 参数来筛选目标。核心思路是：**将玩家的朝向视为一个“锥形区域”，判断目标是否落在这个锥形背后**。

具体来说，玩家面朝方向的反方向（即背后方向）是一个以玩家为顶点、朝向玩家背后的锥体。我们可以通过 `execute rotated` 将执行者的旋转设置为玩家朝向的反方向，然后使用 `@s[旋转角度范围]` 来检测目标是否在这个锥体内。

### 完整代码

#### 1. 获取玩家朝向并计算反方向

`data/<namespace>/function/check_behind.mcfunction`
```mcfunction
# 获取玩家的 yaw 和 pitch
execute as @a at @s run function <namespace>:check_behind/player
```

`data/<namespace>/function/check_behind/player.mcfunction`
```mcfunction
# 存储玩家朝向到 storage
data modify storage <namespace>:temp player_yaw set from entity @s Rotation[0]
data modify storage <namespace>:temp player_pitch set from entity @s Rotation[1]

# 计算反方向：yaw + 180，pitch 取反
# 注意：yaw 范围 -180~180，需要处理边界
scoreboard players operation #yaw <namespace> = #180 <namespace>
scoreboard players operation #yaw <namespace> -= #player_yaw <namespace>
# 实际上反方向 yaw = player_yaw + 180，但需要归一化到 -180~180
# 这里简化处理：直接使用 execute rotated 配合 ~ ~ 旋转

# 方法：在玩家位置，朝向反方向，检测目标
execute positioned as @s rotated ~ ~180 run function <namespace>:check_behind/detect
```

#### 2. 检测目标是否在背后

`data/<namespace>/function/check_behind/detect.mcfunction`
```mcfunction
# 此时执行位置在玩家位置，朝向是玩家朝向的反方向
# 检测所有实体（排除玩家自己）是否在背后锥形区域内
# 使用 x_rotation 和 y_rotation 选择器参数
# 注意：这里的旋转是相对于当前执行朝向的

# 检测背后 90 度锥形区域（即 y_rotation 范围 -45~45，x_rotation 范围 -45~45）
execute as @e[type=!minecraft:player, distance=..10, x_rotation=-45..45, y_rotation=-45..45] run say 我在你背后！
```

#### 3. 完整的 tick 函数

`data/<namespace>/function/tick.mcfunction`
```mcfunction
execute as @a at @s run function <namespace>:check_behind
```

### 陷阱与注意事项

1. **旋转边界问题**：当玩家 yaw 接近 180 或 -180 时，加 180 会超出范围。例如 yaw=170，加 180 得 350，但 Minecraft 中 yaw 范围是 -180~180，350 会被自动归一化为 -10。这会导致检测方向错误。**解决方案**：使用 `execute rotated` 时，Minecraft 会自动处理归一化，所以直接使用 `~ ~180` 是安全的。

2. **锥形角度选择**：`x_rotation` 和 `y_rotation` 是相对于当前执行朝向的。如果使用 `~ ~180` 旋转，那么 `x_rotation=-45..45` 表示相对于反方向左右各 45 度，`y_rotation=-45..45` 表示上下各 45 度。这实际上检测的是一个 90 度锥形区域。如果需要更精确的“正背后”，可以缩小角度范围。

3. **玩家自身排除**：`@e[type=!minecraft:player]` 会排除所有玩家，包括检测目标。如果需要检测其他玩家，需要使用 `@e[type=#minecraft:players]` 或 `@a` 但排除自己。

4. **距离限制**：`distance=..10` 限制了检测范围，避免性能问题。根据实际需求调整。

5. **版本兼容性**：此方案在 1.13+ 可用，因为 `execute rotated` 和 `x_rotation`/`y_rotation` 选择器参数是从 1.13 引入的。

## 方案二：利用 `facing` 谓词（1.19.4+）

### 原理

Minecraft 1.19.4 引入了 `facing` 谓词，可以直接检测实体是否朝向某个位置或实体。结合 `execute if predicate` 可以判断目标是否面向玩家。但我们需要的是“目标在玩家背后”，即**玩家面向目标的反方向**。因此，我们可以检测目标是否面向玩家，然后取反。

### 完整代码

#### 1. 创建谓词

`data/<namespace>/predicate/is_facing_player.json`
```json
{
  "condition": "minecraft:entity_properties",
  "entity": "this",
  "predicate": {
    "facing": {
      "entity": "minecraft:player",
      "use_eye_height": true
    }
  }
}
```

#### 2. 检测函数

`data/<namespace>/function/check_behind.mcfunction`
```mcfunction
# 检测所有实体，如果它们面向玩家，则说明玩家在它们面前，即目标在玩家背后
execute as @e[type=!minecraft:player, distance=..10] at @s if predicate <namespace>:is_facing_player run say 我在你背后！
```

### 陷阱与注意事项

1. **逻辑取反**：`facing` 谓词检测的是目标是否面向玩家。如果目标面向玩家，说明玩家在目标面前，即目标在玩家背后。所以这个方案检测的是“目标面向玩家”的情况，而不是“玩家面向目标”。需要理解这个逻辑。

2. **精度问题**：`facing` 谓词使用实体的视线方向，精度较高。但默认使用实体眼睛位置，对于非玩家实体（如僵尸），眼睛位置可能不准确。

3. **性能**：`facing` 谓词在 1.19.4+ 中性能较好，但每个 tick 对所有实体执行谓词检测可能会有开销。建议限制检测范围。

4. **版本要求**：仅 1.19.4+ 可用。

## 方案三：利用 `execute if entity` 和 `distance` 配合 `rotated`（1.13+，低精度方案）

### 原理

不依赖精确的角度计算，而是通过 `execute rotated` 改变执行朝向，然后使用 `@s[distance=..]` 检测目标是否在“背后”的某个区域内。这种方法精度较低，但实现简单。

### 完整代码

`data/<namespace>/function/check_behind_simple.mcfunction`
```mcfunction
# 在玩家位置，朝向玩家朝向的反方向
execute as @a at @s rotated ~ ~180 run \
  execute as @e[type=!minecraft:player, distance=..5, x_rotation=-30..30, y_rotation=-30..30] run say 我在你背后！
```

### 陷阱与注意事项

1. **精度低**：`x_rotation` 和 `y_rotation` 是相对于当前执行朝向的，但 `distance` 是绝对距离。这个方案实际上检测的是“在玩家背后一定距离内的一个锥形区域”，而不是精确的“背后”。

2. **距离与角度耦合**：距离越远，锥形区域越大，检测到的实体可能不在正背后。

3. **适用场景**：适合对精度要求不高的场景，如简单的背后偷袭检测。

## 方案对比

| 方案 | 版本要求 | 精度 | 性能开销 | 适用场景 |
|------|---------|------|---------|---------|
| 方案一：旋转+选择器 | 1.13+ | 中（锥形区域） | 低 | 通用场景，需要一定精度 |
| 方案二：facing 谓词 | 1.19.4+ | 高（精确视线） | 中 | 需要精确判断目标是否面向玩家 |
| 方案三：简化旋转 | 1.13+ | 低 | 低 | 快速实现，精度要求不高 |

## 推荐方案

**推荐方案一**，因为它：
- 版本兼容性好（1.13+）
- 精度可控（通过调整角度范围）
- 性能开销低
- 不依赖新版本特性

如果项目要求 1.19.4+ 且需要高精度，可以考虑方案二。

## 陷阱总结

1. **旋转边界**：`execute rotated ~ ~180` 会自动处理 yaw 边界，但 `x_rotation` 和 `y_rotation` 选择器参数是相对于当前执行朝向的，需要理解这个坐标系。

2. **玩家自身**：使用 `@e[type=!minecraft:player]` 会排除所有玩家。如果需要检测其他玩家，使用 `@a[tag=!self]` 或类似方式。

3. **性能**：每个 tick 对所有玩家执行检测，如果玩家数量多或检测范围大，可能会有性能问题。建议限制 `distance` 和 `type`。

4. **精度与角度**：`x_rotation` 和 `y_rotation` 的精度受限于选择器参数，无法做到精确的“正背后”。如果需要精确到 1 度以内，需要使用更复杂的计算（如 scoreboard 运算模拟三角函数），但原版数据包无法实现。

5. **版本差异**：`x_rotation` 和 `y_rotation` 选择器参数在 1.13 引入，但行为在 1.16 有细微变化（⚠️ 需验证：1.16 是否修改了旋转选择器的坐标系？）。建议在目标版本测试。
