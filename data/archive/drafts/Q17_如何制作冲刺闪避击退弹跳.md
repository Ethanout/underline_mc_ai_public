# 如何制作冲刺闪避击退弹跳

## 一、核心挑战分析

冲刺闪避击退弹跳的核心机制是：**玩家在冲刺状态下受到攻击时，触发一个带有额外击退和弹跳效果的闪避动作**。原版 Minecraft 没有直接的“闪避”机制，需要通过组合多个系统来实现：

1. **检测玩家冲刺状态** — 使用 `predicate` 或 `scoreboard`
2. **检测玩家受到伤害** — 使用 `minecraft:entity_hurt_player` 进度
3. **施加击退和弹跳** — 使用 `attribute` 修改或 `velocity` 命令
4. **防止滥用** — 添加冷却机制

## 二、方案一：进度触发 + 属性修改法（推荐，1.16+）

### 原理

利用 `minecraft:entity_hurt_player` 进度监听玩家受伤事件，结合 `predicate` 判断玩家是否在冲刺。触发后通过 `attribute` 临时修改玩家的击退抗性（负值）和跳跃加成，实现闪避弹跳效果。

### 完整代码

#### 1. 检测进度

`data/<namespace>/advancement/dodge/dodge_trigger.json`
```json
{
  "criteria": {
    "hurt_while_sprinting": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "flags": {
                "is_sprinting": true
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:dodge/on_hurt"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/dodge/on_hurt.mcfunction`
```mcfunction
# 检查冷却（使用 scoreboard）
scoreboard players get @s dodge_cooldown
execute if score @s dodge_cooldown matches 1.. run return fail

# 设置冷却（20 ticks = 1秒）
scoreboard players set @s dodge_cooldown 20

# 施加击退效果：临时降低击退抗性（负值 = 增加击退）
attribute @s minecraft:generic.knockback_resistance modifier add <namespace>-dodge-kb "Dodge Knockback" -1.0 multiply_base

# 施加弹跳效果：临时增加跳跃加成
attribute @s minecraft:generic.jump_strength modifier add <namespace>-dodge-jump "Dodge Jump" 0.5 multiply_base

# 播放音效和粒子效果
playsound minecraft:entity.player.attack.sweep player @s ~ ~ ~ 1.0 1.2
particle minecraft:cloud @s ~ ~0.5 ~ 0.5 0.5 0.5 0.1 20

# 延迟移除属性修改（5 ticks后）
schedule function <namespace>:dodge/remove_effects 5
```

#### 3. 移除效果函数

`data/<namespace>/function/dodge/remove_effects.mcfunction`
```mcfunction
# 移除击退抗性修改
attribute @s minecraft:generic.knockback_resistance modifier remove <namespace>-dodge-kb

# 移除跳跃加成修改
attribute @s minecraft:generic.jump_strength modifier remove <namespace>-dodge-jump
```

#### 4. 冷却递减（tick 函数）

`data/<namespace>/function/dodge/tick.mcfunction`
```mcfunction
# 每 tick 对所有有冷却的玩家递减
scoreboard players remove @a[scores={dodge_cooldown=1..}] dodge_cooldown 1
```

#### 5. 初始化（load）

`data/<namespace>/function/load.mcfunction`
```mcfunction
# 创建计分板
scoreboard objectives add dodge_cooldown dummy

# 注册 tick 函数
schedule function <namespace>:dodge/tick 1t
```

### 陷阱与注意事项

1. **属性修改的叠加问题**：如果玩家在 5 tick 内连续受伤，`attribute add` 会重复添加同名 modifier，导致效果叠加。解决方案：在 `on_hurt` 中先 `remove` 再 `add`。
2. **击退方向**：`knockback_resistance` 负值会增加所有方向的击退，无法控制方向。如需定向击退，请使用方案二。
3. **跳跃加成**：`jump_strength` 修改会影响玩家的跳跃高度，闪避结束后必须及时移除。
4. **进度触发延迟**：`entity_hurt_player` 进度在伤害计算**之后**触发，因此无法减少伤害，只能增加击退和弹跳。

## 三、方案二：velocity 命令 + 方向计算法（1.13+，更可控）

### 原理

同样使用 `entity_hurt_player` 进度检测，但不用属性修改，而是通过 `execute` 计算攻击者方向，用 `velocity` 命令直接设置玩家的速度向量，实现定向击退和弹跳。

### 完整代码

#### 1. 检测进度（同方案一）

`data/<namespace>/advancement/dodge/dodge_trigger.json`
```json
{
  "criteria": {
    "hurt_while_sprinting": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "flags": {
                "is_sprinting": true
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:dodge/on_hurt_v2"
  }
}
```

#### 2. 触发函数

`data/<namespace>/function/dodge/on_hurt_v2.mcfunction`
```mcfunction
# 检查冷却
scoreboard players get @s dodge_cooldown
execute if score @s dodge_cooldown matches 1.. run return fail

# 设置冷却
scoreboard players set @s dodge_cooldown 20

# 存储攻击者位置到 storage
execute store result score $attacker_x <namespace>_temp run data get entity @s LastDamageSource.DamageSourcePosition.X 1000
execute store result score $attacker_z <namespace>_temp run data get entity @s LastDamageSource.DamageSourcePosition.Z 1000

# 计算方向向量（简化版：从攻击者指向玩家）
# 注意：这里需要更精确的向量计算，实际使用中建议用函数宏
execute store result score $player_x <namespace>_temp run data get entity @s Pos[0] 1000
execute store result score $player_z <namespace>_temp run data get entity @s Pos[2] 1000

# 计算差值（攻击者 -> 玩家）
scoreboard players operation $diff_x <namespace>_temp = $player_x <namespace>_temp
scoreboard players operation $diff_x <namespace>_temp -= $attacker_x <namespace>_temp
scoreboard players operation $diff_z <namespace>_temp = $player_z <namespace>_temp
scoreboard players operation $diff_z <namespace>_temp -= $attacker_z <namespace>_temp

# 归一化并设置速度（简化：直接使用差值方向，速度固定）
execute store result entity @s Motion[0] double 0.001 run scoreboard players get $diff_x <namespace>_temp
execute store result entity @s Motion[1] double 0.001 run scoreboard players get $diff_z <namespace>_temp
data modify entity @s Motion[1] set value 0.5

# 播放效果
playsound minecraft:entity.player.attack.sweep player @s ~ ~ ~ 1.0 1.2
particle minecraft:cloud @s ~ ~0.5 ~ 0.5 0.5 0.5 0.1 20
```

### 陷阱与注意事项

1. **方向计算精度**：上述代码使用整数运算（乘以1000再除），精度有限。如需精确方向，建议使用 `execute positioned` 配合 `facing` 检测。
2. **Motion 直接修改**：直接修改 `Motion` 会覆盖玩家当前速度，可能导致卡顿或异常。建议在修改前保存原速度。
3. **LastDamageSource 可用性**：`LastDamageSource` 在玩家受伤后的一 tick 内可用，但某些伤害类型可能没有 `DamageSourcePosition`（如魔法伤害）。⚠️ 需验证：`DamageSourcePosition` 是否对所有伤害类型都存在。
4. **多玩家场景**：如果多个玩家同时攻击，`LastDamageSource` 可能被覆盖。建议使用 `@s` 确保上下文正确。

## 四、方案三：宏 + 精确向量计算法（1.20.2+，最精确）

### 原理

利用 1.20.2 引入的宏功能，在触发函数中动态计算攻击方向向量，实现精确的定向击退和弹跳。

### 完整代码

#### 1. 触发进度（同方案一）

#### 2. 触发函数（使用宏）

`data/<namespace>/function/dodge/on_hurt_macro.mcfunction`
```mcfunction
# 检查冷却
scoreboard players get @s dodge_cooldown
execute if score @s dodge_cooldown matches 1.. run return fail

# 设置冷却
scoreboard players set @s dodge_cooldown 20

# 获取攻击者位置和玩家位置
execute store result score $ax <namespace>_temp run data get entity @s LastDamageSource.DamageSourcePosition.X 1000
execute store result score $az <namespace>_temp run data get entity @s LastDamageSource.DamageSourcePosition.Z 1000
execute store result score $px <namespace>_temp run data get entity @s Pos[0] 1000
execute store result score $pz <namespace>_temp run data get entity @s Pos[2] 1000

# 计算方向向量并存储到 storage
execute store result storage <namespace>:temp dodge.dx double 0.001 run scoreboard players operation $px <namespace>_temp -= $ax <namespace>_temp
execute store result storage <namespace>:temp dodge.dz double 0.001 run scoreboard players operation $pz <namespace>_temp -= $az <namespace>_temp

# 调用宏函数，传入方向向量
function <namespace>:dodge/apply_velocity with storage <namespace>:temp dodge
```

#### 3. 宏函数

`data/<namespace>/function/dodge/apply_velocity.mcfunction`
```mcfunction
# 宏参数：$(dx), $(dz)
# 应用速度
execute as @s at @s run data modify entity @s Motion set value [$(dx)d, 0.5d, $(dz)d]

# 播放效果
playsound minecraft:entity.player.attack.sweep player @s ~ ~ ~ 1.0 1.2
particle minecraft:cloud @s ~ ~0.5 ~ 0.5 0.5 0.5 0.1 20
```

### 陷阱与注意事项

1. **宏参数类型**：`$(dx)` 会被替换为字符串，需要确保是有效的 NBT 数字格式（如 `0.5d`）。
2. **性能开销**：宏调用比普通函数略慢，但在此场景下（玩家受伤时触发）频率很低，影响可忽略。
3. **版本要求**：宏功能需要 Minecraft 1.20.2+。

## 六、通用陷阱与最佳实践

1. **冷却机制**：必须添加冷却，否则玩家可以无限闪避。建议冷却时间 1-2 秒（20-40 ticks）。
2. **进度撤销**：每次触发后必须 `revoke` 进度，否则不会再次触发。
   ```mcfunction
   advancement revoke @s only <namespace>:dodge/dodge_trigger
   ```
3. **多玩家兼容**：使用 `@s` 确保每个玩家独立触发，不要在函数中使用 `@a` 或 `@e` 进行全局操作。
4. **伤害类型过滤**：如果只想对特定伤害类型生效（如近战攻击），可以在进度条件中添加：
   ```json
   "damage": {
     "type": {
       "is_projectile": false,
       "is_explosion": false,
       "is_fire": false
     }
   }
   ```
5. **测试建议**：在创造模式中先用 `/damage` 命令测试，确认效果后再用于生存模式。
