# 如何重置一个房间

## 核心挑战

在 Minecraft 数据包开发中，“重置一个房间”通常指将某个特定区域（房间）恢复到初始状态，包括：
- 清除玩家放置/破坏的方块
- 重置房间内的实体（怪物、物品展示框、盔甲架等）
- 重置红石状态（门、活塞、命令方块等）
- 重置玩家的状态（位置、物品、效果等）

核心挑战在于：**原版没有“区域快照/恢复”机制**，必须通过数据包模拟实现。不同方案在性能、复杂度、功能完整性上有显著差异。

---

## 方案一：结构方块 + 函数调用（推荐，1.13+）

### 原理

利用原版的结构方块（Structure Block）保存和加载结构。数据包在初始化时保存房间的初始状态为一个结构文件，重置时加载该结构覆盖当前区域。

### 完整实现

#### 1. 保存初始结构（手动操作或通过数据包自动保存）

手动操作：
1. 在游戏中放置结构方块，框选房间区域
2. 保存为结构文件（如 `room_1`）
3. 将生成的结构文件（位于 `.minecraft/saves/<世界名>/generated/minecraft/structures/`）复制到数据包的 `data/<namespace>/structures/` 目录下

自动保存（通过数据包，1.13+）：
```mcfunction
# 在初始化时执行一次
# 假设房间从 (100, 64, 100) 到 (115, 70, 115)
data modify block 100 64 100 SaveMode set value "SAVE"
data modify block 100 64 100 Name set value "<namespace>:room_1"
data modify block 100 64 100 SizeX set value 16
data modify block 100 64 100 SizeY set value 7
data modify block 100 64 100 SizeZ set value 16
data modify block 100 64 100 IncludeEntities set value 1b
data modify block 100 64 100 ShowBoundingBox set value 0b
data modify block 100 64 100 Power set value 1
```

#### 2. 重置函数

`data/<namespace>/functions/room/reset.mcfunction`
```mcfunction
# 加载结构覆盖房间区域
# 注意：结构加载会覆盖所有方块，包括空气
place structure <namespace>:room_1 100 64 100

# 可选：清除区域内的掉落物（结构加载不会清除掉落物）
kill @e[type=item,x=100,y=64,z=100,dx=15,dy=6,dz=15]

# 可选：重置玩家位置（如果房间包含玩家）
# execute as @a[x=100,y=64,z=100,dx=15,dy=6,dz=15] at @s run tp @s 107.5 65 107.5
```

### 陷阱与注意事项

1. **结构方块保存的实体限制**：结构方块不会保存所有实体类型。它会保存：盔甲架、物品展示框、画、矿车、船、掉落物（如果勾选实体）。**不会保存**：玩家、怪物、被动生物（除非在保存时这些生物在区域内且勾选了实体）。⚠️ 需验证：1.13 版本中结构方块保存实体的具体列表。
2. **红石状态不保存**：结构方块只保存方块 ID 和 NBT 数据，不保存红石元件的激活状态（如拉杆的开关状态、红石火把的亮灭）。重置后需要额外命令设置红石状态。
3. **性能开销**：结构加载是原版操作，性能开销较低。但频繁加载大型结构（如 32x32x32）可能引起短暂卡顿。
4. **结构文件大小**：结构文件会保存区域内所有方块，包括空气。对于大型房间，文件可能较大（但通常可接受）。

## 方案二：命令方块链 + 方块替换（1.13+，适合小型房间）

### 原理

在初始化时记录房间内所有非空气方块的坐标和类型，重置时使用 `fill` 或 `setblock` 命令逐个恢复。通常配合 `fill` 命令的批量操作。

### 完整实现

#### 1. 初始化：记录方块状态（手动或通过数据包自动生成）

手动方式：在数据包中预定义所有需要重置的方块位置。

自动方式（通过数据包生成命令文件）：
```mcfunction
# 在初始化时执行，生成重置命令文件
# 假设房间从 (100, 64, 100) 到 (115, 70, 115)
# 使用循环遍历所有坐标（这里仅展示原理，实际需要脚本生成）
schedule function <namespace>:room/scan 1t
```

`data/<namespace>/functions/room/scan.mcfunction`
```mcfunction
# 扫描并记录方块（简化版，实际需要更复杂的逻辑）
# 这里假设已经有一个 storage 存储了所有方块数据
data modify storage <namespace>:room blocks set value []
# ... 遍历所有坐标，将方块数据写入 storage
```

#### 2. 重置函数

`data/<namespace>/functions/room/reset.mcfunction`
```mcfunction
# 方法A：使用 fill 命令批量重置（适合规则形状的房间）
fill 100 64 100 115 70 115 minecraft:stone
fill 100 64 100 115 64 115 minecraft:stone_bricks
fill 100 65 100 115 65 115 minecraft:air
# ... 更多 fill 命令

# 方法B：使用 setblock 逐个重置（适合不规则形状）
# 从 storage 中读取数据并执行
data modify storage <namespace>:room temp set from storage <namespace>:room blocks
execute if data storage <namespace>:room temp[0] run function <namespace>:room/reset_block
```

`data/<namespace>/functions/room/reset_block.mcfunction`
```mcfunction
# 从 storage 中取出第一个方块数据并放置
execute store result score #x <namespace> run data get storage <namespace>:room temp[0].x
execute store result score #y <namespace> run data get storage <namespace>:room temp[0].y
execute store result score #z <namespace> run data get storage <namespace>:room temp[0].z
execute store result storage <namespace>:room block_id string 1 run data get storage <namespace>:room temp[0].id

# 放置方块
execute if score #x <namespace> matches * run setblock ^^^ minecraft:stone
# 实际需要根据 block_id 动态设置，这里简化

# 移除已处理的方块
data remove storage <namespace>:room temp[0]
# 继续处理下一个
execute if data storage <namespace>:room temp[0] run function <namespace>:room/reset_block
```

### 陷阱与注意事项

1. **命令数量爆炸**：对于 16x7x16 的房间（1792 个方块），如果每个方块都需要单独命令，性能极差。必须使用 `fill` 批量操作。
2. **方块状态丢失**：`fill` 命令只能设置方块 ID，不能保留精确的方块状态（如楼梯的方向、箱子的朝向）。如需保留，必须使用 `setblock` 并指定完整状态。
3. **实体无法恢复**：此方案只能恢复方块，不能恢复实体（怪物、物品展示框等）。
4. **性能开销**：对于小型房间（如 10x10x10），使用少量 `fill` 命令即可，性能开销较低。对于大型房间，命令数量会显著增加。

## 方案三：函数递归 + 区域克隆（1.13+，适合中型房间）

### 原理

利用 `/clone` 命令从一个“模板区域”复制方块到目标区域。初始化时在远离玩家的位置（如虚空）构建一个模板房间，重置时从模板克隆到目标位置。

### 完整实现

#### 1. 初始化：构建模板房间

`data/<namespace>/functions/room/init.mcfunction`
```mcfunction
# 在虚空位置构建模板房间（假设模板位置在 0 0 0 到 15 6 15）
# 注意：模板位置必须加载（可以通过传送玩家或使用 forceload）
fill 0 0 0 15 6 15 minecraft:stone
fill 0 1 0 15 5 15 minecraft:air
# ... 构建房间结构
```

#### 2. 重置函数

`data/<namespace>/functions/room/reset.mcfunction`
```mcfunction
# 从模板克隆到目标位置
clone 0 0 0 15 6 15 100 64 100

# 可选：清除掉落物
kill @e[type=item,x=100,y=64,z=100,dx=15,dy=6,dz=15]

# 可选：重置实体（需要额外处理）
```

### 陷阱与注意事项

1. **模板区域必须保持加载**：如果模板区域所在的区块卸载，`/clone` 命令会失败。可以使用 `/forceload` 强制加载。
2. **实体不克隆**：`/clone` 命令默认不克隆实体（1.13+ 中 `clone` 命令没有 `masked` 或 `filtered` 模式可以克隆实体）。如需重置实体，需要额外处理。
3. **红石状态不克隆**：与结构方块类似，红石元件的激活状态不会被克隆。
4. **性能开销**：`/clone` 命令性能较好，但克隆大型区域（如 32x32x32）可能引起短暂卡顿。
5. **版本要求**：`/clone` 命令在 1.13 中语法有变化，1.13+ 使用 `clone <源坐标> <目标坐标>` 格式。

## 方案四：数据包 + 进度监听 + 函数重置（1.16+，适合玩家触发的重置）

### 原理

通过进度（Advancement）监听玩家行为（如按下按钮、踩压力板），触发重置函数。结合上述任一重置方案。

### 完整实现

#### 1. 进度定义

`data/<namespace>/advancements/room/reset_trigger.json`
```json
{
  "criteria": {
    "press_button": {
      "trigger": "minecraft:enter_block",
      "conditions": {
        "block": "minecraft:stone_button",
        "player": [
          {
            "condition": "minecraft:entity_properties",
            "entity": "this",
            "predicate": {
              "location": {
                "position": {
                  "x": 107,
                  "y": 65,
                  "z": 107
                }
              }
            }
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "<namespace>:room/reset"
  }
}
```

#### 2. 重置函数（结合方案一）

`data/<namespace>/functions/room/reset.mcfunction`
```mcfunction
# 重置房间
place structure <namespace>:room_1 100 64 100

# 清除掉落物
kill @e[type=item,x=100,y=64,z=100,dx=15,dy=6,dz=15]

# 重置玩家位置
execute as @a[x=100,y=64,z=100,dx=15,dy=6,dz=15] at @s run tp @s 107.5 65 107.5

# 撤销进度，以便下次触发
advancement revoke @s only <namespace>:room/reset_trigger
```

### 陷阱与注意事项

1. **进度触发延迟**：进度触发有 1 tick 的延迟（从事件发生到函数执行），对于需要即时响应的场景可能不够快。
2. **玩家状态重置**：如果房间内有多个玩家，需要决定是否重置所有玩家的位置。
3. **进度冲突**：如果玩家同时满足多个进度条件，可能触发多次重置。需要在函数开头添加防重复逻辑。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 复杂度 | 功能完整性 | 适用场景 |
|------|---------|---------|-------|-----------|---------|
| 结构方块 | 1.13+ | 低 | 低 | 中（不保存红石状态） | 大多数房间重置 |
| 命令方块链 | 1.13+ | 中-高 | 高 | 低（仅方块） | 小型规则房间 |
| 区域克隆 | 1.13+ | 低-中 | 中 | 中（不保存实体） | 中型房间 |
| 进度触发 | 1.16+ | 低 | 中 | 取决于底层方案 | 玩家触发的重置 |

## 综合推荐

对于大多数场景，推荐 **方案一（结构方块）**，原因如下：
- 实现简单，只需保存一次结构文件
- 性能开销低
- 支持实体重置（部分）
- 适合各种大小的房间

如果需要重置红石状态，可以结合方案一和额外的命令：
```mcfunction
# 重置结构
place structure <namespace>:room_1 100 64 100

# 额外重置红石状态
setblock 105 65 105 minecraft:redstone_torch[lit=false]
setblock 110 65 110 minecraft:lever[powered=false]
```

如果需要完全重置（包括所有实体和红石状态），可以考虑 **方案一 + 方案二** 的组合，但复杂度会显著增加。
