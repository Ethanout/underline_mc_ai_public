# 如何制作动态场景

## 一、什么是动态场景

动态场景（Dynamic Scene）指在 Minecraft 中通过数据包实现的环境变化效果，包括但不限于：天气变化、昼夜交替、季节变换、粒子特效、实体动画、地形渐变等。核心挑战在于：**原版数据包没有内置的动画系统或场景管理机制**，所有动态效果都必须通过 tick 函数、进度触发、实体操作等机制组合实现。

## 二、方案一：基于 Tick 函数的逐帧驱动（最通用）

### 原理

利用 `#minecraft:tick` 函数标签，每 tick（1/20 秒）执行一次场景更新逻辑。通过 scoreboard 计数器或 storage 中的数值来控制场景状态，配合粒子、实体、方块操作等实现动态效果。

### 版本要求

- 最低版本：1.13（函数系统引入）
- 推荐版本：1.20.5+（支持更丰富的粒子控制）

### 完整实现：昼夜粒子场景

#### 目录结构
```
data/
  <namespace>/
    functions/
      tick.mcfunction
      scene/
        init.mcfunction
        update.mcfunction
        particles/
          day.mcfunction
          night.mcfunction
        time/
          get_time.mcfunction
          set_time.mcfunction
    tags/
      functions/
        tick.json
```

#### 1. 注册 tick 函数
`data/<namespace>/tags/functions/tick.json`
```json
{
    "values": [
        "<namespace>:tick"
    ]
}
```

#### 2. 主 tick 函数
`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 执行场景更新
execute as @a at @s run function <namespace>:scene/update
```

#### 3. 场景更新逻辑
`data/<namespace>/functions/scene/update.mcfunction`
```mcfunction
# 获取当前时间（使用 day_time 分数）
scoreboard players get @s day_time

# 根据时间切换粒子效果
execute if score @s day_time matches 0..12000 run function <namespace>:scene/particles/day
execute if score @s day_time matches 12001..24000 run function <namespace>:scene/particles/night

# 更新场景状态（每 20 tick 更新一次时间显示）
scoreboard players add @s scene_timer 1
execute if score @s scene_timer matches 20.. run function <namespace>:scene/time/get_time
```

#### 4. 白天粒子效果
`data/<namespace>/functions/scene/particles/day.mcfunction`
```mcfunction
# 在玩家周围生成阳光粒子
particle minecraft:sunlight ~ ~1 ~ 0.5 0.5 0.5 0 10 normal
```

#### 5. 夜晚粒子效果
`data/<namespace>/functions/scene/particles/night.mcfunction`
```mcfunction
# 在玩家周围生成萤火虫粒子
particle minecraft:end_rod ~ ~1 ~ 0.3 0.3 0.3 0.01 5 normal
```

#### 6. 时间获取与设置
`data/<namespace>/functions/scene/time/get_time.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set @s scene_timer 0

# 获取当前游戏时间（day_time 分数）
execute store result score @s day_time run time query day

# 根据时间调整场景亮度（通过 effect 模拟）
execute if score @s day_time matches 0..12000 run effect give @s minecraft:night_vision 1 0 true
execute if score @s day_time matches 12001..24000 run effect clear @s minecraft:night_vision
```

`data/<namespace>/functions/scene/time/set_time.mcfunction`
```mcfunction
# 设置时间为正午（用于测试）
time set 6000
```

### 陷阱与注意事项

1. **性能开销**：每 tick 执行粒子生成会带来较高开销。建议使用 `execute if predicate <namespace>:chance/0.1` 控制生成频率，或只在玩家移动时生成。
2. **时间同步**：`time query day` 返回的是游戏内时间（0-24000），但不同维度时间不同。如果需要在多个维度同步，需使用 `time query gametime` 并自行计算。
3. **粒子限制**：Minecraft 有粒子数量上限（默认 16384），超过上限的粒子会被丢弃。高频粒子场景需注意控制数量。
4. **玩家离线**：`@a` 选择器只选择在线玩家。如果场景需要持续运行（如季节变化），应使用 `@e[type=marker]` 或 `@e[type=area_effect_cloud]` 作为场景控制器。

## 三、方案二：基于进度触发的条件驱动（低性能开销）

### 原理

利用进度（Advancement）的 `tick` 触发器，在特定条件下触发场景变化。相比 tick 函数，进度触发只在条件满足时执行，适合低频场景变化（如天气切换、季节更替）。

### 版本要求

- 最低版本：1.15（`tick` 触发器引入）
- 推荐版本：1.20+

### 完整实现：基于时间的天气切换

#### 目录结构
```
data/
  <namespace>/
    advancements/
      scene/
        weather_change.json
    functions/
      scene/
        weather/
          clear.mcfunction
          rain.mcfunction
          thunder.mcfunction
```

#### 1. 天气变化进度
`data/<namespace>/advancements/scene/weather_change.json`
```json
{
    "criteria": {
        "check_time": {
            "trigger": "minecraft:tick",
            "conditions": {
                "player": [
                    {
                        "condition": "minecraft:value_check",
                        "value": {
                            "type": "minecraft:score",
                            "target": {
                                "type": "minecraft:fixed",
                                "name": "weather_timer"
                            },
                            "score": "weather_timer"
                        },
                        "range": {
                            "min": 1200
                        }
                    }
                ]
            }
        }
    },
    "rewards": {
        "function": "<namespace>:scene/weather/change"
    }
}
```

#### 2. 天气切换函数
`data/<namespace>/functions/scene/weather/change.mcfunction`
```mcfunction
# 重置计时器
scoreboard players set weather_timer 0

# 随机选择天气（使用随机数）
execute if predicate <namespace>:chance/0.3 run function <namespace>:scene/weather/thunder
execute if predicate <namespace>:chance/0.5 run function <namespace>:scene/weather/rain
execute unless predicate <namespace>:chance/0.5 run function <namespace>:scene/weather/clear
```

#### 3. 具体天气函数
`data/<namespace>/functions/scene/weather/clear.mcfunction`
```mcfunction
weather clear 6000
tellraw @a {"text":"天气转晴","color":"yellow"}
```

`data/<namespace>/functions/scene/weather/rain.mcfunction`
```mcfunction
weather rain 6000
tellraw @a {"text":"开始下雨","color":"blue"}
```

`data/<namespace>/functions/scene/weather/thunder.mcfunction`
```mcfunction
weather thunder 6000
tellraw @a {"text":"雷雨交加","color":"dark_red"}
```

#### 4. 计时器更新（在 tick 函数中）
`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 增加计时器
scoreboard players add weather_timer 1
```

### 陷阱与注意事项

1. **进度触发延迟**：进度触发不是即时的，可能有 1-2 tick 的延迟。对于需要精确时序的场景（如粒子动画），应使用 tick 函数。
2. **进度重复触发**：进度触发后需要 `advancement revoke` 才能再次触发。如果忘记 revoke，进度只会触发一次。
3. **条件检查频率**：`tick` 触发器每 tick 检查一次条件，但进度系统本身有性能开销。对于高频条件检查，tick 函数更高效。
4. **随机数谓词**：`predicate` 中的随机数每次调用都会重新计算，可能导致预期外的行为。建议使用 scoreboard 存储随机数。

## 四、方案三：基于实体动画的物理驱动（复杂场景）

### 原理

利用实体的运动、旋转、变换等属性，通过 `data merge entity` 或 `execute` 链控制实体状态，实现复杂的场景动画（如旋转的风车、移动的云朵、飘动的旗帜）。

### 版本要求

- 最低版本：1.13
- 推荐版本：1.20.5+（支持更丰富的实体 NBT 操作）

### 完整实现：旋转风车

#### 目录结构
```
data/
  <namespace>/
    functions/
      scene/
        windmill/
          init.mcfunction
          rotate.mcfunction
          spawn.mcfunction
      tick.mcfunction
```

#### 1. 初始化风车实体
`data/<namespace>/functions/scene/windmill/init.mcfunction`
```mcfunction
# 在指定位置生成风车底座（盔甲架）
summon minecraft:armor_stand ~ ~ ~ {NoGravity:1b,Invisible:1b,Marker:1b,Tags:["windmill_base"]}

# 生成风车叶片（另一个盔甲架，作为子实体）
summon minecraft:armor_stand ~ ~1 ~ {NoGravity:1b,Invisible:1b,Small:1b,Tags:["windmill_blade"],Rotation:[0f,0f]}

# 设置叶片实体为底座实体的乘客
execute as @e[tag=windmill_base,limit=1] at @s run data merge entity @e[tag=windmill_blade,limit=1] {Passengers:[{id:"minecraft:armor_stand"}]}
```

#### 2. 旋转动画（每 tick 执行）
`data/<namespace>/functions/scene/windmill/rotate.mcfunction`
```mcfunction
# 获取当前旋转角度
scoreboard players get windmill_angle windmill

# 增加角度（每 tick 增加 2 度）
scoreboard players add windmill_angle windmill 2

# 限制角度范围（0-360）
execute if score windmill_angle windmill matches 360.. run scoreboard players set windmill_angle windmill 0

# 计算弧度（简化版：直接使用角度）
# 注意：Minecraft 的 Rotation 使用角度制，范围 0-360
execute as @e[tag=windmill_blade,limit=1] at @s run data merge entity @s {Rotation:[0f,0f]}

# 使用 execute 链实现旋转（更精确）
execute as @e[tag=windmill_blade,limit=1] at @s run tp @s ~ ~ ~ ~2 ~
```

#### 3. 主 tick 函数
`data/<namespace>/functions/tick.mcfunction`
```mcfunction
# 每 tick 更新风车旋转
function <namespace>:scene/windmill/rotate
```

### 陷阱与注意事项

1. **实体数量限制**：大量实体（尤其是盔甲架）会显著影响性能。建议使用 `@e[type=armor_stand,tag=windmill_blade,limit=1]` 限制操作范围。
2. **旋转精度**：`tp` 命令的旋转参数使用角度制，但浮点数精度有限。长时间运行后可能出现角度偏移，建议定期重置。
3. **乘客关系**：使用 `Passengers` 时，子实体的位置是相对于父实体的。如果父实体移动，子实体也会跟随。
4. **实体碰撞**：盔甲架默认有碰撞箱，可能影响玩家移动。使用 `Marker:1b` 可以禁用碰撞，但也会禁用部分交互功能。

## 五、方案对比

| 方案 | 版本要求 | 性能开销 | 适用场景 | 复杂度 |
|------|---------|---------|---------|--------|
| Tick 函数驱动 | 1.13+ | 中-高 | 粒子效果、实时动画、高频更新 | 低 |
| 进度触发驱动 | 1.15+ | 低 | 天气切换、季节变化、低频事件 | 中 |
| 实体动画驱动 | 1.13+ | 高 | 机械动画、移动场景、复杂交互 | 高 |

## 六、最佳实践建议

1. **性能优先**：对于需要持续运行的场景，优先使用 tick 函数 + 条件判断，避免不必要的实体操作。
2. **模块化设计**：将场景逻辑拆分为独立的函数，便于维护和复用。
3. **使用 Storage**：对于复杂的状态管理，使用 `storage` 替代 `scoreboard`，避免实体数量膨胀。
4. **测试环境**：在超平坦世界测试场景效果，避免地形干扰。
5. **版本兼容**：如果目标版本低于 1.20.5，注意粒子命令的差异（如 `particle <name> <pos> <delta> <speed> <count>` 格式）。
