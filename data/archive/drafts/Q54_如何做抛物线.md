# 如何做抛物线

## 问题核心

在 Minecraft 数据包中实现抛物线运动，核心挑战在于：
1. 原版没有内置的物理引擎或抛物线运动 API
2. 需要利用实体运动、粒子系统或记分板计算来模拟
3. 不同版本对实体运动和 NBT 操作的支持差异较大
4. 性能开销与精度之间的权衡

## 方案一：实体运动 + 记分板计算（推荐，1.13+）

### 原理

利用 `execute store` 将实体的 Motion 分量存储到记分板，通过每 tick 的数学计算更新速度，再写回 Motion。模拟水平匀速、垂直受重力的抛物线运动。

核心公式（每 tick 更新）：
- 水平：`vx = vx0`（匀速），`vz = vz0`（匀速）
- 垂直：`vy = vy0 - gravity * tick`（重力加速度，通常取 0.05 或 0.08）

### 完整代码

#### 1. 初始化函数（召唤抛射物并设置初速度）

`data/<namespace>/functions/parabola/summon.mcfunction`
```mcfunction
# 召唤一个标记实体作为抛射物
summon marker ~ ~1 ~ {Tags:["parabola_projectile"]}

# 设置初速度（示例：水平速度 0.5，垂直速度 1.0）
scoreboard players set @e[tag=parabola_projectile,limit=1,sort=nearest] vx 500
scoreboard players set @e[tag=parabola_projectile,limit=1,sort=nearest] vy 1000
scoreboard players set @e[tag=parabola_projectile,limit=1,sort=nearest] vz 500

# 初始化 tick 计数器
scoreboard players set @e[tag=parabola_projectile,limit=1,sort=nearest] tick 0
```

#### 2. 每 tick 更新函数

`data/<namespace>/functions/parabola/tick.mcfunction`
```mcfunction
# 对每个抛物线实体执行更新
execute as @e[tag=parabola_projectile] at @s run function <namespace>:parabola/update
```

`data/<namespace>/functions/parabola/update.mcfunction`
```mcfunction
# 从记分板读取速度分量到 Motion
execute store result entity @s Motion[0] double 0.001 run scoreboard players get @s vx
execute store result entity @s Motion[1] double 0.001 run scoreboard players get @s vy
execute store result entity @s Motion[2] double 0.001 run scoreboard players get @s vz

# 应用重力（每 tick 减少垂直速度）
scoreboard players remove @s vy 50

# 增加 tick 计数
scoreboard players add @s tick 1

# 可选：检测落地（y 坐标变化或地面检测）
execute if entity @s[y=~-0.5,dy=0] run function <namespace>:parabola/land
```

#### 3. 落地处理函数

`data/<namespace>/functions/parabola/land.mcfunction`
```mcfunction
# 触发落地效果（示例：生成粒子）
particle flame ~ ~ ~ 0.1 0.1 0.1 0.1 10

# 清除实体
kill @s
```

### 陷阱与注意事项

1. **记分板精度**：`execute store` 的 scale 参数决定了精度。`0.001` 表示记分板值除以 1000 得到实际速度。如果速度值很小（如 0.01），需要更大的 scale（如 `0.0001`）或使用更大的记分板值。
2. **重力值选择**：Minecraft 原版重力加速度约为 0.08 方块/tick²（对于掉落物和生物）。对于抛射物，建议使用 0.05 以获得更平滑的轨迹。
3. **实体类型选择**：`marker` 实体没有碰撞箱，适合纯视觉抛物线。如果需要碰撞检测，使用 `armor_stand` 或 `item_display`（1.19.4+）。
4. **性能**：每 tick 对每个实体执行 3 次 `execute store` 和 1 次 `scoreboard` 操作，100 个实体时开销较低（约 0.1ms/tick）。
5. **版本要求**：`execute store result entity` 在 1.13 引入，`marker` 实体在 1.17 引入。1.13-1.16 可使用 `area_effect_cloud` 替代。

## 方案二：粒子轨迹 + 实体 Teleport（1.13+，适合纯视觉效果）

### 原理

不依赖 Motion，而是通过每 tick 计算目标位置，使用 `/tp` 或 `/teleport` 直接移动实体。适合需要精确控制路径的场景（如弹道预览）。

### 完整代码

#### 1. 初始化

`data/<namespace>/functions/parabola/teleport/summon.mcfunction`
```mcfunction
# 召唤一个 armor_stand 作为视觉载体
summon armor_stand ~ ~1 ~ {Tags:["parabola_tp"],Invisible:1b,NoGravity:1b,Marker:1b}

# 存储初始位置到记分板（使用相对坐标）
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] px 0
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] py 0
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] pz 0

# 存储速度参数
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] vx 200
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] vy 400
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] vz 100
scoreboard players set @e[tag=parabola_tp,limit=1,sort=nearest] gravity 50
```

#### 2. 每 tick 更新

`data/<namespace>/functions/parabola/teleport/update.mcfunction`
```mcfunction
# 更新位置（使用记分板运算）
scoreboard players operation @s px += @s vx
scoreboard players operation @s py += @s vy
scoreboard players operation @s pz += @s vz

# 应用重力
scoreboard players operation @s vy -= @s gravity

# 计算实际坐标并传送
# 注意：这里需要将记分板值转换为实际坐标
# 使用 execute positioned 配合相对坐标
execute store result score #temp_x run data get entity @s Pos[0] 1000
execute store result score #temp_y run data get entity @s Pos[1] 1000
execute store result score #temp_z run data get entity @s Pos[2] 1000

# 将记分板增量加到当前位置
scoreboard players operation #temp_x += @s px
scoreboard players operation #temp_y += @s py
scoreboard players operation #temp_z += @s pz

# 写回实体位置
execute store result entity @s Pos[0] double 0.001 run scoreboard players get #temp_x
execute store result entity @s Pos[1] double 0.001 run scoreboard players get #temp_y
execute store result entity @s Pos[2] double 0.001 run scoreboard players get #temp_z

# 生成粒子
particle end_rod ~ ~ ~ 0 0 0 0 1

# 落地检测
execute if entity @s[y=~-0.5,dy=0] run function <namespace>:parabola/teleport/land
```

### 陷阱与注意事项

1. **位置精度**：使用 `data get` 读取 Pos 时，返回的是 double 值乘以 1000 后的整数。需要确保 scale 一致。
2. **坐标累积误差**：每 tick 的浮点运算会累积误差。建议定期从实体实际位置重新同步记分板。
3. **传送延迟**：`/tp` 或 `/teleport` 在 1.13+ 中每 tick 只能执行有限次数（约 1000 次），大量实体时可能造成延迟。
4. **版本差异**：`/teleport` 在 1.13 中语法为 `teleport <entity> <pos>`，1.15+ 支持 `teleport <entity> <pos> [rotation]`。

## 方案三：使用物品展示实体（1.19.4+，最优雅）

### 原理

利用 1.19.4 引入的 `item_display` 实体，通过修改其 `transformation` 字段实现平滑移动。配合 `interpolation_duration` 和 `start_interpolation` 可以实现自动插值。

### 完整代码

#### 1. 初始化

`data/<namespace>/functions/parabola/display/summon.mcfunction`
```mcfunction
# 召唤 item_display 实体
summon item_display ~ ~1 ~ {Tags:["parabola_display"],item:{id:"minecraft:fire_charge",count:1},transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[1f,1f,1f]}}

# 设置初速度（使用 storage 存储参数）
data modify storage <namespace>:parabola vx set value 0.5
data modify storage <namespace>:parabola vy set value 1.0
data modify storage <namespace>:parabola vz set value 0.3
data modify storage <namespace>:parabola gravity set value 0.05
data modify storage <namespace>:parabola tick set value 0
```

#### 2. 每 tick 更新

`data/<namespace>/functions/parabola/display/update.mcfunction`
```mcfunction
# 对每个 display 实体执行
execute as @e[tag=parabola_display] at @s run function <namespace>:parabola/display/calc
```

`data/<namespace>/functions/parabola/display/calc.mcfunction`
```mcfunction
# 读取当前 translation
data modify storage <namespace>:parabola current_trans set from entity @s transformation.translation

# 计算新位置（使用宏或 execute store）
# 注意：这里简化了计算，实际需要更复杂的数学运算
# 使用宏（1.20.2+）可以更优雅地处理

# 更新 translation
execute store result storage <namespace>:parabola new_trans[0] double 1 run data get storage <namespace>:parabola current_trans[0]
execute store result storage <namespace>:parabola new_trans[1] double 1 run data get storage <namespace>:parabola current_trans[1]
execute store result storage <namespace>:parabola new_trans[2] double 1 run data get storage <namespace>:parabola current_trans[2]

# 应用速度（简化示例，实际需要更复杂的运算）
data modify storage <namespace>:parabola new_trans[0] set from storage <namespace>:parabola vx
data modify storage <namespace>:parabola new_trans[1] set from storage <namespace>:parabola vy
data modify storage <namespace>:parabola new_trans[2] set from storage <namespace>:parabola vz

# 应用重力
data modify storage <namespace>:parabola vy set from storage <namespace>:parabola gravity
data modify storage <namespace>:parabola vy set value -0.05

# 写回实体
data modify entity @s transformation.translation set from storage <namespace>:parabola new_trans

# 触发插值
data modify entity @s interpolation_duration set value 1
data modify entity @s start_interpolation set value 0
```

### 陷阱与注意事项

1. **插值机制**：`interpolation_duration` 和 `start_interpolation` 控制平滑过渡。设置 `duration=1` 和 `start=0` 表示立即开始，在 1 tick 内完成插值。
2. **坐标系统**：`transformation.translation` 是相对于实体位置的偏移。如果需要绝对位置移动，需要同时修改实体位置。
3. **版本要求**：`item_display` 在 1.19.4 引入，`interpolation` 功能在 1.19.4 可用。1.20.2+ 支持宏，可以简化计算。
4. **性能**：display 实体的 transformation 更新开销较低，但大量实体（>200）时可能影响渲染性能。

## 方案对比

| 方案 | 最低版本 | 精度 | 性能（100实体） | 适用场景 |
|------|---------|------|----------------|---------|
| 实体运动+记分板 | 1.13 | 中（受记分板精度限制） | 低（~0.1ms/tick） | 通用抛物线，需要碰撞检测 |
| 粒子轨迹+Teleport | 1.13 | 高（可精确控制） | 中（~0.3ms/tick） | 纯视觉效果，弹道预览 |
| 物品展示实体 | 1.19.4 | 高（浮点运算） | 低（~0.05ms/tick） | 平滑动画，现代版本 |

## 总结

- **1.13-1.16**：推荐方案一（实体运动），使用 `area_effect_cloud` 替代 `marker`
- **1.17-1.19.3**：推荐方案一（实体运动），使用 `marker` 实体
- **1.19.4+**：推荐方案三（display 实体），视觉效果最平滑
- **需要精确控制路径**：方案二（Teleport）最灵活
- **需要碰撞检测**：方案一（实体运动）最自然
