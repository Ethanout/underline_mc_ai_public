# 如何做无敌帧

## 核心挑战

在 Minecraft 原版数据包中实现"无敌帧"（Invincibility Frames，简称 i-frames）的核心挑战在于：**原版没有内置的"伤害免疫时间"控制接口**。玩家受伤后自带的 0.5 秒（10 game ticks）无敌时间是由游戏硬编码的，数据包无法直接修改这个值。因此，我们需要通过间接手段来实现自定义的无敌帧系统。

## 方案一：基于 `hurt_time` 的硬编码无敌帧检测（最推荐）

### 原理

玩家实体有一个 NBT 字段 `hurt_time`，当玩家受伤时，该值被设置为 10（代表 10 game ticks = 0.5 秒），然后每 tick 递减 1，直到 0。我们可以利用这个字段来判断玩家是否处于"原生无敌帧"状态。

**核心思路**：在玩家受伤时，通过 `execute if entity @s[nbt={hurt_time:10s}]` 检测到受伤事件，然后使用 `schedule` 或 `scoreboard` 计时器来实现自定义长度的无敌帧。

### 完整实现

#### 1. 检测受伤并启动无敌帧计时

`<namespace>/function/tick.mcfunction`
```mcfunction
# 检测玩家是否刚受伤（hurt_time 刚被设为 10）
execute as @a[nbt={hurt_time:10s}] run function <namespace>:on_hurt
```

`<namespace>/function/on_hurt.mcfunction`
```mcfunction
# 设置无敌帧标记（使用 scoreboard）
scoreboard players set @s <namespace>.invincible 20  # 20 ticks = 1 秒无敌

# 可选：播放音效或粒子效果
playsound minecraft:entity.player.hurt master @s ~ ~ ~ 1 1
```

#### 2. 无敌帧逻辑处理

`<namespace>/function/tick.mcfunction`（接上面）
```mcfunction
# 处理无敌帧逻辑
execute as @a[scores={<namespace>.invincible=1..}] run function <namespace>:invincible_tick
```

`<namespace>/function/invincible_tick.mcfunction`
```mcfunction
# 递减无敌帧计数器
scoreboard players remove @s <namespace>.invincible 1

# 在无敌帧期间，阻止伤害（通过修改伤害值或取消伤害事件）
# 注意：原版无法直接取消伤害，但可以通过以下方式间接实现
```

#### 3. 阻止伤害的两种子方案

##### 子方案 A：伤害吸收效果（推荐，1.20.5+）

在玩家受伤时，给予伤害吸收效果来抵消伤害。

`<namespace>/function/on_hurt.mcfunction`（修改版）
```mcfunction
# 设置无敌帧标记
scoreboard players set @s <namespace>.invincible 20

# 给予伤害吸收效果（4 点吸收 = 2 颗心）
effect give @s minecraft:absorption 1 4 true

# 播放音效
playsound minecraft:entity.player.hurt master @s ~ ~ ~ 1 1
```

##### 子方案 B：属性修改法（1.20.5+）

通过修改玩家的 `generic.armor` 或 `generic.armor_toughness` 属性来临时增加防御。

`<namespace>/function/on_hurt.mcfunction`（修改版）
```mcfunction
# 设置无敌帧标记
scoreboard players set @s <namespace>.invincible 20

# 临时增加护甲值（需要 attribute 命令）
attribute @s minecraft:generic.armor base set 30
```

`<namespace>/function/invincible_tick.mcfunction`（修改版）
```mcfunction
# 递减无敌帧计数器
scoreboard players remove @s <namespace>.invincible 1

# 当无敌帧结束时，恢复护甲值
execute if score @s <namespace>.invincible matches 0 run attribute @s minecraft:generic.armor base set 0
```

### 陷阱与注意事项

1. **`hurt_time` 的初始值**：玩家受伤时 `hurt_time` 被设置为 10，但如果你在同一个 tick 内多次检测，可能检测不到。建议在 tick 函数中只检测一次。
2. **多段伤害**：如果玩家在无敌帧期间受到多次伤害，`hurt_time` 会被重置为 10，导致原生无敌帧延长。我们的自定义系统需要处理这种情况。
3. **属性修改的副作用**：临时修改护甲值会影响所有伤害，包括环境伤害（如摔落、火焰）。需要根据需求决定是否覆盖所有伤害类型。
4. **版本要求**：`attribute` 命令在 1.16+ 可用，但 `generic.armor` 属性在 1.20.5+ 才支持通过命令修改 base 值。⚠️ 需验证：1.16-1.20.4 是否支持 `attribute` 命令修改 base 值。

## 方案二：基于 `scoreboard` 计时器的纯逻辑无敌帧

### 原理

不依赖原生的 `hurt_time`，而是通过 `scoreboard` 计时器来实现完全自定义的无敌帧。玩家受伤时，通过某种方式检测到伤害事件（如 `health` 变化），然后启动计时器，在计时器运行期间忽略所有伤害。

### 完整实现

#### 1. 检测伤害事件

`<namespace>/function/tick.mcfunction`
```mcfunction
# 存储上一 tick 的玩家血量
execute as @a store result score @s <namespace>.prev_health run data get entity @s Health

# 检测血量变化（受伤）
execute as @a if score @s <namespace>.health < @s <namespace>.prev_health run function <namespace>:on_hurt
```

`<namespace>/function/on_hurt.mcfunction`
```mcfunction
# 检查是否处于无敌帧
execute unless score @s <namespace>.invincible matches 1.. run function <namespace>:start_invincible
```

`<namespace>/function/start_invincible.mcfunction`
```mcfunction
# 启动无敌帧
scoreboard players set @s <namespace>.invincible 20

# 记录受伤时的血量（用于后续恢复）
scoreboard players operation @s <namespace>.hurt_health = @s <namespace>.health

# 播放音效
playsound minecraft:entity.player.hurt master @s ~ ~ ~ 1 1
```

#### 2. 无敌帧逻辑

`<namespace>/function/tick.mcfunction`（接上面）
```mcfunction
# 处理无敌帧
execute as @a[scores={<namespace>.invincible=1..}] run function <namespace>:invincible_tick
```

`<namespace>/function/invincible_tick.mcfunction`
```mcfunction
# 递减无敌帧计数器
scoreboard players remove @s <namespace>.invincible 1

# 在无敌帧期间，强制恢复血量到受伤前的值
execute store result score @s <namespace>.current_health run data get entity @s Health
execute if score @s <namespace>.current_health < @s <namespace>.hurt_health run function <namespace>:restore_health
```

`<namespace>/function/restore_health.mcfunction`
```mcfunction
# 恢复血量（使用 attribute 或 effect）
# 方法1：使用 instant health 效果
effect give @s minecraft:instant_health 1 0 true

# 方法2：使用 attribute 修改（1.20.5+）
# attribute @s minecraft:generic.max_health base set 40
# 然后使用 heal 命令（1.20.5+）
# heal @s 2
```

### 陷阱与注意事项

1. **血量检测延迟**：`health` 变化检测有一个 tick 的延迟，因为我们在 tick 开始时存储上一 tick 的血量。这意味着玩家受伤后，需要 1 tick 才能启动无敌帧。
2. **多段伤害**：如果玩家在 1 tick 内受到多次伤害（如快速连射的箭），我们的系统可能只检测到第一次伤害，后续伤害会被忽略（如果无敌帧已启动）。
3. **恢复血量的副作用**：使用 `instant_health` 效果恢复血量会触发粒子效果和音效，可能造成视觉上的不自然。使用 `heal` 命令（1.20.5+）更干净。
4. **性能开销**：每个 tick 对所有玩家执行 `data get entity` 操作，性能开销中等。对于 20 人服务器，大约每秒 20 次 NBT 读取，可以接受。

## 方案三：基于 `advancement` 的伤害检测（1.20.5+）

### 原理

使用 `minecraft:entity_hurt_player` 进度触发器来检测玩家受伤事件。这个触发器在 1.20.5 引入，可以精确检测玩家受到伤害的事件，并获取伤害来源、伤害值等信息。

### 完整实现

#### 1. 创建进度

`<namespace>/advancement/on_hurt.json`
```json
{
  "criteria": {
    "hurt": {
      "trigger": "minecraft:entity_hurt_player",
      "conditions": {}
    }
  },
  "rewards": {
    "function": "<namespace>:on_hurt"
  }
}
```

#### 2. 处理受伤事件

`<namespace>/function/on_hurt.mcfunction`
```mcfunction
# 检查是否处于无敌帧
execute unless score @s <namespace>.invincible matches 1.. run function <namespace>:start_invincible

# 撤销进度，以便下次触发
advancement revoke @s only <namespace>:on_hurt
```

`<namespace>/function/start_invincible.mcfunction`
```mcfunction
# 启动无敌帧
scoreboard players set @s <namespace>.invincible 20

# 记录受伤时的血量
scoreboard players operation @s <namespace>.hurt_health = @s <namespace>.health

# 播放音效
playsound minecraft:entity.player.hurt master @s ~ ~ ~ 1 1
```

#### 3. 无敌帧逻辑

`<namespace>/function/tick.mcfunction`
```mcfunction
# 处理无敌帧
execute as @a[scores={<namespace>.invincible=1..}] run function <namespace>:invincible_tick
```

`<namespace>/function/invincible_tick.mcfunction`
```mcfunction
# 递减无敌帧计数器
scoreboard players remove @s <namespace>.invincible 1

# 在无敌帧期间，阻止伤害
execute store result score @s <namespace>.current_health run data get entity @s Health
execute if score @s <namespace>.current_health < @s <namespace>.hurt_health run function <namespace>:restore_health
```

`<namespace>/function/restore_health.mcfunction`
```mcfunction
# 恢复血量（1.20.5+ 推荐使用 heal 命令）
heal @s 2
```

### 陷阱与注意事项

1. **版本要求**：`entity_hurt_player` 触发器在 1.20.5 引入，1.20.4 及以下版本不可用。
2. **进度触发延迟**：进度触发是在事件发生后立即执行的，但函数执行可能在同一 tick 的稍后阶段，因此仍然存在 1 tick 的延迟。
3. **多段伤害**：如果玩家在 1 tick 内受到多次伤害，进度只会触发一次（因为进度触发后需要撤销才能再次触发）。这意味着第二次伤害可能无法被检测到。
4. **性能开销**：进度触发本身开销较低，但 `data get entity` 操作仍然存在。整体性能开销中等。

## 方案对比

| 方案 | 版本要求 | 性能开销 | 延迟 | 多段伤害处理 | 适用场景 |
|------|---------|---------|------|-------------|---------|
| 方案一（hurt_time） | 1.13+ | 低 | 0 tick | 自动处理（原生机制） | 通用，推荐 |
| 方案二（血量检测） | 1.13+ | 中 | 1 tick | 需额外处理 | 需要完全自定义无敌帧 |
| 方案三（advancement） | 1.20.5+ | 中 | 1 tick | 需额外处理 | 需要精确伤害信息 |

## 推荐方案

**方案一（基于 `hurt_time`）** 是最推荐的选择，因为：
1. 版本兼容性好（1.13+）
2. 性能开销最低
3. 延迟为 0 tick
4. 原生处理多段伤害

如果需要完全自定义无敌帧长度（如 2 秒、3 秒），可以在方案一的基础上，通过 `scoreboard` 计时器扩展无敌帧时间。

## 完整示例：自定义 2 秒无敌帧（基于方案一）

### 初始化

`<namespace>/function/load.mcfunction`
```mcfunction
# 创建 scoreboard 目标
scoreboard objectives add <namespace>.invincible dummy
scoreboard objectives add <namespace>.hurt_time dummy
```

### Tick 函数

`<namespace>/function/tick.mcfunction`
```mcfunction
# 检测玩家受伤
execute as @a[nbt={hurt_time:10s}] run function <namespace>:on_hurt

# 处理无敌帧
execute as @a[scores={<namespace>.invincible=1..}] run function <namespace>:invincible_tick
```

### 受伤处理

`<namespace>/function/on_hurt.mcfunction`
```mcfunction
# 检查是否处于自定义无敌帧
execute unless score @s <namespace>.invincible matches 1.. run function <namespace>:start_invincible
```

`<namespace>/function/start_invincible.mcfunction`
```mcfunction
# 设置 40 tick（2 秒）无敌帧
scoreboard players set @s <namespace>.invincible 40

# 给予伤害吸收效果（抵消原生无敌帧结束后的伤害）
effect give @s minecraft:absorption 2 4 true

# 播放音效
playsound minecraft:entity.player.hurt master @s ~ ~ ~ 1 1
```

### 无敌帧递减

`<namespace>/function/invincible_tick.mcfunction`
```mcfunction
# 递减无敌帧计数器
scoreboard players remove @s <namespace>.invincible 1

# 当无敌帧结束时，移除伤害吸收效果
execute if score @s <namespace>.invincible matches 0 run effect clear @s minecraft:absorption
```

### 陷阱与注意事项（补充）

1. **伤害吸收效果的叠加**：如果玩家在无敌帧期间再次受伤，`on_hurt` 函数会再次触发，给予新的伤害吸收效果。这可能导致吸收效果叠加，需要处理。
2. **原生无敌帧的干扰**：原生的 0.5 秒无敌帧和我们的自定义无敌帧可能重叠。我们的系统在原生无敌帧结束后（0.5 秒后）仍然有效，因为伤害吸收效果会持续 2 秒。
3. **创造模式玩家**：创造模式玩家不会受到伤害，因此 `hurt_time` 不会被设置。如果需要检测创造模式玩家的"受伤"事件，需要其他方法。
