# 如何播放一个角色动画

## 问题背景

在 Minecraft 数据包开发中，“角色动画”通常指让一个实体（如盔甲架、展示实体、玩家模型）执行一系列连续的姿态变化，模拟行走、攻击、挥手等动作。核心挑战在于：原版 Minecraft 没有内置的骨骼动画系统，所有动画必须通过**逐帧修改实体的 NBT 数据**（如姿态角度、位置偏移）来实现。因此，开发者需要解决三个问题：**如何驱动帧序列**、**如何存储帧数据**、**如何保证动画流畅且性能可控**。

## 方案一：基于盔甲架 + 逐帧函数调用（最经典，1.13+）

### 原理

使用盔甲架（Armor Stand）作为动画载体，利用其 `Pose` NBT 字段控制各部位的旋转角度（如 `Head`、`LeftArm`、`RightArm`、`LeftLeg`、`RightLeg`）。在 tick 函数中，通过 `data modify` 或 `data merge` 逐帧修改盔甲架的姿态，配合 `schedule` 或 tick 循环实现时间驱动。

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      animation/
        load.mcfunction          # 初始化动画实体
        tick.mcfunction          # 每 tick 驱动动画
        frames/
          frame_0.mcfunction     # 第0帧姿态
          frame_1.mcfunction     # 第1帧姿态
          ...
        start.mcfunction         # 启动动画
        stop.mcfunction          # 停止动画
    advancements/
      animation_tick.json        # 用于 tick 循环的进度（可选）
```

#### 1. 创建动画实体（load.mcfunction）
```mcfunction
# 在玩家位置生成盔甲架
summon minecraft:armor_stand ~ ~ ~ {NoGravity:1b,Invisible:1b,ShowArms:1b,Small:1b,Tags:["anim_actor"]}
# 存储动画状态到 storage
data modify storage <namespace>:anim state set value {current_frame:0,total_frames:10,playing:0b}
```

#### 2. 帧数据定义（frame_0.mcfunction）
```mcfunction
# 第0帧：站立姿态
data merge entity @e[tag=anim_actor,limit=1] {Pose:{Head:[0f,0f,0f],LeftArm:[0f,0f,0f],RightArm:[0f,0f,0f],LeftLeg:[0f,0f,0f],RightLeg:[0f,0f,0f]}}
```

#### 3. 帧数据定义（frame_1.mcfunction）—— 挥手动作
```mcfunction
# 第1帧：右臂抬起
data merge entity @e[tag=anim_actor,limit=1] {Pose:{Head:[0f,0f,0f],LeftArm:[0f,0f,0f],RightArm:[-45f,0f,0f],LeftLeg:[0f,0f,0f],RightLeg:[0f,0f,0f]}}
```

#### 4. 动画驱动核心（tick.mcfunction）
```mcfunction
# 检查是否正在播放
execute if data storage <namespace>:anim {playing:1b} run function <namespace>:animation/advance_frame
```

#### 5. 帧推进逻辑（advance_frame.mcfunction）
```mcfunction
# 读取当前帧
execute store result score #frame <namespace> run data get storage <namespace>:anim state.current_frame

# 执行对应帧函数
execute if score #frame <namespace> matches 0 run function <namespace>:animation/frames/frame_0
execute if score #frame <namespace> matches 1 run function <namespace>:animation/frames/frame_1
# ... 更多帧

# 帧数+1
scoreboard players add #frame <namespace> 1

# 检查是否到达总帧数
execute if score #frame <namespace> matches 10.. run function <namespace>:animation/stop
# 写回 storage
data modify storage <namespace>:anim state.current_frame set from score #frame <namespace>
```

#### 6. 启动/停止动画
```mcfunction
# start.mcfunction
data modify storage <namespace>:anim state.playing set value 1b
data modify storage <namespace>:anim state.current_frame set value 0

# stop.mcfunction
data modify storage <namespace>:anim state.playing set value 0b
data modify storage <namespace>:anim state.current_frame set value 0
# 重置姿态到默认
data merge entity @e[tag=anim_actor,limit=1] {Pose:{Head:[0f,0f,0f],LeftArm:[0f,0f,0f],RightArm:[0f,0f,0f],LeftLeg:[0f,0f,0f],RightLeg:[0f,0f,0f]}}
```

### 陷阱与注意事项

1. **帧率限制**：Minecraft 的 tick 是 20 ticks/秒，因此动画帧率只能是 20fps 的整数倍（如 20fps、10fps、5fps）。如果需要更高帧率，必须使用 `schedule` 函数在同一个 tick 内多次调用，但会显著增加性能开销。
2. **实体选择器性能**：每 tick 使用 `@e[tag=anim_actor,limit=1]` 选择实体，如果场景中有大量动画实体，建议使用 `@e[type=armor_stand,tag=anim_actor,limit=1]` 缩小范围。
3. **姿态角度范围**：`Pose` 中的角度单位是度（float），但实际有效范围是 -180 到 180。超出范围的值会被自动取模，可能导致意外旋转。
4. **多人同步**：如果动画需要所有玩家看到一致效果，必须确保动画实体是全局实体（如生成在固定坐标），而不是每个玩家独立的实体。

## 方案二：基于展示实体 + 插值动画（1.19.4+，推荐）

### 原理

Minecraft 1.19.4 引入了展示实体（Item Display、Block Display、Text Display），它们支持 `interpolation_duration` 和 `interpolation_start` 字段，可以实现平滑的线性插值动画。开发者只需定义起始帧和结束帧的姿态，设置插值时间，展示实体就会自动在两者之间平滑过渡。

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      animation/
        load.mcfunction          # 创建展示实体
        start.mcfunction         # 启动动画
        update.mcfunction        # 更新动画目标姿态
    advancements/
      animation_tick.json        # 用于 tick 循环的进度
```

#### 1. 创建展示实体（load.mcfunction）
```mcfunction
# 生成一个物品展示实体，显示一个玩家头颅作为角色
summon minecraft:item_display ~ ~ ~ {item:{id:"minecraft:player_head",count:1},transformation:{left_rotation:[0f,0f,0f,1f],right_rotation:[0f,0f,0f,1f],translation:[0f,0f,0f],scale:[1f,1f,1f]},Tags:["anim_display"],interpolation_duration:0,start_interpolation:0}
```

#### 2. 启动动画（start.mcfunction）
```mcfunction
# 设置插值持续时间为 10 ticks（0.5秒）
data merge entity @e[tag=anim_display,limit=1] {interpolation_duration:10}
# 记录当前 tick 作为插值起点
execute store result storage <namespace>:anim start_tick int 1 run time query gametime
```

#### 3. 更新目标姿态（update.mcfunction）
```mcfunction
# 设置新的目标变换（例如：向右旋转45度并上移1格）
data merge entity @e[tag=anim_display,limit=1] {transformation:{left_rotation:[0f,0f,0.382683f,0.92388f],right_rotation:[0f,0f,0.382683f,0.92388f],translation:[0f,1f,0f],scale:[1f,1f,1f]}}
# 重置插值起点为当前 tick
execute store result storage <namespace>:anim start_tick int 1 run time query gametime
```

#### 4. 循环更新（可选，用于连续动画）
```mcfunction
# 每 10 ticks 调用一次 update，实现循环摆动
schedule function <namespace>:animation/update 10 replace
```

### 陷阱与注意事项

1. **插值方向**：`interpolation_duration` 设置后，展示实体会从**当前姿态**平滑过渡到**最新设置的姿态**。如果连续多次修改目标姿态，插值会重新从当前姿态开始，可能导致跳跃。
2. **旋转插值**：`left_rotation` 和 `right_rotation` 使用四元数表示旋转。直接修改角度值可能导致插值路径不是最短路径（万向锁问题）。建议使用 `data modify` 整体替换 transformation，而不是单独修改某个字段。
3. **版本要求**：展示实体和插值功能仅在 1.19.4+ 可用。1.20.5+ 中，`interpolation_duration` 字段被重命名为 `interpolation_duration`（⚠️ 需验证：1.20.5 后字段名是否变化？根据 wiki，1.20.5 中 `interpolation_duration` 和 `start_interpolation` 仍然有效，但新增了 `teleport_duration` 字段）。
4. **性能**：展示实体的插值由客户端计算，服务端只需在关键帧发送数据，性能开销远低于方案一的逐帧修改。

## 方案三：基于玩家模型 + 资源包（1.20.5+，高级）

### 原理

利用 1.20.5 引入的 `minecraft:custom_model_data` 组件和资源包中的模型文件，通过切换玩家手持物品的模型来实现“伪动画”。这种方法实际上是在不同模型之间切换，而不是真正的骨骼动画，但可以实现复杂的视觉效果（如武器挥舞、角色变形）。

### 完整实现

#### 目录结构
```
data/
  <namespace>/
    functions/
      animation/
        start.mcfunction         # 启动动画
        tick.mcfunction          # 每 tick 切换模型
    item_modifier/
      set_model.mcfunction       # 设置自定义模型数据
```

#### 1. 资源包准备（需额外打包）
```
assets/
  minecraft/
    models/
      item/
        custom/
          frame_0.json           # 第0帧模型
          frame_1.json           # 第1帧模型
          ...
```

#### 2. 启动动画（start.mcfunction）
```mcfunction
# 给玩家主手物品设置自定义模型数据
item modify entity @s weapon.mainhand <namespace>:animation/set_model_0
# 启动 tick 循环
schedule function <namespace>:animation/tick 1 replace
```

#### 3. 每 tick 切换模型（tick.mcfunction）
```mcfunction
# 读取当前帧
execute store result score #frame <namespace> run data get storage <namespace>:anim state.current_frame

# 根据帧数设置不同的模型
execute if score #frame <namespace> matches 0 run item modify entity @s weapon.mainhand <namespace>:animation/set_model_0
execute if score #frame <namespace> matches 1 run item modify entity @s weapon.mainhand <namespace>:animation/set_model_1
# ... 更多帧

# 帧数+1
scoreboard players add #frame <namespace> 1

# 检查是否结束
execute if score #frame <namespace> matches 10.. run function <namespace>:animation/stop
```

#### 4. item_modifier 示例（set_model_0.json）
```json
{
  "function": "minecraft:set_components",
  "components": {
    "minecraft:custom_model_data": 1000
  }
}
```

### 陷阱与注意事项

1. **仅限玩家视角**：这种方法只改变玩家自己看到的物品模型，其他玩家看到的仍然是原版物品。如果需要全局可见，必须使用展示实体方案。
2. **模型切换延迟**：资源包模型切换需要客户端加载，可能产生 1-2 tick 的延迟。
3. **物品限制**：只能对玩家手持的物品进行模型切换，无法控制实体全身动画。
4. **资源包依赖**：必须配合资源包使用，增加了分发复杂度。

## 方案对比

| 特性 | 盔甲架逐帧法 | 展示实体插值法 | 玩家模型切换法 |
|------|-------------|---------------|---------------|
| 最低版本 | 1.13 | 1.19.4 | 1.20.5 |
| 动画平滑度 | 低（20fps 阶梯） | 高（线性插值） | 中（取决于帧数） |
| 性能开销 | 中（每 tick 修改 NBT） | 低（仅关键帧通信） | 低（仅修改物品组件） |
| 全局可见 | 是 | 是 | 否（仅玩家自己） |
| 骨骼控制 | 支持（头、臂、腿） | 仅整体变换 | 仅物品模型 |
| 实现复杂度 | 高（需逐帧编写） | 中（需计算四元数） | 中（需资源包） |
| 适用场景 | 简单角色动画（行走、挥手） | 平滑移动/旋转动画 | 武器特效、UI 动画 |

## 总结与推荐

- **1.19.4 以下**：只能使用方案一（盔甲架逐帧法），注意帧率限制和性能优化。
- **1.19.4+**：强烈推荐方案二（展示实体插值法），平滑度高、性能好、实现简单。
- **1.20.5+ 且仅需玩家视角**：方案三（玩家模型切换法）适合武器挥舞、技能特效等场景。

对于大多数数据包开发者，**方案二（展示实体插值法）** 是最佳选择：它平衡了版本兼容性、性能、视觉效果和实现难度。
