# 变量和数据

mc中的变量/常量分为3大类型：
1. 后端变量（假玩家记分板，storage）
2. 前端变量（实体/方块的nbt数据，@s上的记分板）
3. 上下文变量（执行者，执行方位（位置，维度，方向），store标记，基准，分支栈）
版本 1.14~至今
其中，1.2.为全局变量，3.为局部变量。

---

# 后端变量

## 假玩家记分板
假玩家记分板应该都存储在 `<namespace>` 记分板，或者其他统一名字的记分板上。其命名可以无视命名空间，如命名为 `num` 或 `int` 等其他名字。

### 假玩家记分板极其常量
`<namespace>/function/load.mcfunction`
```mcfunction
# 声明记分板（其他编程语言的int不需要声明，在mc中需要预先定义int容器）
scoreboard objectives add <namespace> dummy

# 声明数字常量
scoreboard objectives set 123 <namespace> 123

# 前面可以加上#（略微10%的性能提升）
scoreboard objectives set #123 <namespace> 123

# 声明可配置常量（比如一些设置/配置类的常量）
scoreboard objectives set config <namespace> 123
```

### 假玩家记分板极其临时变量
类似python，若无特殊情况，变量会进行自动赋值，如：
`<namespace>/function/test_auto_assign.mcfunction`
```mcfunction
execute store result score #y <namespace> run data get entity @s Pos[1] 100
```
但和python不同的是，在scoreboard命令中，未赋值项会先被强行赋值为0。且div0不会阻断命令运行。
`<namespace>/function/test_fail_assign.mcfunction`
```mcfunction
scoreboard players reset #test1 <namespace>
scoreboard players set #test2 <namespace> 1
scoreboard players operation #test2 <namespace> /= #test1 <namespace>
# 逻辑类似：
# def op(a,b,operator):
#    if a not exist: a = 0
#    if b not exist: b = 0
#    operator(a, b)
```

当一个代码中出现记分板变量时，必须先在load中声明记分板。

### 记分板运算
```mcfunction
# 加法
scoreboard players add @s var 5

# 减法
scoreboard players remove @s var 5

# 赋值
scoreboard players operation @s result = @p input

# 四则运算
scoreboard players operation @s result += #2 var     # result = result + #2
scoreboard players operation @s result -= #2 var     # result = result - #2
scoreboard players operation @s result *= #2 var     # result = result * #2
scoreboard players operation @s result /= #2 var     # result = result / #2（整数截断）
scoreboard players operation @s result %= #2 var     # result = result % #2

# 比较运算（只能作为 execute if/unless score 的条件）
# = < <= > >=  五种比较符
```

### 假玩家命名约定
- `#` 前缀：内部计算用临时变量（如 `#tmp`、`#i`、`#result`），性能优于无前缀
- 无 `#` 前缀：作为对外暴露的接口变量，其他数据包可通过此名字读写
- 纯数字假玩家名：常量值（如 `123`、`0`、`-1`）

```mcfunction
# load.mcfunction
scoreboard objectives add ns dummy
scoreboard players set #TRUE ns 1
scoreboard players set #FALSE ns 0
scoreboard players set #PI ns 3141        # 3141 = 3.141（×1000 定点数）
```

### 布尔值约定
mcf中没有bool，一般保持布尔值的变量直接用0/1：
```mcfunction
scoreboard players set #flag ns 1    # True
scoreboard players set #flag ns 0    # False
execute if score #flag ns matches 1 run say 成立
```

## Storage（命令存储）

Storage 是挂载在服务端的全局 NBT 复合容器，不依附任何实体或方块，**无需声明初始化和维度限制，服务器启动即存在**。

### 基本读写
```mcfunction
# 写入
data modify storage ns:data var set value {a:1b, b:"hello", c:[1,2,3]}

# 读取（到计分板）
execute store result score #val ns run data get storage ns:data var.a

# 读取（到另一个 storage 路径）
data modify storage ns:io tmp set from storage ns:data var.b

# 删除
data remove storage ns:data var
```

### 数据类型支持
storage 支持所有 NBT 类型，远超市面上的其他方案：
```mcfunction
data modify storage ns:data x set value {
    byte: 1b,                              # byte
    short: 1000s,                          # short
    int: 114514,                           # int
    long: 999999999999L,                   # long
    float: 3.1415f,                        # float
    double: 2.718281828d,                  # double
    string: "hello world",                 # string
    list: [1, 2, 3, 4, 5],                # list（异构亦可）
    compound: {nested: "value"},           # compound
    bool_true: true,                       # boolean
    bool_false: false,
    byte_array: [B; 1b, 2b, 3b],          # byte array
    int_array: [I; 1, 2, 3],              # int array
    long_array: [L; 1L, 2L, 3L]           # long array
}
```

### 读取数据到计分板（int）
```mcfunction
# storage double/float → scoreboard（自动截断取整）
execute store result score #val ns run data get storage ns:data x.int

# 带缩放（val = storage_value * scale）
execute store result score #val ns run data get storage ns:data x.float 1000
```

### 列表操作
```mcfunction
# 追加到列表末尾
data modify storage ns:data list append value "new_item"

# 从列表头部插入
data modify storage ns:data list prepend value "new_item"

# 合并列表（另一个列表所有元素追加）
data modify storage ns:data list append from storage ns:io other_list

# 读取指定下标
data modify storage ns:io item set from storage ns:data list[0]
data modify storage ns:io last set from storage ns:data list[-1]

# 删除指定下标
data remove storage ns:data list[0]
```

### NBT path 的高级筛选
```mcfunction
# 按条件筛选列表元素
data modify storage ns:io found set from storage ns:data players[{name:"Alice"}].score

# 复合条件
data modify storage ns:io found set from storage ns:data items[{type:"sword",level:10..}]

# 用 tag 做精确匹配时用 # 区分 NBT path 里的同名
data modify storage ns:io tag_value set from storage ns:data item.tag."custom_tag_xxx"
# 注意上面这种，要避免和 storage ns:data item 及 tag 同名冲突
```

### 读取到 storage
```mcfunction
# 实体 NBT → storage
data modify storage ns:io player_pos set from entity @s Pos

# 方块 NBT → storage
data modify storage ns:io block_data set from block ~ ~-1 ~

# 另一个 storage → storage
data modify storage ns:io copy set from storage ns:data original
```

### Storage 命名空间惯例
```
ns:io <class>       - 暂存/IO传递（tick 结束后视为销毁，不可跨 tick）
ns:data <class>     - 内部持久数据（跨 tick 的动态/静态数据）
ns:ins <class>      - 构建数据列表（类似变量栈，[{...},{...},...]）
ns:preset <class>   - 静态预设/配置数据
```
`ns:preset <class>.name` 一般作为 `ns:io <class>` 的预设值使用。

### Storage 的存储量
storage 输出大小由 `maxCommandChainLength`（默认65536）限制，每个字符占 1 字节，实际能输出的上限约为 2000+ 个复合标签（每个约 30 字符）。

# 前端变量

## 实体 NBT 数据

实体自身的 NBT 可以直接作为变量存储，通过 `data get/modify/remove entity` 读写。

### 读取实体 NBT
```mcfunction
# 读取到计分板
execute store result score #hp ns run data get entity @s Health

# 读取到 storage
data modify storage ns:io pos set from entity @s Pos

# 读取特定路径
execute store result score #count ns run data get entity @e[type=item,limit=1] Item.count

# 条件检查
execute if data entity @s Inventory[{id:"minecraft:diamond"}] run say 有钻石
```

### 修改实体 NBT
```mcfunction
# 直接设置
data modify entity @s Health set value 20.0f

# 从另一个实体复制
data modify entity @e[tag=target,limit=1] CustomName set from entity @s CustomName

# 追加到列表
data modify entity @s ArmorItems append value {id:"leather_boots",count:1}

# 插入到指定位置
data modify entity @s Inventory insert 0 value {id:"diamond",count:1}
```

### NBT Path 语法速查
```
Path         含义
root.a       复合标签 root 下的 a
root.a.b     a 下的 b
root[0]      列表第 1 个元素
root[-1]     列表最后一个元素
root[{k:v}]  列表中等式匹配的元素
root[].a     列表中所有元素的 a
root{a:b}    同时匹配多个条件
```

### 实体 NBT 作为变量存储的优劣
**优点**：按实体隔离（天然作用域），无需额外选择器去关联
**缺点**：高频读写时开销较高，带选择器定位时需要遍历实体列表；大量实体私有数据时推荐 OhMyDat / UUID实体

### 常用实体 NBT 读写位置
| NBT Path | 类型 | 用途 |
|----------|------|------|
| `Health` | float | 生命值 |
| `Pos` | list[double] | 坐标 |
| `Rotation` | list[float] | 旋转 |
| `CustomName` | string/json | 名称 |
| `Tags` | list[string] | 标签 |
| `AbsorptionAmount` | float | 伤害吸收 |
| `Invulnerable` | byte | 无敌状态 |
| `NoGravity` | byte | 无重力 |
| `Motion` | list[double] | 速度 |

## 方块 NBT 数据

方块实体（如箱子、熔炉、告示牌等）的 NBT 同样可读写。

### 基本读写
```mcfunction
# 读取方块 NBT
data get block ~ ~-1 ~ Items

# 修改方块 NBT
data modify block ~ ~-1 ~ CustomName set value '{"text":"宝箱"}'

# 存储到计分板
execute store result score #fuel ns run data get block ~ ~ ~ BurnTime

# 条件检查
execute if data block ~ ~-1 ~ Items[{id:"minecraft:diamond"}] run say 箱子里有钻石
```

### 操作方块物品栏
```mcfunction
# 用 item 命令（更推荐，1.20.5+）
item replace block ~ ~-1 ~ container.0 from entity @s weapon.mainhand
# 或 id: container.<slot>  .0~.26（箱子大小）

# 修改物品 NBT
data modify block ~ ~-1 ~ Items[0].components."minecraft:custom_data".my_tag set value "data"
# 注意：1.20.5 后 slot tag 消失，物品数据结构变更，直接 Items[0].tag 不行
# 如果目标是 1.20.5+，推荐用 item modify 或直接操作 components
```

## @s 上的记分板（玩家真实记分板）

与假玩家记分板不同，这里记分板挂载在真实玩家或实体（@s）上。

### 实时读写
```mcfunction
# 读取实体生命值到它身上的记分板
execute store result score @s hp ns run data get entity @s Health

# 修改
scoreboard players set @s flag 1

# 检测玩家分值
execute if score @s hp matches 1.. run say 受伤了
execute if score @s hp matches ..0 run say 死了

# 实体间赋值
scoreboard players operation @e[tag=target,limit=1] hp = @s hp
```

### trigger 记分板（玩家输入）
trigger 是一种特殊的记分板 criteria，允许非 OP 玩家通过 `/trigger` 命令设置分值。
```mcfunction
# load——声明 trigger 记分板
scoreboard objectives add menu trigger

# load——为每个在线玩家启用
scoreboard players enable @a menu

# 玩家在聊天栏输入：/trigger menu set 1
# 玩家输入后 data pack 检测
execute as @a if score @s menu matches 1 run function mypack:menu/open
scoreboard players set @s menu 0    # 重置（防止重复触发）
```
新玩家加入后需要调 `scoreboard players enable`。

### criteria 自动统计
Minecraft 内置的自动跟踪统计器：
| criteria | 自动统计 |
|----------|----------|
| `dummy` | 纯手动（最常用） |
| `trigger` | 玩家输入 |
| `deathCount` | 死亡次数 |
| `playerKillCount` | 玩家击杀数 |
| `totalKillCount` | 总击杀数 |
| `health` | 当前生命值（0~20） |
| `xp` | 经验值 |
| `level` | 等级 |
| `food` | 饥饿值 |
| `air` | 氧气值 |
| `armor` | 护甲值 |
| `minecraft.custom:minecraft.xxx` | 自定义统计 |

# 上下文变量（局部变量）

上下文变量仅在当前命令执行链中有效，跟随 `execute` 子命令变化，不持久化。

## 执行者（@s）

`@s` 指向当前命令的**执行实体**，是 mcf 最重要的上下文变量之一。

```mcfunction
# 默认情况：由 tick/load 执行时 @s 无实体
# 通过 as 切换执行者
execute as @a run say my name is @s

# 执行者可以链式切换
execute as @a at @s run particle ~ ~ ~
execute as @e[type=arrow] on origin run say 射箭的玩家是 @s
```

**注意**：`@s` 必须在有执行实体时使用，否则报错。load/tick/schedule 无执行者时 @s 不可用，但 # 虚拟玩家全局记分板仍可用。

## 执行位置（Position）

位置包含三个部分：**坐标（x,y,z）、维度、旋转（yaw,pitch）**。

```mcfunction
# at：设置位置为实体位置（保留执行者）
execute as @a at @s run setblock ~ ~-1 ~ stone

# positioned：直接设坐标
execute positioned 0 100 0 run setblock ~ ~ ~ stone
execute positioned as @s run setblock ~ ~-1 ~ stone      # 只改位置，不改执行者
execute positioned over world_surface run setblock ~ ~ ~ air  # 地面高度

# rotated：设置旋转
execute rotated 0 0 run particle flame ^ ^ ^1
execute rotated as @s run summon arrow ^ ^ ^1              # 向实体面向方向生成

# in：切换维度
execute in minecraft:the_nether run say 我在下界
```

### 三种坐标
```mcfunction
# 绝对坐标（世界坐标）
setblock 100 64 100 stone

# 相对坐标（相对于当前执行位置，~ 为各轴偏移）
setblock ~ ~10 ~ stone        # 当前位置上方10格
setblock ~1 ~ ~-2 stone       # x+1, z-2

# 局部坐标（相对于执行者面向方向，^ 为前后左右上下）
particle flame ^ ^ ^1          # 面向前方1格
setblock ^1 ^ ^ stone         # 左侧1格
setblock ^ ^-1 ^ stone        # 下方1格
```

## 执行方位汇总

执行方位 = **执行者(@s) + 位置(positioned/at) + 旋转(rotated) + 维度(in) + 锚点(anchored)**

```mcfunction
# 完整示例：以每个玩家身份，在他的位置，看向最近的僵尸，在他的头顶生成粒子
execute as @a at @s anchored eyes facing entity @e[type=zombie,limit=1] feet positioned ^ ^ ^1 run particle flame ^ ^ ^
```

## store 标记（execute store）

`execute store` 将命令的返回值写入指定位置，是连接不同类型变量之间的桥梁。

```mcfunction
# result：存储命令返回值（数值型）
# success：存储命令的成功次数（0 或 1，布尔型）

# → 计分板
execute store result score #val ns run data get entity @s Health
execute store success score #found ns run data get storage ns:data flag

# → storage
execute store result storage ns:io val int 1 run scoreboard players get #count ns
execute store result storage ns:io val double 0.001 run data get entity @s Health

# → 实体 NBT
execute store result entity @s Health float 1 run scoreboard players get #new_hp ns

# → 方块 NBT
execute store result block ~ ~-1 ~ Items[0].count byte 1 run scoreboard players get #num ns

# → bossbar
execute store result bossbar my:bar value run scoreboard players get #progress ns
```

### store 的缩放参数
`execute store result score <target> <obj> run <cmd>` 等价于 `score = <cmd_return>`
`execute store result entity <target> <path> <type> <scale> run <cmd>` 等价于 `nbt_value = <type>(<cmd_return> * <scale>)`

注意：score 不支持 scale（自动截断），entity/storage/block 支持 scale。

## 基准

### 宏参数（Macro）
宏函数通过 `$` 前缀的变量，将外部数据注入为函数内上下文：

```mcfunction
# 调用宏（带参数）
function mypack:set_block with storage ns:io {block_id:"stone", y:100}
# 或使用 NBC 参数（1.21.5+ 以 SNBT 形式传入）
function mypack:set_block {block_id:"stone", y:100}

# 宏函数内部
$setblock ~ $(y) ~ $(block_id)
$say 放置了 $(block_id) 在 y=$(y)
```

宏参数仅在**当前函数调用栈**有效，每次 function 调用都会新建一层。宏内的 `$(var)` 在编译期就被替换，这也是性能最高的"变量引用"方式。

### on 关系追溯
`execute on <relation>` 允许不通过扫描（选择器）来得到相关实体：

```mcfunction
# 关系类型
on owner       # 宠物的主人、投射物的发射者
on passengers  # 所有乘客（包括骑乘者）
on vehicle     # 骑乘的实体
on origin      # 箭的发射者、物品的投掷者
on attacker    # 最后攻击本实体的实体
on controller  # 控制者（leash）
on target      # 被攻击目标
on leasher     # 用缰绳牵引的实体
```

```mcfunction
# 例：箭击中实体后，对射击者执行
execute as @e[type=arrow] on origin run say 射箭的是我
# on origin 后 @s 变为 origin，位置也变为 origin 的位置
```

### 函数标签上的基准
使用函数标签（tag）调用函数时，标签本身可能带参数/上下文：
```json
// data/<namespace>/tags/function/iterate.json
{
  "values": [
    {"id": "mypack:step", "required": false}
  ]
}
```
具体运行时，宏函数内可通过 `$(<nbc_param>)` 注入。

## 分支栈

mcf 中的 `execute if/unless` 会产生**条件分支**。`execute if` 失败时跳过后续子命令，继续执行下一条顶层命令（即函数内不阻断）。这一点与 `return run` 不同：

```mcfunction
# 分支不会阻断后续命令
execute if score #flag ns matches 1 run say flag is 1
say 这句话一定会执行

# return run 会中止当前函数
execute if score #flag ns matches 1 run return run say flag is 1
say 这句话如果 flag=1 就不会执行
```

`/return` 是真正的函数返回，会产生**分支栈**：
```mcfunction
# 子函数返回
# main.mcfunction
function mypack:sub
say 子函数执行完毕

# sub.mcfunction
scoreboard players set #result ns 42
return 1    # 返回整数 1（子函数返回值是 1）
```

`return` 不影响主调函数的后续流程，但可以传递整型返回值供 `execute store result` 捕获：
```mcfunction
# 捕获返回值
execute store result score #out ns run function mypack:sub
# 如果 sub 里写了 return 42，那么 #out 就是 42
```

### return run 与 store 的交互
```mcfunction
# 在一些情况下 return run 后的 store 会失败
# 一般来说：
execute store result score #out ns run function foo
# foo 内是 return 42   → #out = 42

execute store result score #out ns run return 42
# return 42              → #out = 42（直接 return 也可以）

# 但如果 foo 内 return run 了另一个 function
# execute store 的链路可能被打断（具体取决于版本）
```

### schedule 的上下文
`schedule` 在新 tick 执行，但**不保留**原调用的执行者、位置等上下文：
```mcfunction
# ❌ 错误：schedule 后 @s 不存在
execute as @a run schedule function mypack:delayed 1t

# ✅ 正确：schedule 函数内用选择器重新获取目标
# schedule 函数内部：
execute as @a[tag=delayed_action] run say 延迟执行
```

## 变量选型速查

| 场景 | 推荐方案 |
|------|----------|
| 整数的增删改查 | 计分板 `scoreboard players` |
| 整数的复杂运算 | 计分板 `scoreboard players operation` |
| 浮点数存储 | storage / NBT (float, double) |
| 字符串 | storage 或 text_component NBT |
| 列表/数组 | storage list |
| 复合结构（key-value） | storage compound |
| 布尔标记（选择器筛选） | tag（实体） 或 计分板 0/1 |
| 跨函数传参 | storage ns:io（或用宏参数） |
| 跨维度传参 | storage（唯一可行方案） |
| 跨 tick 持久 | storage / 计分板 / 实体 NBT |
| 高频读写 | 计分板 #虚拟玩家 > storage > 实体 NBT |
| 按实体隔离的数据 | 实体 NBT（少量）或 OhMyDat（大量） |
