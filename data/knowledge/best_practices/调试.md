# 查看数据通用流程

## 关键概念：上下文
执行者：@s读取的对象
执行方位：维度+位置+朝向（at一次性设置三者，也可以单独设置：positioned as 选择器 / positioned x y z / rotated as 选择器 / rotated roty rotx / in <维度>）
基准：脚/眼睛，为隐藏变量，输入给^ ^ ^，决定^ ^ ^是否读取@s来增加初始眼睛偏移
返回值地址：了解即可，调试中一般用不到

## 查看数据
### 核心思路
1. `execute at <选择器>`/`execute in 维度 positioned x y z` → 确定执行方位
2. `as <选择器>` → 创建分支，相当于for @s in 选择器
3. `data get / scoreboard players get / tellraw / ...` → 读取数据
> 1.或2.可以视情况省略，如果上下文就是在调试的实体和要调试的位置处，则只要写第三步。
> 1.和2.可以交换顺序和任意排列组合。如as <选择器> at @n[distance=0.01..] positioned ~ ~1 ~ run ...

### 聊天框调试
```mcfunction
# 1. 验证实体是否存在，存在几个
execute at <player> run say 一共有：@e[type=interaction,distance=..5]
# 2. 查看实体 NBT，如果有多个，则会逐条返回，也可以加nbt路径调试特定值
execute at <player> as @e[type=interaction,distance=..5] run data get entity @s
execute at <player> as @e[type=interaction,distance=..5] run data get entity @s attack
# 3. 查看计分板
execute at <player> as @e[type=interaction,distance=..5] run scoreboard players get @s <namespace>.owner
# 4. 查看玩家 ID
execute as <player> run scoreboard players get @s <namespace>.id
```

### 数据包内调试
#### 注意
不建议使用除了say和tellraw以外的手段来调试。其他调试手段多次触发时难以辨识，可能导致漏掉错误。

#### tellraw 格式化输出示例
```mcfunction
# 类似"".join([...])
tellraw @a [\
  {score:{objective:"<计分板>",name:"<玩家假名或选择器或uuid>"}},\
  "\n换行，这里可以加任意文本\n",\
  {storage:"<命名空间>:<路径>",nbt:"<NBT路径>"},"\n ",\
  {entity:"@s",nbt:"<NBT路径>"},"\n ",\
  {block:"<x> <y> <z>",nbt:"Items"},"\n "\
]

# 类似"".format(...)
tellraw @a {"translate":"也可以使用格式化字符串：\n%s, \n%s, \n%s, \n%s, \n%s",with:[\
  {score:{objective:"<计分板>",name:"<玩家假名或选择器或uuid>"}},\
  "\n换行，这里可以加任意文本\n",\
  {storage:"<命名空间>:<路径>",nbt:"<NBT路径>"}," ",\
  {entity:"@s",nbt:"<NBT路径>"}," ",\
  {block:"<x> <y> <z>",nbt:"Items"}," "\
]}
```

#### say 快速输出
`say` 是最快的"print 执行流"方式。`say` 会自动带上 `@s` 的名字，可以辅助查看当前执行上下文是谁。
`say` 的message中也可以加入选择器，当mcf解析器遇到@之后会自动解析后面的内容。
```mcfunction
execute if ... run return run function ...

# 这里say 1可以用来判断function有没有被执行
say 1
```

#### 函数截断
```
say 1
# 拦截后续行为
return run say break!
say 2
```

### 快速获取坐标
execute 内联 summon 可以快速创造幽灵物品，以此获取上下文位置。
所有幽灵实体会在下tick内消失。
但是幽灵物品会改变 @s 引用的对象，因此幽灵物品一般放在 run 之前。
同tick内召唤大量幽灵实体可能导致内存泄漏，阈值大约为5万。
```mcfunction
execute at @a[sort=random,limit=1] positioned ^ ^ ^1 summon item run data get 
```
