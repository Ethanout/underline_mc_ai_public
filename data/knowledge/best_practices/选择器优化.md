# 选择器优化：源码层分析

## 核心原则

### 1. 永远用 `type=` 限制 @e
MC 内部按类型索引实体。`@e[tag=target]` 扫所有实体；`@e[type=zombie,tag=target]` 只扫僵尸实体。
```mcfunction
# 差：全量扫描
execute as @e[tag=target] run ...
# 好：类型索引后过滤
execute as @e[type=zombie,tag=target] run ...
```

### 2. 永远加 `distance=`
`@e` 不加 `distance` 会扫所有维度。`distance=0..` 是无实际限制的最快写法。
```mcfunction
# 差：扫全部维度
@e[type=item]
# 好：限定当前维度
@e[type=item,distance=0..]
```

### 3. `nbt=` 是最后一道防线
`nbt=` 在选择器内会复制所有匹配实体的完整 NBT，**消耗极大**。永远用 `if data` 替代。
```mcfunction
# 差：选择器内用 nbt=
@a[nbt={SelectedItem:{id:"minecraft:stone"}}]
# 好：轻量过滤后 + if data
execute as @a if data entity @s SelectedItem{id:"minecraft:stone"} run ...
```

### 4. `limit` 只在无 `sort` 时高效
`limit=1` 无 sort：命中的第一个即返回。`sort=nearest,limit=1`：先扫全部再排序再取第一个。

### 5. `dx/dy/dz` 是高效的预过滤器
形成 Box 后 MC 先检测区块交集，再测试其他谓词。大范围扫描先缩小盒子。

## 常见陷阱
```
@s + sort=nearest → 退化为 @a 行为（Mojang 没有阻止这种写法）
scores={} 重复键 → HashMap 覆盖，最后一个生效
tag= 矛盾 → @e[tag=a,tag=!a] 永远为空
```

## NBT 缓存模式
```mcfunction
# 差——读 3 次玩家 NBT
execute if data entity @s SelectedItem{id:"stone"} run ...
execute if data entity @s SelectedItem{id:"dirt"} run ...

# 好——读一次到 storage
data modify storage tmp:cache item set from entity @s SelectedItem
execute if data storage tmp:cache item{id:"stone"} run ...
execute if data storage tmp:cache item{id:"dirt"} run ...
```
