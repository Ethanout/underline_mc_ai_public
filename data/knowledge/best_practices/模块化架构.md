# 模块化架构（MCBookshelf 模式）

## 核心理念
```
每个模块 = 一个独立数据包

mcbui/pack.mcmeta        → UI 框架
mcbui/data/mcbui/func/    → 公有 API + 私有实现

myui-pack/pack.mcmeta       → 依赖 mcbui 的 UI 包
pack.txt / manifest.json     → 声明依赖
```

## 模块接口定义
```json
// mcbui/data/mcbui/tags/function/api.json
{
  "values": [
    "mcbui:api/open_menu",
    "mcbui:api/close_menu",
    "mcbui:api/update_slot"
  ]
}
```

## 依赖管理（pack.txt）
```
# pack.txt
name: MyUI
author: You
version: 1.0.0
dependencies:
  - mcbui: ^2.0.0
  - oh_my_dat: ^3.1.0
```

## 注册模式
```mcfunction
# #minecraft:load
execute unless score mcbui.registered bs_init matches 1 run function mcbui:_register
scoreboard players set mcbui.registered bs_init 1
```

## 帮助系统
```mcfunction
# module_name:help
tellraw @a [{"text":"== ModuleName v1.0 ==","color":"gold"}]
tellraw @a [{"text":"  #module:api/function1 - 描述","color":"gray"}]
```

## I/O 规格化
- 建议统一使用 `namespace:io` / `namespace:data` 命名空间
- 输入输出严格文档化
- 使用 `#` 虚拟玩家作为计分板命名空间

## 模块粒度建议
- 不要太大：一个模块只做一件事
- 不要太小：避免大量单函数模块
- 参考标准：MCBookshelf 的一个典型模块 ≈ 5~20 个函数
