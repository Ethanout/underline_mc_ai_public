# 存储选型：storage vs 实体 vs 计分板

## 决策树

```
需要存什么？
├── 整数 → 计分板（最快，O(1) 哈希）
│   └── 虚拟玩家用 #/前缀性能最好
├── 复杂数据（复合/列表/字符串）
│   ├── 全局数据 → storage（无实体开销）
│   ├── 大量实体私有数据 → OhMyDat 或 UUID实体
│   ├── 少量实体私有数据 → entity NBT
│   └── 跨维度传递 → storage（唯一全局容器）
└── 布尔标记 → 计分板 或 tag
    └── tag 对选择器友好，计分板对运算友好
```

## 各方案成本
| 方案 | 读开销 | 写开销 | 优点 | 缺点 |
|------|--------|--------|------|------|
| 计分板 #虚拟玩家 | 极低 | 极低 | 最快，支持运算 | 只有整数 |
| storage | 低 | 低 | 支持复合数据 | 层数多时变慢 |
| 实体 NBT | 中 | 中 | 按实体隔离 | 需选择器定位 |
| 玩家 NBT | 高 | 高 | 随玩家存档 | 最慢的 NBT |
| 方块实体 | 中高 | 中高 | 按位置固定 | 需加载区块 |

## 经验法则
- **跨函数传参**：storage（namespace:io）
- **跨维度传参**：storage（唯一方案）
- **高频计数器**：计分板 `#` 虚拟玩家
- **大量实体的私有数据**：OhMyDat 或 UUID 映射
- **不用选择器时的实体数据**：固定 UUID 实体
- **不要**把复杂数据存在玩家或普通实体的 NBT 中高频读写
