# 可维护性：版本兼容策略

## overlay 分层结构
```
<datapack>/
├── pack.mcmeta       # 声明 min/max_format + overlays
├── data/             # 主目录（当前版本兼容）
├── overlay_v48/      # 低版本覆盖
│   └── data/
│       └── minecraft/
│           └── recipe/  # 覆盖低版本的配方
└── overlay_v71/      # 中间版本覆盖
    └── data/
```

## pack.mcmeta 配置
```json
{
  "pack": {
    "description": "Multi-version pack",
    "min_format": [88, 0],
    "max_format": [101, 1]
  },
  "overlays": {
    "entries": [
      { "directory": "legacy_v48", "min_format": 48, "max_format": 71 },
      { "directory": "legacy_v72", "min_format": 72, "max_format": 87 }
    ]
  }
}
```

## 需要版本隔离的常见差异
| 差异点 | 分水岭版本 |
|--------|-----------|
| 文件夹单复数（functions→function） | 1.21 (pf 48) |
| 物品组件系统 | 1.20.5 (pf 41) |
| 配方输出写组件 | 1.20.5 (pf 41) |
| 文本组件→NBT对象 | 1.21.5 (pf 72) |
| pack.mcmeta min/max_format | 1.21.9 (pf 88) |
| 副手位置（Inventory→equipment） | 26.1 (pf 97) |

## 最佳实践
1. 尽量兼容向下到 1.21（pf 48），用 overlays 处理关键差异
2. 重大格式变更（如组件系统）建议用 overlays 拆版本层
3. 不要在 tick 函数里做版本判断——在 load 时判断一次并存入标记
