# 性能分析与调试

## 日常监控
- `Ctrl+F3`：查看实体数和 TPS
- `/perf`：性能报告（MSPT、实体耗时等）
- `F3+L`：启动 Profiler，10 秒后导出到 `debug/profiler/`
- `/debug start` / `/debug stop`：详细诊断

## 识别卡顿源头

### 看 MSPT
- MSPT < 25ms → 完美
- MSPT 25~40ms → 卡顿感
- MSPT > 40ms → 严重卡顿

### 看 /perf 报告
- `root` 下的 `tick` 阶段：
  - `entities`：实体数量/逻辑
  - `blocks`：方块更新
  - `commandFunctions`：数据包函数执行时间

## 常见卡顿模式

### 模式 1：每 tick 大量实体
```
entities 阶段 > 10ms → 实体太多
```
解决：用 marker + UUID 替代常规实体；减少 tick 函数的选择器扫描。

### 模式 2：递归函数太深
```
commandFunctions 阶段高 → 函数递归深度过大
```
解决：用计分板计数器控制递归深度；拆分为批次调度。

### 模式 3：展示实体编组更新
```
entities → display entities 阶段高
```
解决：展示实体变换拆分太多；考虑 `interpolation_duration` 缓动或替代方案（如粒子）。

## 函数级 Profiling
在关键函数前后插入时间戳：
```mcfunction
schedule function mypack:tick 1t

# tick
schedule function mypack:tick 1t
execute store result score #tick_start bs.data run time query gametime
... your logic ...
execute store result score #tick_end bs.data run time query gametime
scoreboard players operation #tick_cost bs.data = #tick_end bs.data
scoreboard players remove #tick_cost bs.data #tick_start bs.data
```
（精度仅 1 tick = 50ms，适合检测"哪个函数跑超过 1 tick"）

## 压力测试（/tick sprint）
```mcfunction
/tick sprint 10s
```
在虚空存档把被测命令复制 1000 次放大消耗，对比空载 ms/tick：
```
(测试ms - 空载ms) / 1000 = 单次运行消耗时间
```

## F3+2 性能监视器
- 左边 = 渲染（显卡）
- 右边 = 逻辑（CPU），应保持 < 10ms

## F3+L 火焰图
按 `F3+L` 录制 10 秒，自动生成 profiler 压缩包。
解压后 `server/profiling/` 下的 HTML 文件可查看详细火焰图。

## 调试技巧
- `/reload`：热重载函数/配方/战利品表/谓词/标签
- 用 `say` 或 `tellraw` 追踪执行流
- `data get entity @s`：随时查看实体 NBT
- 在 `#minecraft:load` 中 `say` 确认加载成功
