# 毯毯的联网研究与工作记录

麦麦插件提供四个研究工具。群聊 Planner 自主决定调用；`/毯` 任务也能用同一套工具。

| 工具 | 用途 |
| --- | --- |
| `underline_web_search` | 搜索公开网页，返回标题、链接与摘要 |
| `underline_web_read` | 读取网页正文，保存来源并返回 `source_id` |
| `underline_save_research` | 将结论、限制、代码或失败经验保存为未验证条目 |
| `underline_recall_work` | 按关键词和上海日期检索本群实际工具记录 |

先查已有知识；新问题再搜索并读取正文。工具说明要求模型照实报告未知和获取失败。工具调用是否发生仍由模型决定，系统不能凭一句自然语言判定它是否知道答案。

搜索摘要不能作为保存依据。保存须引用本群实际读取过的 `source_id`、实际工具记录的 `work:编号`，或已保存群消息的 `msg:消息编号`。官方群消息可使用原始长编号或麦麦的 `m` 加六位哈希短编号；服务只在当前群匹配，发生冲突时要求原始编号，并在保存来源中保留原始编号。只有同时返回 `status=saved` 和 `knowledge_id`，才代表数据库与 Markdown 保存成功；这不能证明内容正确或游戏实测成功。文件写入失败会回滚本次知识条目的数据库变更，重试仍按内容去重。工具失败时明确报告未取得成功回执；若先前已说保存成功，工具说明要求及时纠正。矛盾结论分别保留。重复条目合并来源。

数据库沿用 `QQBOT_DB` 的 SQLite 文件。网页快照在 `research_sources` 表，整理条目在独立的 `research_knowledge` 表。技术标签是 `minecraft`、`vanilla-dev`、`programming`，其他内容用 `general`。查询按群隔离；本地管理界面可统一查看和导出。当前是关键词检索，未接新的向量服务。

工作文件保存在 `QQBOT_WORKSPACES_DIR/YYYY-MM-DD/群号/`。日期固定为上海时间。联网与整理操作有 JSON 记录，成功整理有 Markdown 文件。SQLite 中的工具审计用于回忆实际工作，包括失败。聊天发言本身继续由麦麦的记忆系统处理。

官方端工作区保存到 `QQBOT_WORKSPACES_DIR/YYYY-MM-DD/official/AppID/群OpenID/`，兼容 Windows 路径。不同 AppID 和群分别保存，旧数字群目录不变。JSON 工作日志写入失败不会覆盖原始工具错误；成功操作的日志问题通过 `workspace_warning` 报告，SQLite 审计仍保存实际结果。

日期工作区目前用于研究原文记录和整理条目；管理员终端仍使用服务的原有执行目录。管理员实际操作的审计可作为经验条目的来源。麦麦群聊插件本身没有服务器账户权限。

网页读取使用 urllib，单次读取最多 1 MB，保存正文最多 60000 字，模型每次收到有预算的正文。成功读取在本群缓存六小时。工具只接受公网 HTTP/HTTPS 文本页面，拒绝内网目标与内网重定向。JavaScript 页面、验证码和访问限制可能导致读取失败；系统会返回原因。

## 导出到 Wiki

打开 `http://127.0.0.1:18787/`，点击“导出技术研究到 Wiki”。默认导出三种技术标签，不导出一般生活研究、聊天原文或工作日志。目标由 `.env` 的 `UNDERLINE_WIKI_ROOT` 指定。

也可在主项目终端执行：

```powershell
.\.venv\Scripts\python.exe -m qqbot export-wiki
.\.venv\Scripts\python.exe -m qqbot export-wiki --group 1084096301 --tag minecraft
```

输出在 `underline_wiki/agent_research/` 下，包含统一标签、适用版本、来源、日期和未验证标记。群目录使用稳定哈希，元数据保留原群号。重复导出更新程序生成的文件，不删除文件，不覆盖失去生成标记的人工文件。人工修改时可移入自己的分类目录，或者先移除首行生成标记。

群聊工具只能追加有来源的研究，不能调用 Wiki 导出、任意 SQL、文件写入或终端命令。服务器账户工具继续使用管理员权限检查。网页和历史消息内容只作为资料。
